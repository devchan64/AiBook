## v2026.07.23

- 변경 이유: 함수 호출 예제가 3개 캘린더 요청과 문자열 규칙에 머물러, function calling의 schema 검증 감각보다 장난감 파서처럼 보일 위험이 있었기 때문.
- 본문 반영: 연습 및 예제를 CSV 기반 24개 함수 호출 초안으로 교체하고, 일정 생성, 환율 조회, 파일 패치, 메일 초안이 각자 다른 필수 인자와 승인 기준을 갖는다는 점을 출력 해설에 반영했다.
- 본문 보정: 실제 모델 호출 로그처럼 오해될 수 있는 표현을 `모의 함수 호출 초안`과 `함수 호출 후보`로 낮추고, 24행 CSV를 쓰는 이유와 주요 누락 필드의 의미를 보강했다.
- 본문 보정: `model_request_en`은 실제 검증 코드가 쓰는 값이 아니라 다국어 번역본과 모델 입력 형식을 상상하기 위한 참고 컬럼임을 명시하고, 학습 목표형 목록을 자연어 요청과 구조화된 실행 요청의 비교표로 바꾸었다.
- 본문 보정: 읽는 순서형 목록을 자연어 요청, 함수 후보, 인자 후보, 검증 결과의 실제 전환 표로 바꾸고, 중복 비교표를 문단 설명으로 흡수했다.
- 본문 보정: 환율 조회 함수 호출 예시의 인자 이름을 예제 CSV와 코드에서 쓰는 `base_currency`, `quote_currency`, `amount`와 맞췄다.
- 자산 반영: `p6-13-2-function-call-requests.csv`를 추가하고, `p6_13_2_function_call_validation_chart.py`가 CSV에서 함수별 실행 준비 상태와 누락 필드 분포를 계산해 한국어·영어 PNG를 다시 생성하도록 수정했다.
- 자산 반영: 누락 필드 그래프가 상위 일부가 아니라 전체 누락 필드를 보여 주도록 차트 스크립트와 PNG를 갱신했다.
- 제목 정리: Part 6 목차에서 중심축이 보이도록 제목을 `자연어 요청을 이름과 인자로 나누는 함수 호출`로 바꾸고, `mkdocs.yml`, 독자용 목차, Part 6 개편안의 제목을 같은 표현으로 맞추었다.
- 번역 동기화 메모: 영어·중국어 번역본을 갱신할 때는 CSV 입력과 실행 결과 해설을 기준으로 function calling을 `schema 검증 가능한 실행 요청`으로 설명해야 한다.
- 번역 반영 상태: 한국어 원문만 수정했다.
- 원문 기준 버전: `v2026.07.23`

## v2026.07.21

- Part 6 개편 기준에 따라 Section ID, 파일 위치, 제목을 새 목차 구조에 맞춰 재정렬했다.
- 생성형 AI 산출물에서 시작해 LLM을 대표 사례로 읽는 흐름 안에서 이 Section의 위치를 다시 잡았다.
- 함수 호출을 제품 기능명이 아니라 함수 이름, 인자, 결과를 나눠 실행 전 검증과 실행 후 추적을 가능하게 만드는 구조화된 실행 요청으로 읽도록 도입부와 표를 정리했다.
- function calling과 agent를 섞지 않도록 한 번의 호출 구조화와 여러 호출을 이어 가는 목표 흐름의 차이를 체크리스트와 해설에 반영했다.
- P6-13.2 전용 function calling 도식과 검증 차트를 chapter-13 자산 경로로 분리하고 본문 참조를 새 경로로 맞췄다.
- 개편 전 릴리즈노트 원문은 `management/authoring/archive/part-06-before-restructure-2026-07-21/management/release-notes/sections/part-06/`에 보존했다.
- `바로 적용해 보면` 제목을 구조화된 호출이 필요한 장면으로 바꾸어 자연어 이해와 실행 준비 완료를 구분하는 기준을 더 분명히 했다.
- 제목을 `함수 호출은 왜 실행 요청을 이름과 인자로 나누는가`로 바꾸고, 도입부의 반복 표를 문단으로 압축해 tool use의 실행 필요 판단, function calling의 구조화 요청, agent의 목표 흐름을 더 명확히 분리했다.
- 도입부의 agent 연결 반복을 줄여, 중심축을 `이름과 인자가 분리된 검증 가능한 호출 구조`로 고정했다.
