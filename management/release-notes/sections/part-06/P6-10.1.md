- 생성형 AI 산출물에서 시작해 LLM을 대표 사례로 읽는 흐름 안에서 이 Section의 위치를 다시 잡았다.
- 프롬프트 엔지니어링을 좋은 문장 요령이 아니라 지시, 맥락, 예시 중 비어 있는 칸을 찾아 채우는 입력 설계로 읽도록 도입부를 정리했다.
- 프롬프트 입력 조정, RAG 근거 연결, tool use/agent 실행 구조의 층위를 번호 나열이 아니라 역할 구분으로 보강했다.
- P6-10.1 전용 도식과 차트 자산을 chapter-10 경로로 분리하고, 독자 진행 안내식 표현을 개념 경계 중심 문장으로 정리했다.
- 개편 전 릴리즈노트 원문은 `management/authoring/archive/part-06-before-restructure-2026-07-21/management/release-notes/sections/part-06/`에 보존했다.
- `바로 적용해 보면` 제목을 입력 설계로 먼저 줄일 수 있는 장면으로 바꾸어 프롬프트가 맡는 조정 범위를 더 분명히 드러냈다.
- 요약, 분류, 문서 기반 질의응답 사례에서 막연한 기대와 입력 설계 기준 전환을 문단으로 나누어 프롬프트가 조정하는 범위가 더 선명하게 읽히도록 했다.
- 문서 기반 질의응답 사례의 근거 문단 제공과 기준 전환 해설을 추가로 분리해 질문 작성과 문서 범위 고정의 차이를 더 또렷하게 했다.
- 제목을 `프롬프트 엔지니어링은 무엇을 입력에서 조정하는가`로 바꾸고, 도입부와 사례 요약의 반복 표를 문단 설명으로 압축해 입력 설계라는 중심축을 더 선명하게 했다.
