- 본문 반영: `지금 이 보충학습에서 읽는 것` 표 머리글을 내용 중심 표현으로 낮추고, `바로 적용해 보면` 표를 사례 뒤의 `실패 장면에서 다시 보는 기준`으로 옮겼다.
- 중복 정리: 적용 표와 기존 실패 표가 연속으로 같은 역할을 반복하지 않도록 실패 기준 표를 하나로 통합했다.
- 관련 자산: `긴 입력 문제 -> 계산 부담 / 단서 유지 -> sparse attention / long-context 설계` 흐름을 보강하는 Mermaid 도식 `p6-c03-s05-diagram-01-en.mmd` / `p6-c03-s05-diagram-01-ko.mmd`를 추가했다.
- 사례 정리: 독립 사례라기보다 오해 정리에 가까웠던 `길이는 길어졌는데 핵심 단서는 약해지는 경우`를 별도 사례에서 내리고, 로그 분석과 계약서 읽기 사례 뒤의 연결 문단으로 압축했다.
- 연습 정리: 바로 앞 실패 기준 표와 같은 분류를 반복하던 연습 표를 삭제하고, 긴 로그와 배포 문서가 섞인 장면에서 계산 부담과 단서 유지를 직접 분리해 보는 적용 연습으로 바꿨다.
- 정리 반영: 본문 메타데이터를 현재 Section 가이드 형식과 날짜 버전에 맞췄다.
- 번역 동기화 메모: 대응 번역본이 생기면 도입부 구분 목록 압축과 실패 장면 적용 표의 위치 변경을 함께 반영해야 한다.

### v2026.07.18
- 본문 반영: `초심자는 두 이름을 처음 보면`, `초심자가 실제 실패 장면을 봤을 때`, `초심자라면` 같은 표지를 더 줄여, sparse attention과 long-context를 가르는 질문이 독자 라벨보다 계산 부담과 단서 유지 차이로 먼저 보이게 다듬었다.; `이 보충학습의 범위`, `이 보충학습의 목표`처럼 보충 절의 진행을 드러내는 메타 제목을 `장문맥 계산과 유지가 다루는 질문`, `여기서 남겨야 할 구분`으로 바꿔, 실제 구분해야 할 문제가 먼저 보이게 정리했다.; 본문 중 `초심자 기준에서는`처럼 설명 바깥에서 독자층을 다시 표지하던 문장을 줄이고, 긴 입력 문제를 어떤 질문으로 가를지 바로 설명하는 구조로 다듬었다.; 도입 첫 문장에서 sparse attention과 long-context가 모두 긴 입력 문제와 연결되지만 같은 기술 이름은 아니며, `연결 수 조절`과 `핵심 단서 유지`라는 다른 층위로 읽어야 한다는 점을 더 직접 적었다.
- 추가 반영: 범위 안내에서도 이 절의 닫힘을 `긴 입력 문제` 일반론이 아니라 계산 부담과 단서 유지라는 두 질문을 갈라 놓는 일로 다시 못 박았다.; 제목을 `sparse attention과 long-context를 처음 읽는 법`에서 `sparse attention과 long-context는 장문맥에서 무엇이 다른가`로 바꿔, 집필 메타 표현보다 `연결 수 조절`과 `장문맥 유지`를 가르는 실제 질문이 먼저 보이게 정리했다.; 기존 `P6-3.4`에 함께 있던 sparse attention과 long-context 설명을 새 보충학습으로 분리해, `연결 수 조절`과 `장문맥 유지`를 한 질문 축 안에서 따로 읽게 정리했다.; 현재 절은 긴 로그 분석, 계약서 읽기, 길이 증가와 핵심 단서 유지 구분 사례를 통해 sparse attention과 long-context를 같은 최적화 이름이 아니라 다른 층위의 문제로 구분하도록 구성했다.
- 정리 반영: 같은 날짜 재수정에서 `모든 연결을 줄이는 문제`와 `긴 문맥에서 핵심 단서를 유지하는 문제`를 더 또렷하게 나누기 위해, 기본 self-attention 대비 sparse attention이 무엇을 줄이려는지, long-context가 왜 단순 길이 숫자보다 넓은 설계 문제인지, 둘이 막으려는 실패 장면이 무엇인지 초심자 기준 문장과 비교표로 보강했다.; 같은 날짜 후속 재검토에서 `긴 입력 문제` 안에 `비교 수 증가`, `핵심 단서 유지`, `context window 숫자 증가`가 다시 뭉개지지 않도록, 실제 실패 장면을 `먼저 던질 질문 -> 더 직접 연결되는 것`으로 가르는 `바로 적용해 보면` 표를 추가했다.; 제목 아래 `Section ID`, `Version` 표기를 저장소 규칙 형식으로 바로잡았다.
- 번역 동기화 메모: 대응 번역본이 생기면 새 Section 추가와 함께 sparse attention/long-context 분리 구조를 같이 반영해야 한다.
