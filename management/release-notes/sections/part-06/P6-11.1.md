## v2026.07.24

- 변경 이유: RAG 설명에서 벡터 데이터베이스를 아예 배경 밖으로 밀면 문서가 어디서 검색되는지 흐려지고, 반대로 ChromaDB 구현을 길게 넣으면 P6-12.1의 저장 구조 중심과 겹치기 때문.
- 본문 반영: 도입부의 반복 질문과 진행 문구를 줄이고, RAG의 중심을 `기억 답변 대신 질문 주제와 맞는 현재 근거 문서를 먼저 붙이는 구조`로 더 빠르게 고정했다.
- 본문 반영: RAG에서 문서가 저절로 붙는 것이 아니라 검색 가능한 저장 구조에서 회수되며, 그 저장 구조 중 벡터 데이터베이스가 자주 쓰인다는 연결 문장을 추가했다.
- 본문 반영: `grounding_ready`를 검색된 문서 개수와 분리하고, 상위 문서의 주제 일치, 현재 버전, 답변 안 최신 단서 언급 여부가 함께 맞을 때만 준비된 근거 연결로 보도록 출력과 해설을 조정했다.
- 본문 반영: 도입부의 프롬프트/RAG 구분 표를 문단으로 축약하고, 사례 뒤 판단 표가 실제 회수 역할을 맡도록 중복을 줄였다.
- 본문 반영: `current_signal`이 정답 신호처럼 보이지 않도록 코드와 출력의 이름을 `expected_update` 언급 여부로 낮추고, 관찰용 단서라는 해설을 보강했다.
- 본문 반영: 마지막 요약 절을 그래프 해설 문단으로 합쳐 `RAG의 핵심은 답변 전에 현재 근거를 회수하는 구조`라는 결론이 반복되지 않게 했다.
- 본문 반영: ChromaDB와 payload 회수 보강 예제는 P6-12.1의 중심 질문과 겹치므로 P6-11.1 본문에서는 제거하고, 이 절은 `답변 전에 근거를 찾아 붙인다`는 구조 확인에 집중하도록 조정했다.
- 번역 동기화 메모: 향후 번역본도 P6-11.1에서는 벡터 데이터베이스를 검색 저장소의 대표 예로 짧게 언급하고, ChromaDB API와 payload 반환 구조는 P6-12.1에서 본격 설명한다.
- 번역 반영 상태: 한국어 원문만 수정했다.
- 원문 기준 버전: `v2026.07.24`

- RAG를 긴 프롬프트 작성 요령이 아니라 답변 전에 외부 근거 문서를 연결하는 구조로 읽도록 도입부와 판단 표를 정리했다.
- 프롬프트 조정, RAG 근거 연결, tool use 실행 연결의 층위를 분리해 후속 검색·실행 구조와 자연스럽게 이어지도록 문장을 보강했다.
- P6-11.1 전용 RAG 도식과 근거 점검 차트를 chapter-11 자산 경로로 분리하고, 후속 Section 연결 번호를 현재 목차에 맞게 정리했다.
- 개편 전 릴리즈노트 원문은 `management/authoring/archive/part-06-before-restructure-2026-07-21/management/release-notes/sections/part-06/`에 보존했다.
- `바로 적용해 보면` 제목을 근거 연결이 필요한 장면으로 바꾸어 RAG를 질문 표현보다 답의 재료를 현재 문서로 고르는 구조로 읽게 정리했다.
- 제목을 `RAG는 왜 답변 전에 외부 근거를 붙이는가`로 바꾸고, 도입부의 반복 표를 문단으로 압축해 답의 출발점이 모델 기억에서 문서 근거로 이동한다는 중심축을 더 선명하게 했다.
- 도입부의 RAG 경계 설명 반복을 줄여, 중심축을 `답하기 전에 어떤 문서를 먼저 붙일 것인가`로 고정했다.
