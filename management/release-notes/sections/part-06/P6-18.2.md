## v2026.07.23

- 변경 이유: Part 6 목차에서 질문형 제목이 반복되어 Section 중심축이 한눈에 구분되기 어려웠기 때문.
- 본문 반영: 제목을 `응답보다 근거·상태·회고를 먼저 남기는 최소 구현`으로 바꾸어 Part 7로 넘어가기 전 남겨야 할 기록 축을 목차에서 보이게 했다.
- 목차 반영: `mkdocs.yml`, 독자용 목차, Part 6 개편안의 제목을 같은 표현으로 맞추었다.
- 예제 반영: 코드 안에 직접 넣던 정책 문서 4개와 질문 3개를 정책 문서 CSV와 36개 질문 CSV 기반 실행 기록 예제로 바꾸어, 요청 상태와 사람 검토 필요 여부가 여러 입력에서 어떻게 분포하는지 보이게 했다.
- 예제 보강: 대표 상세 기록에 문서 점수, 선택 근거, 답변 초안, 평가 상태를 함께 출력해 실행 기록이 무엇을 남겨야 하는지 결과에서 바로 확인되게 했다.
- 해설 보강: 질문 키워드 그룹과 문서 키워드 그룹을 대조하는 단순 검색의 한계를 설명하고, 주변 문서가 함께 잡히는 결과를 재순위화와 groundedness 점검 필요성으로 읽게 했다.
- 그래프 반영: 그래프 생성 스크립트가 같은 CSV 기반 실행 기록 요약을 읽어 요청 실행 상태와 사람 검토 필요 분포를 생성하도록 바꾸었다.
- 번역 동기화 메모: 향후 번역본도 최소 구현을 응답 자체보다 근거, 상태, 회고 기록을 남기는 관점으로 제목화한다.
- 번역 반영 상태: 한국어 원문과 목차만 수정했다.
- 원문 기준 버전: `v2026.07.23`

## v2026.07.22

- 변경 이유: Part 6 본문에서 진행 메타형 소제목을 구체 개념, 비교 대상, 판단 기준이 드러나는 제목으로 정리하기 위함.
- 본문 반영: `여기서 남겨야 할 구분`, `여기까지를 한 줄로 묶으면`, `보는 순서`, `이 예제를 ... 다시 보면` 계열 제목을 현재 절의 실제 구분 축과 설명 흐름이 보이는 소제목으로 바꾸었다.
- 번역 동기화 메모: 향후 번역본도 진행 안내형 제목보다 현재 절의 구체 개념, 비교 대상, 판단 기준이 보이는 소제목으로 맞춘다.
- 번역 반영 상태: 한국어 원문만 수정했다.
- 원문 기준 버전: `v2026.07.22`

## v2026.07.21

- Part 6 개편 기준에 따라 Section ID, 파일 위치, 제목을 새 목차 구조에 맞춰 재정렬했다.
- 생성형 AI 산출물에서 시작해 LLM을 대표 사례로 읽는 흐름 안에서 이 Section의 위치를 다시 잡았다.
- 제목을 실행 기록 중심 질문형 제목으로 조정하고, 목차와 개편 기준 문서의 Section 명칭을 함께 맞췄다.
- 최소 구현을 `돌아가는 코드`가 아니라 검색 품질, 상태 분류, 사람 검토 handoff의 패치 우선순위를 읽는 기준선 구현으로 정리했다.
- 진행 메타 중심 문장을 줄이고, 요청 실행 기록이 근거 부족, 문서 미회수, 사람 검토 필요 상태를 숨기지 않게 하는 학습 축을 보강했다.
- 답변 문자열, 근거 문서, 실행 상태의 차이가 한 문단 안에 압축되지 않도록 사례 문단을 문제 장면, 필요한 기록, 확인 결과로 나누어 정리했다.
- P6-18 전용 요청 실행 상태 그래프 참조로 바꾸고, 직접적인 독자 호명 표현을 일반화해 원고 톤을 정리했다.
- 요청 실행 기록 회고 구간의 반복 표를 문단으로 압축해 실패 단계와 다음 개선 방향의 연결을 더 직접적으로 드러냈다.
- 말미의 다음 학습 연결을 개편 후 목차에 맞춰 RAG, 벡터 데이터베이스, tool use, agent, 평가, 운영 장으로 다시 정렬했다.
