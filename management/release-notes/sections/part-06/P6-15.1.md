## v2026.07.23

- 변경 이유: Part 6 목차에서 질문형 제목이 반복되어 Section 중심축이 한눈에 구분되기 어려웠기 때문.
- 본문 반영: 제목을 `도구와 자원을 공통 형식으로 연결하는 MCP`로 바꾸어 MCP의 중심축을 공통 연결 형식으로 고정했다.
- 목차 반영: `mkdocs.yml`, 독자용 목차, Part 6 개편안의 제목을 같은 표현으로 맞추었다.
- 원고 재정리: 도입부와 모델 능력 구분 절의 메타형 질문 목록을 줄이고, MCP를 모델 성능이 아니라 도구·자원 연결 형식 문제로 읽도록 문단 흐름을 정리했다.
- 원고 재정리: `기록` 표현을 `연결 정보`로 바로잡고, MCP 설명의 반복 소제목을 압축해 SDK 예제와 연결 형식 판단으로 흐름을 모았다.
- 원고 보강: 모델 능력과 도구 연결 규칙의 구분 절에 `먼저 보인 막힘` 기준 표를 보강해, 연결 실패를 모델 성능 문제로 오해하지 않도록 판단 질문을 앞쪽에 고정했다.
- 원고 보강: 파일 읽기, 검색, 데이터베이스 조회, API 호출이 한 에이전트 흐름 안에서 섞일 때 MCP가 왜 `연결 정리 도구`로 필요한지 문단 설명을 추가했다.
- 원고 정리: 뒤쪽의 반복 판단표를 줄이고 실무 점검 질문만 남겨, 앞쪽은 개념 구분, 뒤쪽은 적용 질문 역할로 나누었다.
- 예제 재구성: 공식 MCP Python SDK의 `FastMCP` 서버 예제로 도구와 자원을 실제 SDK 형식으로 노출하는 감각을 앞세우고, 도구 카탈로그·자원 카탈로그·연결 요청 CSV 기반 비교는 `common_layer`와 `mixed_layer`의 부분 성공·실패를 보는 그래프용 보조 실험으로 낮추었다.
- 그래프 갱신: MCP 연결 그래프를 요청 완료, 연결 준비, 도구 해석, 자원 해석 비교로 바꾸어 연결 계층이 무엇을 안정화하는지 보이게 했다.
- 번역 동기화 메모: 향후 번역본도 MCP를 도구와 자원을 공통 형식으로 연결하는 층위로 제목화한다.
- 번역 반영 상태: 한국어 원문과 목차만 수정했다.
- 원문 기준 버전: `v2026.07.23`

## v2026.07.21

- Part 6 개편 기준에 따라 Section ID, 파일 위치, 제목을 새 목차 구조에 맞춰 재정렬했다.
- 생성형 AI 산출물에서 시작해 LLM을 대표 사례로 읽는 흐름 안에서 이 Section의 위치를 다시 잡았다.
- MCP를 모델 능력이나 운영 장치가 아니라 도구 설명, 자원 접근, 요청/응답 형식을 덜 제각각으로 만드는 공통 연결 인터페이스 관점으로 읽도록 도입부와 판단 표를 정리했다.
- MCP, harness, evaluation, operations의 층위를 분리해 연결 형식, 실행 기록, 품질 판단, 운영 통제가 섞이지 않게 문장을 다듬었다.
- P6-15 전용 MCP 도식과 연결 계층 그래프 참조로 바꿔, P6-14 agent 자산과 P6-15 연결 자산의 경계를 분리했다.
- 개편 전 릴리즈노트 원문은 `management/authoring/archive/part-06-before-restructure-2026-07-21/management/release-notes/sections/part-06/`에 보존했다.
- `바로 적용해 보면` 제목을 연결 규칙을 먼저 봐야 하는 장면으로 바꾸어 MCP를 모델 성능보다 도구·자원 연결 형식 문제로 읽게 정리했다.
- 문서 읽기와 검색, 코딩 에이전트, 내부 시스템 연결 사례에서 자원·도구가 제각각 붙을 때의 문제와 공통 연결 기준을 문단으로 나누었다.
- 제목을 `MCP는 왜 도구와 자원을 공통 형식으로 연결하려 하는가`로 바꾸고, 도입부와 사례 요약의 반복 표를 문단으로 압축해 MCP를 도구 추가가 아니라 연결 형식 안정화 관점으로 읽게 정리했다.
- 도입부의 MCP·하네스·평가·운영 층위 반복 표를 줄여, 중심축을 `도구와 자원을 공통 형식으로 노출하는 연결 인터페이스`로 고정했다.
