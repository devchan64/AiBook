- 관련 자산: Python 예제의 `캐시 없음 -> 전체 prefix 재투영`과 `KV cache 있음 -> 저장된 K/V 재사용 -> 새 토큰 K/V만 추가` 비교 흐름을 보강하는 Mermaid 도식 `p6-c03-s04-diagram-01-en.mmd` / `p6-c03-s04-diagram-01-ko.mmd`를 추가했다.

- 연습 정리: Python 예제 앞의 `문제 상황`과 `입력(input)` 반복 블록을 삭제하고, 확인 항목을 `같은 attention 결과를 더 적은 재투영으로 만드는가`라는 핵심 비교로 압축했다.
- 정리 반영: 본문 메타데이터를 현재 Section 가이드 형식과 날짜 버전에 맞췄다.

### v2026.07.18
- 본문 반영: 사례 정리 문장의 `초심자가 붙잡아야 할 기준`을 `붙잡아야 할 기준`으로 낮춰, `이미 본 앞부분을 새 토큰마다 또 계산하는가`라는 질문이 독자 라벨 없이 바로 남게 다듬었다.; `이 보충학습의 범위`, `이 보충학습의 목표`라는 메타 제목을 `반복 생성 재사용이 다루는 질문`, `여기서 남겨야 할 구분`으로 바꿔, 절의 안내보다 실제 판단 기준이 먼저 보이게 정리했다.; 제목을 `KV cache를 처음 읽는 법`에서 `KV cache는 반복 생성에서 무엇을 다시 계산하지 않는가`로 바꿔, 메타형 안내보다 `앞부분 재계산 감소`라는 실제 학습 질문이 먼저 보이게 정리했다.; 기존 `P6-3.3`에서 분리했던 `KV cache, sparse attention, long-context` 묶음도 다시 나누어, 현재 절은 `KV cache` 단독 보충학습으로 다시 좁혔다.
- 추가 반영: 현재 절은 `같은 결과를 유지하면서 무엇을 다시 계산하지 않을 것인가`라는 질문에 집중하도록 범위, 사례, Python 예제를 모두 KV cache 중심으로 다시 정리했다.; 같은 날짜 재수정에서 `재사용 장치`라는 정의를 더 생활 장면으로 풀어, 긴 대화·긴 코드 생성·긴 문서 초안 수정에서 왜 `이미 본 앞부분을 새 토큰마다 또 계산하는가`가 핵심 질문이 되는지, context window가 길어질수록 왜 체감 차이가 커지는지, KV cache가 막으려는 실패 장면이 무엇인지 초심자 기준 문단과 비교표로 보강했다.; 제목 아래 `Section ID`, `Version` 표기를 저장소 규칙 형식으로 바로잡았다.
- 번역 동기화 메모: 대응 번역본이 생기면 현재 절을 KV cache 단독 보충학습으로 읽히게 맞추고, sparse attention과 long-context는 새 `P6-3.5`로 분리한 구조를 함께 반영해야 한다.
