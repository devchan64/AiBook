### v2026.07.14

- 변경 이유: 기존 Python 예제가 `quality_factor * visible_ratio / difficulty` 같은 임의 품질 점수에 기대고 있어, 스케일의 핵심인 데이터·모델·계산량의 동시 확대와 비용·검증 부담 증가를 직접 학습시키는 힘이 약했다.
- 본문 반영: 예제를 `스케일 단계별 trade-off 추적`으로 교체했다. `small -> medium -> large` 단계에서 데이터 양, 파라미터 수, 학습 계산량, context window, 처리 가능한 요청 수, 총 추론 비용, 지연 시간, 데이터 검증 묶음이 어떻게 함께 달라지는지 출력하도록 바꿨다.
- 추가 반영: 예제 출력 뒤에 처리 가능한 요청 수, 총 추론 비용, 데이터 검증 부담 그래프를 분리해 배치했다. 통합 그래프 대신 축별 PNG를 나누어 스케일의 이득과 부담을 따로 읽게 했다.
- 변경 이유 추가: 기존 세 사례는 `더 큰 모델은 더 많은 일을 할 수 있지만 비용이 든다`는 결론을 반복해, 새 예제와 역할이 겹치고 현재 절의 중심 판단을 분산시켰다.
- 본문 반영 추가: 사례를 `스케일업 결정 회의` 하나로 압축하고, 능력 축·비용 축·데이터 축을 함께 보는 결정 장면으로 재구성했다. 대응 Mermaid 도식도 세 사례 요약이 아니라 스케일업 결정의 세 판단 축을 보여 주도록 수정했다.
- 번역 동기화 메모: Korean source now replaces the arbitrary quality-score example with a scale-step trade-off trace and three separated chart assets. Future translations should preserve the split between context coverage, inference cost, and data review burden.
- 번역 반영 상태: 향후 번역 반영 필요
- 관련 자산: `docs/assets/part-06/chapter-06/p6-c06-s02-diagram-02-en.mmd`, `docs/assets/part-06/chapter-06/p6-c06-s02-diagram-02-ko.mmd`, `docs/assets/part-06/chapter-06/p6_6_2_scale_tradeoff_charts.py`, `docs/assets/part-06/chapter-06/scale-context-coverage-en.png`, `docs/assets/part-06/chapter-06/scale-context-coverage-ko.png`, `docs/assets/part-06/chapter-06/scale-inference-cost-en.png`, `docs/assets/part-06/chapter-06/scale-inference-cost-ko.png`, `docs/assets/part-06/chapter-06/scale-data-review-burden-en.png`, `docs/assets/part-06/chapter-06/scale-data-review-burden-ko.png`
