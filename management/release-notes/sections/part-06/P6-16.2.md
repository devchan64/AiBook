## v2026.07.23

- 변경 이유: Part 6 목차에서 질문형 제목이 반복되어 Section 중심축이 한눈에 구분되기 어려웠기 때문.
- 본문 반영: 제목을 `실행 기록과 재현 환경을 감싸는 하네스`로 바꾸어 하네스의 중심축을 기록과 재현 환경으로 고정했다.
- 목차 반영: `mkdocs.yml`, 독자용 목차, Part 6 개편안의 제목을 같은 표현으로 맞추었다.
- 원고 재정리: 진행 메타형 질문과 학습목표 목록을 문단 안으로 흡수하고, 소제목을 실행 기록·재현·연결 형식 구분이 드러나는 표현으로 정리했다.
- 후반 해설 정리: 예제 조작 결과를 문제 소거가 아니라 다음 병목 노출로 읽도록 보강하고, 마지막 문단을 P6-16 평가 입력과 P6-17 운영 통제 연결로 압축했다.
- 표현 정리: 하네스의 세 축, 최종 답만 볼 때 사라지는 실행 원인, 하네스가 대신 해결하지 않는 판단을 소제목과 표에서 더 직접 드러내도록 다듬었다.
- SDK·로컬 모델 예제 전환: OpenAI Agents SDK의 `Agent`, `function_tool`, `trace`, `Runner`로 도구 계약과 승인 경계를 정의하고, API 키 없이 Ollama `qwen2.5:1.5b`가 문서 후보 순서에 따라 정책 선택과 답변 초안을 만들도록 바꾸었다.
- 예제 기록 보강: 모델 판단용 프롬프트는 Python 예제 가이드라인에 맞춰 영어로 작성하고, 모델 출력, 정책 조회 도구 실행, approval gate 차단, run artifact 저장, replay 비교를 함께 남기도록 정리했다.
- 그래프 재정렬: 로컬 모델 실행 기록이 남기는 관측 기록, 모델 판단, 도구 계약, 승인 gate, replay 비교 항목을 답변만 저장한 실행과 비교하도록 갱신했다.
- 예외 처리 보강: 모델 boolean 출력과 알 수 없는 정책 버전을 안전하게 정규화하고, Ollama 연결 실패와 깨진 chart artifact를 더 명확하게 처리하도록 보정했다.
- 번역 동기화 메모: 향후 번역본도 harness를 실행 기록과 재현 환경을 감싸는 구조로 제목화한다.
- 번역 반영 상태: 한국어 원문과 목차만 수정했다.
- 원문 기준 버전: `v2026.07.23`

## v2026.07.21

- Part 6 개편 기준에 따라 Section ID, 파일 위치, 제목을 새 목차 구조에 맞춰 재정렬했다.
- 생성형 AI 산출물에서 시작해 LLM을 대표 사례로 읽는 흐름 안에서 이 Section의 위치를 다시 잡았다.
- 하네스를 단순 로그 저장 장치가 아니라 trace, replay, approval로 실행을 다시 설명하고 평가·운영 조치로 넘기는 실행 기록 환경으로 읽도록 도입부와 표를 정리했다.
- MCP 연결 형식, harness 실행 기록, evaluation·operations 판정의 층위를 분리해 기록과 품질 판단이 같은 말처럼 읽히지 않게 보강했다.
- P6-15 전용 harness 도식과 실행 원인 분리 그래프 참조로 바꿔, 이전 장 자산을 빌려 쓰던 혼선을 줄였다.
- 개편 전 릴리즈노트 원문은 `management/authoring/archive/part-06-before-restructure-2026-07-21/management/release-notes/sections/part-06/`에 보존했다.
- `바로 적용해 보면` 제목을 실행 기록을 먼저 봐야 하는 장면으로 바꾸어 trace, approval, replay가 평가와 운영 조치의 입력이라는 점을 더 직접 드러냈다.
- 코딩, 문서 조사, 고객 지원 에이전트 사례에서 최종 실패 장면과 하네스가 남겨야 할 실행 경로를 문단으로 분리해 기록의 역할이 더 선명하게 보이도록 했다.
- 제목을 질문형 중심축으로 바꾸고, 도입부와 사례 후반의 반복 표를 줄여 하네스를 실행 기록과 재현 가능성의 관점에서 읽는 흐름을 더 직접 드러냈다.
