## v2026.07.24

- 변경 이유: P6-16.2가 자동 평가와 사람 평가의 분업을 다루므로, 출처 블록도 최신 OpenAI Datasets의 annotation/graders 설명, Graders의 자동 평가기 유형 설명, agent trace/eval 설명을 직접 가리키는 편이 더 적절하다고 판단했다.
- 본문 반영 내용: Section 버전을 `v2026.07.24`로 올리고, 참고 자료에서 `Working with evals` 대신 `Getting started with datasets`를 주 근거로 반영했다. 자동 채점기(automatic grader)의 직접 근거로 `Graders` 문서도 추가했다. 예제는 코드 채점기와 선택적 LLM 판정기(LLM-as-a-judge grader)를 함께 기록하고, LLM 판정기의 이유가 비거나 약하면 코드 채점기 관측값으로 보강한 `reason_source`를 출력하도록 수정했다. 확인 날짜도 2026-07-24로 갱신했다.
- 추가 반영: 에이전트 실행 사례에서 비용·지연 최적화 설명을 줄이고, P6-16.2의 범위인 자동 신호와 사람 해석의 분업에 맞췄다. 예제 코드에는 `GRADER_AXIS_MAP`을 추가해 자동 채점기 항목이 P6-16.1의 근거성·유용성·형식 적합성·안전성 축과 어떻게 이어지는지 드러내고, 실제 출력의 수정 메모에도 평가 축을 함께 표시했다.
- 근거 확인: OpenAI Datasets 문서의 annotation, subject matter expert annotation, graders at scale 설명이 사람 평가와 자동 평가 분업을 직접 지지한다. OpenAI Graders 문서는 grader가 reference answer와 model-generated answer를 비교해 0~1 grade를 반환하고, string check, text similarity, score model, label model, Python code execution 같은 유형이 있음을 설명하므로 자동 채점기의 직접 근거가 된다. OpenAI Agent evals 문서는 traces, graders, datasets, eval runs가 agent quality 개선에 쓰이고 trace가 model calls, tool calls, guardrails, handoffs 기록을 담는다는 점에서 하네스/기록 연결 문장을 지지한다. Chang et al.의 LLM evaluation survey는 LLM 평가가 task, risk, benchmark, method 차원을 포함하는 넓은 평가 분야라는 배경 근거로 유지한다.
- 번역 동기화 메모: 향후 번역본도 P6-16.2 출처는 Datasets annotation/graders, Graders 유형, Agent eval traces, LLM evaluation survey 순서로 맞춘다.
- 번역 반영 상태: 한국어 원문과 공용 Python/차트 자산만 수정했다.
- 원문 기준 버전: `v2026.07.24`
