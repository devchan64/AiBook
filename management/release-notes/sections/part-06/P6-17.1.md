### v2026.07.18

- 체크리스트 정리: 본문 요약 항목과 다음 절 전환 항목을 덜고, 현재 Section 중심 질문을 닫는 자기 확인 항목만 남겼다.
- 본문 반영: `## 이 절의 범위`, `## 이 절의 목표` 같은 메타 소제목을 `요청 하나로 다시 묶는 기준`, `여기서 남겨야 할 구분`으로 바꾸고, 도입부 반문형 연결을 직접 설명형으로 정리했다.; 본문 중 `초심자 기준에서는` 같은 메타 표지를 한 번 더 줄이고, 요청 상태를 가르는 질문이 바로 보이도록 설명 문장을 더 직접적으로 다듬었다.; 앞 장의 자동 게이트·사람 검토·retry/fallback/stop/approval 판단이 이번 절에서 `상태 판단 -> 기록`으로 실제 요청 구조 안에 내려온다는 점을 초반 범위 설명과 전환 문장에서 더 직접 드러냈다.; 이 절의 전환이 `실패 경로 선택`에서 끝나는 것이 아니라, 그 판단이 다음 절의 요청 실행 기록과 패치 우선순위 입력으로 이어진다는 점을 보강했다.; `바로 적용해 보면` 아래에 요청을 `답변 초안 가능`, `근거 보강 필요`, `상태 조회 필요`, `사람 검토 또는 근거 부족` 중 어떤 상태로 남길지 바로 고르게 하는 짧은 상태 결정표를 덧붙여, 구조 선택과 요청 상태값이 한 번 더 직접 이어지게 보강했다.
- 추가 반영: 제목 아래 `Section ID`, `Version` 표기를 저장소 공통 형식에 맞춰 blockquote 대신 일반 메타데이터 줄로 정리했다.; 절 앞부분에서 같은 역할을 반복하던 연결 문단과 표를 압축하고, 이 절이 `요청 하나가 실제로 닫히는 구조`를 묶는 자리라는 점이 먼저 보이도록 정리했다.; 잘못 앞 장으로 되돌아가던 참조를 Part 7 프로젝트 문맥과 바로 다음 `P6-17.2` 기준으로 바로잡고, 내부 기록 키처럼 읽히는 예시도 일반 독자용 표현으로 다시 묶었다.; `이 절은 ... 답합니다`, `지금 읽는 층위는`처럼 설명 바깥에서 절의 역할을 다시 말하던 문장을 줄이고, 요청 흐름 통합 설명이 바로 시작되도록 앞머리 톤을 더 직접적으로 다듬었다.; `이 절에서 먼저`, `즉, 여기서 중요한 전환은`, `이 절의 목적은` 같은 진행형 문장을 줄이고, 요청 상태와 구조 선택 기준이 더 바로 보이도록 도입부와 전환 문장을 직접 설명형으로 다듬었다.
- 정리 반영: `이 절을 읽는 순서` 안내를 걷고, `prompt 중심 종료`, `근거 문서 확인`, `상태 조회 필요`, `사람 검토/근거 부족`을 먼저 가르는 요청 상태 분기 표로 바꿔 초심자 첫 질문이 요청 상태 판정으로 바로 이어지게 정리했다.; 세 사례 요약 뒤에 `바로 적용해 보면` 블록을 추가해, 초심자가 `prompt 중심`, `retrieval 결합`, `tool use 결합`을 실제 질문 구조에 맞춰 먼저 가르도록 보강했다.; 같은 날짜 재검토에서 `요청 흐름 통합`이 여전히 추상적으로 읽히는 압축을 줄이기 위해, 같은 인사 도우미 질문이 `바로 답변 초안`, `근거 문서 확인 필요`, `현재 상태 조회 필요`, `사람 검토 또는 근거 부족` 중 어디로 갈리는지 보여 주는 상태 비교표와 `답변 상태를 남긴다`는 6번째 흐름 단계를 앞부분에 덧붙였다.; 같은 날짜 후속 재검토에서 앞부분 상태 비교표가 세운 `사람 검토 또는 근거 부족` 축이 `바로 적용해 보면`에서는 약하게 보인다는 점을 보완하려고, `확답이 불안한 요청을 사람 검토·추가 질문·근거 부족 상태로 남기는가`를 먼저 묻게 하는 행과 요약 문장을 추가했다.; `바로 적용해 보면`에 남아 있던 `초심자가 ...` 독자 표지를 `자주 생기는 오해`로 낮춰, 요청 구조 선택 설명이 메타 독자 안내보다 상태 판정 기준에 더 직접 이어지게 다듬었다.
- 번역 동기화 메모: 대응 번역본이 생기면 초반 압축 구조와 Part 7 방향 연결도 함께 반영해야 한다.
