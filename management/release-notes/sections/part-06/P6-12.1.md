## v2026.07.22

- 본문 반영: Python 예제를 손으로 만든 3차원 벡터 계산에서 CSV 기반 문서 조각 검색 예제로 바꾸어, 원문과 메타데이터가 검색 payload로 함께 반환되는 흐름을 실제 텍스트 입력에서 확인하도록 했다.
- 본문 반영: 질문 CSV와 출력에서 기대 범주 대조를 제거하고, top-k 후보 변화, 반환된 범주, 원문, 출처, 버전, 상태 보존 여부를 중심으로 해석하도록 조정했다.
- 본문 반영: 도입부의 학습 목표형 bullet을 설명 문단으로 흡수하고, 반복되던 검색 필요 장면 표를 예제에서 볼 값 중심 표로 압축했다.
- 본문 반영: Python 예제를 ChromaDB 인메모리 컬렉션의 `add` / `query` 흐름으로 바꾸어, 라이브러리형 벡터 DB에 문서, 임베딩, 메타데이터를 넣고 payload를 다시 받는 경험을 제공하도록 했다.
- 자산 반영: `p6-12-vector-db-documents.csv` / `p6-12-vector-db-queries.csv`를 추가하고, `vector-db-payload-check-ko.png` / `vector-db-payload-check-en.png` 차트가 CSV 검색 결과를 직접 계산해 그리도록 수정했다.
- 의존성 반영: P6-12.1 예제 실행을 위해 `requirements.txt`에 `chromadb==1.5.9`를 추가했다.

- 번역 반영 상태: 한국어 원문만 수정했다.

## v2026.07.21

- Part 6 개편 기준에 따라 Section ID, 파일 위치, 제목을 새 목차 구조에 맞춰 재정렬했다.
- 생성형 AI 산출물에서 시작해 LLM을 대표 사례로 읽는 흐름 안에서 이 Section의 위치를 다시 잡았다.
- 벡터 데이터베이스를 유행 기술명이 아니라 임베딩, 원문, 메타데이터를 함께 다루는 RAG 검색 저장 구조로 읽도록 도입부와 판단 표를 정리했다.
- 검색 저장소, 후보 압축, 도구 호출의 층위를 분리해 후속 인덱스 품질 설명과 실행 구조 설명이 섞이지 않게 문장을 다듬었다.
- P6-12.1 전용 벡터 저장소 도식과 payload 차트를 chapter-12 자산 경로로 분리하고, 진행 안내식 표현을 개념 경계 중심 문장으로 정리했다.
- 벡터 데이터베이스 차트를 단순 통과 수에서 질문별 1위 후보와 다음 후보의 유사도 차이로 바꿔 검색 후보 분리 감각을 더 직접 보여 주도록 조정했다.
- 개편 전 릴리즈노트 원문은 `management/authoring/archive/part-06-before-restructure-2026-07-21/management/release-notes/sections/part-06/`에 보존했다.
- `바로 적용해 보면` 제목을 벡터 저장 구조가 필요한 장면으로 바꾸어 임베딩, 원문, 메타데이터를 함께 돌려주는 저장 구조의 필요성을 더 직접 보이게 정리했다.
- 제목을 `벡터 데이터베이스는 왜 원문과 메타데이터까지 함께 저장하는가`로 바꾸고, 도입부의 반복 표를 문단으로 압축해 P6-11.2의 검색-생성 결합에서 P6-12.2의 인덱스·검색 품질로 이어지는 저장 구조의 역할을 더 직접 드러냈다.
- 도입부의 저장 구조 설명 반복을 줄여, 중심축을 `임베딩, 원문, 메타데이터를 함께 다루는 RAG 검색 저장 구조`로 고정했다.
