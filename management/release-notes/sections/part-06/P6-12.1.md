- 벡터 데이터베이스를 유행 기술명이 아니라 임베딩, 원문, 메타데이터를 함께 다루는 RAG 검색 저장 구조로 읽도록 도입부와 판단 표를 정리했다.
- 검색 저장소, 후보 압축, 도구 호출의 층위를 분리해 후속 인덱스 품질 설명과 실행 구조 설명이 섞이지 않게 문장을 다듬었다.
- P6-12.1 전용 벡터 저장소 도식과 payload 차트를 chapter-12 자산 경로로 분리하고, 진행 안내식 표현을 개념 경계 중심 문장으로 정리했다.
- 벡터 데이터베이스 차트를 단순 통과 수에서 질문별 1위 후보와 다음 후보의 유사도 차이로 바꿔 검색 후보 분리 감각을 더 직접 보여 주도록 조정했다.
- 개편 전 릴리즈노트 원문은 `management/authoring/archive/part-06-before-restructure-2026-07-21/management/release-notes/sections/part-06/`에 보존했다.
- `바로 적용해 보면` 제목을 벡터 저장 구조가 필요한 장면으로 바꾸어 임베딩, 원문, 메타데이터를 함께 돌려주는 저장 구조의 필요성을 더 직접 보이게 정리했다.
- 제목을 `벡터 데이터베이스는 왜 원문과 메타데이터까지 함께 저장하는가`로 바꾸고, 도입부의 반복 표를 문단으로 압축해 P6-11.2의 검색-생성 결합에서 P6-12.2의 인덱스·검색 품질로 이어지는 저장 구조의 역할을 더 직접 드러냈다.
- 도입부의 저장 구조 설명 반복을 줄여, 중심축을 `임베딩, 원문, 메타데이터를 함께 다루는 RAG 검색 저장 구조`로 고정했다.
