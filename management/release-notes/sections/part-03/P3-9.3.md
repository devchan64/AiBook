### v2026.07.10

- 변경 이유: 세 산출물의 차이를 설명하는 도입부가 `정의 문단 -> 목적 문단 -> 질문 비교 표`로 이어지며 같은 구분을 반복해, 독자가 `같은 사건 목록을 질문에 따라 다시 조직한다`는 핵심을 바로 잡기 어려웠다.
- 본문 반영: 도입을 한 문단으로 압축해 목표 라벨 후보의 의미와 세 산출물의 차이를 함께 세웠다. 이어지는 질문 비교 표는 일반 문장으로 흡수하고, 도식 뒤 중복 정리 문장도 한 문단으로 합쳐 현재 산출물 구분이 더 빨리 읽히도록 재배치했다.

- 번역 동기화 메모: English and Simplified Chinese translations now preserve the three-output frame in which the same event list is reorganized into a comparison report, review queue, and target-candidate table for different purposes. / reflected in `docs/en/parts/part-03/chapter-09/section-03.md`, `docs/zh/parts/part-03/chapter-09/section-03.md`
- 번역 반영 상태: 영문·중국어 간체 반영 완료
- 관련 자산: 없음.

### v2026.07.08

- 변경 이유: 도입부가 `앞 절까지 읽으면`, `특히 어려운 지점은 여기입니다` 같은 독서 메모형 문장으로 시작해, 세 산출물의 차이를 직접 세우는 설명보다 편집자 문장이 먼저 보였다.
- 본문 반영: 첫 문단을 `같은 사건 목록도 목적에 따라 세 표로 달라진다`는 현재 구조 차이 설명으로 다시 열고, 각 표가 무엇을 앞세우는지만 곧바로 대비하도록 정리했다.

- 변경 이유: 도입이 `예측 문제로 넘긴다`는 handoff 표현을 먼저 세워, 현재 절의 산출물 구분보다 뒤 단계 인계가 앞서 보였다.
- 본문 반영: 첫 문단을 `비교 리포트`, `검토 후보 큐`, `목표 라벨 후보`라는 현재 산출물 이름과 표 구조 차이 중심으로 다시 열고, `예측 문제로 넘긴다`는 표현은 입력 열과 결과 후보 열이 갈린 표 설명으로 바꿨다.

- 변경 이유: 도입부에서 `목표 라벨 후보` 개념사전 직접 링크가 같은 Section 안에서 반복되어, `한 Section 1회 직접 링크` 원칙과 어긋났다.
- 본문 반영: 도입 첫 문단의 직접 링크만 남기고, 바로 뒤 정의 문장에서는 일반 표기로 바꿔 개념사전 입구를 한 번만 사용하도록 정리했다.

- 변경 이유: 후속 Section 도입부가 `비교 리포트`, `검토 후보 큐`, `목표 라벨 후보`를 반복 핵심 개념으로 다시 세우면서도 개념사전 직접 앵커로 충분히 되돌리지 않아, 대표 개념 복귀 규칙이 약하게 보였다.
- 본문 반영: 도입 첫 문장과 핵심 정의 문장에서 `비교 리포트(comparison report)`, `검토 후보 큐(review queue)`, `목표 라벨 후보(target candidate)`를 개념사전 직접 앵커로 연결했다.

- 변경 이유: `상위 프레임` 재진술 표가 다른 Section들과 같은 마감 템플릿으로 반복되어, 본문이 교안형으로 굳어 보였다.
- 본문 반영: 말미의 `상위 프레임` 표를 제거하고, 현재 설명을 표 재진술 없이 직접 마무리하도록 정리했다.

- 변경 이유: `일반화된 상위 프레임으로 다시 보면` 제목이 Part 3 전반에 반복되어, 현재 절 설명도 같은 템플릿형 마감으로 굳어 보였다.
- 본문 반영: 반복 제목을 제거하고, 상위 프레임 표와 정리 문장을 현재 설명 흐름 안에 직접 이어 붙였다.

- 변경 이유: 도입부가 산출물 차이 설명보다 `표제어 안내` 문장을 먼저 세워, 목표 라벨 후보의 역할 설명보다 메타 안내가 앞서 보였다.
- 본문 반영: 별도 표제어 안내 문장을 제거하고, `목표 라벨 후보(target candidate)` 링크를 같은 원천데이터가 세 산출물로 갈라지는 설명 문장 안으로 흡수했다.

- 변경 이유: `목표 라벨 후보`가 Chapter 9 후반의 반복 핵심 개념인데도 대표 Section 입구에서 개념사전 직접 연결이 없어, 독자가 현재 절의 대표 설명 위치를 바로 붙잡기 어려웠다.
- 본문 반영: 도입부에 `목표 라벨 후보(target candidate)` 개념사전 앵커 링크를 추가하고, 이 절에서는 이를 입력 열과 결과 열을 가르는 문제 구조 안의 결과 후보 열로 읽는다는 문장을 보강했다.

- 변경 이유: 세 산출물의 차이를 설명하는 Section 안에서 `Part 4로 넘길` 같은 handoff 표현이 반복되어, 현재 절의 산출물 구조 설명보다 뒤 Part 인계 목적이 더 크게 보였다.
- 본문 반영: `학습으로 넘긴다`, `Part 4로 넘길 입력과 결과` 같은 문장을 `입력 열과 결과 열을 가르는 문제 구조 정리` 중심으로 바꾸고, 절 끝도 현재 세 산출물의 역할 구분으로 닫도록 정리했다.

- 변경 이유: 세 산출물의 역할 차이를 설명하는 흐름에 메타 템플릿과 handoff 성격의 문장이 남아 있었고, 이를 일반화된 산출물 구조와 외부 근거로 다시 받쳐 줄 보강이 더 필요했다.
- 본문 반영: 마무리를 현재 절의 구분 설명에 맞게 직접화하고, `변화 설명 -> 운영 선택 -> 학습 준비` 프레임과 출처를 추가해 같은 사건 목록이 목적에 따라 다시 조직된다는 점을 더 선명하게 했다.

- 번역 동기화 메모: preserve the direct prose, the three-output frame, and the source-backed explanation that the same event list is reorganized for different purposes. / pending

### v2026.07.07

- 변경 이유: Chapter 9에서 비교 리포트, 검토 후보 큐, 목표 라벨 후보 표가 각각 무엇을 위해 존재하는지 한 번에 묶어 설명하는 연결 절이 필요했다.
- 본문 반영: 새 Section `P3-9.3 비교 리포트, 검토 후보 큐, 목표 라벨 후보 표는 어떻게 다른가`를 추가했다. 같은 사건 목록이 세 산출물로 갈라지는 표 비교, 세 단계 절차, 열 구성 차이를 보여 주는 작은 코드 예시, `언제 무엇으로 멈춰야 하는가` 판정 표를 넣어 Chapter 9와 Chapter 10 사이의 연결을 보강했다.
- 변경 이유: 기존 코드 예시는 세 산출물의 열 이름만 나열하는 쪽에 가까워, 같은 사건 목록이 실제로 어떻게 비교 리포트, 검토 후보 큐, 목표 라벨 후보 표로 다시 구성되는지 직접 보여 주지 못했다.
- 본문 반영: 하나의 `events` 표에서 `report_table`, `queue_table`, `target_candidate_table`을 각각 만들어 세 표를 모두 출력하도록 예시를 교체했다. 변화 설명 중심 표, 우선순위 중심 표, Part 4 인계용 표가 어떻게 달라지는지 실제 표 단위로 읽을 수 있게 보강했다.
- 변경 이유: 이 절은 열 선택 규칙보다 `한 사건 목록이 세 질문에 맞춰 갈라지는 구조`를 보여 주는 편이 더 중요하므로, 의사결정 도식이 코드 예시보다 적합하다.
- 본문 반영: 코드 예시를 Mermaid 도식으로 교체했다. 같은 출발점이 비교 리포트, 검토 후보 큐, 목표 라벨 후보 표로 분기되고, 각 산출물이 어떤 열 역할을 앞세우는지 한눈에 보이도록 정리했다.
