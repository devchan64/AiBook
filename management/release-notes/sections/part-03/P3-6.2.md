- 본문 반영: 반복 제목을 제거하고, 상위 프레임 표와 정리 문장을 현재 설명 흐름 안에 직접 이어 붙였다.

- 변경 이유: 도입부가 중간 표현 설명보다 `표제어 안내` 문장을 먼저 세워, 개념 자체보다 편집자 안내가 앞서 보였다.
- 본문 반영: 별도 표제어 안내 문장을 제거하고, `중간 표현(intermediate representation)` 링크와 정의를 첫 설명 문단 안으로 직접 흡수했다.

- 변경 이유: `중간 표현(intermediate representation)`이 Part 3 안에서 반복 핵심 개념으로 쓰이는데도 개념사전 직접 연결이 없어, 대표 Section 입구에서 이 개념을 다시 붙잡을 복귀 경로가 약했다.
- 본문 반영: 도입부에 `중간 표현(intermediate representation)` 개념사전 앵커 링크를 추가하고, 이 절에서는 이를 원시 로그와 요약 특징 사이의 사람 주도 입력 재표현으로 읽는다는 문장을 보강했다.

- 변경 이유: 메타 템플릿을 걷어낸 뒤에도 `특징과 나중에 모델이 학습하는 표현 사이의 다리 역할` 같은 설계 메모형 표현이 남아, 중간 표현의 성질 설명보다 배치 의도가 먼저 보였다.
- 본문 반영: 원시 로그와 요약 특징 사이의 `중간 표현` 상위 프레임, TensorFlow와 Google 참고 자료, 토큰화 전후 출력 제목 보강은 유지하되, 해당 문장을 일반 설명형으로 바꿨다. 세그먼트 토큰이 사람이 정한 표현이면서도 순서를 가진 입력 구조라는 점과, 그래서 숫자 특징이 놓치는 구조를 더 직접 남길 수 있다는 설명은 그대로 유지했다.

- 번역 동기화 메모: preserve the intermediate-representation framing, the before/after tokenization stage labels, and the source note that links segment tokens to an officially documented preprocessing pattern by analogy. / pending

### v2026.07.06

- 변경 이유: 중간 표현 절이 토큰화의 역할은 설명하고 있었지만, 숫자 특징과 세그먼트 표현을 언제 나누어 쓰는지와 절 끝 점검 장치가 더 필요했다.
- 본문 반영: 수치 비교, 구간 순서 읽기, 기호열 비교에 각각 어떤 표현이 더 직접적인지 정리한 보강 표를 추가하고, 절 끝에는 중간 표현 사용 기준을 확인하는 짧은 질문을 넣었다.
- 변경 이유: 세그먼트 표현 절에서도 반복되는 초심자 메타 안내를 줄이고, 토큰화가 맡는 중간 표현 역할이 본문 전개에서 바로 드러나게 정리.
- 본문 반영: `이 표현이 왜 필요한가` 비교 표의 도입을 역할 설명 중심으로 바꾸고, 마지막 균형 감각 문단에서 `초심자 단계에서는` 같은 메타 표지를 제거했다. 토큰화의 장점과 정보 손실 경계 설명은 유지했다.
- 변경 이유: 세그먼트 표현 절의 도입, 예제 읽기 순서, 다음 장 연결에 남아 있던 `떠올려 보겠습니다`, `확인하면 좋습니다`, `넘어가겠습니다` 같은 유도형 표현을 직접 설명형으로 정리할 필요가 있었다.
- 본문 반영: 초반-중반-후반 패턴 도입을 `생각해 보겠습니다`로 조정하고, 예제 읽기 순서를 `토큰화가 맡는 역할이 더 분명해진다`는 설명으로 바꾸었다. 마지막 문단도 최근 구간/기준선 비교 장으로 `넘어갑니다`로 정리해 중간 표현의 위치를 더 직접적으로 드러냈다.
- 변경 이유: Part 3 앞단에 데이터 모델링 진입 챕터를 추가하면서 기존 Section의 번호 체계와 파일 경로를 한 칸씩 뒤로 재배치할 필요가 있었다.
- 본문 반영: Section 제목 번호, Section ID, 본문 경로, 목차 대응 위치를 새 Part 3 번호 체계에 맞춰 갱신했다. 본문 설명 구조와 사례 흐름은 유지했다.
- 변경 이유: 세그먼트 표현 절도 독립 기법 소개보다 `특징만으로 부족할 때 추가하는 중간 표현`이라는 흐름 안에서 더 분명히 읽히게 조정할 필요가 있었다.
- 본문 반영: Section 제목을 `특징만으로 부족할 때 어떤 중간 표현을 더 둘 수 있는가`로 바꾸고, 도입과 마지막 연결 문장을 특징 설계와 기준선 비교 사이의 다리 역할 중심으로 다듬었다. 토큰화 예제와 정보 손실 경계 설명은 유지했다.
- 변경 이유: 3.12가 특징 설계 자체를 다시 반복하는 절처럼 읽히지 않도록, 이 절이 숫자 특징만으로 부족할 때 중간 표현을 어디까지 더 둘 수 있는지에 집중하는 후속 절이라는 점을 더 분명히 할 필요가 있었다.
- 본문 반영: 이 절의 역할은 특징 설계의 재설명이 아니라, 앞 절에서 만든 숫자 특징만으로 구조가 충분히 남지 않을 때 세그먼트 표현과 토큰화 같은 중간 표현을 추가로 두는 범위를 다루는 데 있다는 문장을 추가했다.
