### v2026.07.07

- 변경 이유: `모델 이름`, `모델 유형` 같은 표현이 반복되면 독자의 주의가 다시 이름 고르기 자체로 쏠려, 이 절이 경계하는 `문제 구조보다 학습 문제 틀을 먼저 정하는 습관`이 흐려질 수 있었다.
- 본문 반영: 도입, 잘못된 시작 비교표, 핵심 경고 문장, 점검 질문에서 `모델 이름/유형` 표현을 줄이고 `예측 문제`, `분류 문제`, `이상 징후 판별 문제`처럼 더 일반화된 학습 문제 틀 언어로 바꿨다.
- 변경 이유: 표현을 낮추는 과정에서 `뒤 단계가 앞 단계를 전제로 하므로 여섯 항목을 같은 순서로 읽어야 한다`는 이 절의 핵심 주장이 함께 약해졌다.
- 본문 반영: 상위 프레임 문장은 유지하되, 여섯 항목을 `모델을 붙이기 전에 먼저 닫아야 할 판단`으로 다시 세웠다. 방어적인 `표준 목록` 문장은 걷어내고, 여섯 항목의 연결을 보여 주는 Mermaid 도식을 다시 넣었으며, 마무리와 재호출 문장도 `이 설명 순서`보다 `여섯 항목` 자체를 다시 떠올리게 고쳤다.
- 변경 이유: `먼저 닫아야 할 판단`, `어떤 순서로 고정해야 한다` 같은 표현이 여전히 일반화되지 않은 강한 주장으로 읽힐 수 있었다.
- 본문 반영: 여섯 항목을 `앞단에서 함께 점검할 묶음`으로 낮추고, `고정해야 한다`는 문장은 `어떤 흐름으로 읽으면 뒤 설명이 덜 흩어지는가` 쪽으로 조정했다. 마무리와 재호출 문장도 `같은 순서를 따라야 한다`보다 `이 흐름을 기준으로 다시 읽는다`는 뜻이 남도록 다듬었다.
- 변경 이유: 이 절의 여섯 항목이 어떤 공식 개념군을 바탕으로 다시 묶인 것인지 본문 안에서 드러나지 않아, 설명 spine과 외부 근거의 연결이 약했다.
- 본문 반영: `task`, `example`, `feature engineering`, `label/target`, `preprocessing`, `classification threshold` 같은 공식 용어들이 보통 따로 설명된다는 문단을 추가하고, Part 3이 이를 `학습 전에 문제 구조를 읽는 흐름`으로 다시 묶는다고 명시했다. 또한 `출처와 참고 자료` 절을 추가해 Google Glossary, scikit-learn, CRISP-ML(Q)를 직접 연결했다.
- 변경 이유: 여섯 항목 순서가 외부 표준 파이프라인처럼 읽힐 수 있었지만, 현재 근거 수준에서는 `Part 3이 학습 전 문제 구조를 설명하기 위해 묶은 설명 순서`로 두는 편이 더 정확했다.
- 본문 반영: 도입을 `일반적인 머신러닝 작업의 큰 흐름` 아래에 두고, 여섯 항목을 `Part 3의 설명 순서`라고 명시했다. `표준 목록`처럼 읽히는 문장을 낮췄고, Mermaid 파이프라인은 제거했으며, 마무리와 재호출 문장도 `설명 순서` 표현으로 맞췄다.
- 변경 이유: `모델 이름부터 떠올린다`는 표현이 제품명이나 구체 모델명을 고르는 뜻으로도 읽혀, Part 3이 경계하는 `문제 구조보다 분류/회귀 같은 문제 틀을 먼저 정하는 습관`이 바로 드러나지 않았다.
- 본문 반영: 도입 문장을 `문제 구조보다 먼저 분류(classification), 회귀(regression), 이상 탐지(anomaly detection) 같은 모델 유형을 정하고 싶어지는 상황`으로 바꾸고, 비교 표의 시작 방식도 `문제 구조보다 모델 유형부터 정한다`로 맞췄다.
- 변경 이유: 도입부가 `진행 순서` 자체보다 이 Section의 위치 설명을 먼저 말해 직접 설명 원칙과 충돌했다.
- 본문 반영: 절 역할 안내를 삭제하고, 샘플 단위와 비교 기준이 왜 순서를 강제하는지부터 설명하도록 첫 문단을 다시 썼다.
- 변경 이유: 여섯 단계 순서는 제시되어 있었지만, 초심자가 `왜 꼭 이 순서여야 하는가`를 실제 실패 장면으로 체감하기 어려워 진입 초반에 절차를 형식적 체크리스트처럼 읽을 여지가 있었다.
- 본문 반영: `잘못된 시작 순서`와 `질문/샘플부터 고정하는 올바른 시작`을 비교하는 표와 보강 문단을 추가해, 모델 이름이나 특징을 먼저 고를 때 어떤 문제가 생기는지 직접 설명했다.
- 변경 이유: 진행 순서 절도 대표 설명 위치 문장과 절 역할 소개를 더 직접 설명형으로 맞출 필요가 있었다.
- 본문 반영: `이 절은 ... 대표 설명 위치입니다`와 `이 절의 역할은 ...` 문장을 `여기서는 ... 맡습니다`, `여기서는 ... 제공합니다` 형태로 다듬어 Part 3 절차 지도 역할이 더 직접적으로 읽히게 정리했다.
- 변경 이유: 데이터 모델링 순서 절도 마지막 점검 구간의 역할을 절차 재호출과 확인 항목으로 분리할 필요가 있었다.
- 본문 반영: 여섯 단계 진행 순서를 다시 떠올려야 하는 상황을 `언제 이 관점을 먼저 떠올려야 하는가`로 추가하고, 기존 `짧은 점검`은 유지했다.
