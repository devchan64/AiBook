### v2026.07.08

- 변경 이유: 전처리를 처음 들어 본 독자에게는 세부 범주 설명이 나오기 전에 `전처리가 왜 필요한가`를 아주 짧게 잡아 주는 입문 소개 블록이 부족했다.
- 본문 반영: 주요 학습내용 첫머리에 `전처리를 처음 들으면 이렇게 잡으면 된다` 소제목을 추가해, 전처리 전 표와 전처리 후 입력 형태를 대비시키고 결측치 처리, 스케일 조정, 인코딩의 세 대표 장면으로 이어지게 보강했다.
- 변경 이유: 전처리의 일반 흐름과 설명은 충분했지만, 고객 데이터 사례에서 결측치·수치형·범주형 규칙이 어떻게 다시 하나의 비교 가능한 입력으로 모이는지 사례 도식이 약했다.
- 본문 반영: 사례로 보기 절에 `customer table -> missing rule / numeric rule / category rule -> same transform rules -> comparable model input` 흐름의 Mermaid 도식을 추가해, 전처리를 컬럼 상태별 규칙 묶음으로 읽게 했다.
- 변경 이유: 절 전체가 전처리의 큰 개념은 설명하고 있었지만, 같은 입력이 왜 결측치·스케일·인코딩·`fit/transform`의 서로 다른 질문으로 갈라지는지와 잘못된 전처리가 어떤 착시를 만드는지에 비해 밀도가 가벼웠다.
- 본문 반영: 전처리를 `모델이 볼 세계를 다시 좌표화하는 일`로 보강하고, 입력 문제 유형표, 결측치 오해 표, 스케일 대조, 인코딩 오해, train/test 규칙 학습 착시 비교, 전처리 설명의 네 문장 기준을 추가해 판단 밀도를 높였다.
- 변경 이유: 전처리의 대표 예시 설명은 있었지만, 전처리 종류 전체를 조감하는 표와 각 범주가 어떤 입력 문제에 대응하는지의 큰 지도가 부족했다.
- 본문 반영: 전처리 큰 범주 표를 추가해 결측치 처리, 스케일 조정, 인코딩 외에 이상치 대응, 특징 생성, 차원 축소의 자리를 함께 짚고, 입력 문제별로 어떤 전처리 종류가 먼저 연결되는지 다시 묶었다.
- 변경 이유: 전처리 종류와 판단표가 보강된 뒤에도, 전처리를 머릿속에서 `원시 입력 한 행이 모델 입력 한 행으로 어떻게 바뀌는가`로 그리는 직관이 아직 약했다.
- 본문 반영: 전처리 전후 한 행 비교표와 특징 선택 대비표를 추가해, 전처리를 `입력 행을 모델의 언어로 번역하는 일`로 더 직접 이해할 수 있게 보강했다.
- 변경 이유: 행 단위 직관은 보강됐지만, 전처리가 절차 전체로는 `원시 표 -> 규칙 학습 -> 동일 규칙 재사용 -> 모델 입력 행렬`이라는 흐름으로 남지 않아 여전히 밀도가 약했다.
- 본문 반영: train 분할 이후 전처리 규칙을 학습하고 같은 규칙으로 행렬을 만드는 Mermaid 흐름도, 전처리 판단 순서표, 결측 보정값의 성격, 모델 계열과 전처리 민감도 연결 문장을 추가해 절차 이해를 보강했다.
- 변경 이유: 절차 설명이 늘어도, 전처리가 없으면 무엇이 무너지는지와 같은 표가 어떻게 `모델 입력 행렬`로 바뀌는지가 한 장면으로 보이지 않아 체감 밀도가 여전히 약했다.
- 본문 반영: 전처리 부재 시 계산·비교·재현이 무너지는 대비표와, 고객 표가 결측 보정·스케일 조정·범주형 확장을 거쳐 입력 벡터 묶음으로 바뀌는 전후 표를 추가해 전처리의 필요성과 결과 형태를 더 직접적으로 보강했다.
- 변경 이유: 전처리의 큰 틀과 절차는 보강됐지만, 결측치 처리, 스케일 조정, 인코딩 각각이 내부적으로 어떤 방식들로 나뉘고 언제 더 어울리는지에 대한 세부 설명은 아직 얕았다.
- 본문 반영: 결측치 처리 방식 비교, 스케일 조정 방식 비교, 인코딩 방식 구분과 각각의 장점·주의점·자연스러운 사용 장면을 추가해 세부 전처리 설명의 밀도를 높였다.
- 번역 동기화 메모: 향후 번역본에서도 train 단계에서 배운 전처리 규칙을 validation/test에 그대로 재사용하는 흐름과 규칙 병합 도식을 유지해야 한다.
- 번역 반영 상태: 향후 반영 필요
- 관련 자산: 없음.
- 원문 기준 버전: `v2026.07.08`
