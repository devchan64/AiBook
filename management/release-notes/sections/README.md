# Section 버전·릴리즈노트 관리

작성일: 2026-07-05

이 디렉터리는 `management/release-notes/` 아래에서 Section 본문의 버전 코드와 개정 이력을 관리한다. 목적은 다음 세 가지다.

- Section별 변경 이력을 따로 남겨 이후 회고, 검토, 번역 동기화에 재사용할 수 있게 한다.
- 다국어 본문이 생겼을 때 원문과 번역본의 대응 버전을 추적할 수 있게 한다.

이 디렉터리의 파일은 `Section Release Note` 하나로만 관리한다. 별도의 체인지로그를 따로 두지 않는다.

## 기본 원칙

- Section을 실제로 수정했다면 본문만 고치고 끝내지 않는다.
- 수정한 Section의 제목 바로 아래에는 다음 두 줄만 둔다.
  - `Section ID`
  - `Version`
- 버전 코드는 수정일 기준 `vYYYY.MM.DD` 형식을 사용한다.
- `Section ID`는 목차 인덱스와 같은 값을 사용한다. 예를 들어 `P5-11.1`처럼 본문 번호와 직접 대응해야 한다.
- Section의 날짜성 메타데이터는 `Version` 한 줄만 사용한다.
- `Last Updated` 같은 별도 수정일 메타데이터는 Section 본문에 두지 않는다.
- 같은 날 여러 번 수정해도 Section 본문 안의 버전 코드는 날짜 기준으로 유지하고, 세부 변경 차이는 릴리즈노트에서 분리해 기록한다.

## 본문 메타데이터 형식

Section 제목 바로 아래에 다음 형식을 둔다.

```md
> Section ID: `P5-11.1`
> Version: `v2026.07.05`
```

규칙:

- `Section ID`는 언어가 달라도 같은 개념 단위를 가리켜야 한다.
- `Version`은 수정일 기준 버전이다.
- 날짜성 메타데이터는 `Version` 한 줄로만 관리한다.
- `Last Updated` 같은 중복 날짜 표시는 추가하지 않는다.
- 번역본이 추가되더라도 이 두 값은 언어별 파일명보다 먼저 Section 단위의 기준 키로 취급한다.

## 릴리즈노트 파일 위치

- 파일은 `management/release-notes/sections/part-XX/` 아래에 둔다.
- 파일명은 기본적으로 `Px-y.z.md` 형식을 사용한다.
- 예:
  - `management/release-notes/sections/part-05/P5-11.1.md`
  - `management/release-notes/sections/part-06/P6-15.2.md`

## 릴리즈노트 항목 형식

릴리즈노트 파일 상단에는 식별용 고정 항목만 남긴다.

- Section ID
- 대응 본문 경로

릴리즈노트의 버전별 개정 내용은 각 `### vYYYY.MM.DD` 항목에만 기록한다. 각 버전 항목에는 다음을 우선 남긴다.

- 변경 이유
- 본문 반영 내용
- 번역 동기화 메모
- 번역 반영 상태
- 관련 자산
- 원문 기준 버전

세부 형식과 표기 순서는 같은 디렉터리의 `section-release-note-template.md`를 따른다.

## 기본 작업 순서

1. 수정한 본문의 `Section ID`를 확인한다.
2. 본문 제목 아래 메타데이터의 `Version`을 수정일 기준으로 갱신한다.
3. 대응하는 `part-XX/Section ID.md` 릴리즈노트 파일을 갱신하거나 새로 만든다.
4. 상단 식별 항목과 최신 버전 항목을 함께 갱신한다.
5. 번역본이 아직 없더라도 최신 버전 항목의 `번역 동기화 메모`에는 최소 판단을 남긴다.

## Part 디렉터리 운영

- Part별 하위 폴더는 `part-01`, `part-02`처럼 현재 책의 Part 번호와 일치시킨다.
- 새 Part에서 처음 Section 릴리즈노트를 만들 때는 해당 Part 폴더를 먼저 만든다.
- Part 시작 페이지와 Part 마무리 페이지는 현재 기본 릴리즈노트 대상이 아니며, Section 본문 수정이 우선 대상이다.
- 다만 필요하면 Part 소개/요약 페이지도 별도 운영 규칙을 정한 뒤 같은 디렉터리 체계에 확장할 수 있다.

## 번역본 대응 원칙

- 번역본이 생기면 `Section ID`는 동일하게 유지한다.
- 릴리즈노트에는 다음을 구분해 남긴다.
  - 원문 기준 버전
  - 번역 반영 상태
  - 번역만 따로 손본 부분
- 공용 자산 수정 여부도 함께 남긴다.
- 번역본을 아직 만들지 않았더라도, 나중에 번역 동기화를 판단할 수 있게 `번역 동기화 메모`는 비워 두지 않고 최소 판단을 남긴다.

## 지금부터의 적용 범위

- 이 규칙은 지금부터 수정하는 Section부터 적용한다.
- 기존 Section 전체를 한 번에 소급 정리하지 않는다.
- 다만 이미 손대는 Section이라면 버전 코드와 릴리즈노트를 함께 추가하는 것을 기본으로 한다.
