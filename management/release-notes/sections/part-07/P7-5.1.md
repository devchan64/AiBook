### v2026.08.03

- 원고를 `화풍 계약 → 장면 행렬 → 행별 원본 생성 → 사람 검수와 구조적 재생성 → 전체 팩 승인 → 다음 단계 입력` 파이프라인으로 정리했다. Mermaid 흐름도와 입력·산출물 표로 모델 생성과 사람 승인의 역할을 구분한다.

- P7-5.1이 정하는 배경 화풍 계약과 P7-5.2가 정해야 하는 피부·머리카락·눈·의상 character contract를 분리했다. 장소의 광원은 컷신의 반사광에는 쓸 수 있지만 인물 기본색을 다시 정하는 근거는 아니라는 경계를 명시했다.

- 승인 원본 단락에 남아 있던 과거 검수 대기 상태 문구를 정리했다. 창가 독서실이 여객기 행을 대체해 다섯 필수 행을 채웠고, courtyard를 포함한 네 보조 행도 모두 승인됐다는 현재 ledger·manifest 상태로 맞췄다.
- 모델 파이프라인 도식과 해설을 tokenizer·text encoder, seed·latent, FlowMatch scheduler·transformer 반복, VAE decode, PNG 저장, 사람 검수 단계로 세분화했다. 생성 조건과 승인 판단을 구분하는 표를 추가하고, Diffusers Flux2 문서 링크의 확인일을 갱신했다.
- 모델 파이프라인 해설과 실행 코드 해설에 반복되던 seed·guidance·offload·승인 경계 설명을 정리했다. 문단 흐름을 `모델 실행 조건 이해 -> 코드에서 바꿀 값 구분 -> 사람 검수와 ledger/manifest 분리` 순서로 재배치했다.
- P7-5.1의 화풍 참조 셋이 일반 배경 스타일 수집이 아니라, P7-5.2에서 FLUX.2 Klein 4B로 캐릭터 기준 참조 패키지를 만들기 위해 먼저 고정하는 입력 조건임을 도입부·모델 해설·ledger/manifest 연결 문장에 명시했다.
- `Flux2KleinPipeline` 도식은 실행 준비를 별도 구역으로 분리한 뒤, 입력 조건 구역에는 scene 행, 공통 화풍 계약, 해상도, 추론 반복과 guidance, CPU seed를 상세 노드로 넣었다. 표는 같은 입력값의 코드 위치와 검수 의미를 설명하는 보조 자료로 유지했다.
- FLUX.2 Klein 4B 가중치 로드, `torch_dtype=torch.bfloat16`, `enable_sequential_cpu_offload()`를 `Flux2KleinPipeline` 내부 추론 단계가 아니라 실행 준비 구역으로 분리했다. 본문도 offload가 내부 알고리즘 변경이 아니라 단계별 GPU 상주 메모리를 줄이는 운용임을 명확히 했다.
- 차트 가이드라인에 맞춰 `pipe prompt` 구성을 입력 조건 구역으로 옮기고, `Flux2KleinPipeline` 내부에는 tokenizer/text encoder, latent, scheduler/transformer, VAE decode만 남겼다. 각 subgraph에는 세로 배치 방향을 명시해 Mermaid가 과도하게 가로로 늘어나는 것을 줄였다.
- Mermaid 입력 조건을 `텍스트 입력`, `이미지 출발 조건`, `추론 설정` 세 묶음으로 정리하고, 산출 구역의 터미널 요약 노드를 제거해 도식의 중심을 `입력 -> pipeline -> 검수 -> manifest` 흐름으로 좁혔다. offload 연결은 점선으로 바꿔 추론 알고리즘이 아니라 메모리 운용임을 구분했다.
- Mermaid 화살표를 정리했다. 세 입력 조건은 `pipe 호출 입력`으로 합류시키고, 실행 준비는 `실행 준비 완료` 노드로 모은 뒤 pipeline의 `입력 적용` 단계에만 연결했다. 이를 통해 offload와 입력 조건이 내부 단계마다 반복 연결되어 보이는 문제를 줄였다.
- `Diffusers Flux2KleinPipeline` 블록 내부 화살표를 실제 추론 구조에 맞게 다시 나눴다. `pipe 입력 분배`에서 text encoder, 초기 latent, FlowMatch scheduler로 갈라지고, transformer가 text embedding·timestep·latent를 받아 50 step 반복 갱신한 뒤 VAE decode로 넘어가도록 표현했다.
- 원고 검수에서 `guidance_scale` 설명을 보정했다. guidance가 scheduler만의 입력처럼 읽히지 않도록 transformer의 반복 갱신 조건에 관여한다고 도식·표·본문 표현을 맞췄다.
- 개념사전 연계 검수 결과, 제품·라이브러리명인 FLUX.2 Klein 4B, Diffusers, `Flux2KleinPipeline`은 새 표제로 만들지 않았다. 대신 기존 표제인 프롬프트, 토큰화, 임베딩, 트랜스포머의 첫 등장 링크를 본문에 추가하고, 프롬프트·토큰화·트랜스포머 항목의 등장 Section에 `P7-5.1`을 반영했다.
- 외부 참조 근거 누락 검수 결과, `enable_sequential_cpu_offload()`의 메모리 운용 설명은 Flux2 pipeline 문서보다 Diffusers 메모리 최적화 문서가 직접 근거이므로 참고 자료에 `Diffusers Reduce memory usage`를 추가했다.
- 전체 생성 흐름을 `화풍 참조 셋 -> 캐릭터 참조 셋 -> 컷씬 -> 화풍 보정` 네 단계로 분절한 8 GB VRAM 실험으로 명시했다. P7-5.1은 첫 단계로서 다음 FLUX.2 Klein 4B 캐릭터 참조 패키지 생성에 넘길 화풍 입력 조건을 고정하는 역할로 정리했다.
- FLUX.2 Klein 4B의 4B rectified-flow transformer, text-to-image·image editing·multi-reference editing, Apache 2.0 공개 가중치, Diffusers 실행 가능성 같은 장점과, 약 13 GB VRAM 공식 기준·8 GB 환경의 offload 필요·prompt 미준수 가능성 같은 한계를 함께 설명했다.
- 코드 발췌 해설에 `enable_sequential_cpu_offload()`가 모델 구성 요소를 실행 순서에 맞춰 CPU와 GPU 사이에서 옮기는 메모리 운용임을 추가했다. 또한 아홉 장면을 한 batch로 묶지 않고 `for scene in scenes`로 행별 생성·저장·캐시 반환하는 것이 8 GB VRAM에서 파이프라인을 분절하는 방식임을 설명했다.
- 승인 원본 9개 이미지를 목록형 grid에서 3x3 Markdown 표로 바꿔, 필수 행과 보조 행의 배치·장소·시간·camera 조건을 한눈에 비교할 수 있게 했다. 표 중간에 별도 머리글 행을 넣지 않고 각 이미지 셀 첫 줄에 `필수 행 1`~`필수 행 5`, `보조 행 1`~`보조 행 4` 라벨을 같은 굵은 글자 형식으로 배치했다.
- 공통 lazy-load source 뷰어는 긴 코드 줄을 본문 폭에서 줄바꿈하고, 가로 스크롤 대신 세로 스크롤만 사용하도록 개선했다. 펼치기 헤더에는 열린 상태와 hover 상태를 구분하는 표면을 추가했다.
