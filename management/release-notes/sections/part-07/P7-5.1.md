### v2026.08.03

- 원고를 `화풍 계약 → 장면 행렬 → 행별 원본 생성 → 사람 검수와 구조적 재생성 → 전체 팩 승인 → 다음 단계 입력` 파이프라인으로 정리했다. Mermaid 흐름도와 입력·산출물 표로 모델 생성과 사람 승인의 역할을 구분한다.
- FLUX.2 Klein AI 모델 파이프라인도 별도 도식으로 추가했다. text condition과 seed, 사전 학습 가중치, sequential CPU offload, 반복 추론, PNG·실행 기록, 사람 검수의 경계를 설명하고, seed·guidance·금지 문구가 승인 판정을 대신하지 않음을 명시했다.
- 후보 배치와 표적 재생성은 같은 실행 골격에서 당시 `SCENES`만 바꾼 이력으로 정리했다. 원고에는 현재 아홉 행을 생성하는 단일 local-GPU 재생성 코드만 연결하고, 공통 화풍 계약·장면별 변수·sequential CPU offload·실행 기록의 역할을 해설한다.
- 단일 재생성 코드의 환경변수 기반 행 선택, VRAM peak 관측, BF16 sequential CPU offload, 행별 PNG 저장, 터미널 실행 요약, 예외 시 성공처럼 출력하지 않는 흐름을 표로 해설했다.
- 검수 gate Python 코드와 실제 `BLOCKED style pack` 출력을 추가했다. 이 코드는 camera·시간·장소 행렬과 사람의 최종 승인 상태를 검사하지만, 이미지 미적 품질을 자동 판정하거나 ledger 상태를 바꾸지는 않는다는 경계를 설명했다.
- 내장 이미지 생성으로 만든 v2 원본 아홉 장과 관련 승인 기록을 P7-5.1의 입력·승인·manifest에서 제외했다. 다른 절의 provenance 기록을 정리한 뒤 파일도 폐기하며, P7-5.1은 로컬 GPU 생성 원본만 허용한다. manifest와 ledger의 상태를 `blocked_pending_local_gpu_regeneration`으로 되돌렸다.
- 같은 다섯 필수 행과 네 보조 행을 대상으로 로컬 GPU 재생성 스크립트를 추가했다. 생성 결과는 모두 `review_required`이고, 사람 승인을 거치기 전에는 원고 그리드나 P7-5.2 입력에 쓰지 않는다.
- 로컬 GPU 생성 스크립트의 공통 화풍 계약·장면 행·pipeline 호출 핵심을 Python 코드 블록으로 원고에 발췌하고, 무엇을 바꾸면 어떤 생성 조건이 달라지는지 해설했다. 본문 설정값을 실행 파일과 같은 `guidance_scale=4.0`으로 정정했다.
- 승인 원본 그리드의 HTML 이미지 경로를 사이트 루트 기준 `/AiBook/assets/...`로 수정해 `/AiBook/parts/assets/...` 404를 해소했다.
- 아트리움 `local-gpu-v5`와 도심·주택가·옥상 광장·베니스 `local-gpu-v1`을 사람 승인 원본으로 기록했다. 여객기 실내 v1은 물리적으로 성립하지 않는 객실 구조 때문에 불합격으로 기록하고 재생성한다. courtyard·공원·승강장 검수가 남아 있어 전체 팩과 P7-5.2 입력은 계속 차단한다.
- 불합격한 여객기 실내 `local-gpu-v1` PNG를 삭제하고, 실행 기록에는 삭제 사실과 `local-gpu-v2` 재생성 후보의 대체 관계만 남겼다.
- 공원·열차 승강장 `local-gpu-v1`과 물리적으로 가능한 객실 구조로 다시 만든 여객기 실내 `local-gpu-v2`를 사람 승인으로 기록하고, 원고의 행 표·승인 원본 그리드에 반영했다. courtyard 한 보조 행의 검수만 남아 전체 팩 manifest는 계속 비워 둔다.
- 원고 그리드가 아홉 장면을 모두 보이도록 courtyard `review_required` 후보도 점선 카드와 상태 표기로 추가했다. 이 후보는 비교용으로만 표시하며 manifest와 P7-5.2 입력에서는 제외한다.
- 승인·검수 대기 원본 아홉 장의 표시는 HTML `div/figure` 대신 Markdown 목록으로 바꾸고, 목록 클래스에 CSS Grid를 적용했다. 화면이 넓으면 두 열, 좁으면 한 열로 이어진 이미지가 배치된다.

### v2026.08.04

- 원고를 Markdown 중심으로 정리했다. 아홉 이미지가 들어 있는 Markdown 목록에 CSS Grid를 적용해, 넓은 화면에서는 두 열, 모바일에서는 한 열로 연속 배치된다.
- 검수 ledger에서 삭제·교체된 과거 후보 45건과 중복된 초기 검토 블록을 제거했다. 현재 존재하는 아홉 local-GPU 원본의 사람 판정만 남기고, `next_run_matrix`는 gate 호환성을 위해 유지했다.
- 후속 gate·manifest·P7-5.2가 읽지 않는 `p7-5-1-local-gpu-regeneration-runs.json`을 제거했다. 생성 스크립트는 PNG와 터미널 실행 요약만 만들고, 지속적으로 보존할 사람 판정은 ledger에만 기록한다.
- 현재 원고·ledger·gate·manifest에서 참조하지 않는 과거 P7-5.1 후보 PNG·sidecar JSON과 probe·재생성 스크립트를 폐기했다. 단, P7-5.2 provenance가 참조하는 daylight park 후보 쌍은 보존했다.
- 여객기 실내 `local-gpu-v2`는 별이 천장처럼 드러나 물리적으로 가능한 객실 구조를 만족하지 못해 불합격으로 되돌렸다. v3 prompt에는 불투명한 연속 천장·오버헤드 빈과 창문으로만 보이는 외부 야경 조건을 추가했다.
- 강화한 조건으로 여객기 실내 `local-gpu-v3`를 local GPU에서 생성해 원고 그리드와 ledger의 `review_required` 후보로 교체했다. v2는 불합격 이력으로만 보존한다.
- 여객기 v3는 닫힌 천장은 충족했지만 단독 좌석·좁은 객실로 읽혀 불합격 처리했다. v4에는 넓은 2-2 이코노미 객실, 공유 팔걸이를 가진 인접 두 좌석, 넓은 통로 조건을 추가했다.
- 여객기 v4도 전경이 단독 좌석처럼 읽혀 불합격 처리했다. v5는 잘리지 않는 전경의 두 좌석쌍, 붙어 있는 등받이·쿠션·공유 팔걸이, 2-2 반복 배치를 명시한다.
- 여객기 v5에 좌석·천장·창가 조명·바닥의 투명 색층, wet-on-wet 번짐, 안료 고임, granulation을 추가해 수채화 질감이 평면 도색에 묻히지 않게 보강했다.
- 여객기 v5는 좌석쌍은 만들었지만 열린 천장과 과도한 밝기 때문에 불합격 처리했다. v6에는 화면 상단 전체를 닫힌 남청색 천장으로 고정하고, 창문 밖 야경·소수의 낮은 밝기 독서등만 허용했다.
- 여객기 v6은 복잡한 사선 좌석 구도 대신, 중앙 통로를 기준으로 좌우 세 좌석이 붙는 단순한 3+3 이코노미 열을 보이도록 구도를 변경했다.
- 여객기 v6은 닫힌 천장은 충족했지만 3+3 좌석 행을 만들지 못했다. v7은 뒤 중앙의 넓은 샷에서 여섯 등받이가 같은 깊이로 보이는 단순한 3+3 행을 요구한다.
- 3+3만 강조한 뒤 중앙 구도는 창가 사선 시점 조건을 놓쳤다. v8은 왼쪽 창가에서 통로를 가로질러 보는 사선 시점과 하나의 3+3 열을 함께 요구한다.
- 여객기 행 prompt가 공통 수채화 계약과 금지 조건을 반복해 2,065자로 비대해진 것을 확인했다. 중복은 `COMMON_CONTRACT`에 맡기고, v8 장면 prompt는 창가 사선·3+3·닫힌 천장·낮은 야간 조명만 남긴 짧은 구성으로 축소했다.
- 여객기 v8은 닫힌 천장과 창가 사선은 개선됐지만 실내가 너무 밝아 불합격 처리했다. v9에는 천장등을 끄고, 창문과 두 개의 작은 독서등만 남긴 저노출 남청색 조건을 추가했다.
- v8은 창가가 보이지만 통로가 정면에 가까워 사선성이 약했다. v9은 왼쪽 창가에서 통로를 45도 이상 가로지르는 강한 사선 구도를 명시했다.
- 축소한 prompt로 생성한 여객기 v9을 참조 패키지와 원고 그리드의 `review_required` 후보로 교체했다. 사람 승인 전에는 manifest와 P7-5.2 입력에서 제외한다.
- 여객기 v9은 3+3 한 행과 강한 창가 사선을 만들지 못해 불합격 처리했다. v10은 긴 객실 반복을 배제하고, 왼쪽 창가에서 한 행의 여섯 등받이를 55도 사선으로 보는 근접 구도로 변경했다.
- 3+3 요구가 실제 장면 구도를 과도하게 복잡하게 만들어 제거했다. v11은 왼쪽 창가의 붙은 두 좌석과 그 오른쪽의 하나의 사선 복도만 보이는 단순한 장면으로 정의했다.
- 여객기 v11의 복도 소실점을 화면 중앙이 아닌 오른쪽 바깥으로 지정해, 창가 좌석과 복도의 사선 분리를 강화했다.
- 여객기 v11 바닥을 짧은 무늬 없는 짙은 항공기 카펫으로 긍정적으로 지정했다.
- 여객기 실내는 반복 생성으로도 좌석 모듈·천장·사선 구도를 함께 안정적으로 충족하지 못해 P7-5.1 후보군에서 폐기했다. 여객기 PNG와 ledger·원고·생성 스크립트의 해당 행을 제거하고, 실내·밤·oblique 필수 행은 창밖이 밤이고 작은 스탠드 조명이 있는 창가 독서실의 사선 구도로 대체했다.
- 대체 장면 창가 독서실 `local-gpu-v1`을 생성해 검수 후보로 원고와 ledger에 반영했다. 바깥 밤과 작은 스탠드 조명은 충족했으나, 화면 가장자리와 사선 수렴은 사람 검수가 필요해 manifest에는 넣지 않았다.
- 창가 독서실 `local-gpu-v1`은 사람 승인으로 전환해 실내·밤·oblique 필수 행을 채웠다. courtyard 검수가 남아 전체 manifest와 P7-5.2 입력은 계속 차단한다.
- courtyard `local-gpu-v1`도 사람 승인으로 전환했다. 아홉 원본을 승인 manifest에 기록하고 ledger를 `approved_for_character_reference`로 전환했으며, P7-5.2는 이 중 하나의 개별 원본을 화풍 입력으로 선택할 수 있다.
- P7-5.1이 정하는 배경 화풍 계약과 P7-5.2가 정해야 하는 피부·머리카락·눈·의상 character contract를 분리했다. 장소의 광원은 컷신의 반사광에는 쓸 수 있지만 인물 기본색을 다시 정하는 근거는 아니라는 경계를 명시했다.
- courtyard·베니스·공원·승강장의 네 보조 행 역할을 표로 추가하고, 현재 아홉 local-GPU 후보를 직접 생성하는 스크립트를 lazy-load source로 연결했다.
- 공통 lazy-load source 뷰어는 긴 코드 줄을 본문 폭에서 줄바꿈하고, 가로 스크롤 대신 세로 스크롤만 사용하도록 개선했다. 펼치기 헤더에는 열린 상태와 hover 상태를 구분하는 표면을 추가했다.
- 불합격·교체 이력과 최종 사람 판단은 review ledger에 남긴다. 별도의 contact sheet는 생성하거나 보존하지 않는다.
- P7-5.2의 참조 상태 검사는 최종 로컬 GPU 승인 상태를 요구한다. 단, 캐릭터 identity·시점 묶음·권리 확인은 P7-5.2의 별도 승인 대상이다.
- lazy-load source는 문서 변환의 상대경로 재작성 영향을 받지 않도록 사이트 루트 기준 `/AiBook/assets/...`를 사용한다. 세 Python 원문 요청이 `200 OK`로 확인되었고, `/parts/assets/...` 404를 해소했다.
