- 추가 반영: 실제 SD 1.5 UNet-LoRA preflight 및 anchor profile 스크립트를 실행 자산 목록에 연결했다. 입력은 종횡비 보존 resize와 흰 padding만 사용하며, 비유한 loss 또는 gradient는 실패로 기록한다.
- 검증 결과: RTX 5070 Laptop GPU 8 GB 환경에서 rank 8 UNet LoRA의 forward/backward 1회를 성공했고, trainable parameter `1,594,368`, peak VRAM 약 `2,326 MiB`를 기록했다.
- 실행 결과: 새 SD 1.5 base에서 100-step FP16 AdamW profile은 마지막 loss가 비유한 값이 되어 수치 안정성 실패로 기록했다. 같은 무크롭 profile을 BF16으로 다시 실행해 100 step을 모두 완료했고 loss `0.2029 -> 0.1741`, peak VRAM 약 `2,351 MiB`를 기록했다. 이 실행은 어댑터를 보존하거나 held-out 이미지를 생성하지 않았으므로 캐릭터·화풍 품질 통과를 주장하지 않는다.
- 실행 결과: BF16 100-step adapter를 LoRA-only safetensors로 저장해 네 held-out 장면의 fixed seed LoRA off/on 비교를 실제 생성했다. 원본 caption은 CLIP 77-token 한도를 넘어 첫 출력을 무효로 처리했고, evaluator가 길이를 사전 차단하도록 보정한 뒤 압축 prompt로 재실행했다. 재실행에서도 네 컷 모두 얼굴·청록 단발·가방 구조·전신·장소/camera·clean-line-art를 함께 보존하지 못해 품질 미통과로 판정했다. 해당 adapter와 PNG는 보존하지 않고 스크립트·manifest·판정만 남긴다.
- 실행 결과: LoRA 없는 prompt-only base probe에서 일반 SD 1.5와 WD 1.5를 같은 compact prompt·negative prompt·seed·`384 x 512`·25 step으로 비교했다. SD 1.5는 얼굴·인체·화풍이 크게 흔들렸고, WD 1.5는 청록 머리·흰 재킷·청록 바지·전신 일러스트를 더 자주 유지했지만 가방·동작·장소/camera·절제된 clean-line-art를 안정적으로 만족하지 못했다. 두 base 모두 prompt-only 해법으로는 미통과이며, WD 1.5만 새 참조 제어 실험 후보로 제한했다. 비교 contact sheet는 이 판정의 진단 자산으로 보존했다.
- 실행 결과: SDXL 전용 IP-Adapter를 WD 1.5에 억지로 결합하거나 새 가중치를 받지 않고, 승인된 Mira 전신을 WD 1.5 img2img 초기 이미지로 사용했다. 같은 네 held-out prompt·seed에서 `strength` `0.25`·`0.55`·`0.80`을 비교한 결과, 낮은 strength는 얼굴·의상·가방을 보존하지만 흰 배경의 가까운 정면 전신 구도에 고정됐다. 높은 strength는 일부 팔·몸통·난간 변화를 내지만 요청 scene/camera/action을 완성하지 못하고 identity·가방 세부도 이탈했다. 단일 참조 img2img는 동적 웹툰 컷 경로에서 제외하고, 두 contact sheet를 한계 검증 자산으로 보존했다.
- 모델 전환: SD 1.5 품질 실패 뒤 base를 고정하지 않았다. train을 scene 16장에서 승인된 전신 다각도 19장으로 바꾸고, caption의 `101~114 token` 초과·무음 절단을 `68~73 token` 계약과 사전 실패 검사로 교정했다.
- 실행 결과: Animagine XL 4.0과 SDXL base 1.0은 frozen text encoder·VAE의 CPU offload를 사용하는 rank 8 BF16 UNet LoRA로 모두 8 GB 학습 게이트를 통과했다. Animagine XL은 100-step held-out에서 장면별 인물이 사라져 제외했다. SDXL base 1.0은 100 step, peak 약 `6,315 MiB`, loss `0.0258 -> 0.00210`으로 완료했고, held-out LoRA on에서 머리·재킷·바지·신발·가방의 반복성이 늘었다.
- 판정: SDXL base 1.0은 identity·style 부분 통과이나 얼굴·clip·가방 geometry·손-소품 접점·저각도 camera는 미통과다. StoryDiffusion과 inpaint는 아직 실행하지 않으며, 다음은 이 base LoRA에 구조 조건 하나만 더하는 비교다. Animagine XL의 PNG와 adapter는 품질 미통과로 제거하고 통합 JSON 판정만 보존했다.
- 실행 결과: SDXL base identity-only LoRA의 학습 해상도를 전신 최종 frame과 같은 `512 x 768`으로 올려 8 GB 실행을 확인했다. one-step peak는 약 `6,261 MiB`, 100-step peak는 약 `6,315 MiB`였다. 같은 cinema held-out에서 Canny scale `0.0`/`0.10`/`0.35`/`0.75`를 비교한 결과, `0.10`은 identity를 대체로 지키지만 pose를 바꾸지 못했고 `0.35` 이상은 굽힘·원근을 만들지만 재킷·바지·가방을 바꿨다. 이 조합에는 identity와 구조를 함께 통과시키는 scale이 없으므로 inpaint나 두 번째 조건으로 확장하지 않는다. scale contact sheet·판정·두 실행 코드는 남기고 adapter·dataset·개별 sheet는 제거했다.
- 실행 결과: 같은 native-resolution LoRA adapter에서 전체 Canny와 character-and-bag ROI를 지운 scene-only Canny를 `0.35`/`0.75`로 비교했다. scene-only Canny는 흰 재킷·청록 바지 보존을 일부 회복하고 foyer 배경을 바꾸지만 upright 또는 축소된 인물을 만들며 가방·대각 끈은 계속 실패했다. 전체 Canny만 굽힘을 전달하지만 의상·가방을 바꿨다. scene-only Canny는 배경/camera 보조 입력으로만 부분 통과이며, 다음 pose 제어는 foreground human-pose 조건으로 분리한다.
- 모델 전환: Hugging Face 인증이 없는 환경을 전제로 gated model 후보를 제외하고, InvokeAI의 공개 FLUX.2 Klein 4B GGUF Q4 + 공개 VAE + 공개 Qwen3 4B encoder 조합을 별도 런타임에 설치했다.
- 출처·이용 조건 공개: 기준 참조 `single-01`은 Codex `image_gen.imagegen`으로, 첫 FLUX.2 전체 컷 PNG 두 장은 로컬 InvokeAI runtime으로, 이후 FLUX.2 비교 PNG는 직접 Diffusers로 생성했음을 원고에 분리 표기했다. InvokeAI Apache-2.0 코드는 실행 runtime의 조건일 뿐 모델·변환물·생성물의 이용 조건을 대체하지 않으며, 이 표기는 저작권 귀속을 법적으로 판정하지 않는 provenance 기록이다.
- 실행 결과: Mira `single-01` 한 장을 내장 reference conditioning으로 연결한 `512 x 768`, Euler 4-step, seed `320241` 영화관 티켓 장면은 `14.4`초, peak `5,552 MiB`에서 생성됐다. 전신, 얼굴·청록 단발·clip, 흰 재킷, 청록 바지, 흰 운동화, 오른쪽 hip의 navy flap bag과 단일 대각 strap을 사람 검수에서 통과했다.
- 실행 결과: 같은 참조와 seed에서 지하철 계단 하행·보행·저각도 3/4 camera만 바꾼 두 번째 gate는 `20.6`초, peak `5,673 MiB`였다. 전신 보행·계단 원근과 character/object contract를 함께 확인해, OpenPose 없이 자연어 pose/camera 지시를 받는 단일 참조 전체 컷 후보로 보존했다.
- 판정: 두 단일 reference prompt의 통과는 multi-reference, side/rear 또는 극단 camera, 손-소품 접점, 여러 장소 반복 및 inpaint 품질을 보장하지 않는다. 이 gate를 통과하기 전처럼 국소 보정을 앞당기지 않으며, 다음은 복수 pose·camera·장소의 일반화 비교다.
- 실행기 비교: BFL raw CLI는 Qwen3·보조 모델·VAE의 초기 GPU 적재에서 8 GB에 맞지 않았고, InvokeAI는 GGUF Q4와 component 교대로 두 gate를 통과했다. 같은 공개 FLUX.2 Klein 4B를 Diffusers `Flux2KleinPipeline`과 `enable_sequential_cpu_offload()`만으로 직접 실행해 InvokeAI 의존 없는 대안을 검증했다.
- 실행 결과: 순수 Diffusers 기준 장면은 `11.7`초, peak `1,834 MiB`, 저각도 계단 보행은 `11.6`초, peak `2,090 MiB`였다. 두 이미지 모두 full body, face/hair clip, 의상, right-hip navy flap bag + one diagonal strap과 장면 contract를 통과했다.
- 판정: InvokeAI와 Diffusers 결과는 Q4/BF16 정밀도와 loader 차이로 동일 pixel이 아니지만, 두 품질 gate를 모두 통과했다. 현재 유효한 최소 파이프라인은 GUI나 InvokeAI model manager가 아니라 public FLUX.2 Klein direct reference conditioning + Diffusers sequential CPU offload다. 원본 BF16 cache 약 13 GB와 CPU-side load는 운영 비용으로 남는다.
- 비교군 확장: Mira 참조, 가방 없는 남성 clean-webtoon 참조, 가방 없는 여성 수채화·ink 참조, text-only를 같은 Mira 영화관 prompt에서 비교했다. 두 외부 참조에서도 Mira의 청록 bob·silver clip, 흰 재킷·청록 바지·흰 신발, right-hip navy flap bag과 하나의 strap, clean flat-color webtoon rendering이 회복돼 세 이미지가 통과했다.
- 판정 보강: 이 결과는 한 장면에서 prompt가 단일 호환되지 않는 참조보다 강하게 작동한다는 근거다. text-only는 무관한 panel border 때문에 이미지 자산에서 제외했다. 저각도 보행, side/rear, 얼굴·손 detail, 다른 장소의 반복 전에는 style lock이나 일반화를 주장하지 않는다.
- 일반화 gate: 같은 네 입력군으로 카메라를 한 계단 아래 무릎 높이에 두는 저각도 지하철 보행과 true side-profile 우천 도로 보행을 재실행했다. 두 gate는 `4/4` 통과했으며, 전신·pose·camera·의상·가방 contract가 함께 남았다.
- reference camera 비교: 같은 cinema 측면 전체 컷 prompt에서 정면 `single-01`과 angle-matched 측면 `single-14`만 바꾸고 `512 x 768`, 4 step, guidance `1.0`, seed `320301`을 고정했다. 두 출력 모두 측면 보행·전신·신발·ticket·의상·navy flap bag과 단일 strap을 통과했고, 합계 `22.4`초, peak `2,090 MiB`였다. 측면 참조는 이 조건에서 정면 참조보다 뚜렷한 품질 이득을 보이지 않았으므로, 다음 rear·소품 gate에서만 참조 각도 효과를 다시 검증한다.
- rear reference 비교: 기존 rear 일반화 gate의 `2/4` 부분 통과를 직접 참조 조건과 구분하기 위해 정면 `single-01`과 rear three-quarter `single-12`만 바꾸고 cinema rear walk prompt, `512 x 768`, 4 step, guidance `1.0`, seed `320302`을 고정했다. 두 출력 모두 후면 3/4 보행·전신·두 신발·의상·하나의 navy flap bag 및 등 위의 단일 strap을 통과했고, 합계 `22.1`초, peak `1,843 MiB`였다. rear 참조는 가방 위치와 보행 다리를 더 분명하게 뒤쪽 구도로 수렴시켰지만, 정면 참조도 같은 contract를 통과했다.
- local character/style pack: 외부 생성 기준 없이 `FLUX.2-klein-base-4B`가 만든 대칭·무소품 full-body master와 `FLUX.2-klein-4B` reference expansion으로 local-only character/style anchor pack을 구성했다. master는 `768 x 1152`, 50 step, guidance `4.0`, seed `410201`, `152.5`초, peak `2,894 MiB`였고, 한쪽 3/4·strict profile·rear 3/4를 생성한 뒤 대칭 contract에서만 반대쪽을 deterministic mirror로 만들었다. contact sheet, manifest, 세 generation probe와 builder를 원고의 lazy-load 자산으로 공개했다. 이 pack의 승인은 대칭 의상·무소품·중립 전신·화풍 anchor로 제한하며 가방·strap·손-소품·비대칭 액세서리·dynamic pose·scene·face close-up은 통과 근거가 아니다.
- 경계 재구성: 화풍 팩 생성은 `P7-5.1`으로 분리했다. station 기반 style pack과 수채화 v2는 frame-free 원본과 camera family 다양성을 통과하지 못했으므로 character reference 입력으로 승인하지 않는다. 수채화 PNG·crop builder·실행 코드는 제거하고, 실패 원인과 다음 입력 행렬은 P7-5.1 review ledger에만 남겼다.
- 컷씬 비교: 같은 우천 주거 골목 full-body walk prompt·seed `420301`에서 character-only와 style-plus-character reference를 비교했다. 두 결과는 인물·의상·무소품·전신 보행·장소를 유지했고 `33.5`초, peak `2,395 MiB`에서 끝났다. 다중 참조는 이 조건에서 뚜렷한 style 개선을 보이지 않아 자동 보정으로 채택하지 않는다. 이후 whole-cut에 style correction을 적용한 출력은 골목을 실내 계단으로 바꿔 scene continuity 미통과로 판정했으며 PNG와 코드는 보존하지 않았다.
- 제한 확인: `768 x 1152` full-body ticket detail은 얼굴·눈·양손·ticket 접점을 읽을 수 있었으나 수채화 참조에서 flap bag이 변형돼 `3/4` 부분 통과였다. 45도 rear three-quarter는 male webtoon·text-only `2/4`만 하나의 bag·strap을 지켰고, Mira 기준의 double bag과 수채화 입력의 crossing strap은 미통과로 이미지 자산에서 제외했다.
- 파이프라인 정리: 현재 local inpaint는 전신을 포함한 전체 컷 gate가 pose·camera·bag/strap contract를 통과한 이미지에만 적용한다. 후면 소품 안정화는 다음 개선 과제로 분리했다.
