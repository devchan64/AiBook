- IK→FLUX 입력 계약 검수: 자연어를 직접 관절값으로 쓰지 않고, 지지발·관절 제한·전후 가림을 결정론적으로 해석한 표면 blockout을 FLUX.2 Klein 4B의 단일 `image=` 입력으로 전달했다. `512×768`·50 step·seed `5416`에서 얼굴·두 팔·두 다리·지지발을 가진 사람은 생성됐지만, blockout의 수직 든 다리를 수평으로 재해석하고 팔의 후방 가림도 따르지 않았다. 따라서 이 경로는 “관절을 사람이 되게 그릴 수 있는가”에는 부분 통과지만, “IK의 정확한 pose·가림을 스토리보드에 전달하는가”에는 미통과다. 실패 PNG와 blockout은 삭제했고 guide도 만들지 않았다. 동일 blockout의 seed·step·문구만 바꾼 반복은 하지 않는다. 다음 대안은 더 강한 공간 제어 계약 또는 사람 검수 3D 작화 원본이어야 한다.
- IK→FLUX 긍정 prompt 보강 검수: 같은 blockout·seed `5416`·`512×768`·50 step을 고정하고, 수직 축·오른발 접지·전면 든 다리·후방 팔을 긍정 문장으로 반복했다. 사람 얼굴·양팔·양다리·지지발과 수직으로 선 발은 회복됐지만, blockout의 직선 든 다리를 무릎이 크게 굽은 자세로 바꾸었고 후방 가림도 엄격히 보존하지 않았다. 이전 결과보다 인체 수용도는 개선됐으나 정확한 IK pose 전달 기준에는 미통과다. PNG·blockout·guide는 삭제하며, 이것을 승인 스토리보드나 다음 단계의 guide 원본으로 쓰지 않는다.
- 승인 경로 폐기·FLUX 재정리: Animagine XL 4.0을 현 스토리보드 후보 모델에서 제외하고, 기존 승인 Animagine 스토리보드·lineart·Canny·depth를 삭제했다. 그 장면을 입력으로 쓴 FLUX 캐릭터 컷 PNG·실행 JSON·실행 코드도 실행 불능의 승인 경로가 되므로 함께 제거했다. 현재 승인 스토리보드·guide·최종 컷은 없다. 스토리보드 코드는 FLUX.2 Klein 4B 한 모델과 seed `5416`·`512×768`·50 step·guidance 1.0 계약만 유지하며, 기본 생성은 후보 PNG만 저장한다. 사람 검수로 통과한 PNG를 `--derive-guides-from`에 명시할 때만 lineart·Canny·상대 depth를 뽑아 형상 오류가 guide 입력으로 고정되는 것을 막는다.
- 거리·표현 계약 갱신: FLUX prompt에서 흑백·스케치 등 화풍 표현과 모든 부정 지시를 제거했다. 절벽은 인물의 양옆·뒤에 가깝게 솟고 인물 실루엣과의 간격은 보이도록 긍정 지시로 바꿨다.
- 가까운 절벽 재생성: 기본 seed `5416`·50 step으로 한 번 생성한 결과는 절벽 거리는 가까워졌지만 든 다리가 수직이 아닌 옆으로 뻗고 오른손이 발을 잡아 팔의 후방 가림도 잃었다. guide를 만들지 않았고 후보 PNG를 삭제했다. 거리 표현만 바꾼 재실행은 인체·가림 오류의 해법으로 반복하지 않는다.
- FLUX 스토리보드 옵션: 텍스트 전용 스토리보드 코드에 `--model flux2-klein`을 추가했다. Animagine 기본 승인 계약은 유지하고, FLUX.2 Klein 4B는 자연어 prompt·`512×768`·50 step·guidance 1.0·CPU generator·sequential CPU offload의 별도 후보 계약으로 실행한다. 출력 파일명에 모델명을 넣어 승인 스토리보드와 섞이지 않게 했으며, 같은 PNG에서 lineart·Canny·상대 depth를 추출해 별도 사람 검수 대상으로 둔다.
- FLUX 스토리보드 실행 검수: seed `5413`의 첫 자연어 prompt는 빈 상단 패널과 옆으로 든 다리를 만들어 미통과로 판정하고 PNG·guide를 삭제했다. `단일 full-bleed 패널`·`빈 frame 금지`·`수직 위쪽 다리, 옆차기 금지`를 보강한 같은 seed 출력은 한 패널 안에 수직 든 다리·양팔·지지발·열린 바닥·멀리 분리된 절벽을 보여 사람 검수 후보로 기록했다. 복장 표현은 흑백 스토리보드 수준의 임시 표기로만 보며, Animagine 승인 스토리보드를 자동 교체하지 않는다.
- 두 모델 공통 실행 계약: `--model both`를 기본값으로 추가해 Animagine XL 4.0과 FLUX.2 Klein 4B를 순차 실행한다. 지원 모델은 이 두 개뿐이며, `MODEL_DEFAULTS`에 Animagine `832×1216`·28 step·CFG 5.0·CUDA generator와 FLUX `512×768`·50 step·guidance 1.0·CPU generator를 고정했다. 두 prompt에는 수직으로 든 다리가 앞에 오고, 팔은 그 뒤에 배치돼 교차 지점에서는 팔이 가려진다는 깊이 계약을 추가했다.
- Animagine prompt 한도 보정: 팔의 앞뒤 관계를 보강하면서 태그형 prompt가 CLIP 77-token 한도를 넘는 것을 실행 전에 발견했다. 부분 생성본은 삭제했고, 같은 장면 조건을 73 tokens로 압축해 뒤쪽의 협곡·선화 지시가 잘리지 않게 했다.
- 헤어 기준 보강: 후속 캐릭터 병합의 기준으로 두 스토리보드 prompt에 턱선 길이의 짧은 단발을 명시했다. Animagine 태그형 prompt는 이 조건을 포함해 76 tokens로 다시 계수했으며, FLUX prompt에는 ponytail·긴 머리 제외도 함께 넣었다.
- FLUX 기본 seed: `--seed`를 생략한 FLUX.2 Klein 4B 실행의 기본값을 `5416`으로 바꿨다. Animagine XL 4.0은 기존 `5411`을 유지하며, `--model both`는 각 모델의 기본 seed를 독립적으로 쓴다. 명시적 `--seed`는 두 모델에 같은 시작 seed를 적용한다.
- 두 모델 3쌍 재생성: 새 seed `5414`·`5415`·`5416`에서 두 모델을 순차 실행했다. Animagine 세 출력은 수직 다리·지지발·팔의 후방 가림 계약을 모두 만족하지 못해 PNG·guide를 삭제했다. FLUX 세 출력은 짧은 단발, 수직 든 다리, 협곡과 열린 바닥을 함께 보여 사람 검수 후보로 기록했지만 승인하지 않았으므로, 사용자 지시에 따라 모든 후보 PNG·guide를 삭제했다. 이 세트는 승인 스토리보드를 자동 교체하지 않는다.
- Animagine step 단일 비교: 같은 짧은 단발·팔 가림 prompt와 seed `5416`에서 `28`과 `40` step을 한 번씩 비교했다. 28 step은 수직 다리·지지발 계약에 미통과였고, 40 step은 옆차기·긴 뒷머리·팔과 다리의 관계가 더 흔들려 개선되지 않았다. 기본값 28 step을 유지하고, 두 출력과 파생 guide는 모두 삭제했다. 이 실패 유형은 step만 높여 재실행하지 않는다.
- 승인 갱신: 텍스트 전용 Animagine XL 4.0 스토리보드(`832×1216`, 28 step, CFG 5.0, seed `5413`)와 그 파생 guide를 장면 기준으로 승인했다. 이어 Apache-2.0 FLUX.2 Klein 4B에 이 스토리보드·P7-5.2 얼굴·전신 복장 기준을 세 이미지 입력으로 주고, `512×768`·50 step·seed `5413`·sequential CPU offload에서 생성한 캐릭터 컷을 최종 승인했다(285.8초, peak 3.36 GiB). 협곡·열린 바닥·수직 든 다리·지지발·두 팔, 턱선 길이 청록 단발, 흰 재킷·청록 넓은 바지·흰 운동화·남색 가방이 함께 읽힌다. 8-step 승인본과 비교해 선화·얼굴·단발·가방·넓은 바지 형태가 더 안정적이어서 교체했으며, 든 다리의 드러난 발목은 넓은 바지의 자연스러운 동작 연출로 수용했다. 승인 PNG와 실행 JSON만 공개 자산으로 남기고, 4-step·8-step 비교와 미승인 ControlNet·Posecode·SCAIL·참조 후보 자산은 제거했다. 그 실패·보류 판단은 아래 항목의 기록으로만 유지한다.
- SCAIL 로컬 실행 기록: SCAIL-Preview Q2 GGUF와 CPU offload를 8 GB GPU에서 `352×512`·5 frame·4 step으로 실제 실행했다. model patch·text encode·sampling·VAE decode가 38.78초, peak allocated 6.09 GiB·reserved 6.31 GiB로 완료되어 실행 가능성만 확인했다. 다만 전신 기준 이미지와 정지 골격 한 장(공식 pose 영상 아님)의 축약 입력에서는 협곡·수직 든 다리·수평 양팔이 재현되지 않아 미통과였다. PNG 다섯 장은 삭제하고 입력 기록만 남겼다. 공식 `512p`·긴 pose 영상 조건과 다르므로 모델 일반 실패로 단정하지 않되, 현 8 GB 축약 계약은 승인하지 않고 재실행하지 않는다. 후속은 리그·skin·헤어·의상 mesh를 갖춘 3D 자산처럼 입력 계약이 달라질 때만 검토한다.
- 경로 경고 정리: 본문이 현재 추적 자산에 없는 `p7-5-3-guide-adherence-benchmark/` 폴더를 상대 링크로 가리키던 문장을 제거하고, 공개 자산에는 승인 스토리보드·파생 guide PNG만 유지한다는 설명으로 바꿨다.
- 반복 재실험 경고: 본문 체크리스트에 미통과 `backbone + guide 종류/출처 + 해상도 계약`을 seed·step·강도만 바꿔 반복하지 않도록 명시했다. 재개에는 실패 원인을 바꿀 새 가설과 입력 계약 변화, 그리고 실행 기록의 차이 설명이 필요하다.
- text-to-pose 인체 수용도 검수: image-to-pose 경로를 제외하고, 자연어 지시를 `지지발=오른발`·`왼다리 수직 들기`·`양팔 수평` pose ticket으로 제한한 뒤 운동학적 제약 22관절→OpenPose·관절 depth로 렌더했다. 지도 자체는 지지발·무릎·발목·양팔 연결을 통과했다. SDXL OpenPose+관절 depth(`512×768`, 24 step, 23.3초, peak 1.50 GiB)는 든 다리를 머리 뒤 부속지로 해석했다. 관절 depth를 원본 협곡 depth로 바꾼 23.2초·peak 1.50 GiB 재실행도 양팔이 사라지고 든 다리·몸통이 합쳐져 미통과였다. 두 PNG·JSON은 삭제했다. 즉 text-to-pose 관절 컴파일은 통과했지만 현 ControlNet의 인체 수용도는 미통과다.
- Animagine XL OpenPose 재판정: 동일 text pose ticket과 원본 협곡 depth를 512×768·24 step으로 실행했다(23.0초·peak 972 MiB). 인체가 정면 대칭 장식물처럼 변형돼 수직 다리·양팔·협곡을 모두 잃었다. PNG·JSON을 삭제했으며 Animagine XL OpenPose도 text-to-pose 후보에서 제외한다.
- text-to-pose 전용 후보 탐색: PoseDiffusion/GUNet은 텍스트에서 17채널 관절 heatmap을 생성해 OpenPose로 변환하는 Apache-2.0 가중치 후보라 image-to-pose와 구분해 실제 검증했다. 공식 256×256·27 step 계약도 현 PyTorch에서는 내부 관절 행렬 자료형·CFG batch=2 가정의 임시 보정이 필요했고, sequential CPU offload·CFG 단일 배치까지 적용해도 중간 블록에서 8 GB VRAM 부족으로 완주하지 못했다. 검수할 PNG가 없으므로 임시 소스·5.2 GB 가중치·부분 산출물을 삭제하고 8 GB 단일 GPU 후보에서 제외했다. HumanSD는 사람 골격 특화 코드가 Apache-2.0이지만 공식 저장소가 추론 코드·사전학습 가중치 공개를 TODO로 두고 가중치 사용권도 명시하지 않아 채택하지 않는다.
- 다음 대안 실행 검수: Posecode는 텍스트를 관절 DSL로 컴파일하고 `ground-lock: foot_right`·관절 각·IK를 검사한다. 가동범위는 배제 사유가 아닌 입력 일관성 제약으로 수용했다. `hip_left: flex 135`·`knee_left: extend 0`·`shoulders: abduct 90`·오른발 접지 DSL을 두 번 변환한 22관절 JSON의 SHA-256이 동일했고, 오른발 접지는 y=0.01 m로 유지됐다. 이 결정론적 좌표에서 OpenPose·관절 depth·surface Canny·surface depth 네 지도를 만들어 사람 검수 후보로 보존했다. 든 다리가 몸통보다 앞이라는 z-order는 고정하지만, 기본 가동범위가 원본의 극단 수직 다리를 완전히 재현하지 않고 생성 컷 품질도 아직 검증하지 않았으므로 승인하지 않는다. HY-Motion 1.0은 24–26 GB 최소 VRAM, UniPose는 LLaVA Mistral 7B 의존성으로 8 GB 단일 GPU 후보에서 제외한다.
- Posecode 사람·캐릭터 동시 수용 검수: 정확한 Posecode surface guide와 P7-5.2 전신·얼굴 기준 두 장을 Animagine XL Plus IP-Adapter에 넣는 명시적 저해상도 검증 경로를 추가했다. 512×768·24 step·sequential CPU offload에서 Canny+surface-depth는 24.235초·peak 974.6 MiB로 끝났지만 사람 대신 회색 고체 실루엣을 만들었다. Canny를 빼고 surface depth만 준 별도 계약은 17.7초·peak 970.1 MiB에서 얼굴은 만들었지만 든 다리와 팔이 원통형으로 붕괴했다. 두 PNG·JSON은 삭제했다. 따라서 다중 구조 조건과 IP-Adapter의 API 조합은 가능해도, 현재 8 GB·단일 생성에서 교차 순서·해부학·캐릭터 특징을 동시에 통과했다는 근거는 없다. 동일 조합의 seed·강도 재실행은 금지하고, 다음 대안은 통과한 인체 초안의 국소 mask/inpaint 또는 인체 표면 전용 조건 모델처럼 입력 계약을 바꿀 때만 검증한다.
- 3D 리그 대안 검수: Posecode 관절을 직접 연결하고 검정 타이즈, 얼굴 reference texture, 지지발 그림자를 둔 절차적 3D 리그 프록시를 렌더했다. 든 다리의 전면 z-order·두 팔·두 다리·접지 순서는 결정론적으로 유지됐지만, 프록시는 캐릭터의 몸·팔·의상 mesh를 만들지 못했다. 즉 3D 관절과 2D reference만으로 캐릭터 3D 표면이 생기지는 않는다. 검수할 작화 품질이 아니므로 PNG·JSON·임시 렌더러를 삭제했다. 다음 3D 경로는 사용 허가된 리깅·skin·헤어·의상 mesh를 가진 캐릭터 자산을 별도로 확보할 때만 진행한다.
- pose-transfer 후보 조사: MimicMotion은 DWPose와 기준 이미지를 직접 받으며 16-frame U-Net은 8 GB, VAE decoder는 CPU 실행 가능하다고 안내하지만, 공개 가중치는 연구·교육 전용 및 Stable Video Diffusion 사용 조건을 따르므로 개방 라이선스 기준에서 제외했다. ControlNet은 공간 조건 추가 구조이며 가림·표면·정체성의 완전 제약은 아니다. 현 모델 카드는 기본 관절선 렌더링 불안정과 1024 bucket 권장을 명시하고 HumanArt 생성 평가 mAP 0.357을 제시한다. Stable-Pose도 기존 pose-guided T2I가 복잡한 측면·후면 자세에서 제한됨을 보고한다. 따라서 이 절에서는 SD 계열 OpenPose를 단순 비가림 포즈 보조 조건으로 한정하고, 현 8 GB·단일 생성·극단 교차 자세의 인체 수용도에는 불충분하다고 판정했다.

SDXL Canny `0.50`과 `0.80`은 각각 약 27.19초·5.70 GiB, 27.08초·5.70 GiB로 실행됐지만 지지발 접지와 협곡 경계가 충분히 선명하지 않아 미통과다. 이 판정은 이 guide·seed 한 표본의 구조 수용도이며, 모델 일반 품질 판정은 아니다. 공개 자산에는 승인 스토리보드와 파생 guide PNG만 유지하고, 세부 실행 수치는 이 항목에 남긴다.
- 후속 일관성 경로 조사: ControlNet은 현재 단계의 인체·발/지면·지형 구조 수용도에 한정하고, 이후 컷신에서는 별도 캐릭터 참조와 화풍 참조를 IP-Adapter 또는 Flux.2 다중 참조로 결합하는 경로를 검토 대상으로 분리했다. SD 계열에서 IP-Adapter와 ControlNet의 병용은 공식 Diffusers 문서로 확인했으며, Flux.2 다중 참조는 현 ControlNet 경로와 입력 계약이 다르므로 한 번에 섞어 성능을 주장하지 않는다.
- Flux.1·Flux.2 구분 검토: Flux.1은 Canny·depth·Union ControlNet이 있는 구조 제어 후보이고, Flux.2 Klein은 한 장 또는 여러 장의 `image=` 참조를 받는 이미지 편집·다중 참조 후보임을 기록했다. 현 Diffusers와 로컬 설치본에서 Flux.2 ControlNet pipeline은 확인하지 못했으므로, Flux.2는 Canny/depth 전용 `BACKBONE_DEFAULTS`에 넣지 않고 별도 비교 대상으로 분리했다. 이 판단은 다운로드·실행·GPU 테스트 없이 문서·설치본 API 조사만으로 남겼다.
- 거리 계약 보강: 무용수를 열린 평지의 중앙에 두고 절벽을 양옆과 뒤쪽의 먼 배경으로 배치하도록, 스토리보드·후속 웹툰 prompt와 공간 검수 기준을 보강했다. 지지발 주위의 빈 바닥과 인물 실루엣의 분리도 이 거리 계약으로 함께 검수한다.
- 복장 계약 보강: 다리·무릎·발의 연결을 가리지 않도록 검정 민소매 레오타드와 불투명 타이즈를 고정하고, 치마·드레스·흩날리는 천·과도하게 큰 옷을 negative prompt에서 제외했다.
- 복장 재검수: 첫 복장 보강 후보는 레오타드만 검게 반영되고 다리 타이즈가 빠져 미통과로 기록했다. `black footed opaque tights`와 `bare legs` 제외를 추가해 전신 복장 조건을 다시 생성·검수한다.
- 본문·실행 계약 반영: `airborne`와 `one leg grounded`의 상충 지시를 제거하고, 지지발·밑창의 접지, 바위와 발 외곽의 분리, 인물 아래의 빈 평면을 태그형 스토리보드 prompt와 후속 웹툰 prompt에 추가했다. negative prompt에는 부유, 발 숨김·crop, 발/지면 융합, 신발/바위 융합, 발목·발 변형을 추가했다.
- 검수 기준 반영: P7-5.3의 사람 검수 표와 체크리스트에 지지발·바닥 그림자·지형의 분리 조건을 추가했다. 이 조건을 통과하지 못한 스토리보드는 guide 추출이나 후속 ControlNet 입력으로 넘기지 않는다.
- 재생성 상태: 현재 실행 환경의 NVIDIA 드라이버가 GPU와 통신하지 못해, 강화한 prompt의 새 PNG와 후속 guide·웹툰 컷은 아직 재생성·시각 검수하지 못했다. 기존 PNG는 새 계약의 통과 근거로 재사용하지 않는다.
- 변경 이유: 이전 시험에는 모델별 입력 계약이 섞여 있어, 텍스트 전용 스토리보드 모델을 같은 장면에서 권장 prompt 형식·해상도·step·guidance로 다시 검수했다.
- 본문 반영: 현대무용자와 기암절벽 한 장면으로 P7-5.3의 표본을 교체했다. 참조 사진은 자세를 문장으로 바꾸는 데만 사용하며, 모든 스토리보드 모델 입력은 텍스트뿐이라는 경계를 명시했다.
- 모델 실행 검수: Flux.2 Klein Base 4B(768 x 1152, 50 step, guidance 4.0)는 머리 구조가 사라졌고, SDXL Base(832 x 1216, 30 step, CFG 7)는 세 팔, SD 1.5(512 x 768, 30 step, CFG 7)는 절벽·선화 지시를 잃어 미통과로 기록했다. Animagine XL 4.0의 태그형 prompt(832 x 1216, 28 step, CFG 5)는 두 팔·두 다리와 기암절벽을 함께 보여 다음 단계 후보로 채택했다. 이 판정은 한 장면·한 seed의 결과이며 모델 일반의 품질 판정은 아니다.
- guide와 후속 실행 검수: 선택 스토리보드에서 lineart·canny·Depth Anything V2 Small의 상대 depth를 실제 추출했다. 스토리보드 RGB를 초기 이미지로 쓰지 않고 guide PNG 하나만 SD 1.5 ControlNet 조건으로 전달했다. CLIP 77-token 한도 안으로 압축한 prompt에서 depth 강도 0.65는 큰 자세·절벽 통로를 대체로 유지했고, 같은 seed의 0.0 기준선은 다른 부유 장면이 됐다. Canny 0.65는 큰 인물 실루엣과 절벽 경계를 가장 잘 보존했고, lineart 0.65는 머리·몸통 경계가 무너져 미통과였다. peak VRAM은 약 3.64 GiB였다.
- 다중 guide 실행 검수: 같은 통과 스토리보드의 Canny 0.65와 depth 0.35를 함께 SD 1.5 ControlNet 조건으로 전달했다. 두 팔·두 다리, 큰 동작 실루엣, 절벽 통로가 함께 읽혔으며, peak VRAM은 약 4.34 GiB였다. 이는 RGB 참조나 img2img 없이 두 파생 구조 guide만 쓴 통과 후보로 기록한다.
- SDXL 실행 검수: 원본보다 7배 작은 실험적 SDXL Canny ControlNet을 `.tmp`에 내려받아 Canny 0.50·28 step·768 x 1152·CPU offload로 실제 실행했다. 8 GB GPU에서 peak VRAM은 약 5.70 GiB였고, 두 팔·두 다리·얼굴 윤곽·절벽 통로를 유지해 SD 1.5 다중 guide보다 이 표본의 최종 웹툰 컷 후보로 채택했다. 이 경로도 스토리보드 RGB·참조 사진·img2img 없이 텍스트와 파생 Canny만 사용한다.
- 기본값 검수: 구조 guide 예제의 기본 backbone을 SDXL Canny로 바꾸고, `--guide`와 `--seed`만 준 실행이 명시적 `768 x 1152`·28 step·Canny 0.50 실행과 SHA-256까지 동일함을 확인했다. SD 1.5는 명시적 `--backbone sd15` 선택으로 유지한다.
- 스토리보드 승인: Animagine XL 4.0의 현대무용·기암절벽 스토리보드(`seed=5411`)를 사람 검수로 승인했다. 이 PNG와 같은 PNG에서 추출한 Canny·depth만 후속 구조 guide 입력으로 유지한다.
