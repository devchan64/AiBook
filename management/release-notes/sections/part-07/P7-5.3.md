### v2026.08.07

- 경로 경고 정리: 본문이 현재 추적 자산에 없는 `p7-5-3-guide-adherence-benchmark/` 폴더를 상대 링크로 가리키던 문장을 제거하고, 공개 자산에는 승인 스토리보드·파생 guide PNG만 유지한다는 설명으로 바꿨다.
- 반복 재실험 경고: 본문 체크리스트에 미통과 `backbone + guide 종류/출처 + 해상도 계약`을 seed·step·강도만 바꿔 반복하지 않도록 명시했다. 재개에는 실패 원인을 바꿀 새 가설과 입력 계약 변화, 그리고 실행 기록의 차이 설명이 필요하다.
- text-to-pose 인체 수용도 검수: image-to-pose 경로를 제외하고, 자연어 지시를 `지지발=오른발`·`왼다리 수직 들기`·`양팔 수평` pose ticket으로 제한한 뒤 운동학적 제약 22관절→OpenPose·관절 depth로 렌더했다. 지도 자체는 지지발·무릎·발목·양팔 연결을 통과했다. SDXL OpenPose+관절 depth(`512×768`, 24 step, 23.3초, peak 1.50 GiB)는 든 다리를 머리 뒤 부속지로 해석했다. 관절 depth를 원본 협곡 depth로 바꾼 23.2초·peak 1.50 GiB 재실행도 양팔이 사라지고 든 다리·몸통이 합쳐져 미통과였다. 두 PNG·JSON은 삭제했다. 즉 text-to-pose 관절 컴파일은 통과했지만 현 ControlNet의 인체 수용도는 미통과다.
- Animagine XL OpenPose 재판정: 동일 text pose ticket과 원본 협곡 depth를 512×768·24 step으로 실행했다(23.0초·peak 972 MiB). 인체가 정면 대칭 장식물처럼 변형돼 수직 다리·양팔·협곡을 모두 잃었다. PNG·JSON을 삭제했으며 Animagine XL OpenPose도 text-to-pose 후보에서 제외한다.
- 외부 근거 비교: ControlNet 원논문, xinsir SDXL OpenPose 모델 카드, NeurIPS 2024 Stable-Pose를 대조했다. ControlNet은 공간 조건 추가 구조이며 가림·표면·정체성의 완전 제약은 아니다. 현 모델 카드는 기본 관절선 렌더링 불안정과 1024 bucket 권장을 명시하고 HumanArt 생성 평가 mAP 0.357을 제시한다. Stable-Pose도 기존 pose-guided T2I가 복잡한 측면·후면 자세에서 제한됨을 보고한다. 따라서 이 절에서는 SD 계열 OpenPose를 단순 비가림 포즈 보조 조건으로 한정하고, 현 8 GB·단일 생성·극단 교차 자세의 인체 수용도에는 불충분하다고 판정했다.
- DWPose 대안 재판정: OpenPose가 빈 map을 낸 승인 스토리보드에 Apache-2.0 DWPose ONNX 사람 검출·whole-body pose를 적용해 사람 1명, 134 keypoint 중 129개를 검출했다. `--extract-dwpose-from`·`--dwpose-output`을 추가했지만, 사람이 map을 검수한 결과 들어 올린 다리의 무릎·발목 관절 연결이 실제 자세와 달랐다. DWPose+상대 depth·sequential CPU offload의 512×768(23.12초·peak 972 MiB)과 768×1152(35.876초·peak 2.17 GiB)도 장면 또는 수직 다리 관계를 유지하지 못해 PNG·JSON을 삭제했다. keypoint 수·신뢰도는 통과 기준이 아니며, DWPose도 이 장면의 관절 추출 대안으로 미통과다.
- 가려짐 대안 실행 검수: Apache-2.0 T2M-GPT를 `.tmp`에 내려받아 동작 prompt에서 HumanML3D 22관절 168 frame을 실제 생성했다(peak 1.30 GiB). `--render-3d-joints`로 한 frame을 OpenPose와 관절·뼈대 z-order depth PNG로 렌더하고, `--use-rendered-skeleton-depth`와 `--sequential-cpu-offload`를 추가했다. 일반 CPU offload의 SDXL ControlNet 두 개는 768×1152와 512×768 모두 8 GB OOM이었다. 순차 CPU offload는 512×768·24 step·24.9초·peak 972 MiB로 실행됐으나 얼굴·한쪽 다리·팔 연결이 사라져 PNG·JSON을 삭제했다. T2M-GPT도 수직 다리라는 세부 동작을 맞추지 못했다. 따라서 OpenPose+뼈대 depth는 채택하지 않으며, 인체 표면 가림에는 mesh/DensePose 또는 사람 검수 3D blockout의 normal·depth·mask를 별도 검증해야 한다.
- surface blockout 실행 검수: SMPL 원본 body model의 별도 배포 조건을 피하기 위해, 같은 22관절을 capsule 표면으로 z-buffer 렌더한 `--use-rendered-surface-guides`를 추가했다. silhouette Canny+surface-depth는 교차한 팔다리의 앞뒤 순서를 유지했지만, T2M-GPT의 부정확한 동작과 거친 surface proxy 때문에 512×768·19.6초·peak 972 MiB 생성에서 얼굴·사지 세부가 뭉개졌다. PNG·JSON을 삭제했으며, 자동 capsule surface도 채택하지 않는다.
- 캐릭터 일관성 재판정: 얼굴 turnaround Plus-Face, 흰 마스크 얼굴 Inpaint, 그리고 P7-5.2 최신 얼굴·전신 기준 11장으로 학습한 Animagine XL UNet LoRA(rank 8, 384×512, BF16, 300 step)를 다시 비교했다. LoRA 학습 peak는 6.56 GiB였다. 두 Canny 컷 모두 가방·바지·두 다리 또는 기준 얼굴의 눈·얼굴형·머리 형태가 무너져 삭제했다. Inpaint/Plus-Face도 기준 얼굴을 재현하지 못했다. 따라서 기본 실행에서 자동 얼굴 참조를 제거하고, IP-Adapter·Inpaint·LoRA 모두 캐릭터 통과 근거가 아닌 실험 옵션으로 격하했다.
- OpenPose 추출 경로: `--extract-openpose-from`으로 승인 스토리보드 RGB에서 body-only OpenPose map을 만들어 `openpose` ControlNet guide로 넘기도록 확장했다. 현 무용 스토리보드는 높이 `512`·`768`·`1024`·원본 `1216`에서 모두 사람 후보 0개였고, 같은 detector는 일반 전신 기준 이미지에서 18개 관절을 찾았다. 수직으로 든 다리의 몸통 가림, 팔·타이즈와 단색 협곡 윤곽의 중첩이 원인이므로 검은 map을 삭제했다. 코드가 빈 map을 오류로 거부하므로, OpenPose+LoRA 생성은 실제 관절 지도를 얻은 뒤에만 시험한다.
- 기본값 반복 검수: Animagine XL에서 동일 Canny·얼굴 turnaround 조건으로 guide scale `0.65`, `0.80`, `0.95`, step `24`, `28`, `32`, 참조 scale `0.20`, `0.35`를 비교했다. `0.65`는 문자 artifact로 제거했고, `0.95`는 윤곽이 경직됐다. `0.80`이 구조·인체 분리를 유지했다. 24·28·32 step 중 24 step이 같은 구조를 19.1초에 생성해 28 step(21.6초), 32 step(24.4초)보다 빨랐으며, 참조 scale `0.20`이 `0.35`보다 얼굴·머리 형태가 안정적이었다.
- 기본 실행 검수: 기본 seed를 `5413`으로 바꾸고, 기본 Animagine 실행에 검수한 얼굴 turnaround 네 장을 Plus-Face로 연결했다. 옵션을 생략한 실제 실행은 19.5초·peak 6.43 GiB로 두 팔·두 다리·지지발·협곡을 유지했다. 구조만 비교할 때는 `--no-face-reference`를 사용한다. Canny와 depth는 더 이상 암묵적으로 결합하지 않으며, 두 guide는 명시적으로 지정해야 한다.
- 비교 모델 재판정: 보강한 복장 prompt에서도 SD 1.5 Canny `0.65`·`0.80`은 세 팔 또는 접지 실패였고, SDXL Canny `0.50`·`0.80`은 다리 수 또는 노출된 들어 올린 발로 미통과였다. SDXL에 얼굴 turnaround를 더해도 흰 머리·노출된 발이 남았다. 각 실패 PNG·JSON은 삭제했고, SD 1.5와 SDXL은 실행 선택지로만 유지한다.
- 후보 입력 계약 정정: 로컬의 Z-Image Union safetensors는 ComfyUI model-patch여서 Diffusers `ZImageControlNetModel` 입력이 아님을 확인했다. 코드에는 `config.json`을 포함한 Diffusers Union 폴더 계약을 남겼다. Z-Image Turbo 공식 모델 카드의 16 GB 기준과 Qwen-Image 20B, Flux.1-dev의 비상업 조건은 8 GB·개방 라이선스 기본 후보에서 제외한다.
- 번역 반영 상태: 한국어 원문만 반영됨. 원문 기준 버전: `v2026.08.07`.

### v2026.08.06

- 재검수·기본값 변경: 처음의 SD 1.5 Canny+depth와 SDXL 후보를 다시 판정해 모두 사람 형상 또는 발·지형 분리 기준 미통과로 확정하고 PNG·JSON을 제거했다. Animagine XL을 기본 backbone으로 바꾸고, Canny 단일 guide `0.80`·`768 x 1152`·28 step·CFG 5를 8 GB 기본 계약으로 기록했다.
- 다중 참조 입력 검수: SDXL 계열에서 Plus IP-Adapter(전신·의상)와 Plus-Face(얼굴)를 별도 `--character-reference`, `--face-reference` 그룹으로 받도록 구현했다. 얼굴 turnaround 네 장과 Canny 하나는 21.6초·peak 6.43 GiB로 실제 생성되어 사람 형상·지지발·협곡을 유지했다. 두 adapter를 동시에 적재한 실행은 8 GB에서 14 MiB 추가 할당에 실패했으므로 코드가 명시적으로 거부한다. 전신 그룹 단독은 실행되었으나 얼굴 전용 그룹보다 얼굴 일치가 약했다.
- 후속 보정 경로 정리: Inpaint는 이미 통과한 컷의 발·손·의상 경계를 마스크로 국소 수정하는 단계이며, 정체성 기준을 새로 만드는 수단으로 쓰지 않는다. Flux Redux는 참조 일관성 adapter지만 FLUX.1 base·라이선스·8 GB 검증이 별도이므로 기본 경로에서 제외했다.
- 이미지 배치 정리: P7-5.1의 승인 원본 비교표 방식을 따라, 승인 스토리보드와 같은 원본에서 파생한 lineart·Canny·상대 depth를 2×2 비교표로 묶었다. 각 이미지의 역할과 검수 순서를 바로 읽을 수 있게 했다.
- 반복 재생성·신체 계약 검수: 스토리보드 코드에 `--runs`를 추가해 모델을 한 번만 올린 뒤 seed를 1씩 증가시키며 반복 생성하도록 했다. `5411`부터 3건을 실제 생성해 모두 두 팔·두 다리, 들어 올린 다리, 바닥에 닿는 지지발을 육안 확인했다. 사람 승인한 `seed=5413` 세트로 기존 승인 스토리보드와 lineart·Canny·depth를 교체하고, 나머지 후보는 삭제했다.
- 변경 이유: 승인 스토리보드의 발과 절벽 지형이 닿는 부분에서 신발 외형과 접지면이 뭉개질 수 있음을 재검수에서 확인했다.
- Flux 후보 추가: Diffusers의 Flux.1 ControlNet 문서에 따라 `flux1-dev` backbone과 InstantX Canny·depth ControlNet의 로컬 경로를 추가했다. 기본값은 공식 Canny 예시를 따른 `1024 x 1024`, 28 step, Canny scale `0.50`, guidance `3.5`다. Flux는 별도 `FluxControlNetPipeline`과 `control_image` 인자를 사용하도록 분기했으며, 로컬 가중치가 없으므로 다운로드·실행·GPU 테스트는 하지 않았다.
- 구조 수용도 벤치마크 확장: 후속 구조 guide 스크립트의 기본 prompt를 `full body dancer`로 최소화하고, `sd15`, `sdxl`, `flux1-dev`(명시적 비상업 비교 동의 필요), `qwen-image`, `z-image-turbo`의 ControlNet 입력 계약을 분리했다. Qwen은 Union ControlNet·30 step·true CFG 4.0, Z-Image Turbo는 단일 safetensors Union·9 step·CFG 0을 반영했다. 각 실행은 PNG뿐 아니라 seed, guide, 제어 강도, 시간, peak VRAM, 사람 검수 기준을 JSON으로 남긴다. 새 가중치 다운로드나 GPU 성능 실행은 하지 않았다.
- 구조 수용도 실행 검수: `20260806-233009` Animagine 스토리보드의 Canny·depth·lineart를 같은 seed `5413`, 최소 prompt로 실제 생성했다. SD 1.5 Canny `0.65`는 12.63초·3.64 GiB, depth `0.65`는 12.37초·3.64 GiB, lineart `0.65`는 12.94초·3.64 GiB였다. Canny+depth `0.65+0.35`는 12.34초·4.34 GiB로, 인물 윤곽·협곡 통로·지지발 위치를 함께 가장 잘 유지해 이 표본의 통과 후보로 둔다. Depth 단독은 협곡을 잃었고 lineart 단독은 인체 방향이 뒤집혀 미통과다. SDXL Canny `0.50`과 `0.80`은 각각 약 27.19초·5.70 GiB, 27.08초·5.70 GiB로 실행됐지만 지지발 접지와 협곡 경계가 충분히 선명하지 않아 미통과다. 이 판정은 이 guide·seed 한 표본의 구조 수용도이며, 모델 일반 품질 판정은 아니다. 공개 자산에는 승인 스토리보드와 파생 guide PNG만 유지하고, 세부 실행 수치는 이 항목에 남긴다.
- 후속 일관성 경로 조사: ControlNet은 현재 단계의 인체·발/지면·지형 구조 수용도에 한정하고, 이후 컷신에서는 별도 캐릭터 참조와 화풍 참조를 IP-Adapter 또는 Flux.2 다중 참조로 결합하는 경로를 검토 대상으로 분리했다. SD 계열에서 IP-Adapter와 ControlNet의 병용은 공식 Diffusers 문서로 확인했으며, Flux.2 다중 참조는 현 ControlNet 경로와 입력 계약이 다르므로 한 번에 섞어 성능을 주장하지 않는다.
- Flux.1·Flux.2 구분 검토: Flux.1은 Canny·depth·Union ControlNet이 있는 구조 제어 후보이고, Flux.2 Klein은 한 장 또는 여러 장의 `image=` 참조를 받는 이미지 편집·다중 참조 후보임을 기록했다. 현 Diffusers와 로컬 설치본에서 Flux.2 ControlNet pipeline은 확인하지 못했으므로, Flux.2는 Canny/depth 전용 `BACKBONE_DEFAULTS`에 넣지 않고 별도 비교 대상으로 분리했다. 이 판단은 다운로드·실행·GPU 테스트 없이 문서·설치본 API 조사만으로 남겼다.
- 거리 계약 보강: 무용수를 열린 평지의 중앙에 두고 절벽을 양옆과 뒤쪽의 먼 배경으로 배치하도록, 스토리보드·후속 웹툰 prompt와 공간 검수 기준을 보강했다. 지지발 주위의 빈 바닥과 인물 실루엣의 분리도 이 거리 계약으로 함께 검수한다.
- 복장 계약 보강: 다리·무릎·발의 연결을 가리지 않도록 검정 민소매 레오타드와 불투명 타이즈를 고정하고, 치마·드레스·흩날리는 천·과도하게 큰 옷을 negative prompt에서 제외했다.
- 복장 재검수: 첫 복장 보강 후보는 레오타드만 검게 반영되고 다리 타이즈가 빠져 미통과로 기록했다. `black footed opaque tights`와 `bare legs` 제외를 추가해 전신 복장 조건을 다시 생성·검수한다.

- 검수 기준 반영: P7-5.3의 사람 검수 표와 체크리스트에 지지발·바닥 그림자·지형의 분리 조건을 추가했다. 이 조건을 통과하지 못한 스토리보드는 guide 추출이나 후속 ControlNet 입력으로 넘기지 않는다.
- 재생성 상태: 현재 실행 환경의 NVIDIA 드라이버가 GPU와 통신하지 못해, 강화한 prompt의 새 PNG와 후속 guide·웹툰 컷은 아직 재생성·시각 검수하지 못했다. 기존 PNG는 새 계약의 통과 근거로 재사용하지 않는다.
- 변경 이유: 이전 시험에는 모델별 입력 계약이 섞여 있어, 텍스트 전용 스토리보드 모델을 같은 장면에서 권장 prompt 형식·해상도·step·guidance로 다시 검수했다.
- 본문 반영: 현대무용자와 기암절벽 한 장면으로 P7-5.3의 표본을 교체했다. 참조 사진은 자세를 문장으로 바꾸는 데만 사용하며, 모든 스토리보드 모델 입력은 텍스트뿐이라는 경계를 명시했다.

Animagine XL 4.0의 태그형 prompt(832 x 1216, 28 step, CFG 5)는 두 팔·두 다리와 기암절벽을 함께 보여 다음 단계 후보로 채택했다. 이 판정은 한 장면·한 seed의 결과이며 모델 일반의 품질 판정은 아니다.
