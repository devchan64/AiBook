### v2026.08.01

- 변경 이유: 사용자가 요청한 `만화 캐릭터를 유지하면서 웹툰을 그리기 위한 AI 파이프라인`을 Part 7 생성형 이미지 workflow 실습 안에 반영하기 위해 원고를 보강했다.

- 추가 반영: 참고자료 노트를 바탕으로 DreamBooth, Diffusers LoRA training, IP-Adapter 논문, ControlNet 논문, T2I-Adapter, ComfyUI Workflow Templates, ComfyUI ControlNet examples, kohya-ss/sd-scripts를 출처 목록에 보강하고, workflow 기록 양식에 `workflow_version`, `template_name`을 추가했다.
- 추가 반영: Python 실습으로 변경 전후 ComfyUI workflow API JSON을 읽어 checkpoint, LoRA, ControlNet, IP-Adapter, sampler 역할의 존재와 바뀐 입력값을 출력하는 비교 스크립트를 추가했다. 축약 JSON 두 개를 실행 입력으로 두고, 실제 실습에서는 독자가 내보낸 workflow JSON으로 같은 비교를 수행하게 했다.
- 추가 반영: 실행 결과를 확인해 고정된 seed·sampler 조건과 여러 제어 역할이 동시에 바뀌었다는 경고를 출력하도록 보완했다. 결과 이미지 차이를 단일 장치 효과로 성급히 해석하지 않게 실제 출력 일부와 해석을 본문에 넣었다.
- 추가 반영: Python 비교 스크립트에 `--report` 옵션을 추가하고, 축약 workflow JSON을 실제 실행해 생성한 검증 리포트를 본문 자산으로 연결했다. 리포트가 검증하는 범위는 workflow 설정이며 생성 이미지 품질 평가는 아니라는 경계를 명시했다.
- 추가 반영: 로컬 GPU에서 같은 seed와 prompt로 LoRA weight `0.0`, `3.0`의 세로 컷 두 장과 비교 이미지를 실제 생성하고, 실행 조건 JSON과 함께 본문에 넣었다. 머리·의상은 유지되지만 시선·자세·구도가 흔들린 관찰을 기록해 LoRA만으로 캐릭터 일관성을 검증할 수 없으며 IP-Adapter와 ControlNet을 추가 비교해야 한다는 결론으로 연결했다.
- 추가 반영: 실제 출력에 사용한 Stable Diffusion XL base 모델과 pixel-art LoRA의 model card를 출처 목록에 추가했다.
- 추가 반영: 프롬프트만으로 pose·camera view 변화를 주장한 3 x 3 출력을 폐기했다. Apache-2.0 OpenPose SDXL ControlNet의 관절 지도를 입력으로 사용해 공원·지하철·서점의 3 x 3 매트릭스를 실제 재생성하고, pose와 프레이밍 변화는 확인했지만 IP-Adapter 참조가 없는 동일 인물성은 미검증이라고 분리해 기록했다. `over-the-shoulder`라고 검증할 수 없던 조건은 `비대칭 자세`로 바로잡았다.
- 추가 반영: Apache-2.0 IP-Adapter SDXL을 추가해, 자체 생성한 허리 위 기준 이미지와 같은 OpenPose 조건으로 두 번째 3 x 3 매트릭스를 실제 실행했다. 의상 색과 짧은 단발의 반복성은 개선됐지만 얼굴 세부와 후드 배색은 계속 흔들려 동일 인물성은 미통과로 기록했다.
- 추가 반영: SDXL 공식 문서와 Diffusers 메모리 최적화 문서를 근거로 `768 x 1024`를 preview 해상도로 규정하고, 해상도 상승은 얼굴·손·의상 세부의 재검수와 VRAM·생성 시간 기록을 함께 요구하도록 보강했다.
- 추가 반영: 단일 래스터 이미지를 Python cutout으로 분해해 회전한 기존 2D rig 실험은 관절·가림·원근이 자연스럽지 않아 폐기했다. 관련 script, GIF, matrix, 실행 기록을 제거하고 이를 캐릭터 일관성 통과 근거로 사용하지 않도록 본문을 바로잡았다.
- 추가 반영: Blender 4.0.2 headless 환경에서 하나의 armature와 blockout mesh를 `arrive`, `walk`, `notice`, `ticket` pose, 46·55·62·70 mm 카메라로 실제 렌더했다. `.blend` 원본, 네 PNG, 실행 기록, Python contact sheet 검사 결과를 남겼다. 이 결과는 pose·camera 공간 제어만 통과하며 얼굴·화풍·손·소품의 최종 품질은 미검증으로 분리했다.
- 추가 반영: 로컬 `Qwen2.5-0.5B-Instruct`가 두 한국어 컷 지시에서 각각 `present_ticket`·`medium`·`low_angle`, `walk`·`full_body`·`eye_level` pose DSL을 선택하고, Python resolver가 관절·손 target·표 소품·카메라 값으로 전개한 뒤 Blender에서 실제 렌더했다. 처음의 직접 관절 JSON은 예시 값 복사·허용하지 않은 bone·의미 불일치가 있어 거부됐으며, LLM은 제한된 행동 DSL만 고르고 validator가 최종 구조를 허용하는 경계로 수정했다. 보행 cut의 eye-level DSL과 기존 camera preset이 어긋난 것도 발견해 camera·target 높이가 같은 46 mm preset으로 다시 렌더했다.
- 추가 반영: 네 Blender blockout에서 Canny edge를 뽑아 SDXL Canny ControlNet으로 실제 생성했다. pose·화면 크기 변화는 일부 남았지만 동일 장소, 얼굴·머리카락, 의상·화풍, 손·티켓은 모두 미통과로 기록했다. 8 GB GPU에서는 한 프로세스로 여러 컷을 연속 생성하지 못해 컷별 독립 실행 뒤 contact sheet를 조립했다.
- 추가 반영: 같은 Blender `walk` Canny 입력에서 기준 이미지 없이 만든 패널과 IP-Adapter 기준 이미지를 추가한 패널을 실제 비교했다. `256 x 384`, 12 step, 8 GB 호환 CPU offload 조건에서 큰 색 덩어리만 일부 바뀌었고, 얼굴·의상·장소·카메라와 최종 작화 해상도는 통과하지 못했다. IP-Adapter를 로드한 UNet은 image embedding을 필수로 하므로 기준/비교를 별도 파이프라인 실행으로 분리한 기록을 남겼다.
- 추가 반영: 포즈 트랜스퍼 공개 사례를 조사해, MimicMotion은 짧은 동작 참고 영상 후보로, MusePose·MagicDance는 모델/코드 사용 조건과 detail consistency 한계 때문에 본문 기본 예제에서 제외하는 판단을 출처 노트에 남겼다.
- 자산 정리: 본문이 직접 쓰지 않는 OpenPose control map, 개별 생성 프레임, 폐기된 full-body crop 실험 산출물과 script를 삭제했다. OpenPose·IP-Adapter는 매트릭스와 실행 기록만 저장하고, 2D cutout rig 자산은 남기지 않는다.
- 번역 동기화 메모: 향후 번역본도 character sheet, character LoRA, reference image, ControlNet pose/lineart, inpaint, panel consistency의 대응 표현을 유지해야 한다.
- 번역 반영 상태: 한국어 원문만 반영됨.
- 관련 자산: 이 버전에서 기록한 미채택 자산은 `v2026.08.02`에서 폐기했고, LLM pose 예제 자산만 유지한다.
