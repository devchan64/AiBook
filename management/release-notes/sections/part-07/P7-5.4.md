### v2026.08.10

- LoRA 본시험·베이스 비교: 사람 승인한 P7-5.1 배경 16장과 held-out 4장을 caption·SHA-256·승인 기록으로 고정했다. Animagine XL 4.0의 300-step 본시험은 `217.19초`, peak `6,043 MiB`로 실행됐지만, 자연어 caption·표준 bf16 파이프라인 비교가 해당 모델의 tag prompt·fp16·Euler Ancestral 권장 조건을 따르지 않아 checkpoint 선택 근거에서 제외했다. 권장 조건의 100-step 재파일럿은 장면은 유지했으나 승인 화풍의 뚜렷한 이득이 없어 미통과로 기록했다. SDXL base 1.0에서는 rank/alpha `4`, learning rate `5e-5`, 100 step, bf16 학습·fp16 추론을 실행해 `74.41초`, peak `5,997 MiB`로 완료했다. held-out 네 장소와 두 seed의 scale `0.5` 비교에서 장소 범주와 수채화 질감 강화는 확인했지만 일부 구도 변화가 있어 사람 검수 대기이며, adapter를 제작 자산·VTON 입력으로 승인하지 않았다. 관련 자산: `p7-5-4-lora-style-data/`, `p7-5-4-lora-style-dataset-manifest.json`, `p7-5-4-lora-style-trial-plan.json`.
- LoRA 시험 수립·환경 pilot: 의상·pose·Mira identity를 넣지 않는 P7-5.1 배경 화풍 전용 LoRA를 독립 실험으로 정했다. 데이터 분리 전의 승인 배경 9장 반복 pilot에서 Animagine XL 4.0, `384 x 512`, bf16, UNet attention rank/alpha `8`, batch 1을 사용했다. UNet과 text encoder 동시 상주는 OOM이었지만, frozen text/VAE 출력을 CPU에 사전계산한 재시도는 50 step·`12.54초`, peak `6,021 MiB`에서 adapter 저장까지 통과했다. 이 기록은 메모리·실행 경로만 뜻하며, 이후 16/4 분리 데이터 본시험과 분리한다.
- 비교 구조 정리: 의상 전달과 장면 재현을 하나의 성능으로 일반화하지 않도록, 수동 inpaint + 일반 IP-Adapter, ControlNet + 일반 IP-Adapter, VTON, LoRA를 입력·현재 고정 시험 결과·판단 경계로 나란히 정리했다. CatVTON은 의상 레이어 전달의 사람 검수 후보, FASHN VTON v1.5는 8 GB 첫 실행 통과지만 open-front·안쪽 crop-top 레이어 미통과, generic adapter 조합은 현 조건의 제작 gate 미통과로 기록했다. LoRA는 위의 독립 화풍 시험 결과만 반영하며, 의상·pose·Mira identity 문제의 해법으로 일반화하지 않았다.
- 실험 순서 보완: 8 GB 표에 person·garment 계약, mask 또는 parser, 의상·canvas gate를 기록하는 VTON 실행 계약을 LoRA 최소 학습 전에 추가했다. VTON과 LoRA는 단독 gate 통과 전 결합하지 않는다는 경계를 본문과 출처에 반영했다.
- DiffEdit 첫 8 GB 실행 결과: P7-5.2 승인 전신 정면을 제작 컷이 아닌 고정 시험 입력으로 사용해, cropped white jacket 편집의 자동 mask를 실제 실행했다. SD 1.5 base만으로 `512 x 768`, 20 step, mask map 4개, seed `5404`에서 `20.6초`, peak `2,723 MiB`로 실행은 완료했다. 그러나 mask가 머리·얼굴·바지·신발·바닥까지 번지고 출력도 요청한 재킷과 인물·신발 보존에 실패해 자동 mask baseline은 미통과로 기록했다. contact sheet, 검수 JSON, 재실행 Python을 추가했으며 제작 자산에는 승인하지 않았다.
- DiffEdit 반복 종료: 공통 prompt 압축, mask encode strength `0.2`, mask threshold ratio `8.0`·`5.0`, 단일 의상 목표를 차례로 비교했다. mask 확산을 줄인 설정은 재킷까지 놓쳤고, 완화한 설정은 얼굴·하체·신발로 다시 퍼지며 상의·허리띠 artifact를 만들었다. 세 설정 모두 미통과여서 prompt·step sweep을 중단하고, 반복 검수 JSON과 마지막 contact sheet를 추가했다.
- 다음 실험 준비: 사람의 black/white mask와 승인 full-frame을 필수로 받는 SDXL inpaint 대조 스크립트를 추가했다. checkpoint 자동 다운로드를 막는 offline 기본값과 명시적 `--allow-download`를 두었고, 준비 시점에는 checkpoint와 ComfyUI가 없어 Diffusers 단일 경로만 먼저 실행하도록 정했다.
- 수동 mask SDXL 첫 preflight 정정: 첫 실행은 `width`·`height`를 호출에 전달하지 않아 SDXL 기본 canvas가 섞였으므로, 잘린 출력은 mask 품질 실패가 아니라 출력 canvas 계약 누락으로 판정했다. 첫 다운로드·로딩 포함 `276.4초`, peak `3,292 MiB`의 8 GB 실행 기록은 유지한다.
- 수동 mask SDXL 수정 canvas 비교: 목표 `512 x 768`과 mask 밖 source 복원을 명시해 재실행했다. `strength 0.4`/20 step은 full-frame 보존에 통과했으나 재킷 편집이 거의 없었고, `strength 0.8`/30 step은 회색 긴소매 상의로 바뀌어 open cropped white denim jacket 요청에 실패했다. 두 결과 모두 제작 경로 미통과로 기록하고 contact sheet·mask·검수 JSON을 추가했다.
- 수동 mask SDXL 개선 10회 반복 종료: wide/narrow mask, strength `0.55`~`0.85`, CFG `10`·`12`·`15`, seed `5501`·`62294`·`62382`, prompt 길이를 한 변수씩 바꿔 10개 조건을 비교했다. 전신·mask 밖 보존은 모두 통과했고 peak VRAM은 `1,785`~`2,185 MiB`, 실행 시간은 `13.4`~`19.3초`였지만 흰 open-front cropped jacket 세 조건을 함께 충족한 후보는 없었다. prompt·CFG·strength·seed·coarse mask sweep은 중단하고, 의상 reference conditioning 또는 다른 inpaint 모델 경로를 다음 가설로 남겼다.
- 의상 reference IP-Adapter 첫 실행: 승인한 전면 jacket-crop-top 참조와 일반 `ip-adapter_sdxl.bin`을 수동 mask SDXL inpaint에 추가했다. Plus adapter와 attention slicing의 processor 충돌을 분리해 slicing 없이 실행했고, `512 x 768`, 30 step, scale `0.55`, seed `62294`에서 `20.1초`, peak `1,885 MiB`로 완료했다. 흰 포켓 flap·소매 끝은 부분 전달됐지만 재킷 몸판이 회색으로 남아 제작 후보는 미통과다. contact sheet·검수 JSON·재실행 Python을 추가했다.
- 의상 reference IP-Adapter scale 비교 종료: 같은 입력·seed에서 scale을 `0.85`로 올려 `19.7초`, peak `2,085 MiB`로 실행했다. 포켓 flap·소매 끝만 흰색인 부분 전달 패턴이 유지됐고 몸판 색·open-front 계약은 개선되지 않았다. scale `0.55`→`0.85` sweep을 중단하고, 새 conditioning 또는 다른 inpaint 모델 경로를 다음 가설로 남겼다.
- 정밀 jacket-shell mask 비교: 중앙 charcoal crop top을 black 보존 영역으로 남기고 칼라·좌우 패널·긴소매만 white로 둔 목표 실루엣 mask를 적용했다. 같은 일반 IP-Adapter scale `0.55`, seed `62294`에서 `20.1초`, peak `1,646 MiB`로 open-front·크롭 레이어·긴소매 구조는 회복했다. 재킷 몸판은 여전히 회색이므로 mask 구조는 부분 통과, 흰 fabric color 계약과 제작 후보는 미통과로 기록했다.
- fitted-shell mask 비교 종료: 원본의 어깨·팔·손목·크롭탑 opening·높은 밑단을 더 촘촘히 따른 raster mask로 다시 실행했다. `18.6초`, peak `1,991 MiB`에서 경계 부자연스러움은 줄었으나 재킷 패널은 계속 회색이었다. 다각형·경계 정밀화의 반복은 중단하고, 남은 색·재질 conditioning을 다음 가설로 분리했다.
- fitted-shell border 확장 비교: 같은 mask의 white 편집 영역을 원본 해상도 기준 `16px` 바깥으로 확장했다. `25.8초`, peak `1,608 MiB`에서 버튼·연속 몸판은 더 잘 형성됐지만 회색의 닫힌 크롭 재킷이 되어 흰 fabric color·open-front 계약은 모두 미통과였다. 경계 여유만 더 키우는 반복을 중단하고 색 conditioning 문제로 분리했다.
- 분리된 흰 재킷 참조 비교: 레이어 참조에서 회색 crop top을 제거하고 흰 재킷만 있는 승인 소품을 일반 IP-Adapter 입력으로 사용했다. `19.2초`, peak `1,814 MiB`에서 흰 포켓·소매 끝은 남았지만 몸판은 계속 회색이었다. 회색 top이 참조에 포함된 것이 원인이라는 가설을 기각하고, generic IP-Adapter의 white detail 전달과 white body 색 강제 한계를 기록했다.
- padding-mask-crop 국소 해상도 비교: SDXL inpaint의 `1024 x 1024` 학습 해상도와 Diffusers의 국소 crop 안내를 근거로 fitted-shell에 padding `64`를 적용했다. `26.1초`, peak `2,206 MiB`로 실행됐지만 회색 몸판은 유지되고 소매는 흰 짧은 소매가 되며 open-front도 사라졌다. 국소 해상도 부족만이 원인이라는 가설을 기각하고 padding crop sweep을 종료했다.
- generic IP-Adapter 10조건 탐색 종료: fitted-shell mask·분리된 흰 재킷 참조·seed `62294`를 고정하고 crop padding `32`·`96`, mask border `4px`·`8px`, adapter scale `0.30`·`1.00`, strength `0.60`·`0.85`, CFG `7`을 각각 한 변수씩 비교했다. `16.1`~`23.7초`, peak `1,661`~`2,323 MiB`에서 full-frame 보존은 모두 통과했지만, 열 후보 모두 회색 몸판 또는 짧은 소매에 머물러 흰 몸판·긴 cuffed 소매·open-front 계약을 만족하지 못했다. 이 경로의 미세 sweep을 종료하고 다른 model 또는 conditioning 비교로 전환한다.
- CatVTON virtual try-on 비교: 범용 image prompt 대신 person·garment·operator mask를 받는 CatVTON을 `768 x 1024`, bf16, 50 step, seed `62294`에서 실행했다. 전면 jacket-crop-top 레이어 참조와 jacket-shell mask를 결합하고 border를 `16px` 확장한 guidance `3.5` 조건은 `46.7초`, peak `5,443 MiB`에서 흰 cropped jacket 몸판·긴 소매·open-front·보존된 charcoal crop top을 함께 만들었다. `8px` 확장은 검은 칼라 잔존으로 탈락했다. 최선 출력은 사람 검수 후보이며 제작 자산으로 자동 승인하지 않았다.
- CatVTON 조건 분리: jacket-shell `16px`에서 guidance `2.5`·`3.5`는 기본 jacket gate를 함께 통과했지만 목선·대칭·원단 질감에 뚜렷한 차이가 없어 sweep을 종료했다. 재킷 단독 참조는 회갈색 몸판과 깨진 open front로 탈락했다. 전면 jacket-crop-top 레이어 참조를 유지한 fitted-shell `0px`은 어깨·소매가 어둡게 남아 탈락했으며, fitted-shell `16px`은 `46.2초`, peak `5,451 MiB`에서 흰 cropped jacket·긴소매·open front를 함께 유지했다. 이 출력은 사람 검수 후보로만 기록했다.
- CatVTON 출력 종횡비 계약 확인: `768 x 1152`를 요청하면 source·mask·garment는 2:3으로 준비되지만 candidate가 `768 x 1024`로 반환됐다. `67.9초`, peak `5,447 MiB`의 이 출력은 2:3 비율 후보가 아니므로 탈락 처리했다. 이후 실행기는 요청·반환 해상도가 다르면 저장 전에 오류를 낸다.
- 8 GB 실험 순서 추가: 제작 컷의 승인을 앞당기지 않는 고정 시험 이미지에서 실행 환경→SDXL inpaint 실행기→저정밀 추론→SD 1.5 최소 LoRA→LoRA와 수동·DiffEdit mask 결합→승인 제작 컷 적용 순으로 검증하도록 본문을 추가했다. 각 단계의 OOM, VRAM·RAM·SSD, 시간, mask 경계, identity·style gate를 다음 단계 조건으로 분리했다.
- 대안 경로 정리: ComfyUI Dynamic VRAM, Diffusers FP8/4-bit, CUDA Unified Memory의 역할과 한계를 추가했다. SD 3.5 Medium, T2I-Adapter, StyleAligned는 현 8 GB 기준선이 아니라 후속 비교 후보로 보류했다.

### v2026.08.03

- 구조 재배치: 이 Section을 `화풍·연속성 보정` 단계로 명시했다. 컷신 생성의 실패를 inpaint로 숨기지 않으며, full-frame gate를 통과한 컷에만 구조 조건과 국소 보정을 적용한다.
- 변경 이유: identity 참조가 pose·camera·장면 변화를 막는지 판단하려면, 먼저 구조 제어만 독립적으로 실제 검증해야 했다.
- 실행 결과: 캐시된 `control_v11p_sd15_openpose`와 표준 SD 1.5로 네 held-out 장면의 OpenPose map을 만들고, 같은 prompt·seed에서 ControlNet scale `0.0`·`1.0`을 비교했다. scale `1.0`은 팔·몸통·다리 방향과 주방·난간·영화관·작업대의 큰 구조를 off보다 더 따랐고 peak VRAM 약 `3,211 MiB`로 실행됐다.
- 판정: identity 입력을 넣지 않았으므로 얼굴·머리·의상·가방은 Mira와 일치하지 않는다. 이 결과는 structure 부분 통과일 뿐 최종 웹툰 컷이나 character consistency 통과가 아니다.
- 호환성 확인: WD 1.5 base는 text context `1024`, 이 OpenPose ControlNet은 `768`을 사용해 직접 결합할 수 없었다. WD와 이 ControlNet의 결합 경로를 제외했다.
