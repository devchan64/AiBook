### v2026.07.17
- 변경 이유: Chapter 7을 역할별로 다시 나누면서, 첫 절이 `옵티마이저가 실제로 무엇을 하는가`만 닫도록 구조를 재배치할 필요가 생겼다.
- 본문 반영: P5-7.1을 `옵티마이저(optimizer)의 역할` 중심 절로 다시 정리했다. 손실, 역전파, update의 역할 차이를 먼저 세우고, `gradient를 계산했다`와 `파라미터가 실제로 바뀌었다`를 구분하는 사례와 예제로 재배치했다. 이어서 손실, 역전파, 옵티마이저를 왜 따로 나누어 읽어야 하는지 설명 문단을 풀어 써 단계별 확인 질문이 바로 보이게 다듬었다. `왜 gradient만으로는 충분하지 않은가` 문단도 보강해, 방향 신호와 실제 이동 규칙 사이의 차이가 더 직접 보이게 했다. `옵티마이저는 무엇을 update로 만든다고 읽어야 하는가` 문단도 풀어 써, gradient 계산 결과와 실제 파라미터 이동량 사이의 중간 단계가 더 분명히 보이게 했다. 사례 도입부도 `틀림과 방향은 계산됐지만 가중치 숫자는 아직 그대로인 상태`가 먼저 보이도록 풀어 써 접근성을 높였다. 추가로 도입부와 핵심 설명 문단 전반을 덜 압축된 문장으로 다시 풀어, `학습 한 step 안에서 실제로 어떤 단계가 지나가는가`가 먼저 읽히도록 조정했다. 예제 해설도 더 풀어 써, 출력값을 어떤 순서로 읽어야 하는지가 더 직접 드러나게 했다. 마지막으로 `이 절의 목표`와 `체크리스트`도 본문 설명과 같은 언어로 다시 써, 독자가 무엇을 구분해 말할 수 있어야 하는지가 더 선명하게 보이도록 정리했다. 여기에 update 적용 전후의 위험 가중치, 예측 점수, 손실 변화를 보여 주는 before/after 차트 3개를 추가해, 독자가 예제 출력을 눈으로 다시 확인할 수 있게 했다. 이후 사례 구간은 하나의 강한 장면으로 다시 묶고, `지금 이미 계산된 것`과 `아직 일어나지 않은 것`을 직접 대조하는 표를 추가해 현재 절의 중심 질문을 더 직접 지지하게 조정했다.
- 본문 반영: 예제 자체도 `before update`, `gradient and update`, `after update` 세 구간으로 나누어 출력되게 바꿔, 코드와 출력에서 단계 경계가 더 바로 보이게 했다.
- 번역 동기화 메모: 대응 번역본 없음. 향후 번역 시 P5-7.1은 learning rate 세부 비교나 Adam 설명을 앞당기지 말고, optimizer role 자체를 닫는 구조를 유지해야 한다.
