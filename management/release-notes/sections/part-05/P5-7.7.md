### v2026.07.17
- 변경 이유: P5-7.3에서 `최근 gradient 흐름`과 `좌표별 조절`을 설명한 뒤, optimizer state와 parameter-wise update를 별도로 풀어 주는 회수 위치가 필요해졌다.
- 본문 반영: 새 보충학습 `P5-7.7 보충학습: optimizer state와 parameter-wise update`를 추가했다. parameter, gradient, update, optimizer state를 구분하는 표를 두고, adaptive optimizer가 시간축과 좌표축 state를 어떻게 함께 쓰는지 설명했다. 같은 gradient라도 state가 다르면 다음 update가 달라질 수 있다는 점을 사례와 연습으로 정리했다.
- 본문 반영: 네 항목 구분이 표 설명에만 머물지 않도록 문단을 풀어 쓰고, optimizer state를 모델 내용과 작업 메모로 나누는 비유를 확장했다. `같은 gradient라도 update가 다를 수 있다`는 사례 해설도 현재 입력과 누적 state가 함께 입력이라는 점이 더 직접 보이도록 보강했다.
- 본문 반영: parameter와 state의 차이가 실제 저장/재시작 장면에서 왜 중요한지, 그리고 같은 gradient라도 좌표별 과거 문맥이 다르면 update가 달라질 수 있다는 아주 작은 숫자 장면을 더해 초심자 기준 학습 밀도를 높였다.
- 본문 반영: parameter/state/current gradient를 두 좌표 표로 다시 적어, `현재 gradient는 같아도 문맥은 다를 수 있다`는 점을 숫자와 상태 줄로 함께 읽게 보강했다.
- 본문 반영: `읽을 때` 중심 표현을 줄이고, 학습 코드와 설명 문장 전반에서 재사용할 수 있는 구분 기준이라는 점이 더 직접 드러나도록 핵심 해설 문장을 정리했다.
- 본문 반영: 도입에 checkpoint 저장, 학습 재시작, fine-tuning에서도 parameter/state 구분이 다시 쓰인다는 문장을 추가해, 보충학습의 활용 범위를 더 분명히 했다.
- 본문 반영: `parameter, gradient, update, state`가 모두 비슷한 숫자로 보이는 초심자 혼동을 줄이기 위해, 학습 코드 세 줄을 사건별로 분리해 읽는 표와 parameter-wise update의 직관 비유를 추가했다.
- 본문 반영: `gradient 계산 -> optimizer -> 파라미터 반영` 구간을 `optimizer-loop-flow-ko.mmd` 도식으로 다시 배치해, 현재 절의 네 항목이 학습 루프 안에서 어디에 놓이는지 눈으로 확인할 수 있게 했다.
- 본문 반영: `state-update-comparison-ko.png` 그래프를 추가해, 같은 current gradient라도 좌표별 state가 다르면 resulting update가 달라질 수 있다는 점을 수치 그림으로 다시 확인할 수 있게 했다.
