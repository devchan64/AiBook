# 개념사전 작성 규칙

작성일: 2026-07-06

## 목적

- 개념사전은 책 본문에서 반복해서 등장하는 핵심 개념을 빠르게 다시 찾고 복습할 수 있게 만드는 원고다.
- 본문을 대체하는 요약집이 아니라, 본문을 읽다가 개념의 자리와 용법을 다시 확인하게 하는 참조 원고다.
- 개인의 경험적 설명과 즉흥적 표현이 본문에서 흩어지지 않도록, 검증된 표제어와 일반화된 정의로 정리하는 보조 장치다.

## 파일 위치

- 개념사전 원고는 `docs/reference/concept-glossary.md`에 작성한다.
- 개념사전 작성 규칙은 이 문서에서 관리한다.
- 원칙 문서인 이 파일은 별도 리비전노트를 두지 않고 문서 자체를 직접 갱신한다.

## 기본 원칙

- 개념사전은 원고다. 관리 메모가 아니라 독자가 읽을 수 있는 문장으로 작성한다.
- 개념사전 항목은 본문 내용을 그대로 복제하지 않고, 본문에서 반복되는 개념의 핵심 자리만 압축해 다시 설명한다.
- 개념 정의는 가능한 한 검증 가능한 표준 용어를 기준으로 쓴다.
- 개념사전 표제어는 기본적으로 한국어와 영어를 함께 적는다.
- 같은 한국어 단어라도 영어권 표준 용어로 옮기면 서로 다른 개념으로 갈릴 수 있음을 항상 염두에 둔다.
- 개념사전은 뜻풀이만이 아니라, 같은 한국어 표면형을 같은 개념으로 잘못 묶는 오류와 동음이의어·다의어 혼동을 관찰하는 기준표 역할도 맡는다.
- 개인적 비유나 직관은 항목의 주 정의로 두지 않는다. 꼭 필요하면 항목 설명 안에서 보조적으로만 쓴다.
- 개념사전은 본문보다 짧아도 되지만, 너무 짧아서 독자가 뜻을 오해하게 만들 정도로 압축하지 않는다.
- 항목은 본문에서 실제로 쓰였거나, 곧 반복 사용될 개념을 우선 정리한다.
- 같은 Part 안에서는 같은 주요 개념의 상세 설명을 가능한 한 한 Section에만 둔다.
- 같은 Part 안에서 주요 개념의 상세 설명은 가능한 한 최초 1회만 본문에 충분히 두고, 이후 Section에서는 현재 맥락에 필요한 최소 연결만 남긴다.
- 다른 Section에서 같은 개념을 다시 써야 할 때는 상세 정의를 통째로 반복하지 않고, 기본적으로 개념사전 링크로 되돌아가게 한다.

## 대표 설명 위치 원칙

- 같은 Part 안에서 반복 등장하는 주요 개념은 먼저 `대표 설명 위치`를 정한다.
- 대표 설명 위치는 그 개념이 처음 충분한 맥락, 쉬운 예시, 오해 방지 설명과 함께 나오는 Section를 뜻한다.
- 대표 설명 위치가 정해지면 개념사전의 `중심 Section`도 그 위치 하나만 가리킨다. 이때 `중심 Section`은 개념사전 안에서 쓰는 필드명이자, 산출물 정의의 `대표 Section`과 같은 뜻으로 쓴다.
- 이후 Section에서는 그 개념의 새 층위나 현재 질문과 직접 연결되는 차이만 보강한다.
- 뒤 Part에서 같은 개념이 새로운 문제 설계 층위나 운영 층위로 다시 핵심이 되면, 그 Part 안에서 처음 등장하는 Section에서 다시 정리할 수 있다. 이때도 개념사전의 `중심 Section`은 하나만 유지하고, 새 본문 위치는 `등장 Section`으로 연결해 개념 확장 경로를 드러낸다.
- `등장 Section`은 단순 참고 칸이 아니라, 실제 재등장 위치를 누적 추적해 잘못된 위치 표기나 누락이 생기는지 관측하는 목록으로 유지한다.
- 대표 설명 위치를 다시 정하거나 옮겼다면 관련 본문, 개념사전, 릴리즈노트를 함께 갱신한다.

## 정렬 규칙

- 표제어는 기본적으로 한글 표제어 기준으로 `가나다순` 정렬한다.
- 영어 원어는 표제어 괄호 안에 병기한다.
- 영문 약어가 더 널리 쓰이는 경우에도 가능한 한 한글 표제어를 먼저 세운다.
  - 예: `대규모 언어 모델(LLM)` 대신 책 본문에서 `LLM`이 중심 용어라면 표제어를 `LLM(대규모 언어 모델)`로 둘 수 있다. 이때도 정렬 기준은 실제 표제어 문자열로 고정한다.
- 같은 뜻의 변형 표현을 여러 항목으로 흩어 쓰지 않는다.
- 다만 같은 한국어 표면형이라도 대응하는 영어 개념이 다르면 별도 항목으로 분리한다.
  - 예: 한국어 `추론`은 문맥에 따라 `inference`, `reasoning`, `prediction`, `statistical inference`, `generation`처럼 다른 영어 개념과 연결될 수 있으므로, 하나의 항목으로 무리하게 뭉개지지 않는지 먼저 점검한다.

## 표제어 분리 원칙

- 새 항목을 만들거나 기존 항목을 합칠 때는 먼저 `한국어 표면형이 같은가`보다 `영어 기준 개념이 같은가`를 확인한다.
- 같은 한국어 단어 아래에 서로 다른 영어 개념과 설명 층위가 함께 들어가면 표제어를 분리하는 쪽을 우선 검토한다.
- 하나의 표제어 안에 서로 다른 영어 개념을 억지로 병렬 배치해 두지 않는다.
- 영어 병기는 장식이 아니라, 독자가 원문 자료와 공식 문서에서 같은 개념을 다시 찾고 한국어 동음이의어 오류를 피하게 하는 기준이어야 한다.

## 항목 구조

각 항목은 가능한 한 다음 정보를 포함한다.

- 표제어
- 뜻
- 왜 중요한가
- 함께 볼 개념
- 중심 Section
- 등장 Section 목록

권장 예시는 다음과 같다.

```md
### 모델(model, 모형)

- 뜻: 현실 전체를 그대로 복사한 것이 아니라, 목적에 맞게 줄여 만든 계산용 모형입니다.
- 왜 중요한가: ...
- 함께 볼 개념: `입력(input)`, `출력(output)`
- 중심 Section: `P1-4.1`
- 등장 Section: `P1-14.1`, `P1-14.3`
```

## 후속 Section 작성 원칙

- 같은 Part 안에서 이미 대표 설명 위치가 있는 개념을 다시 다루는 Section는 현재 질문에 필요한 최소 설명만 두고, 기본적으로 개념사전 링크로 연결한다.
- 후속 Section의 상세 반복을 얼마나 줄일지, 사례·예시·연습을 현재 절에 얼마나 남길지는 `manuscript-writing-workflow.md`의 본문 작성·Section 경계 규칙을 따른다.
- 이 문서에서는 개념사전이 어떤 개념을 대표 연결점으로 삼는지와, 본문이 어디로 되돌아가야 하는지만 정한다.
- 같은 용어를 개념사전으로 직접 링크하는 위치는 기본적으로 한 Section 안에서 1회만 둔다.
- 직접 링크는 가능하면 `개념사전 페이지 전체`가 아니라 `해당 표제어 앵커`로 연결한다.

## 본문 연결 규칙

- 같은 Part에서 새로운 핵심 개념이 처음 많이 등장하는 Section 초반에는, 주요 신규 개념을 짧게 묶어 설명하고 개념사전으로 연결하는 입구 블록을 우선 검토한다.
- 이 입구 블록은 이후 본문에서 반복될 핵심 용어를 먼저 한자리에 모아 보여 주는 역할을 한다.
- 초반 입구 블록에서 한 번 직접 링크한 용어는, 같은 Section 뒤쪽에서는 반복 링크보다 일반 텍스트 연결을 우선한다.
- 개념사전 링크는 가능하면 표제어별 세부 앵커를 사용한다. 다만 앵커 규칙이 불명확한 표제어는 빌드 산출물에서 실제 id를 확인한 뒤 연결한다.

## Section 표기 규칙

- 각 항목에는 그 개념을 중심적으로 설명하는 Section을 반드시 적는다.
- Section은 파일 경로가 아니라 `P1-4.1` 같은 `Section ID`로 적는다.
- `중심 Section`은 곧 대표 Section를 적는 칸이다.
- 하나의 개념에는 `중심 Section`을 하나만 적는다.
- `중심 Section`에는 쉼표로 여러 Section를 나열하지 않는다.
- 다른 Section가 같은 개념을 다시 충분히 다루더라도 `등장 Section`으로만 적는다.
- 만약 한 표제어 안에 서로 다른 설명 층위가 섞여 대표 Section를 하나로 잡기 어렵다면, 먼저 뜻을 더 좁히거나 표제어를 분리할지 검토한다.
- 동일한 개념을 여러 항목으로 나눌지 고민될 때는 먼저 기존 항목의 `중심 Section`을 확인한다.
- 같은 Part 안에서 상세 설명이 반복되지 않도록, `중심 Section`은 가능한 한 그 Part의 대표 상세 설명 위치를 먼저 가리키게 한다.
- `등장 Section`은 그 개념이 본문에서 다시 쓰이는 위치를 추적하기 위한 보조 필드이자, 위치 표기 오류와 누락을 관측하기 위한 목록이다.
- `등장 Section`에는 대표 설명 위치를 다시 적기보다, 현재 개념이 설명·사례·비교·체크리스트 안에서 실제로 다시 중요한 역할을 하는 Section를 목록으로 적는다.
- 같은 Part 안에서 `중심 Section`과 `등장 Section`을 함께 두면, 독자는 `어디서 처음 충분히 배워야 하는가`와 `어디서 다시 쓰이는가`를 구분해 따라갈 수 있다.
- `등장 Section`은 이미 순차 보강이 끝난 항목부터 차례대로 채운다. 아직 비어 있는 항목이 있더라도 새로 수정하거나 검토하는 항목에서는 가능하면 함께 보강한다.
- `등장 Section` 목록이 실제 본문 재등장 위치와 맞지 않거나 빠져 있음을 발견하면, 개념사전 항목과 관련 본문, 릴리즈노트를 함께 바로잡는다.

## 중복 방지 규칙

- 하나의 개념에는 가능한 한 하나의 대표 표제어만 둔다.
- 표현이 비슷해도 정의 층위가 다르면 항목을 분리할 수 있다.
  - 예: `특징(feature)`과 `표현(representation)`은 함께 언급되지만 같은 항목으로 합치지 않는다.
- 표현만 다른 동의어는 별도 항목으로 중복 생성하지 말고 기존 대표 항목 안에서 함께 설명한다.
- 새 항목을 추가하기 전에는 반드시 기존 개념사전 파일에서 같은 뜻의 표제어가 이미 있는지 확인한다.

## 본문과의 관계

- 개념사전은 본문 설명을 짧게 다시 읽는 통로다. 따라서 본문과 충돌하는 정의를 만들지 않는다.
- 본문에서 아직 충분히 정의되지 않은 개념을 개념사전에서 먼저 단정하지 않는다.
- 개념사전에 새 항목을 만들 때 본문에 아직 설명이 부족하면, 가능하면 해당 Section 보강을 먼저 검토한다.
- 개념사전은 본문 Section를 대체하지 않는다. 사례, 예시, 연습, 맥락 설명은 본문에 두고, 개념사전은 핵심 뜻과 연결 위치를 정리한다.
- 같은 Part 안에서 동일한 주요 개념을 여러 Section가 길게 다시 설명하고 있다면, 먼저 어느 Section가 대표 설명 위치가 되어야 하는지 결정하고 나머지 Section는 현재 질문에 필요한 만큼만 축약한다.
- 개념사전 항목을 늘리는 것만으로 본문 중복 문제를 해결했다고 보지 않는다. 대표 설명 위치 정리와 후속 Section 축약이 함께 이루어져야 한다.

## 업데이트 원칙

- 본문에 새로운 핵심 개념이 반복 등장하기 시작하면 개념사전 후보로 검토한다.
- 같은 Part 안에서 한 번만 길게 설명하고 이후 여러 Section에서 비교 기준, 평가 기록, 운영 기록으로 다시 쓰이는 개념도 개념사전 후보로 본다.
- 같은 Part 안에서 `학습 모드`, `평가 모드`, `temperature`, `top-k`처럼 계산 상태나 출력 선택 기준을 설명하는 모드·설정값도 여러 Section에서 반복되면 개념사전 후보로 본다.
  - 예: `기준선(baseline)`, `회고(retrospective)`, `권한(permission)`, `어휘 밖(out-of-vocabulary, OOV)`, `토큰 커버리지(token coverage)`
- 기존 항목의 정의나 표제어를 바꾸면 관련 Section와 충돌하지 않는지 다시 본다.
- 개념사전 작성 규칙을 바꾸면, 관련 인덱스 문서와 작업 문서가 이 규칙을 어떻게 참조하는지 함께 점검한다.
- 같은 Part 안에서 대표 설명 위치와 후속 Section 작성 방식이 바뀌면, 관련 Section 릴리즈노트와 개념사전 릴리즈노트도 함께 갱신한다.
