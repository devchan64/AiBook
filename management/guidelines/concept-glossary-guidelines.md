# 개념사전 작성 규칙

최초 작성일: 2026-07-24

## 목적과 범위

- 개념사전은 책 본문에서 반복 등장하는 핵심 개념과 표현 기준을 관리하는 독자용 참조 원고다.
- 본문을 대체하는 요약집이 아니라, 대표 표제어, 일반화 표현, 중의적 표현, 동음이의어·동형이의어, 대표 설명 위치, 재등장 위치를 압축해 연결하는 기준 원고다.
- 이 문서는 개념사전의 표현 관리, 표제 판단, 단어별 원고 구조, 언어별 색인 조립, 본문 링크 정리 기준만 다룬다.
- 영어·중국어 문장 표현, 병기 방식, 번역 품질 판단은 각 번역 가이드를 따른다.
- 원칙 문서인 이 파일은 별도 리비전노트를 두지 않고 문서 자체를 직접 갱신한다.

## 파일 위치

- 공개 진입 원고: `docs/reference/concept-glossary.md`
- 단어별 원고: `docs/reference/concept-glossary-terms/<english-slug>.<lang>.md`
- 한국어 자음별 색인: `docs/reference/concept-glossary-parts/*.md`
- 영어 알파벳별 색인: `docs/reference/concept-glossary.en.md`, `docs/reference/concept-glossary-alpha/*.en.md`
- 중국어 병음별 색인: `docs/reference/concept-glossary.zh.md`, `docs/reference/concept-glossary-pinyin/*.zh.md`
- 이전 단어별 항목 디렉터리: `docs/reference/concept-glossary-entries/`
  - 현재 활성 구조는 `concept-glossary-terms/`이며, `concept-glossary-entries/`는 이전 구조 확인용으로만 본다.

## 기본 구조

- 개념사전 항목 본문은 단어별 원고 파일 하나에 둔다.
- 자음별, 알파벳별, 병음별 색인 파일은 정렬, include 순서, 짧은 안내 문구만 맡는다.
- 단어별 파일명은 언어별 표제어가 아니라 영어 기준 용어의 kebab-case slug로 만든다.
  - 예: `model.ko.md`, `model.en.md`, `model.zh.md`
  - 예: `gradient-descent.ko.md`, `gradient-descent.en.md`, `gradient-descent.zh.md`
- 단어별 파일 안의 앵커는 영어 slug를 기준으로 둔다.
- 항목 본문은 단어별 원고를 `pymdownx.snippets`로 include해 조립하는 것을 목표 구조로 삼는다.
- MkDocs snippets 기준 경로는 `docs`이므로 include 경로는 다음 형식을 쓴다.

```md
--8<-- "reference/concept-glossary-terms/model.ko.md"
```

- 임시 전환 기간에 남아 있는 직접 작성 항목이나 표형 탐색 색인은 이동 대상으로 본다.

## 항목 구조

단어별 원고는 다음 정보를 기본으로 포함한다.

```md
<a id="model"></a>

### 모델(model, 모형)

- 뜻: ...
- 왜 중요한가: ...
- 함께 볼 개념: ...
- 중심 Section: `P1-4.1`
- 등장 Section: `P1-14.1`, `P1-14.3`
```

- 한 파일에는 원칙적으로 하나의 대표 표제어만 둔다.
- 항목 제목 수준은 색인 파일에 include될 때의 문서 구조를 고려한다.
  - 현재 한국어 항목은 `###`, 영어·중국어 항목은 `##`를 기본으로 한다.
  - 같은 언어 안에서는 기존 구조와 맞춘다.
- `중심 Section`은 대표 설명 위치 하나만 적는다.
- `등장 Section`에는 대표 설명 위치를 반복하지 않고 실제 재등장 위치만 적는다.
- Section은 파일 경로가 아니라 `P1-4.1` 같은 `Section ID`로 적는다.
- 단어별 파일은 항목 하나의 `Core/중심 Section`, `Appears/등장 Section` 대응을 파일 단위로 확인할 수 있어야 한다.

## 표제 판단

개념사전 항목은 문서 전체의 용어 기준점이 되는 표현만 등재한다. 반복 등장, 오해 가능성, 후속 Part 연결 가능성은 검토 사유이고, 실제 등재에는 표준성, 독립성, 지속성, 파일 안정성이 함께 필요하다.

개념사전은 다음 표현 기준을 명시한다.

- 대표 표제어: 문서 전체에서 같은 개념을 가리킬 때 기준으로 삼을 이름이다.
- 일반화 표현: 개인적 표현, 국소 사례 표현, 즉흥 번역어를 독자가 다른 문맥에서도 재사용할 수 있게 정리한 표현이다.
- 중의적 표현: 한 표현이 여러 의미로 열릴 때 문맥, 분야, 사용 층위를 좁혀 쓰는 기준이다.
- 동음이의어·동형이의어: 같은 표면형이 다른 영어 기준 개념을 가리킬 때 표제어, slug, 설명 범위를 분리하는 기준이다.

표제어는 다음 조건을 모두 만족할 때만 만든다.

- 표준성: 교과서, 논문, 공식 문서, 널리 쓰이는 교육 자료에서 안정적으로 확인되는 학술·기술 용어다.
- 독립성: 상위 표제나 본문 문맥에 흡수하면 정의 반복이나 개념 연결 혼선이 생긴다.
- 지속성: 특정 예제, 도구, 원고 상태, 작업 절차가 아니라 후속 Part에서도 재사용할 개념 기준점이다.
- 파일 안정성: 한국어 표제어, 영어 기준 용어, slug가 같은 범위를 가리키며 단독 일반어로 과도하게 열리지 않는다.

다음 표현은 새 표제로 만들지 않는다.

- 일반 사전적 의미가 더 강한 단어
- 상위 표제의 하위 설명으로 충분한 표현
- 원고 작업, 검토, 표, 로그, 필드 같은 운영·문서 형식 이름
- 특정 도구, 제품, 라이브러리, 명령, 함수, 파일, 모델 사례에 의미가 묶인 표현
- 개인적 비유, 작업 가설, 임시 번역어, 국소 예제 표현

판단이 분명하지 않으면 새 표제를 만들지 않고 `보류`로 둔다. 표제어 추가의 기본값은 `보류`다.

## 층위 점검

새 표제를 만들거나 기존 표제를 바꾸기 전에는 다음을 확인한다.

- 같은 한국어 표면형이 서로 다른 영어 기준 개념을 덮고 있지 않은가?
- 여러 한국어 표현이 같은 영어 기준 개념을 가리키는데 대표 표제어 없이 흩어져 있지 않은가?
- 같은 영어 일반어가 일반 의미, 기술 일반 의미, AI 문맥 의미를 섞어 쓰고 있지 않은가?
- 중의적 표현을 문맥 한정 없이 단독 표제로 세우고 있지 않은가?
- 동음이의어·동형이의어를 같은 항목 안에 억지로 병렬 배치하고 있지 않은가?
- 작업·형식 이름, 로그 필드, 예제 산출물 이름을 독립 개념처럼 세우고 있지 않은가?
- 상위 표제로 흡수할 수 있는 하위 설명을 새 표제어로 늘리고 있지 않은가?
- 이미 대표 표제어가 있는 개념을 본문에서 즉흥 표현으로 다시 고정하고 있지 않은가?
- 뒤 Part에서 같은 개념이 다시 중요해졌다는 이유로 `중심 Section`을 여러 개로 늘리고 있지 않은가?

표준 수학·기술 용어가 일반어처럼 보이는 경우에도 즉시 삭제하지 않는다. 예를 들어 `topology`는 위치나 거리의 동의어가 아니라 연결성·연속성 같은 공간 구조를 가리키는 표준 수학 용어이므로, 표현 공간이나 데이터 매니폴드 문맥으로 범위를 좁혀 유지할 수 있다.

## 작업 순서

### 새 항목

1. 본문에서 반복되는 표현을 모으고 같은 개념을 가리키는 표현끼리 묶는다.
2. 표준성, 독립성, 지속성, 파일 안정성을 확인한다.
3. 상위 표제, 관련 개념 연결, 본문 안 설명으로 충분하면 새 표제를 만들지 않는다.
4. 영어 기준 용어로 slug를 정하고, 필요한 언어별 단어 원고를 만든다.
5. 대표 설명 위치를 정하고 `중심 Section`을 하나만 적는다.
6. 언어별 공개 색인 include를 갱신한다.
7. 본문 설명이 부족하면 개념사전만 늘리지 말고 해당 Section 보강을 먼저 검토한다.

### 기존 항목

1. 기존 대표 표제어, 영어 병기, `중심 Section`, `등장 Section`을 확인한다.
2. `삭제`, `상위 표제 흡수`, `대표 표제 통일`, `보류` 중 하나를 먼저 정한다.
3. 표제어를 합치거나 나눌 때는 한국어 표면형보다 영어 기준 개념과 사용 층위를 먼저 본다.
4. slug가 바뀌면 단어별 파일명, 언어별 색인 include, 본문 링크를 함께 갱신한다.
5. 대표 설명 위치를 옮겼다면 관련 본문과 관련 Section 릴리즈노트를 함께 확인한다.
6. 개념사전 자체의 전용 릴리즈노트 파일은 만들지 않는다.

### 본문 링크

1. 같은 Section 안에서 같은 개념사전 직접 링크는 기본적으로 첫 등장 1회만 둔다.
2. 개념사전 링크는 가능하면 페이지 전체가 아니라 표제어별 세부 앵커를 사용한다.
3. 언어별 본문에서는 같은 언어의 공개 개념사전 색인과 실제 표제 앵커를 우선 가리킨다.
4. 표제어를 삭제하거나 상위 표제로 흡수했다면 `docs/parts/` 본문 링크도 같은 판단에 맞춰 정리한다.
5. 본문 Section의 개념 설명 자체가 바뀌지 않고 링크 대상만 정리한 경우에는 Section 릴리즈노트를 만들지 않는다.

## 다국어 원칙

- 한국어 표제가 개념사전 등재 기준이다.
- 같은 slug의 한국어 단어 파일이 없는 영어·중국어 단어 파일은 독립 표제로 유지하지 않고, 해당 언어 공개 색인 include에서도 제거한다.
- 영어판은 알파벳별 영문 전용 페이지에서 단어별 영문 원고를 include하고, 각 영어 표제어 링크는 `docs/reference/concept-glossary-alpha/*.en.md`의 대응 앵커로 연결한다.
- 중국어판은 병음별 중국어 전용 페이지에서 단어별 중국어 원고를 include하고, 각 중국어 표제어 링크는 `docs/reference/concept-glossary-pinyin/*.zh.md`의 대응 앵커로 연결한다.
- 영어·중국어 항목은 한국어 개념사전으로 되돌아가는 중간 페이지가 아니라 각 언어 독자가 직접 읽는 전용 본문이어야 한다.
- 관련 개념은 해당 언어의 표제어를 우선 쓰며, 언어별 문장 표현과 병기 판단은 각 번역 가이드를 따른다.

## 정렬 원칙

- 한국어 자음별 파일 안에서는 한국어 표제어 기준 가나다순 include 순서를 유지한다.
- 영어 알파벳별 파일 안에서는 영어 표제어 기준 알파벳순 include 순서를 유지한다.
- 중국어 병음별 파일 안에서는 중국어 표제어의 병음 기준 include 순서를 유지한다.
- 새 항목을 추가하기 전에는 기존 단어별 원고와 언어별 공개 색인에서 같은 뜻의 표제어가 이미 있는지 확인한다.

## 근거 기록

- 대표 표제어, 영어 병기, 핵심 정의를 바꿀 때는 표준화된 외부 레퍼런스를 확인한다.
- 서로 다른 레퍼런스가 다른 용어를 쓰면 한쪽을 바로 표준으로 단정하지 않고, 어느 맥락에서 어떤 표현이 쓰이는지 비교한다.
- 개념사전 항목 본문에는 레퍼런스 목록을 반복해서 붙이지 않는다.
- 검증 근거는 관련 Section의 `출처와 참고 자료` 또는 단어별 원고의 짧은 출처 표기로 추적한다.
- 외부 레퍼런스가 없는 임시 표현은 `검증 필요`로 두고, 대표 표제어가 아니라 본문 안의 작업 가설이나 보조 설명으로 제한한다.

## 점검

작업 후에는 다음을 확인한다.

- 단어별 원고, 언어별 공개 색인 include, 본문 링크가 같은 slug와 앵커를 가리키는가?
- `중심 Section`은 하나만 유지되는가?
- `등장 Section`에 대표 설명 위치를 반복하지 않았는가?
- 같은 Section 안에서 같은 개념사전 링크가 불필요하게 반복되지 않았는가?
- 새 표제를 만든 경우 `management/authoring/concept-glossary-integrated-index.md`도 함께 맞췄는가?
- 배포 준비 또는 배포 지시가 있을 때만 `.venv/bin/python -m mkdocs build`로 최종 빌드를 확인한다.
