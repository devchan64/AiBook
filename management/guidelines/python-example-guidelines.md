# Python 예제 작성 가이드

작성일: 2026-07-12

## 목적

- 이 문서는 책 본문에 Python 예제를 넣거나 수정할 때 반복해서 확인할 기준을 정리한다.
- 목적은 `현재 Section의 중심 질문과 직접 연결되는 예제`, `실행과 출력이 분명한 예제`, `표·사례·체크리스트와 역할이 겹치지 않는 예제`를 유지하는 것이다.

## 언제 이 문서를 보는가

- 새 Python 예제를 처음 넣을 때
- 기존 Python 예제를 다른 예제로 교체할 때
- 코드 블록을 `연습 및 예제`로 유지할지, 표나 사례로 바꿀지 판단할 때
- 초심자에게 필요한 예제 해설 수준을 점검할 때

## 작업 전 확인

- 현재 Section의 중심 질문이 무엇인가
- 예제가 현재 절에서 확인할 개념이 무엇인가
- 출력값이 독자가 바로 읽을 수 있는가

## 작성 규칙

- 코드 앞에 문제 상황, 입력(input), 정답(label) 또는 기대 출력(output), 확인할 개념을 짧게 둔다.
- 가능하면 `print` 또는 이에 준하는 출력 코드를 함께 둔다.
- 코드 블록 아래에는 가능하면 실행 결과 예시도 함께 둔다.
- 우선적으로 보여 줄 값은 샘플 수, `shape`, 분포, 분리 결과, 예측과 실제값 비교처럼 현재 절의 중심 질문과 직접 연결된 값이다.
- 아직 설명하지 않은 고급 지표, 튜닝 로그, 성능 비교는 범위 안에 있을 때만 넣는다.
- 의사 코드보다 실제 실행 가능한 예제를 우선한다.
- 가능하면 실제 라이브러리, 실제 데이터 형식, 실제 전처리 흐름, 실제 모델 입출력 중 적어도 하나와 연결한다.
- 단순화가 필요하면 축약한 부분과 실제 관찰 포인트를 함께 밝힌다.
- 독자가 수치를 바꿔 보며 결과 차이를 다시 확인할 수 있어야 한다.

## 금지 패턴

- 앞 절이나 바로 위 표에서 이미 정리한 대응 관계를 코드가 그대로 다시 `print`만 하는 예제는 두지 않는다.
- 코드가 새 판단을 요구하지 않고, 고정된 정답표를 재출력하는 수준이면 `연습 및 예제`로 보지 않는다.
- 실행 결과가 `무엇이 달라졌는가`, `왜 이 결과가 현재 절의 핵심 질문과 연결되는가`를 보여 주지 못하면 예제를 다시 설계한다.
- 입력 변화, 오답 가능성, 비교 기준이 전혀 없으면 학습 검증용 예제로 보지 않는다.
- `scene -> answer`, `name -> label`처럼 선언적 매핑만 출력하는 블록은 가능한 한 표나 체크리스트로 대체하고, 코드 블록으로 유지하지 않는다.
- 같은 절의 표, 사례, 체크리스트가 이미 더 잘 설명하는 내용을 코드가 반복하면 삭제하거나 검증형 실습으로 바꾼다.

## 초심자 점검

- 코드만 읽어도 예제가 왜 필요한지 드러나는가
- 출력값을 보고 독자가 현재 절의 개념을 다시 확인할 수 있는가
- 코드 블록 아래 설명이 `무엇을 봐야 하는가`를 닫아 주는가
- 표나 사례가 더 적합한데 관성적으로 코드 블록을 쓰고 있지는 않은가
