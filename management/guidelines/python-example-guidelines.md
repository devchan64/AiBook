# Python 예제 작성 가이드

작성일: 2026-07-12

## 목적

- 이 문서는 책 본문에 Python 예제를 넣거나 수정할 때 반복해서 확인할 기준을 정리한다.
- 목적은 `현재 Section의 중심 질문과 직접 연결되는 예제`, `실행과 출력이 분명한 예제`, `표·사례·체크리스트와 역할이 겹치지 않는 예제`를 유지하는 것이다.
- 이 가이드는 `Python 코드가 꼭 필요한가`, `코드가 필요 없다면 어떤 연습으로 개념 적용을 닫을 것인가`도 함께 판단한다.

## 언제 이 문서를 보는가

- 새 Python 예제를 처음 넣을 때
- 기존 Python 예제를 다른 예제로 교체할 때
- 코드 블록을 `연습 및 예제`로 유지할지, 표나 사례로 바꿀지 판단할 때
- 초심자에게 필요한 예제 해설 수준을 점검할 때

## 작업 전 확인

- 현재 Section의 중심 질문이 무엇인가
- 현재 Section이 새로 설명한 핵심 개념이나 핵심 판단 기준이 무엇인가
- 예제가 현재 절에서 확인할 개념이 무엇인가
- 출력값이 독자가 바로 읽을 수 있는가
- 이 절에 이미 비코드 연습이 있다면 Python 예제가 그 연습을 확장하는지, 아니면 같은 말을 반복하는지
- 이 예제가 `설명형`, `검증형`, `실험형` 중 무엇으로 설계되는가

## 예제 유형 구분

- `설명형`: 코드 사용법, 라이브러리 문법, 실행 순서, 입력 형식처럼 `코드 자체를 어떻게 읽고 쓰는가`를 소개하는 예제입니다.
- `검증형`: 입력 변화, 비교 기준, 출력 차이를 통해 현재 절의 핵심 개념이 실제로 어떻게 드러나는지 확인하게 하는 예제입니다. 다만 초심자 중심 원고에서는 표와 사례가 이미 충분할 때 같은 내용을 한 번 더 확인하는 반복으로 흐르기 쉽습니다.
- `실험형`: 독자가 값, 임계값, 편향, 입력 조합, 하이퍼파라미터 같은 요소를 직접 바꿔 보며 경계 이동, 출력 반전, 민감도 차이, 실패 조건을 탐색하게 하는 예제입니다.

판단 원칙:

- `설명형`은 코드 사용법 자체가 현재 절의 중심 질문일 때만 검토합니다. 같은 역할을 표, 사례, 비코드 연습이 더 잘 수행하면 Python 코드를 넣지 않습니다.
- Python 코드를 유지한다면 우선 `실험형` 가능성을 먼저 검토하고, `검증형`은 예외적으로만 유지합니다.
- `설명형` 예제를 유지하려면, 독자가 지금 배워야 하는 것이 개념 자체가 아니라 코드 사용 절차나 문법이라는 근거가 있어야 합니다.
- `검증형` 예제를 유지하려면, 코드가 아니면 확인하기 어려운 출력 구조나 계산 순서를 짧게 확인하는 분명한 이유가 있어야 하며, 같은 내용을 표나 사례로 이미 닫았다면 유지하지 않습니다.
- `실험형` 예제를 유지하려면, 독자가 무엇을 바꿔 볼지와 그때 무엇을 관찰해야 하는지가 코드 앞뒤 설명에 분명해야 합니다.

## 작성 규칙

- 새로운 핵심 개념이나 핵심 판단 기준을 설명한 Section에서는 `예시`와 `연습 또는 예제`가 함께 있어야 한다. Python 코드는 그중 `예제`를 담당할 때만 넣는다.
- 코드가 현재 절의 핵심 개념을 실제 입력 변화, 비교 기준, 출력 차이로 검증해 주지 못하면 Python 예제를 억지로 넣지 말고 비코드 연습으로 닫는다.
- 코드 앞에 문제 상황, 입력(input), 정답(label) 또는 기대 출력(output), 확인할 개념을 짧게 둔다.
- 원시 입력 데이터가 CSV, JSON, 로그 파일처럼 파일 형태를 가질 수 있다면, 가능하면 그 파일을 코드 밖 자산으로 분리하고 본문에서는 `입력 파일 설명`과 `실행 코드`를 구분해 제시한다.
- 입력 파일을 따로 두었다면, Python 코드는 인라인 문자열이나 하드코딩된 배열을 다시 복제하지 말고 실제 파일을 읽는 단계부터 시작한다.
- 가능하면 `print` 또는 이에 준하는 출력 코드를 함께 둔다.
- 코드 블록 아래에는 가능하면 실행 결과 예시도 함께 둔다.
- 우선적으로 보여 줄 값은 샘플 수, `shape`, 분포, 분리 결과, 예측과 실제값 비교처럼 현재 절의 중심 질문과 직접 연결된 값이다.
- 아직 설명하지 않은 고급 지표, 튜닝 로그, 성능 비교는 범위 안에 있을 때만 넣는다.
- 의사 코드보다 실제 실행 가능한 예제를 우선한다.
- 가능하면 실제 라이브러리, 실제 데이터 형식, 실제 전처리 흐름, 실제 모델 입출력 중 적어도 하나와 연결한다.
- 단순화가 필요하면 축약한 부분과 실제 관찰 포인트를 함께 밝힌다.
- 독자가 수치를 바꿔 보며 결과 차이를 다시 확인할 수 있어야 한다.
- 실험형 예제라면 적어도 하나 이상의 `조작할 값`, `관찰할 출력`, `해석할 질문`을 코드 앞뒤에 명시한다.
- 실험형 예제의 출력은 단순 정답 나열보다 `경계 위/아래`, `가장 민감한 입력`, `출력이 뒤집히는 조건`, `실패하는 경우`처럼 탐색 결과를 읽게 하는 쪽을 우선한다.
- 실제 맥락을 단순화하더라도, 가능하면 실제 신호, 실제 컬럼, 실제 모델 입출력, 실제 전처리 형태 중 적어도 하나는 남겨 장난감 계산으로만 보이지 않게 한다.

## 금지 패턴

- 핵심 개념 설명만 있고 독자가 직접 적용해 볼 연습이 없는 Section을 Python 예제 하나로 형식적으로만 메우지 않는다.
- 앞 절이나 바로 위 표에서 이미 정리한 대응 관계를 코드가 그대로 다시 `print`만 하는 예제는 두지 않는다.
- 코드가 새 판단을 요구하지 않고, 고정된 정답표를 재출력하는 수준이면 `연습 및 예제`로 보지 않는다.
- 실행 결과가 `무엇이 달라졌는가`, `왜 이 결과가 현재 절의 핵심 질문과 연결되는가`를 보여 주지 못하면 예제를 다시 설계한다.
- 입력 변화, 오답 가능성, 비교 기준이 전혀 없으면 학습 검증용 예제로 보지 않는다.
- `scene -> answer`, `name -> label`처럼 선언적 매핑만 출력하는 블록은 가능한 한 표나 체크리스트로 대체하고, 코드 블록으로 유지하지 않는다.
- 같은 절의 표, 사례, 체크리스트가 이미 더 잘 설명하는 내용을 코드가 반복하면 삭제하거나 검증형 실습으로 바꾼다.
- 같은 절의 표, 사례, 체크리스트가 이미 더 잘 설명하는 내용을 코드가 반복하면 삭제하거나, 정말 필요할 때만 아주 짧은 예외적 검증형으로 축소한다.
- 코드 사용법을 가르치는 절이 아닌데도, 계산 설명을 다시 보여 주기 위해 설명형 코드를 넣지 않는다.
- 입력 이름만 그럴듯하게 바꾸고 실제로는 추상 수식 값을 재출력하는 예제를 `실험형`으로 포장하지 않는다.
- 독자가 조작할 수 있는 값이 없거나, 값을 바꿔도 관찰 포인트가 달라지지 않으면 `실험형` 예제로 보지 않는다.
- 실제 데이터나 모델과의 연결 없이 고정된 세네 개 숫자만 대입해 결과를 다시 출력하는 블록은 기본적으로 장난감 예제 후보로 보고 재검토한다.
- 표나 사례가 이미 같은 확인을 충분히 수행하는데 코드가 `맞는지 다시 본다` 수준으로만 남아 있으면, 그 검증형 예제는 원고 이해에 기여하지 않는 것으로 보고 제거 후보로 검토한다.
- 코드 블록 바로 위에 CSV 본문을 길게 인라인으로 복제해 두어, `입력 파일 설명`과 `실행 코드`의 경계가 흐려지는 구성은 피한다.

## 초심자 점검

- 예제가 없다면, 그 자리를 대신하는 비코드 연습이 현재 절의 핵심 개념을 충분히 붙잡아 주는가
- 코드만 읽어도 예제가 왜 필요한지 드러나는가
- 출력값을 보고 독자가 현재 절의 개념을 다시 확인할 수 있는가
- 코드 블록 아래 설명이 `무엇을 봐야 하는가`를 닫아 주는가
- 표나 사례가 더 적합한데 관성적으로 코드 블록을 쓰고 있지는 않은가
- 실험형이라면 독자가 `무엇을 바꾸고`, `무엇이 바뀌며`, `왜 그렇게 바뀌는가`를 한 문장으로 말할 수 있는가
