# 생성 산출물 관리 기준

이미지 생성·목표 보충·데이터셋 구성에서 이미 있는 산출물을 다시 만들지 않기 위한 운영 기준이다. 생성 요청은 우선 기존 자산과 연결해 해석하며, 입력 하나가 추가되었다는 이유만으로 목표도 새로 생성하지 않는다.

## 기준 기록과 파일 위치

| 기록 | 맡는 역할 | 변경 원칙 |
| --- | --- | --- |
| 통합 데이터셋 JSON | 현재 사용할 입력·목표 대응, 분할, 준비 상태, 재사용 경로 | 현재 채택 결정을 반영하는 기준 목록 |
| 생성 조건 JSON | 참조 순서, 프롬프트 조합, 시드·설정, 저장 위치, `excluded_items` | 필요한 생성 조건과 지속적인 제외 결정을 함께 관리 |
| 실행 선택 JSON | 이번 실행의 `include_ids`·`exclude_ids` | 실행 범위만 조정하며 새 산출물의 필요성을 결정하지 않음 |
| 후보 카탈로그 | 생성된 파일·결과 기록의 경로와 해시 | 파일 존재·무결성 확인용이며 자동 채택 목록이 아님 |
| 결과 JSON | 당시 참조·프롬프트·설정·출력 해시 | 과거 실행 기록을 현재 조건으로 덮어쓰지 않음 |
| 검수표·검수 기록 | 관찰 내용, 사용자 판단, 채택·보완 사유 | 현재 결정과 과거 관찰을 구분 |
| 실행 상태·PID·로그 | 작업 진행과 복구 정보 | 산출물의 채택·폐기 결정을 대신하지 않음 |

- 입력은 `input-images/`, 목표는 `target-images/`에서 관리한다. 공용 원본이 다른 절에 있으면 경로 또는 상대 심볼릭 링크로 재사용한다.
- 같은 이미지를 데이터셋별로 복사하지 않는다. 같은 목표에 여러 입력이 연결될 수 있으며 이미지 수와 학습 쌍 수를 구분한다.
- 이미지 파일의 SHA-256으로 바이트 중복을 확인한다. 서로 다른 파일 해시는 시각적으로 서로 다른 이미지임을 보장하지 않으므로 유사 후보는 검수에서 별도로 판단한다.
- 과거 학습 목록은 재현에 필요할 때만 고정 기록으로 보존한다. 현재 관리 목록과 과거 실행 목록을 동시에 최신화하지 않는다.

## 생성 전 결정 순서

### 규칙·조건·결과 식별자

| 구분 | 예 | 의미 |
| --- | --- | --- |
| 생성 규칙 ID | `P710-RULE-INPUT-002` | 얼굴 비율 보강 입력 같은 생성 규칙 묶음 |
| 규칙 리비전 | `1` | 등록된 규칙 버전. 등록 파일의 SHA-256과 함께 추적 |
| 조건 ID | `bfs-proportion-torso-level-minus-90-woman-long-photo` | 규칙 안에서 실행할 조합 하나. 기존 항목 `id`를 유지 |
| 조건 요소 ID | `P710-RULE-INPUT-002/1/face/face-01` | 규칙·리비전·축·키를 묶은 방향·얼굴·화풍 등의 식별자 |
| 후보 관리번호 | `P710-PROP-001` | 검수표에서 사용하는 사람용 번호. 폐기해도 재번호를 부여하지 않음 |
| 결과 ID | `sha256:<이미지 파일의 전체 SHA-256>` | 실제로 존재하는 이미지. 경로나 데이터셋이 달라도 같은 바이트면 같은 ID |

규칙 ID와 결과 ID를 같은 것으로 취급하지 않는다. 같은 규칙에서 여러 결과가 나오며, 하나의 결과를 여러 입력·목표 쌍에서 재사용할 수 있다. 생성 전 목표는 조건 ID만 있고 결과 ID는 `null`이다. 서로 다른 인코딩의 파일은 같은 모습이어도 결과 ID가 다를 수 있으므로 시각적 중복은 별도로 확인한다.

규칙 정의는 통합 데이터셋의 `generation_rules`에 등록하고 각 행의 `input_rule_id`·`input_rule_revision`·`input_condition_id`로 연결한다. `input_result_id`·`target_result_id`는 해당 이미지 해시와 일치해야 한다. 아직 규칙을 등록하지 않은 과거 참조 이미지는 결과 ID와 원래 경로·기록만 연결하며, 추측한 규칙 ID를 부여하지 않는다.

실행 중인 생성 목록이나 과거 결과 JSON을 ID 추가만을 위해 수정하지 않는다. 별도 규칙 파일을 늘리지 않고 통합 목록에서 연결한다. 기존 결과 JSON은 조건 ID와 이미지 해시를 통해 규칙·결과 ID에 대응한다. 규칙 파일을 갱신할 때는 등록된 리비전·해시도 함께 관리하되, 메타데이터 변경을 재생성 근거로 삼지 않는다.

### 학습 입력·목표의 공통 ID 운영

학습 입력과 목표는 모두 같은 `sha256:<전체 이미지 해시>` 결과 ID 체계를 사용한다. 입력·목표는 학습 쌍 안의 역할이며 이미지 자체의 ID에 역할 접두사를 붙이지 않는다.

| 역할 | 경로 필드 | 해시 필드 | 결과 ID 필드 |
| --- | --- | --- | --- |
| 입력 | `control_image` | `control_sha256` | `input_result_id` |
| 목표 | `image` | `sha256` | `target_result_id` |

- `items[].id`는 학습 쌍을 식별한다. 입력과 목표에 같은 ID 값을 강제로 부여하지 않는다. 서로 다른 이미지라면 결과 ID도 다르다.
- 같은 목표를 여러 입력과 연결하면 각 행의 `target_result_id`는 동일하다. 같은 파일을 다른 역할로 재사용해도 결과 ID는 유지한다.
- 입력은 `input-images/`, 목표는 `target-images/`에서 관리하되 공용 원본은 기존 경로나 상대 심볼릭 링크로 연결한다. ID 통일을 위해 파일을 복사하거나 이름을 바꾸지 않는다.
- 생성 후 파일 해시를 확인하고 통합 목록에 결과 ID를 등록한다. 미생성 목표는 `null`로 유지하며 검수 전에는 준비 완료로 바꾸지 않는다.
- 이미지 내용이 교체되면 새 해시에 따른 결과 ID로 연결한다. 과거 생성 기록은 보존하며 경로만 바뀐 경우에는 ID를 유지한다.

공용 생성기는 통합 목록에 등록된 규칙 경로·해시를 확인하고 규칙·조건·조합 요소 ID를 새 결과 기록에 기록한다. 선택 JSON의 `rule_id`·`rule_revision`이 지정되면 실행 규칙과 일치해야 한다. 카탈로그와 후보 선택 출력도 같은 이미지 결과 ID를 사용한다. 이 기능은 수정된 코드로 새로 시작한 실행에 적용하며, 과거 결과나 실행 중인 작업의 기록을 자동으로 변경하지 않는다.

### 실행 대상 결정

1. 통합 목록에서 입력과 목표의 관리번호·경로·상태를 확인한다.
2. 현재 출력 폴더뿐 아니라 후보 카탈로그, 기존 방향별 참조, 다른 실험의 채택 산출물에서 재사용 가능한 파일을 확인한다.
3. 재사용 가능 여부는 목표 역할과 검수 기준으로 판단한다. 입력의 방향·포즈·표정·의상·배경에 기존 목표가 적합하면 그대로 연결한다.
4. 기존 목표와 대응하지 않는 항목만 생성 대상으로 지정한다. 검수 의견이 여러 항목에 걸쳐 있어도 개별 ID로 정리하고 전체 묶음 재생성으로 확대하지 않는다.
5. 생성 제외 항목은 생성 조건의 `excluded_items`에도 기록한다. 새 출력 폴더나 다른 선택 목록에서도 제외 결정을 잃지 않아야 한다.
6. `--dry-run`으로 전체 수·완료 수·제외 ID·실제 생성 ID를 확인한 후 실행한다. 남은 항목이 0개면 모델을 로드하지 않는다.

재사용에는 동일한 생성 프롬프트가 필수인 것이 아니다. 다른 조건에서 생성했더라도 역할과 검수 기준을 충족하는 기존 이미지는 재사용할 수 있다. 반면 같은 생성 조건의 완료 결과가 있으면 새로운 생성이 필요한 이유부터 확인한다.

## 항목별 결정과 상태

| 결정 또는 상태 | 기록 | 실행 시 처리 |
| --- | --- | --- |
| 기존 목표 재사용 | 통합 목록에 실제 경로·해시, `target_source: reused_direction_reference` | 해당 목표 생성 ID를 제외하고 복사 없이 연결 |
| 입력 채택, 새 목표 필요 | `pair_status: pending_target_generation_and_review`, 예정 경로 | 해당 ID만 생성; 해시는 생성 후 확인 |
| 생성 완료, 검수 전 | 결과·카탈로그의 출력 해시 | 자동 재생성·학습 편입 금지 |
| 입력·목표 준비 완료 | `pair_status: ready`, 양쪽 이미지와 기록의 해시 | 검증 후 학습 목록에 사용 |
| 폐기 확정 | 생성 조건에 ID·사유·`regenerate: false` | 파일 삭제 여부와 무관하게 제외 |
| 완료 기록은 있으나 파일 누락·손상 | 오류와 해당 ID | Git·원래 경로·이관 정보를 확인해 복구; 자동 재생성 금지 |

입력 채택은 현재 연결된 목표까지 승인했다는 뜻이 아니다. 보완 대상이 목표라면 입력을 유지하고 목표 연결만 바꾼다. 이미 적합한 목표까지 함께 교체하지 않는다. 추가 생성이 필요하다고 확정된 범위 안의 실행은 불필요하게 재확인하지 않는다.

## 조건 변경과 재실행

- 이미지 생성 조건은 기반 모델·리비전·어댑터, 순서가 있는 참조 이미지 해시, 최종 생성 프롬프트, 시드, 해상도·전처리, 스텝·CFG 등이다. 모델 정체성과 수치 설정을 결과 기록에 남긴다.
- `training_caption`, 검수 의견, 분할, 문서 라벨, 관리 경로의 변경만으로 이미지를 재생성하지 않는다. 특히 학습 캡션과 이미지 생성 프롬프트를 구분한다.
- 코드 해시가 달라 재개 검사가 실패해도 새 폴더에서 전체를 다시 만드는 것으로 해결하지 않는다. 실제 추론 조건이 바뀌었는지 먼저 확인한다. 검증 없이 과거 지문을 새 값으로 덮어쓰거나 안전 검사를 우회하지 않는다.
- 실제로 달라진 조건을 실험할 때는 새 조건·산출물 ID를 사용하고 변경 이유를 기록한다. 이것도 기존 산출물 재사용 검토 후 필요한 항목만 실행한다.
- 과거 결과 기록과 모델 가중치는 정리 과정에서 임의로 삭제하지 않는다. 생성 목록의 중복 설명은 기준 해시와 결과 기록으로 검증할 수 있으면 통합한다.

## 실행 중 변경

- 실행 중인 생성 조건과 추론 코드를 수정하지 않는 것을 원칙으로 한다. 필요한 수정은 현재 작업의 완료 또는 안전한 중단 후 적용한다. 입력 대량 생성과 목표 보충은 별도 출력·상태로 추적한다.
- 실행 대상을 줄이면 이미 로드된 대기 프로세스에 파일 수정이 반영될 것이라고 가정하지 않는다. PID와 명령을 확인해 해당 작업만 중단하고 수정한 목록으로 다시 등록한다.
- 미생성 대기 작업의 오래된 상태 파일은 `.tmp/`에 보존한 뒤 교체할 수 있다. 완료 이미지가 있는 작업의 상태를 초기화해 완료 이력을 없애지 않는다.
- 같은 작업을 두 번 실행하지 않는다. PID·명령·상태와 출력 폴더 잠금을 확인한다. 다른 출력 폴더라는 이유만으로 동일 후보의 중복 실행을 허용하지 않는다.
- GPU 사용 여부와 작업 존재 여부를 구분한다. GPU를 기다리는 프로세스도 등록된 작업이다.
- 진행 보고에는 기존 완료 수, 이번 신규 완료 수, 재사용 수, 생성 대기 수를 구분한다. 생성 완료를 품질 검수 완료로 보고하지 않는다.

## P7-5.10 적용

현재 기준 목록은 `docs/assets/part-07/chapter-05/sec-10/p7-5-10-paired-dataset.json`이다.

- 기존 193쌍과 추가 입력 24개를 합한 217개를 관리한다.
- 추가 입력 중 `P710-PROP-001·002·005·006·013·015·016·017·019·022·024`는 기존 Mira 목표를 재사용한다.
- `003·004·007·008·009·010·011·012·014·018·020·021·023`만 새 목표를 생성한다. 생성 조건의 제외 목록에는 재사용 11개를 유지한다.
- 이 결정 시점의 준비 완료는 204쌍, 새 목표 생성·검수 대기는 13개다. 이후 수치는 통합 목록과 실제 결과로 확인하며 이 문서에 진행 로그를 누적하지 않는다.
- 생성 조건을 추가하는 것만으로 통합 데이터셋에 편입하지 않는다. 입력 후보 180개 전체와 현재 채택된 24개는 서로 다른 범위다.

현재 공용 생성기는 선택·제외 처리, 완료 파일 해시 확인, 출력 폴더 잠금, GPU 대기를 수행한다. 학습 준비 코드는 대기 중인 쌍을 차단한다. **폴더를 넘나드는 의미상 재사용 판단, 시각적 중복 판단, 모든 대기 프로세스의 중복 등록 차단은 자동화되어 있지 않다.** 이 부분은 위 생성 전 점검으로 수행하며 자동 보장으로 설명하지 않는다.

## 확정 학습 이미지 저장 위치

P7-5.10의 사용 확정 이미지는 `sec-10/training-images/input-images/`와 `sec-10/training-images/target-images/`에 실제 파일로 저장한다. 생성 후보와 미사용 결과의 위치는 이관 대상과 구분한다. 동일 해시의 목표는 하나만 저장하며, 과거 원고·생성 기록이 참조하는 경로는 상대 심볼릭 링크로 연결한다. 데이터셋과 생성 JSON의 `dataset_usage`는 확정 저장 경로를 직접 가리킨다. 경로 이동으로 결과 ID를 변경하거나 이미지를 재생성하지 않는다.

## 생성 입력 JSON 통합

P7-5.10은 `p7-5-10-image-generation.json` 하나에서 관리번호 색인(`management_index`), 생성 규칙(`rules`), 실행 선택(`selection`)을 관리한다. 별도의 조건·선택 JSON을 만들지 않는다. CLI의 `--rule`과 `--ids`로 규칙과 관리번호를 지정한다. 원래 생성 ID와 결과 해시는 유지하며 관리번호는 재번호를 부여하지 않는다.
