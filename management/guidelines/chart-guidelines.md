# 차트·그래프·다이어그램 작성 기준

이 문서는 책 본문에 들어가는 표, 차트, 그래프, 다이어그램의 선택·작성·검증 기준을 정리한다. 목표는 시각 자료를 늘리는 것이 아니라, 본문만으로 놓치기 쉬운 비교 축, 판단 순서, 위치 관계, 구조 관계를 선명하게 만드는 것이다.

## 목적

- 본문에 시각 자료가 필요한지 먼저 판단한다.
- 표, 플로우차트, 좌표 기반 그래프, 구조 다이어그램의 역할을 구분한다.
- Mermaid, SVG, PNG, Python/Matplotlib 자산의 저장 위치와 검증 기준을 통일한다.
- 다국어 본문에서 도식 내부 언어와 자산 파일명을 일관되게 관리한다.

## 빠른 판단 순서

1. 본문 한두 문장으로 충분히 설명되는지 확인한다.
2. 시각 자료가 필요하다면 중심 질문을 하나로 좁힌다.
3. 중심 질문에 맞는 형식을 고른다.
4. 한 그림 안에 비교, 절차, 좌표, 구조가 섞이면 나눈다.
5. 본문 문장, 표, 도식이 같은 내용을 반복하지 않는지 확인한다.
6. 언어별 라벨, 파일명, 릴리즈노트 반영 여부를 확인한다.

## 형식 선택 기준

| 중심 질문 | 우선 형식 | 피해야 할 선택 |
| --- | --- | --- |
| 무엇이 다른가, 어디서 갈리는가 | Markdown 표 | 절차를 긴 표에 억지로 넣기 |
| 어떤 순서로 판단하는가 | Mermaid 플로우차트 | 단순 비교를 화살표로 복잡하게 만들기 |
| 값이 어디에 놓이고 어떻게 변하는가 | 좌표 기반 그래프·차트 | 곡선·분포를 박스 다이어그램으로 대체하기 |
| 구성요소가 어떻게 연결되는가 | 구조 다이어그램 | 관계 설명을 숫자 표로만 처리하기 |
| 본문이 이미 충분한가 | 추가 형식 없음 | 장식용 도식 추가하기 |

### 표

표는 같은 축 위에서 항목을 나란히 비교할 때 사용한다. 숫자, 범주, 오독 가능성, 판단 기준처럼 행과 열로 바로 대조되는 내용에 적합하다.

다음 경우에는 표를 피한다.

- 독자가 순서대로 따라가야 하는 절차가 중심일 때
- 비교 대상, 원인, 해석, 다음 행동, 예외가 한 표에 모두 들어가 열이 과도하게 늘어날 때
- 표를 읽기 위해 긴 본문 설명이 먼저 필요하고, 표 자체가 독해를 줄이지 못할 때

### Mermaid 플로우차트

Mermaid는 판단 순서, 단계 이동, 조건 분기, 개념 관계를 짧게 압축할 때 사용한다. 사례 문단 바로 아래에 둘 때는 새 이론을 추가하지 말고, 앞 문단의 해석 순서만 다시 보여 준다.

기본 배치 원칙:

- 2~3단계의 짧은 흐름은 `LR`을 사용할 수 있다.
- 4단계 이상이면 `TD`, 2행 배치, 또는 ㄹ자 형태의 꺾인 배치를 먼저 검토한다.
- 3열을 넘는 긴 가로 배치는 피한다.
- 박스 안 문장을 늘려 레이아웃 문제를 해결하지 않는다. 문구를 줄이고, 필요하면 도식을 나눈다.
- 박스 글자가 유난히 작아지면 글자 크기보다 노드 수와 배치를 먼저 줄인다.

### 좌표 기반 그래프·차트

좌표 기반 그래프는 위치와 형태 자체가 설명일 때 사용한다. 함수 곡선, 손실 곡선, 분포, 산점도, 벡터, 임계값, decision boundary, 실험 로그 곡선이 여기에 해당한다.

운영 원칙:

- 숫자 입력, 예제 배열, 실험 로그처럼 재계산 가능한 데이터가 있으면 Python/Matplotlib 생성형을 우선한다.
- 생성 스크립트는 산출 이미지와 같은 `docs/assets/part-XX/chapter-YY/` 폴더에 둔다.
- 스크립트를 다시 실행하면 같은 산출 파일이 만들어져야 한다.
- 수동 SVG는 데이터 생성보다 라벨 배치, 개념 강조, 시각 구조 제어가 더 중요한 경우에만 사용한다.

### 구조 다이어그램

구조 다이어그램은 층, 모듈, 입력/출력, 포함 관계, 연결 관계를 보여 줄 때 사용한다. 시간 순서보다 관계 구조가 중요하면 플로우차트보다 구조 다이어그램을 우선한다.

## 분리 기준

한 시각 자료는 하나의 중심 질문만 맡는다.

- “무엇이 다른가”와 “어떤 순서로 진행되는가”가 모두 필요하면 표와 플로우차트로 나눈다.
- “곡선에서 어디로 움직이는가”와 “학습 루프가 어떤 단계로 반복되는가”는 좌표 그래프와 Mermaid 흐름도로 나눈다.
- 좌표축, 곡선, 점, 벡터처럼 위치가 의미인 요소와 박스-화살표 흐름처럼 관계가 의미인 요소를 한 그림에 억지로 넣지 않는다.
- 같은 내용을 본문, 표, 도식에서 거의 같은 표현으로 세 번 반복하지 않는다.

## 파일 형식과 위치

- 단순 흐름과 관계는 Mermaid를 우선한다.
- 현재 저장소에서 본문 코드블록 직접 렌더링을 기본 지원하는 도식 형식은 Mermaid다.
- Mermaid 원본은 본문 코드블록에 직접 둘 수 있고, 필요하면 `.mmd` 파일로 `docs/assets/` 아래에 분리할 수 있다.
- 사전 렌더링된 SVG/PNG는 직접 코드블록 렌더링이 어렵거나 좌표·수학 그래프·이미지 자산처럼 수동 제어가 필요할 때만 사용한다.
- 이미지 파일은 해당 본문 위치에 맞춰 `docs/assets/part-XX/chapter-YY/` 아래에 둔다.
- Python/Matplotlib 차트는 생성 스크립트와 산출 이미지를 같은 자산 폴더에서 함께 관리한다.
- 새 코드블록 렌더러를 추가하면 `.github/workflows/deploy.yml`의 설치 단계도 함께 확인한다.

## Mermaid 자산 운영

Mermaid를 외부 파일로 분리할 때는 `.mmd` 확장자를 기본으로 사용한다. 특별한 이유가 없으면 `.mermaid`와 혼용하지 않는다.

본문 include 기본 패턴:

````md
```mermaid
--8<-- "assets/part-05/chapter-01/perceptron-flow-ko.mmd"
```
````

운영 기준:

- `pymdownx.snippets.base_path = docs` 기준이므로 include 경로는 `assets/...`를 사용한다.
- 본문 Markdown은 렌더링 진입점이고, 실제 도식 원본은 `docs/assets/part-XX/chapter-YY/` 아래 `.mmd` 파일로 본다.
- 같은 Section 안에 Mermaid가 여러 개 있으면 파일을 분리하고 이름만 보고 역할을 알 수 있게 짓는다.
- `diagram-1.mmd`, `figure-final.mmd` 같은 임시 이름은 피한다.
- 기존 인라인 Mermaid를 자산 파일로 옮길 때는 먼저 렌더링 결과가 같게 분리하고, 라벨 언어와 레이아웃 보정은 별도 수정으로 처리한다.
- Mermaid 자산은 SVG/PNG 산출물을 별도로 커밋하지 않는다. 저장소가 관리하는 원본은 `.mmd` 파일이다.

## 다국어 자산과 링크

- 도식 내부의 보이는 문구는 본문 언어와 일치시킨다.
- 언어별 도식 파일은 기본 운영 단위다.
- 파일명에는 언어 약어를 붙인다. 한국어는 `-ko`, 영어는 `-en`, 중국어는 `-zh`를 사용한다.
- 한국어 본문은 `-ko`, 영어 본문은 `-en`, 중국어 본문은 `-zh` 자산을 직접 참조한다.
- 기준 원본은 둘 수 있지만 의미 구조와 시각 구조는 가능한 한 같게 유지하고, 주로 라벨 언어와 최소 레이아웃만 조정한다.
- 일반 Markdown 이미지 링크, 파일 링크, 예제 링크는 배포 경로와 strict 링크 검사를 함께 고려한다.
- 영어·중국어처럼 다국어 공개 경로에서 strict 링크 경고가 날 수 있는 본문은 `/AiBook/assets/...` 같은 사이트 절대 경로를 기본으로 검토한다.
- 다국어 자산을 추가하거나 바꾸면 기준 원본, 동기화 대상 언어, 본문 참조 경로를 관리 메모나 릴리즈노트에 남긴다.

## SVG와 PNG 작성 기준

### SVG 기본 구조

- SVG에는 `<title>`과 `<desc>`를 넣어 접근성과 검색 가능성을 확보한다.
- 단일 개념 차트는 `viewBox="0 0 760 430"`을 우선 검토한다.
- 좌우 비교나 전후 비교처럼 두 패널이 필요한 차트는 `viewBox="0 0 920 430"`을 사용할 수 있다.
- 2x2 패널, 여러 카드, 하단 요약 박스가 함께 있으면 기본 높이에 억지로 맞추지 말고 `viewBox`와 패널 높이를 늘린다.
- 의미 없는 그라데이션, 그림자, 장식용 도형은 넣지 않는다.

### 그래프 구성 요소

수학 그래프나 차트에는 필요한 범위에서 다음 요소를 둔다.

- 축(axis), 기준선, 격자(grid), 눈금(tick)
- 주요 점(point), 선(line), 벡터(vector), 구간(interval)
- 변화량 표시: `Δx`, `Δy`, 방향 화살표
- 그래프 해독에 필요한 축 라벨, 범례, 구간 라벨, 임계값 라벨

본문이나 캡션이 제목·요약 역할을 이미 맡고 있다면 이미지 내부 제목이나 하단 요약문은 생략할 수 있다.

### 색상과 선

- 같은 차트 안에서 같은 색은 같은 의미로만 사용한다.
- 색상만으로 의미를 전달하지 않고 라벨, 선 종류, 위치 설명을 함께 둔다.
- 그래프 곡선과 이동·반복 화살표는 같은 색상 계열을 피한다.
- 기본 함수나 주 곡선은 파란색 계열, 변화량과 비교 강조는 빨간색 계열, 입력 변화나 보조 방향은 초록색 계열, 축과 보조선은 회색 계열을 우선 검토한다.
- 반복이나 업데이트 루프는 점선, 굵기, 라벨로 일반 흐름과 구분한다.

### 텍스트와 라벨

- 그래프 내부 텍스트는 점·선·구간·색·기호를 읽는 데 필요한 라벨로 제한한다.
- 본문이나 캡션으로 옮겨도 그래프 해독이 유지되는 제목, 설명문, 요약문은 이미지 밖으로 뺀다.
- SVG 텍스트는 일반 라벨 14px 이상, 제목 18px 이상을 기준으로 한다.
- 긴 문장형 라벨보다 짧은 라벨을 우선하고, 세부 해석은 본문이나 캡션으로 넘긴다.
- CJK 라벨이 들어간 PNG는 글자가 네모나 물음표로 깨지지 않는지 직접 확인한다.

### 여백과 겹침

- 텍스트, 선, 화살표, 카드 테두리, 데이터 점은 서로 겹치면 안 된다.
- 패널 내부 요소는 패널 경계선에 닿기 전에 최소 24px 이상의 안전 여백을 둔다.
- 하단 요약 박스는 마지막 도식 요소와 최소 24px 이상의 수직 간격을 둔다.
- 화살표 머리는 박스 내부 텍스트를 덮지 않게 박스 테두리 바깥이나 테두리 직전에 둔다.
- 화살표 라벨이 선과 가까우면 배경색 캡슐 박스 안에 넣는다.
- 노드-엣지 도식의 엣지 라벨은 선 위에 바로 얹지 말고 선에서 약간 떨어뜨린다.
- 코드처럼 줄 단위 텍스트가 들어가는 박스는 마지막 줄이 테두리에 닿지 않도록 아래쪽 내부 여백을 둔다.
- 요소가 잘리거나 겹치면 글자 크기를 먼저 줄이지 말고 `viewBox`, 패널 높이, 배치, 문구 길이를 먼저 조정한다.

## 본문 삽입 기준

- 차트와 그래프는 본문을 대체하지 않고 본문 설명을 보강한다.
- 본문에서 차트를 삽입할 때는 이미지 바로 앞뒤에 차트가 무엇을 보여 주는지 짧게 설명한다.
- 차트나 그래프가 본문 주장에 근거로 쓰이면 근거 메모에 목적, 자체 제작 여부, 외부 자료 참조 여부를 남긴다.
- 외부 자료를 참고해 재작성한 경우에도 출처와 재작성 여부를 남긴다.
- 공개 라이선스나 인용 가능성이 불명확한 외부 도식은 그대로 복사하지 않는다.

## 작업 후 확인

시각 자료를 추가하거나 수정한 뒤에는 다음을 확인한다.

- 중심 질문이 하나인가
- 본문, 표, 도식이 같은 내용을 반복하지 않는가
- 선택한 형식이 비교, 절차, 위치, 구조 중 실제 목적과 맞는가
- Mermaid include 경로 또는 이미지 링크가 실제 파일과 일치하는가
- 언어별 본문이 자기 언어 자산을 직접 참조하는가
- 자산 폴더 README나 릴리즈노트에 관련 자산 변경이 반영됐는가
- Python/Matplotlib 차트는 스크립트 재실행으로 산출 이미지가 만들어지는가
- SVG/PNG의 라벨, 화살표, 하단 요약, 패널 요소가 겹치거나 잘리지 않는가
- 모바일 폭에서 텍스트가 지나치게 작아지지 않는가

MkDocs 빌드는 작은 수정마다 반복하지 않는다. 해당 자산이 포함된 범위의 원고 점검이 끝난 뒤 `.venv/bin/python -m mkdocs build`로 링크와 렌더링 오류를 함께 확인한다.
