# Part 7 미반영 체크리스트

이 문서는 Part 7 프로젝트 파트에서 아직 남아 있는 보강 작업만 모은 체크리스트입니다.

## 품질 상태 메모

- Part 7은 책 전체를 기록과 회고 중심 산출물로 닫아 주는 역할이 분명합니다.
- 현재 남은 과제는 구조 부족보다 산출물 이름과 기록 필드가 초심자에게 메타 용어가 아니라 실제 작성 도구로 읽히게 하는 일입니다.
- 따라서 새 프로젝트 유형을 늘리기보다 템플릿의 직접성, 좋은 기록/나쁜 기록 대비, 필드 의미 설명을 유지하는 편이 중요합니다.

## 체크리스트

- [x] 실패 기록과 회고 문장을 독자가 바로 따라 쓸 수 있는 형태의 템플릿으로 더 보강한다.
- [x] 현재 프로젝트 문서 안에서 예시를 더 보강하는 쪽으로 갈지, 별도 보충학습이 필요한지 다시 점검한다.

## 이관한 기존 메모

- `beginner-reinforcement-review.md`

## 현재 결정

- Part 7에서는 별도 회고 보충학습을 새로 만들지 않습니다.
- 대신 P7-1.2와 P7-7.2 본문 안에 독자가 바로 복붙해 쓸 수 있는 최소 템플릿과 `나쁜 기록/좋은 기록` 대비를 넣어, 회고와 실패 기록이 예시 감상에 그치지 않게 합니다.
- Part 7 전체 기준으로도 별도 프로젝트 보충학습은 추가하지 않습니다.
- 분석, baseline 비교, RAG 검증, agent 권한/로그, 배포 실패 기록 예시가 이미 각 장의 본문 책임 안에 들어와 있으므로, 현재는 새 보충학습보다 본문 안 예시 축을 유지하는 편이 더 적절합니다.

## 이번 반영

- P7-1.2에 `fact / interpretation / next question` 형식의 직접 작성 템플릿을 추가했습니다.
- P7-1.2에 결과 요약만 적는 나쁜 회고와, 관찰·가설·다음 조치를 함께 남기는 좋은 회고를 대비해 넣었습니다.
- P7-7.2에 `incident record / review summary` 형식의 직접 작성 템플릿을 추가했습니다.
- P7-7.2에 실패를 모호하게 남기는 나쁜 기록과, category·priority·next_action까지 남기는 좋은 기록을 대비해 넣었습니다.
- Part 7 index와 summary에 별도 프로젝트 보충학습을 만들지 않는다는 판단을 반영하고, 현재 예시 축이 이미 본문 안에서 분산 회수된다는 점을 명시했습니다.

## 다음 유지 점검

- 산출물 이름이 처음 나오는 문단에서 `왜 이 기록이 필요한가`가 충분히 짧고 직접적으로 보이는지 점검합니다.
- 템플릿 필드가 추상 용어가 아니라 실제 회고와 실패 대응 행동으로 읽히는지 점검합니다.
- Part 6의 평가·운영 기록 언어와 Part 7 템플릿 언어가 계속 같은 방향으로 맞물리는지 점검합니다.
