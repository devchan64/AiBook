# Part 7 미반영 체크리스트

이 문서는 Part 7을 `초심자가 실제로 동작시켜 보며 AI 동작을 이해하는 실습 파트`로 끌어올리기 위해 남아 있는 구조 문제와 보강 작업만 모은 체크리스트입니다.

## 현재 판단

- 현재 Part 7은 공개 목차와 달리 실제 원고 본문에서는 아직 `작은 프로젝트`, `작은 이미지`, `아주 작은 문서 집합` 같은 장난감 축이 강합니다.
- 시작 페이지와 마무리 페이지도 `무엇을 기록할 것인가` 설명이 `무엇을 직접 실행하고 어떻게 읽을 것인가`보다 앞서 나옵니다.
- 초심자에게 필요한 것은 템플릿 이름 암기가 아니라, 입력을 바꾸면 출력과 해석이 함께 바뀌는 장면을 여러 번 직접 보는 것입니다.
- 따라서 남은 작업의 중심은 `기록 용어 정리`가 아니라 `실행 강도`, `예제 규모`, `비교 구조`, `그래프/도식`, `실패 해석`을 실제 원고 안에서 끌어올리는 일입니다.

## 우선 구조 보강

- [x] `index.md`를 기록 문서 중심 소개에서 실행과 검토 중심 소개로 다시 쓴다.
- [ ] `summary.md`도 같은 기준으로 다시 써, Part 7 결론이 `작은 산출물`이 아니라 `실제 실행과 해석`으로 읽히게 한다.
- [ ] `docs/book/table-of-contents.md`의 Part 7 설명과 실제 본문 시작/마무리 페이지가 같은 강도로 맞물리는지 다시 확인한다.

## 공통 품질 기준

아래 기준을 각 Section 재작성의 공통 하한선으로 사용합니다.

- [ ] 장난감 데이터 한 번 출력하고 끝나는 예제를 줄이고, 실제로 비교와 해석이 필요한 입력 규모로 올린다.
- [ ] 모든 실습에 `기준선`, `중간 산출물`, `최종 출력`, `실패 사례`가 함께 남도록 만든다.
- [ ] 코드 블록만 두지 말고, 실행 결과를 읽는 표나 그래프나 도식을 각 장에 최소 1개 이상 붙인다.
- [ ] `왜 이 구조를 택했는가`, `무엇이 실패 신호인가`, `다음 수정은 어디서 시작하는가`가 본문에 직접 적히게 한다.
- [ ] `작은`, `아주 작은`, `간단한`처럼 실습 강도를 낮춰 보이게 하는 표현을 다시 점검한다.

## 장별 보강 체크리스트

### Module 1. 프로젝트 문제 정의와 기준선

#### Chapter 1. 프로젝트 질문과 baseline

- [ ] `P7-1.1`은 현재의 일주일 CSV 장난감 예제를 넘어서, 실제로 입력 단위 재정의가 결과를 바꾸는 데이터 사례로 교체하거나 확장한다.
- [ ] `P7-1.1`에는 `한 행이 무엇인가`, `한 샘플이 무엇인가`, `기준선 구간은 무엇인가`를 눈으로 확인하는 비교표를 강화한다.
- [ ] `P7-1.2`는 회고 템플릿만이 아니라 baseline과 개선 판단이 실제로 어떻게 갈리는지 더 강한 비교 사례를 붙인다.

#### Chapter 2. 결과 해석과 회고

- [ ] `P7-2.1`은 점수와 오류 사례를 함께 읽는 표를 더 실제 프로젝트 수준으로 보강한다.
- [ ] `P7-2.2`는 회고 문장 작성보다, 회고가 어떤 실행 수정으로 이어지는지를 더 직접적으로 보여 준다.

### Module 2. 구조 선택이 드러나는 모델 프로젝트

#### Chapter 3. 입력 구조와 모델 구조 선택

- [ ] `P7-3.1`은 4x4 막대 이미지 같은 장난감 예제 의존을 줄이고, 입력 구조 차이가 정말 준비 코드와 해석 방식을 바꾸는 사례로 재설계한다.
- [ ] `P7-3.2`는 CNN, 순차 모델, attention 계열을 이름 소개가 아니라 `언제 무엇이 깨지는가` 기준으로 비교하게 보강한다.

#### Chapter 4. 학습 결과 검토

- [ ] `P7-4.1`은 loss와 metric을 실제 학습 곡선 그래프로 읽게 하고, 숫자 나열을 줄인다.
- [ ] `P7-4.2`는 실패를 구조/데이터/baseline 문제로 나누는 실제 판단 절차를 차트와 사례로 더 풀어쓴다.

### Module 3. LLM 서비스 프로젝트

#### Chapter 5. RAG 프로젝트 검증

- [ ] `P7-5.1`은 세 문장짜리 문서 집합 수준을 넘어서, 검색 후보 비교가 실제로 갈릴 만큼 문서 수와 모호성을 높인다.
- [ ] `P7-5.1`에는 검색 후보 표, 선택 근거 표, 최종 답변 비교를 모두 남겨 `검색 -> 근거 -> 답변`이 눈에 보이게 만든다.
- [ ] `P7-5.2`는 검색 실패와 답변 실패를 구분하는 실패 사례 묶음을 더 보강한다.

#### Chapter 6. 에이전트 실행 기록 검토

- [ ] `P7-6.1`은 도구 호출 흐름을 단순 소개하지 말고, 실제 승인 필요 지점과 blocked 상태가 생기는 실행 시나리오를 더 분명히 보여 준다.
- [ ] `P7-6.2`는 권한, 로그, 다음 행동이 왜 운영 판단 기준이 되는지 실제 실패 로그 중심으로 강화한다.

### Module 4. 배포와 운영 회고

#### Chapter 7. 배포 점검과 운영 회고

- [ ] `P7-7.1`은 빌드 성공 여부만이 아니라 공개 상태, 핵심 동작, 점검 루틴까지 묶인 검토 표로 보강한다.
- [ ] `P7-7.2`는 장애 기록 템플릿보다 우선순위와 재발 방지 판단이 보이는 운영 회고 사례를 더 강화한다.

## 이번 재점검에서 확인한 핵심 문제

- `P7-1.1`: 여전히 `작은 CSV`, `장난감 데이터` 표현이 강하고, 입력 단위 재정의의 힘보다 가벼운 요약 예제로 읽힌다.
- `P7-3.1`: 4x4 막대 이미지는 구조 감각 입문에는 쓸 수 있지만, 지금 목표인 `실제로 돌려 보며 이해`를 받치기에는 너무 얇다.
- `P7-5.1`: 문서 3개 토큰 겹침 비교는 RAG 흐름 입문 설명에는 유효하지만, 검색 실패와 근거 선택의 실제성을 충분히 만들지 못한다.
- `P7-index`, `P7-summary`: Part 전체를 아직도 `기록 중심 산출물` 파트처럼 묶는 경향이 강하다.

## 현재 결정

- Part 7은 `템플릿 정리 파트`가 아니라 `실행과 해석 실습 파트`로 계속 재구성한다.
- 별도 보충학습을 늘리기보다, 본문 Section 안의 예제 강도와 비교 구조를 올리는 쪽을 우선한다.
- 장난감 예제를 완전히 금지하지는 않지만, 현재 예제가 `실제 판단`을 못 받치면 교체하거나 같은 절 안에서 더 실제적인 2차 사례로 확장한다.
- 다만 현재처럼 한 절 안에 설명과 실험을 모두 몰아넣는 방식만으로는 한계가 있으므로, 필요하면 Chapter별 `연습 전용 섹션(section-03)`을 추가하는 방향도 병행 검토한다.
