# Part 7 체크포인트 노트

이 문서는 Part 7을 목차 순서대로 읽을 때 각 Section이 담아야 할 중심 주제를 개괄식으로 정리한 체크포인트 노트입니다.

## 사용 원칙

- 이 노트는 `docs/table-of-contents.md`를 기준으로 Part 7의 시작/마무리 페이지, Chapter, Section을 같은 순서로 훑기 위한 개요 문서입니다.
- 이 노트는 작업 상태표가 아니라 Part 7 원고가 유지해야 할 중심선 문서입니다.
- 순차 점검 기록, 품질 상태 메모, 구조 재배치 로그는 이 문서에서 운영하지 않습니다.
- 체크포인트는 `실행 -> 비교 -> 실패 해석 -> 운영 회고` 흐름을 실제 실습 단위로 붙잡는 데 목적을 둡니다.
- `학습 관점 누락 점검`은 Part 원고가 잃기 쉬운 설명 흐름을 점검하고, `목차 기준 체크포인트`는 Part 원고가 유지해야 할 구조 흐름을 관리합니다.
- Section ID 기반 자동 대조는 문서 전체가 아니라 `목차 기준 체크포인트` 이후 구간을 기준으로 삼습니다.
- 체크포인트 문장은 집필 기준이며, 본문에는 `오픈체크리스트`, `중심축` 같은 관리 표현으로 노출하지 않습니다. 본문 보강은 문제 장면, 개념 대비, 독자용 판단 문장으로 풀어 씁니다.

## 학습 관점 누락 점검

- 각 Chapter를 볼 때 템플릿이나 결과물 목록보다 `무엇을 실제로 실행하고 무엇을 비교하는가`가 먼저 보이는지 확인합니다.
- 각 Section를 볼 때 `설명 -> 코드 실행 -> 출력 비교 -> 해석 -> 짧은 회고` 리듬이 실제로 보이는지 확인합니다.
- 각 Section를 볼 때 `기준선`, `중간 산출물`, `최종 출력`, `실패 사례`, `다음 수정` 가운데 빠진 축이 없는지 확인합니다.
- 각 Section를 볼 때 코드 블록이 단순 예시가 아니라, 입력을 바꾸면 출력과 해석이 함께 달라지는 실습으로 기능하는지 확인합니다.
- 실습 예제는 너무 작은 장난감 입력에 머물지 않고, 실제로 해석 차이가 드러나는 비교 장면을 포함하는지 확인합니다.
- 각 Chapter에는 가능하면 최소 1개의 도식, 그래프, 또는 비교표가 있어 `입력 -> 처리 -> 출력 -> 검토` 흐름을 눈으로 다시 읽을 수 있어야 합니다.
- 회고 문장은 감상문이 아니라 `무엇을 바꾸면 다음 결과가 달라질까`로 이어지는지 확인합니다.
- 운영 실습 장에서는 `동작 확인`, `장애 재현`, `우선순위 분류`, `재발 방지`가 함께 보이는지 확인합니다.
- Part 7에서는 특히 `실행 없는 요약`, `비교 없는 결과 나열`, `실패 해석 없는 회고`가 빠지지 않는지 다시 봅니다.
- 동작 단위 센서 사례처럼 반복 사용 가능한 공개형 합성 데이터는 Part 7의 연습 Section 후보로 볼 수 있습니다. 다만 도메인 설명을 새로 길게 열기보다 `입력 단위`, `baseline`, `비교 조건`, `실패 해석`, `운영 회고`를 바꾸는 실습 재료로만 사용합니다.

## Section 경계 정리

- Part 7 전체 경계는 새 이론을 추가하는 Part가 아니라, Part 1~6에서 배운 개념을 현재 널리 쓰이는 모델 실습으로 다시 회수하는 데 둡니다. 독자는 Stable Diffusion, 로컬 LLM, 비전 모델, 음성 모델, RAG, agent 같은 실제 모델군을 직접 실행하면서 `질문 -> 입력 -> baseline -> 비교 -> 실패 해석 -> 근거/실행 기록 -> 운영 회고 -> 재현 패키지`를 남겨야 합니다.
- Part 7의 중심은 `모델 소개`가 아니라 `현재 널리 쓰이는 모델을 실습 재료로 삼아 앞 Part의 개념을 다시 확인하는 것`입니다. 모델명과 저장소 목록은 목적이 아니라 실습 입구이며, 각 실습은 Part 1~6의 어떤 개념을 다시 확인하는지 분명히 연결해야 합니다.
- 각 Section은 설명 문서가 아니라 실습 단위여야 합니다. 최소한 입력 또는 조건을 바꾸고, 출력 차이를 비교하며, 그 차이를 다음 수정이나 회고 문장으로 연결해야 합니다.
- P7-1.1~P7-1.3은 프로젝트 질문, 샘플 단위, 기준선 구간을 여는 구간입니다. 데이터셋 소개나 문제 배경 설명으로 길어지지 않고, 무엇을 한 건으로 볼지와 무엇을 baseline으로 둘지가 실험 결론을 어떻게 바꾸는지에 집중합니다.
- P7-2.1~P7-2.3은 전통 머신러닝 비교 실험을 닫습니다. 점수, 오류 사례, 전처리 효과, 데이터 경계 부족을 한 평가 셋에서 비교하게 하고, 알고리즘 설명이나 Part 4 이론 반복으로 돌아가지 않습니다.
- P7-3.1~P7-3.3은 입력 구조가 프로젝트를 어떻게 바꾸는지 확인하는 구간입니다. 표, 이미지, 시퀀스, attention 계열 비교는 모델 이름 나열이 아니라 준비 코드, 샘플 확인, 실패 신호, 표현 축소의 손실을 비교하는 실습으로 유지합니다.
- P7-4.1~P7-4.4는 학습 결과와 표현 문제를 다시 읽는 구간입니다. loss, metric, 오류 샘플, coverage, OOV, 표현 정규화, shape token을 통해 구조 문제, 데이터 문제, baseline 문제를 분리하고, 딥러닝 이론이나 토큰화 일반론으로 확장하지 않습니다.
- P7-5.1~P7-5.4와 P7-5.7은 웹툰 컷 생성 파이프라인을 역할별 독립 단계로 나눕니다. `P7-5.1`은 로컬 GPU 화풍 참조 셋의 프레임·선·수채화·공간·카메라 특징을, `P7-5.2`는 착장·가방·전신·body-only OpenPose의 캐릭터 입력 역할을, `P7-5.7`은 정면 얼굴의 identity·헤어·화풍과 카메라 회전의 재현 범위를 비교합니다. `P7-5.3`은 장면 RGB·상대 depth 생성, 한 축의 카메라 앵글 변환, 인물 재생성 마스크 생성을 각각 독립 코드로 실행해 구조 입력과 편집 영역의 의미·한계를 기록합니다. `P7-5.4`는 고각도 전신에서 ControlNet·mask inpaint·VTON이 네 계약에 보인 일치와 이탈을 비교하고, 구조용 guide·얼굴·완성 착장을 분리한 후속 가설을 검증합니다. P7-5는 승인·미승인 상태를 관리하지 않습니다. 앞 단계의 이미지와 guide는 입력 역할, 생성 조건, 관찰된 일치·이탈, 알려진 한계를 함께 기록한 참고 자산으로 사용하며, 부분 관찰을 일반 품질 보장으로 합치지 않습니다.
- P7-6.1~P7-8.1은 로컬 LLM, 비전, 음성·오디오 모델을 현재 모델 실행 실습으로 다룹니다. 모델 소개가 아니라 양자화, context 길이, promptable segmentation, 전사와 오디오 생성 조건을 바꾸며 Part 1~6의 token, inference, 입력 구조, 시퀀스, 생성 평가 개념을 다시 확인하게 합니다.
- P7-9.1~P7-9.3은 RAG의 검색 후보, 선택 근거, 최종 답변, 검색 실패, 근거 부족, 답변 과장 위험을 한 흐름으로 기록하게 합니다. RAG 개념 설명은 Part 6에서 닫았으므로, Part 7에서는 문서 집합과 질문을 바꾸었을 때 상태가 어떻게 갈리는지 실습에 집중합니다.
- P7-9.4와 P7-9.5는 검색 품질을 더 정밀하게 확인하는 실습입니다. ANN 인덱스 설정, 후보 수, 지연 시간, top-k 포함률, 버전 필터, 검색 평가셋을 다루되, 벡터 DB 제품 사용법이나 대규모 검색 시스템 설계로 확장하지 않습니다.
- P7-10.1은 RAG 평가 도구를 검색과 생성을 분리해 점검하는 기록 장치로 다룹니다. 지표 이름을 외우는 절이 아니라, 검색 누락, 순위 문제, 근거 불충실, 답변 관련성 부족을 다음 수정 행동으로 바꾸는 실습이어야 합니다.
- P7-11.1~P7-11.3은 agent 실행을 계획, 도구 호출, 승인 경계, blocked 상태, 권한, 로그, 다음 행동으로 나누어 기록하는 구간입니다. agent를 자동화 만능 도구로 소개하지 않고, 어디서 멈춰야 하는지와 왜 사람 승인으로 넘겨야 하는지를 실습 결과로 남깁니다.
- P7-12.1은 agent trace를 최종 답변 평가가 아니라 실행 증거로 다시 읽게 합니다. span, tool call, permission, blocked, skipped, next action을 나누어 다음 실행 설계로 연결해야 합니다.
- P7-13.1~P7-14.1은 운영과 반복 개선을 닫는 구간입니다. 배포 확인, 상태 점검, 장애 기록, 운영 신호 분류, 경고 등급, 재현 가능한 프로젝트 패키지를 다루되, 장기 운영 체계 전체나 조직 프로세스 매뉴얼로 확장하지 않습니다.
- P7-14.1은 Part 7 전체의 마감 실습입니다. 질문, 입력, 코드, 환경, 실행 명령, 결과, 한계, 다음 조치를 묶어 다른 사람이 같은 실행을 다시 확인할 수 있는지 점검하는 데 집중하고, 배포 자동화나 협업 플랫폼 사용법으로 넓히지 않습니다.
- Part 7의 합성 데이터와 예제 코드는 도메인 설명을 위한 장치가 아니라 비교 조건을 바꾸기 위한 실습 재료입니다. 새 데이터셋을 추가할 때도 개인정보 없는 공개형 또는 자체 합성 데이터로 유지하고, 데이터 자체의 서사를 본문보다 크게 만들지 않습니다.
- Part 7의 회고 문장은 감상문이 아니라 `사실 -> 해석 -> 다음 질문` 또는 `실패 범주 -> 다음 조치` 형식으로 남아야 합니다. 실패를 숨기거나 성공 결과만 남기는 Section은 경계 밖으로 본다.
- Part 7은 Part 1~6의 재진입 색인 역할도 맡습니다. 비교 실험이 막히면 P7-2.3, 입력 표현 선택이 막히면 P7-3.3, 표현 정보 손실이 막히면 P7-4.4, 착장·전신 기준이 막히면 P7-5.2, 얼굴 identity와 카메라 회전이 막히면 P7-5.7, RAG 검색 품질 점검이 막히면 P7-9.5, 운영 등급 판단이 막히면 P7-13.4, 로컬 LLM 실행 조건이 막히면 P7-6.1, 비전 입력 prompt가 막히면 P7-7.1, 음성·오디오 입출력 비교가 막히면 P7-8.1, 실행 인수인계가 막히면 P7-14.1로 돌아갈 수 있게 연결을 유지합니다.
- 다국어 확장 시에도 Section ID를 기준 단위로 유지합니다. baseline, metric, loss, coverage, RAG, ANN, agent, blocked, deployment, incident review, reproducibility는 언어별 표현이 프로젝트 기록의 같은 축을 가리키도록 맞춥니다.

## Part 7 재구성 검토 기준

- Part 7 재구성은 기존 원고를 폐기하는 작업이 아니라, 기존 Chapter의 `기록 방법`, `비교 방법`, `실패 해석 방법`을 현재 널리 쓰이는 모델 실습 흐름에 맞게 다시 배열하는 작업입니다.
- 기존 Chapter 1과 Chapter 2는 유지합니다. 프로젝트 질문, 입력 단위, baseline, 전통 머신러닝 비교는 뒤쪽 현재 모델 실행 실습을 읽기 위한 기본 기록 형식이기 때문입니다.
- 기존 Chapter 3과 Chapter 4의 앞부분은 `입력 구조와 학습 결과 해석`의 공통 기반으로 유지합니다. Stable Diffusion/LoRA 묶음은 신규 Chapter 5 `생성형 이미지 모델 실습`으로 분리된 상태이므로, 이후에는 FLUX, Web UI X/Y/Z Plot, inpainting 같은 확장을 같은 Chapter 안에서 추가할지 검토합니다.
- RAG 실습은 현재 Chapter 9로 이동된 상태입니다. RAGAS, DeepEval 같은 평가 도구를 넣을 경우 `RAG 구축`과 `RAG 평가`를 한 Chapter 안에 둘지 별도 Chapter로 분리할지 다시 판단합니다.
- agent 실행과 운영 회고는 현재 Chapter 11과 Chapter 13으로 이동된 상태입니다. Langfuse, OpenLLMetry 같은 관측성 도구는 Chapter 12 보강 후보로 두되, 도구 사용법 문서로 확장하지 않습니다.
- 신규 Chapter는 모델군 하나를 소개하는 목적으로 만들지 않습니다. 각 신규 Chapter는 `직접 실행할 모델군`, `바꿀 조건`, `비교할 출력`, `Part 1~6에서 회수할 개념`, `실패를 다음 질문으로 넘기는 기록 양식`을 함께 가져야 합니다.

### Module 5. 통합 운영 실습: 배포, 점검, 회고

#### Chapter 13. 배포와 운영 회고

- 중심축: 공개 상태 점검과 운영 신호 분류를 통해 배포 이후 회고 구조를 실제로 묶습니다.
- `P7-13.1`: 빌드 성공만이 아니라 공개 상태, 핵심 동작, 점검 루틴까지 함께 확인하게 해야 합니다.
