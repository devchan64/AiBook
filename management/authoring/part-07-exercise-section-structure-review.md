# Part 7 연습 Section 분리 구조 검토

작성일: 2026-07-18

## 목적

Part 7에는 앞으로 연습을 계속 추가할 예정이다. 이 문서는 새 연습을 기존 Section 안에 누적할지, 연습별로 별도 Section을 만들지 판단하기 위한 구조 검토 리포트다.

검토 기준은 `management/guidelines/manuscript-writing-workflow.md`의 Section 경계 원칙과 목차 변경 워크플로우를 따른다.

## 현재 구조 관찰

현재 Part 7은 각 Chapter가 대체로 다음 흐름을 갖는다.

- 앞 Section: 프로젝트 개념, 판단 기준, 실행 맥락 설명
- 중간 Section: 실패, 비교, 회고, 운영 판단 설명
- 마지막 Section: 독자가 직접 조건을 바꿔 보는 연습

예를 들면 다음과 같다.

| Chapter | 현재 연습 Section | 역할 |
| --- | --- | --- |
| Chapter 1 | `P7-1.3 기준선 재설계 연습` | 기준선 경계와 비교 단위 변경 |
| Chapter 2 | `P7-2.3 비교 실험 연습` | 여러 비교 실험 결과 해석 |
| Chapter 4 | `P7-4.3 표현 정규화 연습` | 표현 변경과 coverage, 회고 우선순위 비교 |
| Chapter 7 | `P7-7.3 운영 점검 시뮬레이션` | 운영 신호를 행동 구간으로 분류 |

이 구조는 학습 흐름이 좋다. 설명 Section 뒤에 연습 Section이 붙어 있어 독자가 바로 적용할 수 있기 때문이다.

다만 앞으로 연습이 계속 추가되면 한 Section 안에 여러 연습이 쌓이면서 다음 문제가 생길 수 있다.

- Section의 중심 질문이 흐려진다.
- Python 예제, 입력 CSV, 출력 해석이 여러 세트로 섞인다.
- 릴리즈노트와 Section ID 기준 추적이 어려워진다.
- 독자가 특정 연습으로 다시 돌아가기 어렵다.
- 목차에는 하나의 연습으로 보이지만 실제로는 여러 연습이 들어 있는 구조가 된다.

## 판단 결론

연습별 Section 분리는 필요하다. 다만 모든 작은 질문을 Section으로 만들지는 않는 편이 좋다.

권장 기준은 다음이다.

> 하나의 연습이 독립된 입력 자산, 실행 절차, 출력 해석, 회고 질문을 가진다면 별도 Section으로 분리한다.

반대로 다음 정도의 짧은 변형은 기존 Section 안의 `직접 바꿔 볼 것`이나 `선택 과제`로 남기는 편이 좋다.

- threshold 숫자 하나 바꾸기
- 기준선 날짜 하나 더 바꿔 보기
- 기존 코드의 출력 문장만 다시 쓰기
- 같은 표를 두세 줄 추가해 보는 정도의 변형

## 분리 기준

새 연습이 아래 항목 중 3개 이상에 해당하면 별도 Section 후보로 본다.

| 기준 | 별도 Section 후보가 되는 경우 |
| --- | --- |
| 중심 질문 | 기존 Section 질문과 다른 질문을 닫는다 |
| 입력 자산 | 새 CSV, 새 도식, 새 코드 블록이 필요하다 |
| 실행 절차 | 3단계 이상의 독립 실행 흐름이 있다 |
| 출력 해석 | 별도 결과 표나 회고 문장이 필요하다 |
| 재진입 가치 | 독자가 나중에 특정 연습만 다시 찾아볼 가능성이 높다 |
| 릴리즈 추적 | Section ID 단위로 변경 이력을 따로 남기는 편이 명확하다 |

아래 항목에 해당하면 기존 Section 안에 남긴다.

| 기준 | 기존 Section 안에 두는 경우 |
| --- | --- |
| 같은 질문 | 기존 Section의 중심 질문을 보강할 뿐이다 |
| 같은 자산 | 입력 파일과 코드 구조가 거의 같다 |
| 짧은 변형 | 한두 문단이나 작은 표로 충분하다 |
| 선택 과제 | 본문 필수 흐름이 아니라 추가 확인이다 |
| 반복 위험 | 새 Section을 만들면 앞 Section 설명을 다시 써야 한다 |

## 권장 구조

Part 7은 `Chapter 안에서 연습 Section을 늘리는 방식`이 가장 좋다.

즉 새 연습을 Part 7 끝에 몰아 넣거나 별도 연습 Chapter를 새로 만드는 것보다, 해당 개념을 설명한 Chapter 안에 붙인다.

권장 예시는 다음과 같다.

| 추가 후보 | 권장 Section ID | 배치 |
| --- | --- | --- |
| 표본 수와 반복성으로 경고 등급 나누기 | `P7-7.4` | Chapter 7 뒤 |
| 같은 평균, 다른 패턴 비교 | `P7-4.4` | Chapter 4 뒤 |
| 절대 시간축 vs 진행도축 비교 | `P7-2.4` | Chapter 2 뒤 |
| 같은 원시 데이터로 문제 정의 다시 쓰기 | `P7-1.4` | Chapter 1 뒤 |
| 규칙 기반, 기준선 비교, 특징 기반 모델로 같은 질문 다시 쓰기 | `P7-7.5` 또는 Part 7 summary 보강 | 운영 회고 뒤 |

이 방식의 장점은 다음과 같다.

- 학습 흐름이 설명에서 연습으로 바로 이어진다.
- Section ID가 해당 Chapter의 주제와 연결된다.
- 연습이 늘어도 Part 7 끝이 부록처럼 비대해지지 않는다.
- 독자가 목차에서 필요한 연습을 바로 찾을 수 있다.

## 피해야 할 구조

### 기존 `.3` Section에 계속 누적

초기에는 빠르지만 장기적으로 좋지 않다.

예를 들어 `P7-7.3 운영 점검 시뮬레이션` 안에 운영 시나리오, 동작 단위 운영 카드, watch/review/action 등급, 최근성 가중치, 모델링 사다리 회고가 모두 들어가면 하나의 Section이 여러 중심 질문을 갖게 된다.

이 경우 독자는 `운영 점검 시뮬레이션`이라는 제목만 보고는 어떤 연습이 들어 있는지 알기 어렵다.

### Part 7 끝에 연습 모음 Chapter 만들기

연습을 관리하기에는 편하지만 학습 흐름에는 덜 좋다.

Part 7은 실행, 비교, 실패 해석, 운영 회고가 Chapter별로 이어지는 구조다. 연습만 별도 Chapter로 모으면 독자는 앞에서 배운 개념과 연습을 다시 연결해야 한다.

다만 아주 나중에 Part 7 전체를 마무리하는 `종합 프로젝트`를 만들 때는 별도 Chapter를 검토할 수 있다.

### 모든 연습을 독립 Section으로 만들기

너무 잘게 쪼개면 목차가 조각난다.

작은 숫자 변경, 선택 질문, 짧은 회고 문장은 기존 Section 안의 하위 과제로 충분하다. Section은 단순 활동 단위가 아니라 하나의 중심 질문을 닫는 단위로 유지해야 한다.

## 연습 Section 템플릿

새 연습 Section은 가능하면 다음 구조를 따른다.

1. 현재 연습이 닫는 질문
2. 입력 파일 또는 작은 표
3. 바꿔 볼 조건
4. 실행 코드 또는 비코드 절차
5. 출력 예시
6. 출력 해석
7. 회고 문장 예시
8. 체크리스트

소제목 예시는 다음처럼 잡는다.

- `왜 이 조건을 바꿔 보는가`
- `입력 파일`
- `연습 흐름`
- `Python 예제`
- `출력 읽기`
- `회고 문장으로 닫기`
- `직접 바꿔 볼 것`
- `체크리스트`

단, 모든 Section이 같은 제목을 기계적으로 반복할 필요는 없다. 중심 질문에 맞게 줄이되, 입력, 실행, 출력, 해석, 회고는 가능하면 빠지지 않게 한다.

## 메타데이터와 목차 영향

새 Section을 만들면 다음 작업이 함께 필요하다.

- 새 파일: `docs/parts/part-07/chapter-YY/section-ZZ.md`
- 본문 메타데이터: `Section ID`, `Version`
- `mkdocs.yml` nav 반영
- `docs/book/table-of-contents.md` 반영
- 릴리즈노트: `management/release-notes/sections/part-07/P7-X.Y.md`
- 필요 시 자산 README 업데이트
- 필요 시 `management/authoring/part-07-open-checklist.md`의 중심 주제 업데이트

따라서 연습별 Section 분리는 원고 품질에는 좋지만 관리 비용이 있다. 짧은 선택 과제까지 모두 Section으로 만들면 관리 비용이 학습 효과보다 커질 수 있다.

## 현재 동작 단위 센서 소재에 대한 적용

최근 작성한 `action-unit-sensor-part-07-material-report.md` 기준으로 보면 다음처럼 판단할 수 있다.

| 소재 | 분리 판단 | 이유 |
| --- | --- | --- |
| 표본 수와 반복성으로 경고 등급 나누기 | 별도 Section 권장 | `P7-7.3`의 운영 분류보다 한 단계 더 구체적인 등급 설계 질문을 닫는다 |
| 같은 평균, 다른 패턴 비교 | 별도 Section 가능 | 표현 선택과 정보 손실을 독립적으로 확인할 수 있다 |
| 절대 시간축 vs 진행도축 비교 | 선택 과제 우선 | 시계열 정렬 설명이 길어질 수 있어 짧게 시작하는 편이 낫다 |
| 같은 원시 데이터로 문제 정의 다시 쓰기 | 회고 카드 우선 | Part 7 전체의 시작/마무리 질문으로 쓰기 좋지만 독립 코드가 꼭 필요하지 않다 |
| 모델링 사다리로 같은 질문 다시 쓰기 | 마무리 보강 우선 | 범위가 커져 별도 Section으로 만들면 Part 4/6 내용을 반복할 수 있다 |

## 권장 운영 원칙

앞으로 Part 7 연습을 추가할 때는 다음 원칙을 적용한다.

1. 먼저 기존 Chapter 안에 들어갈 수 있는지 본다.
2. 하나의 연습이 하나의 중심 질문을 닫는지 확인한다.
3. 새 자산과 새 코드가 필요하면 별도 Section 후보로 올린다.
4. 단순 변형은 기존 Section의 `직접 바꿔 볼 것`에 남긴다.
5. Section을 만들기로 하면 목차, 메타데이터, 릴리즈노트를 같은 작업에서 처리한다.

## 결론

Part 7은 연습을 계속 추가할 계획이므로, 장기적으로는 연습별 Section 분리가 맞다. 다만 `연습 하나 = 무조건 Section 하나`가 아니라, `독립된 중심 질문과 실행 산출물이 있는 연습 = Section 하나`로 제한하는 편이 좋다.

가장 먼저 분리해 볼 후보는 `P7-7.4 경고 등급 설계 연습`이다. 이 후보는 기존 `P7-7.3 운영 점검 시뮬레이션`과 이어지지만, 표본 수, 반복성, 최근성으로 `watch/review/action` 등급을 설계한다는 별도 중심 질문이 분명하다.
