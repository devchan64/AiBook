# Part 6 Section 검토 메모

## 이 문서의 역할

이 문서는 `18-part-6-execution-draft.md`를 실제 Part 6 본문에 대조해 본 뒤, 어떤 Section에서 사례를 허용할지와 어디서 멈춰야 할지를 정리한 검토 메모다.

핵심 목적은 `프로젝트 예시 추가`보다 `프로젝트 산출물 구조에만 얹는 한계선`을 분명히 하는 데 있다.

## 전체 판단

현재 Part 6 본문은 `질문 -> 입력 -> baseline -> 결과 -> 회고` 흐름이 이미 강하다.

따라서 동작 단위 원천데이터 사례를 넣을 때는 다음 원칙을 지켜야 한다.

- 프로젝트 구조를 설명하는 자리에만 붙인다
- 도메인 사례가 프로젝트 일반론을 밀어내지 않게 한다
- 산출물 표와 짧은 리포트 문장 중심으로만 넣는다
- 실제 운영 판단 체계처럼 보이기 시작하면 중단한다

## Section별 판단

## P6-1.1 데이터 분석 미니 프로젝트 목표

### 현재 Section의 중심 질문

작은 표를 읽고 질문을 세우는 프로젝트는 어떻게 시작하는가.

### 현재 상태 판단

이 절은 동작 단위 원천데이터 사례와 비교적 잘 맞는다.

특히 `원시 로그를 받고 질문을 한 줄로 쓰는 구조`는 이 절에 자연스럽게 들어간다.

### 허용 가능한 삽입

- 프로젝트 질문 한 문장
- 작은 원시 로그 표
- 관찰 메모 예시

### 넣지 말아야 할 것

- 기준선 비교 표
- 긴 동작 단위 요약표
- 운영 해석 문장

### 결론

이 절은 `light` 또는 작게는 `medium`이 가능하다.

## P6-2.1 전통 머신러닝 예측 모델 목표

### 현재 Section의 중심 질문

예측 프로젝트를 baseline과 함께 어떻게 시작하는가.

### 현재 상태 판단

이 절은 baseline과 train/test 구조가 중심이므로, 원천데이터 사례를 강하게 넣기보다 `baseline을 비교 프레임으로 읽는 관점`만 짧게 붙이는 편이 맞다.

### 허용 가능한 삽입

- 기준선 비교라는 baseline 직관을 한 문단으로 연결

### 넣지 말아야 할 것

- 원시 로그 표
- 최근 구간 집계 표
- 복잡한 특징 설명

### 결론

이 절은 `light`만 허용한다.

## P6-3.1 이미지 분류 모델 목표

### 현재 Section의 중심 질문

이미지 입력 프로젝트는 무엇을 먼저 기록해야 하는가.

### 현재 상태 판단

이 절은 입력이 완전히 다르므로 동작 단위 원천데이터 사례를 넣을 이유가 크지 않다.

### 허용 가능한 삽입

- 없음에 가깝다

### 결론

이 절은 사례 비반영이 맞다.

## P6-4.1 텍스트 분류 모델 목표

### 현재 Section의 중심 질문

텍스트 프로젝트에서 문장, 토큰, 라벨을 어떻게 기록하는가.

### 현재 상태 판단

이 절도 입력 구조가 다르므로 직접 사례 반영 대상은 아니다.

다만 `산출물 구조`를 비교하는 메타 관점에서는 간접 참고만 가능하다.

### 결론

이 절은 사례 비반영이 맞다.

## P6-5.1 문서 기반 RAG 챗봇 목표

### 현재 Section의 중심 질문

질문, 검색 결과, 근거, 답변을 어떻게 분리해 기록하는가.

### 현재 상태 판단

이 절은 원천데이터 사례를 직접 넣을 곳은 아니지만, `기준선 비교 표 -> 3문장 설명` 흐름과 기록 철학이 잘 맞는다.

### 허용 가능한 삽입

- 직접 사례 대신, `입력 구조가 달라도 근거와 결과를 분리해 기록한다`는 짧은 연결 문장 정도

### 결론

이 절은 직접 사례 비반영, 간접 관점만 허용한다.
