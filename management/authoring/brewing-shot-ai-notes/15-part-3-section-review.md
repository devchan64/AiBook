# Part 3 Section 검토 메모

## 이 문서의 역할

이 문서는 `14-part-3-execution-draft.md`를 실제 Part 3 본문에 대조해 본 뒤, 어떤 Section에서 사례를 허용할지와 어디서 멈춰야 할지를 정리한 검토 메모다.

이 문서의 목적은 `삽입 초안`을 만드는 것이 아니라 `삽입 한계선`을 먼저 분명히 하는 데 있다.

## 전체 판단

현재 Part 3 본문은 이미 `문제 정의 -> 평가 -> 특징 -> 모델 선택 -> baseline -> 튜닝`의 흐름이 비교적 안정적으로 잡혀 있다.

따라서 동작 단위 원천데이터 사례를 넣을 때는 다음 원칙을 지켜야 한다.

- 기존 개념 문단을 밀어내지 않는다
- 새 사례 문단은 개념을 다시 말하는 수준을 넘지 않는다
- 표는 `새 개념 도입`보다 `기존 개념의 해석 보조` 역할에 머문다
- 사례가 도메인 설명으로 기울기 시작하면 바로 중단한다

## Section별 판단

## P3-6.1 평가 지표(metric)의 역할

### 현재 Section의 중심 질문

평가 지표는 무엇이며, 왜 하나가 아닌가.

### 현재 상태 판단

이 절은 이미 혼동 행렬, precision, recall, 오류 비용, 사회적 장면까지 충분히 촘촘하게 깔려 있다.

여기에 새 사례를 길게 넣으면 `평가 지표의 일반 개념`보다 `특정 운영 사례의 해석`이 앞설 위험이 크다.

### 허용 가능한 삽입

- 아주 짧은 한 문단
- `동작 수가 적은 경고 장면` 같은 한 줄 예시

### 넣지 말아야 할 것

- 기준선 비교 표
- 최근 구간 집계 표
- 긴 운영 라벨 설명

### 결론

이 절은 `light`만 허용한다.

## P3-6.2 문제 유형별 평가 기준

### 현재 Section의 중심 질문

문제 유형이 바뀌면 평가 기준이 왜 달라지는가.

### 현재 상태 판단

이 절은 분류, 회귀, 군집화의 범용 비교가 중심이다.

동작 단위 원천데이터 사례를 강하게 넣으면 분류/회귀/군집화 전체 균형이 깨질 수 있다.

### 허용 가능한 삽입

- `운영 경고 분류`를 분류 예시의 한 행으로 넣는 정도
- `연속값 요약`을 회귀형 출력 비유로 짧게 언급하는 정도

### 넣지 말아야 할 것

- 특징 후보 표
- 기준선과 반복성 설명
- 원시 로그 구조 설명

### 결론

이 절도 `light`만 허용한다.

## P3-7.1 특징 선택(feature selection)

### 현재 Section의 중심 질문

좋은 특징을 어떻게 고를 것인가.

### 현재 상태 판단

이 절은 동작 단위 원천데이터 사례와 가장 자연스럽게 맞물리는 Section 중 하나다.

특히 `구간 평균`, `기울기`, `변동성`, `패턴 토큰` 같은 특징은 이 절의 질문을 바로 선명하게 해 줄 수 있다.

### 허용 가능한 삽입

- 특징 후보 표
- 원시 로그 -> 특징 요약의 짧은 연결 문단
- 신호/잡음/중복 관점에서 특징 후보를 읽는 한 문단

### 넣지 말아야 할 것

- 긴 토큰화 체계 설명
- 순차 모델과의 상세 비교
- 실제 도메인 고유 센서 설명

### 결론

이 절은 `medium`까지 허용 가능하다.

## P3-8.1 모델 선택(model selection)

### 현재 Section의 중심 질문

모델 선택은 무엇을 고르는 일인가.

### 현재 상태 판단

이 절은 후보군을 세우는 사고가 핵심이므로, 사례를 넣더라도 모델 사다리 표 하나로 충분하다.

지금 본문은 이미 문제 유형, 제약, 후보군이라는 큰 지형도를 잘 설명하고 있다.

### 허용 가능한 삽입

- 규칙 기반 -> 기준선 비교 -> 특징 기반 모델 -> 순차 모델의 4행 비교표
- 한 문단짜리 `문제 구조가 같아도 후보군이 달라진다` 설명

### 넣지 말아야 할 것

- 성능 숫자 예시
- 자세한 운영 흐름
- 표본 수와 반복성 이야기

### 결론

이 절은 `light` 또는 작게는 `medium`이 가능하다.

## P3-8.2 기준 모델(baseline)

### 현재 Section의 중심 질문

baseline은 왜 먼저 필요한가.

### 현재 상태 판단

이 절은 동작 단위 원천데이터 사례를 가장 강하게 회수할 수 있는 Section이다.

특히 `비슷한 조건의 평소 상태와 최근 상태 비교`는 baseline을 알고리즘이 아니라 비교 프레임으로 읽게 만들어 준다.

### 허용 가능한 삽입

- 기준선 비교 표
- baseline을 `평소 상태 비교 프레임`으로 읽는 짧은 문단
- dummy baseline과 다른 종류의 baseline이 있다는 보조 설명

### 넣지 말아야 할 것

- 너무 긴 원시 로그 설명
- 실제 임계값
- 구체 도메인 원인 진단

### 결론

이 절은 `medium`까지 허용 가능하며, Part 3에서 가장 우선 검토할 Section이다.

## P3-9.2 튜닝(tuning)과 검증 비용

### 현재 Section의 중심 질문

좋아 보이는 설정값을 실제로 어떻게 고를 것인가.

### 현재 상태 판단

이 절은 검증 절차와 비용 구조가 중심이다.

사례를 너무 많이 넣으면 `튜닝의 일반 원리`가 `특정 운영 사례의 threshold 조정`처럼 오해될 수 있다.

### 허용 가능한 삽입

- 같은 차이값이라도 validation에서 반복 확인이 필요하다는 한 문장
- `표본 수가 적은 장면에서는 작은 개선을 과장하면 안 된다`는 정도의 짧은 해설

### 넣지 말아야 할 것

- 기준선 비교 표
- 특징 후보 표
- 운영 라벨 상세 설명

### 결론

이 절은 `light`만 허용한다.
