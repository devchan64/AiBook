# 추출 센서 노트를 AiBook 본문 업데이트에 연결하기 위한 준비 노트

## 이 문서의 목적

이 문서는 `management/authoring/brewing-shot-ai-notes/` 아래에 만든 노트 묶음을 AiBook 본문 업데이트에 바로 연결할 수 있도록 준비 상태를 정리한다.

핵심 목표는 다음 세 가지다.

- 추출 센서 사례를 책에 넣을 때 기존 목차를 깨지 않고 분산 배치할 기준을 만든다.
- 10개 노트 각각이 어느 Part, 어느 Section 후보에 연결되는지 정리한다.
- 본문 편집을 시작하기 전에 필요한 자산, 주의점, 편집 순서를 미리 고정한다.

이 문서는 `새 Part를 만들기 위한 문서`가 아니다.

오히려 현재 책 구조를 유지한 채, 추출 사례를 `반복 등장하는 실전형 사례`로 삽입하기 위한 관리 문서다.

## 현재 판단

추출 센서 사례는 AiBook 본문에 흡수할 가치가 충분하다.

다만 다음 방식으로 쓰는 것은 피해야 한다.

- 추출 사례만을 위한 별도 Module 추가
- 기존 본문을 대량 교체하는 구조 개편
- 도메인 세부가 개념 설명을 압도하는 서술
- 실제 운영 문서나 내부 구현을 연상시키는 구체 표현

반대로 다음 방식은 적합하다.

- Part 1에서 문제 정의 사례로 짧게 도입
- Part 2에서 표, 시계열, 집계, 시각화 실습 재료로 활용
- Part 3에서 기준선, 특징 공학, 평가, false alarm의 반복 사례로 활용
- Part 4와 Part 5에서 필요한 만큼만 순차 데이터, 토큰화, 설명 가능성 연결 사례로 활용
- Part 6에서 공개형 프로젝트 후보로 회수

즉, 이 사례는 `한 Chapter의 주제`가 아니라 `여러 Part를 가로지르는 반복 사례`로 쓰는 편이 맞다.

## 전제

### 전제 1. 본문 언어는 한국어다

추출 사례도 본문에서는 한국어로 설명하되, 필요한 핵심 기술 용어만 영어를 병기한다.

### 전제 2. 초심자 기준을 유지한다

추출 장비를 모르는 독자도 따라올 수 있어야 한다.

따라서 커피 추출 자체보다 `센서 로그`, `사건 단위`, `구간 요약`, `기준선 비교` 같은 일반 개념으로 설명한다.

### 전제 3. 기존 목차 구조를 우선한다

새 Chapter를 추가하기보다, 현재 Section의 중심 질문에 직접 필요한 경우만 사례 문단, 표, 실습, 보충학습으로 녹인다.

### 전제 4. 공개 안전 원칙을 유지한다

본문과 관리 자료 모두 다음 항목은 직접 반영하지 않는다.

- 구현 전용 경로 표기
- 운영 규칙 세부
- 제품 내부 명칭
- 구현 전용 인터페이스 이름
- 재현 가능한 실제 장비 식별자

## 책 전체 배치 원칙

### 원칙 1. 사례는 Part마다 질문을 달리한다

같은 추출 사례라도 Part마다 다음처럼 역할을 달리한다.

- Part 1: 현실 문제를 모델 문제로 바꾸는 예시
- Part 2: 표와 시계열을 다루는 실습 재료
- Part 3: 기준선, 특징, 평가의 사례
- Part 4: 순차 데이터와 표현 학습의 사례
- Part 5: 토큰 문맥 구분과 설명 리포트의 사례
- Part 6: 공개형 프로젝트 사례

### 원칙 2. 사례가 본문 주제를 먹어버리면 안 된다

Section의 중심 질문은 언제나 현재 Section의 제목이 담당한다.

추출 사례는 그 질문을 더 선명하게 만드는 도구여야 한다.

### 원칙 3. 새 설명보다 기존 설명 보강을 우선한다

추출 사례를 넣기 위해 기존 본문 흐름을 갈아엎지 않는다.

우선은 현재 Section 안에 아래 중 하나를 추가하는 방식으로 본다.

- 짧은 사례 문단
- 작은 표
- 간단한 시계열 예시
- Python 예제
- 보충학습 후보 메모

### 원칙 4. 현재 Section 범위를 넘기면 보충학습으로 분리한다

예를 들어 다음은 현재 Section 안에 짧게 넣기보다 보충학습 후보로 보는 편이 맞다.

- 센서 시계열 정렬 알고리즘 세부
- 길이가 다른 시계열 비교의 수학적 세부
- 복잡한 변화 추세 지표
- 고급 이상 탐지 알고리즘

## 본문 편집 전에 먼저 준비할 것

### 1. 공개형 합성 데이터셋 최소 세트

Part 2와 Part 6 업데이트를 하려면 먼저 다음 정도의 공개형 자산이 필요하다.

- 작은 원시 로그 CSV
- 샷 요약 CSV
- 버킷 요약 CSV

이 자산은 실제 로그를 반영하지 않아야 하며, 다음 질문에 답할 수 있어야 한다.

- 샷 하나는 무엇인가
- 샷 여러 개를 어떻게 묶는가
- 기준선과 최근 버킷은 어떻게 비교되는가

### 2. 작은 Python 예제 세트

Part 2와 Part 6에서 바로 재사용할 수 있는 예제가 필요하다.

- `groupby event_id`
- 구간 평균 계산
- slope 계산
- 최근 버킷 vs 기준선 비교
- 설명 문장 2~3개 생성

### 3. 시각화 자산 후보

최소한 다음 도식 또는 차트가 있으면 편집이 쉬워진다.

- 시간축 vs 진행도축 비교
- 평균은 같지만 패턴은 다른 두 샷
- 샷 -> 버킷 -> 기준선 비교 흐름도
- exact token / shape / density 비교표

## 새 본문을 만들지 말고 기존 Section을 보강하는 이유

추출 사례는 강하지만, 별도 장을 만들면 다음 문제가 생길 수 있다.

- 도메인 사례가 책의 개념 구조를 대신해 버린다
- 초심자가 도메인 지식이 부족하다고 느끼기 쉽다
- Part 간 반복 사례가 아니라 고립된 응용편처럼 읽힌다

반대로 기존 Section을 보강하면 다음 장점이 있다.

- 현재 목차와 충돌이 적다
- 사례를 현재 질문에 맞게 얕고 깊게 조절할 수 있다
- 독자가 같은 사례를 여러 개념과 연결해 기억하게 된다

## 편집 중 계속 확인할 체크리스트

- 이 사례가 현재 Section 질문에 직접 답하는가
- 사례 문단이 기존 개념 설명보다 길어지지 않는가
- 센서 도메인을 모르는 독자도 따라올 수 있는가
- 내부 운영 규칙처럼 보이는 표현이 남지 않았는가
- 같은 문장을 다른 Part에 반복하고 있지 않은가
- 필요한 경우 `보충학습`으로 분리할 후보를 남겼는가

## 새 보충학습 후보

본문에 바로 넣기보다 보충학습 후보로 남기기 좋은 항목은 다음과 같다.

- 길이가 다른 시계열을 비교하는 기본 전략
- 시계열 segmentation을 처음 읽는 법
- 변화 추세를 평균 변화와 구간 구조 변화로 구분하는 법
- false alarm을 운영 비용 관점에서 읽는 법
- 설명 가능한 특징과 표현 학습의 차이

이 후보들은 현재 본문에 꼭 필요한지 판단한 뒤 추가한다.

## 이 문서의 결론

추출 센서 노트 10개는 AiBook 본문 업데이트에 충분히 쓸 수 있다.

다만 그 사용 방식은 `별도 추출 장을 새로 만든다`가 아니라, `기존 목차 안에서 반복 사례, 실습 자산, 프로젝트 재료로 분산 배치한다`가 되어야 한다.

- 공개형 합성 데이터와 작은 예제를 먼저 준비한다.
- 내부 운영 세부가 아니라 일반화된 센서 데이터 관점으로 설명한다.
