# 규칙, 통계, 머신러닝, 딥러닝으로 올라가는 모델링 사다리

## 이 노트의 목적

이 노트는 1회 동작 센서 시계열 사례를 사용해 AI 접근법의 층위를 비교하기 위한 것이다.

이 노트에서는 특정 비즈니스 도메인 이름을 전면에 두지 않고, 기본적으로 `동작 단위 원시 로그`, `동작 단위 요약`, `기준선 비교`, `특징 기반 모델`이라는 일반화 문구를 사용한다.

같은 문제를 두고도 여러 접근이 가능하다는 점을 보여 주면, 초심자는 `AI = 무조건 딥러닝`이라는 오해에서 벗어나기 쉽다.

## 핵심 문장

`좋은 문제에서는 가장 복잡한 모델부터 고르는 것이 아니라, 설명 가능한 가장 작은 접근부터 올라가는 것이 안전하다.`

## 왜 이 사례가 좋은가

이 동작 로그 사례는 다음 사다리를 한 흐름으로 보여 줄 수 있다.

1. 규칙 기반 접근
2. 통계 기반 기준선 비교
3. 특징 기반 머신러닝
4. 시계열 딥러닝
5. 운영 보조용 LLM 설명 생성

이렇게 단계별로 올라가면 독자는 `접근법 선택` 자체가 중요한 설계 문제라는 점을 배우게 된다.

## 1단계. 규칙 기반 접근

예:

- 평균 압력이 특정 범위를 벗어나면 경고
- 후반 유량 하강률이 임계값보다 크면 주의

장점:

- 구현이 쉽다
- 설명이 쉽다
- 데이터가 거의 없어도 시작 가능하다

한계:

- 조건 묶음이나 장비 범주별 차이를 잘 흡수하지 못할 수 있다
- 여러 변수의 조합 패턴을 놓치기 쉽다

책에서는 Part 1의 규칙 기반 시스템 설명과 सीधे 연결된다.

## 2단계. 통계 기반 기준선 비교

예:

- 최근 구간 평균이 과거 기준선보다 얼마나 벗어났는가
- 패턴 토큰 분포가 평소와 얼마나 달라졌는가

장점:

- 절대 임계값보다 현실적이다
- 라벨 부족 상황에 강하다
- 설명 가능성이 높다

한계:

- 원인 분류까지는 어렵다
- 복잡한 비선형 패턴을 놓칠 수 있다

이 단계는 Part 2 통계와 Part 3 모델 평가 사이를 이어 준다.

## 3단계. 특징 기반 머신러닝

예:

- 동작 단위 요약 특징을 입력으로 넣어 `검토 필요 여부`를 예측
- 이상 패턴을 군집화(clustering)로 나누기

입력 특징 예:

- 세그먼트별 평균
- 세그먼트별 slope
- 대표 토큰열
- 변동성
- 표본 품질 지표

장점:

- 사람이 설계한 특징을 활용할 수 있다
- 트리 모델, 선형 모델로도 꽤 강한 기준 모델을 만들 수 있다

한계:

- 특징 설계 품질에 크게 의존한다
- 시계열의 미세 구조를 모두 담기 어렵다

이 단계는 Part 3 본류의 좋은 프로젝트 사례가 된다.

## 4단계. 시계열 딥러닝

예:

- 원시 시계열 또는 고정 길이 시퀀스를 입력으로 넣는 RNN/CNN/Transformer 계열

장점:

- 사람이 손으로 만들기 어려운 패턴을 잡을 가능성이 있다
- 다변수 시계열의 복잡한 상호작용을 표현할 수 있다

한계:

- 데이터와 검증이 더 많이 필요하다
- 설명 가능성이 떨어질 수 있다
- 운영 해석과 연결이 더 어려울 수 있다

책에서는 바로 이 한계를 드러내는 것이 중요하다.

즉 `딥러닝이 더 강력할 수 있지만 항상 더 좋은 첫 선택은 아니다`라는 관점을 보여 준다.

## 5단계. 설명 생성 보조

이 단계는 예측 모델 자체보다 운영 지원에 가깝다.

예:

- 구조화된 지표를 입력으로 받아 사람이 읽을 짧은 요약 문장을 생성

예시 문장:

- 최근 1시간 동안 중반 유량 저하가 반복되어 검토가 필요합니다.

이 단계는 LLM을 `판단의 주체`가 아니라 `설명 초안 생성기`로 두는 안전한 활용법을 보여 준다.

## 이 사다리가 책에서 중요한 이유

많은 입문서는 알고리즘 이름을 나열하지만, 왜 어떤 문제에서 어떤 층위의 접근을 먼저 고려하는지는 약하다.

이 동작 로그 사례는 그 빈틈을 메울 수 있다.

특히 다음 질문이 좋다.

- 규칙으로 충분한가
- 기준선 비교만으로도 충분한가
- 특징 기반 모델을 만들면 무엇이 달라지는가
- 원시 시계열 딥러닝은 언제 검토할 만한가

## 본문 사례 후보

### 사례 1. 규칙 기반 경고

가장 단순한 임계값 경고를 만든다.

질문:

- 왜 쉽게 시작할 수 있는가
- 왜 특정 조건 변화에 취약한가

### 사례 2. 기준선 비교 경고

같은 임계값 대신 최근 평균과 기준선 차이를 본다.

질문:

- 왜 더 현실적인가

### 사례 3. 트리 모델 기준 모델

세그먼트 특징을 넣어 간단한 분류기를 만든다.

질문:

- 어떤 특징이 중요하게 잡히는가
- 설명 가능성은 어느 정도 유지되는가

### 사례 4. 원시 시계열 모델

가능성만 소개하되, 데이터 요구량과 검증 난도를 같이 적는다.

`문제와 데이터, 라벨 품질, 설명 가능성 요구, 운영 비용에 따라 적절한 모델링 층위가 달라진다.`

이 흐름이면 초심자가 `모델 교체`보다 `문제 구조 개선`을 먼저 배우게 된다.

## 이 노트의 현재 결론

추출 센서 사례는 AI 접근법의 사다리를 한 번에 보여 주는 데 탁월하다.

이 주제를 넣으면 책이 알고리즘 나열형이 아니라 모델 선택형 교재에 더 가까워진다.

## 왜 `모델 선택`보다 `모델링 사다리`가 더 좋은 표현인가

초심자는 모델 선택을 종종 `어떤 알고리즘 이름을 고를까` 정도로 이해한다.

하지만 이 동작 로그 사례에서 더 중요한 것은 `문제를 어떤 층위의 접근으로 다룰까`다.

그래서 `모델링 사다리`라는 표현이 더 낫다.

이 표현은 다음을 한 번에 담는다.

- 가장 단순한 규칙부터 시작할 수 있다
- 데이터와 라벨이 늘어나면 더 복잡한 모델로 올라갈 수 있다
- 항상 꼭 가장 위층으로 갈 필요는 없다

즉 이 노트의 핵심은 알고리즘 비교보다 `접근의 층위 비교`다.

## 왜 이 동작 로그 사례가 이 사다리를 잘 보여 주는가

이 동작 로그 사례에는 다음 조건이 함께 있다.

- 라벨이 부족할 수 있다
- 설명 가능성이 중요하다
- 운영자가 바로 행동할 수 있어야 한다
- 원시 시계열은 풍부하지만 복잡하다

이 조건 조합은 `처음부터 딥러닝`보다 `작고 설명 가능한 단계에서 시작해 점진적으로 확장`하는 사다리를 자연스럽게 만든다.

## 사다리의 각 층위가 답하는 질문은 서로 다르다

### 규칙 기반

- 간단한 이상을 빨리 찾을 수 있는가

### 기준선 비교

- 평소와 비교해 최근 상태가 달라졌는가

### 특징 기반 머신러닝

- 여러 특징 조합으로 검토 필요 여부를 더 잘 가를 수 있는가

### 딥러닝

- 사람이 설계하지 못한 복잡한 패턴을 더 잘 포착할 수 있는가

### LLM 설명 보조

- 구조화된 결과를 사람이 읽기 쉬운 문장으로 바꿀 수 있는가

즉 각 층위는 서로 대체만 하는 것이 아니라, 다른 질문을 더 잘 푸는 경우도 있다.

## 규칙 기반 접근을 과소평가하면 안 되는 이유

입문 독자는 규칙 기반을 종종 `옛날 방식`처럼 본다.

하지만 이 동작 로그 사례에서는 규칙 기반이 매우 좋은 첫 단계다.

이유:

- 센서와 도메인 직관이 반영되기 쉽다
- 운영자가 즉시 검증할 수 있다
- 기준 모델(baseline)로 삼기 좋다

예:

- 후반 하강률이 너무 크면 경고
- 압력 추종 오차가 일정 이상이면 점검 후보

규칙 기반은 단순하지만, 바로 이 단순함이 초기 검증에서 강점이다.

## 기준선 비교는 왜 별도 층위로 구분할 만한가

겉보기에는 규칙처럼 보일 수도 있다.

하지만 절대 임계값이 아니라 `평소 대비 차이`를 본다는 점에서 중요한 전환이 있다.

즉 기준선 비교는 규칙 기반과 학습 기반 사이의 중간 지대다.

이 층위는 다음 장점이 있다.

- 라벨 부족 상황에 강하다
- 조건별 상대 차이를 반영한다
- 설명 문장이 잘 나온다

이 동작 로그 사례에서는 이 층위만으로도 상당히 많은 운영 질문을 다룰 수 있다.

## 특징 기반 머신러닝은 무엇이 새로 달라지는가

규칙이나 기준선 비교에서는 사람이 중요 변수 몇 개를 직접 본다.

특징 기반 머신러닝으로 넘어가면 다음이 달라진다.

- 여러 특징 조합을 함께 고려한다
- 경계(boundary)를 사람이 직접 다 쓰지 않아도 된다
- 중요 특징을 다시 분석할 수 있다

예:

- 중반 유량이 조금 낮고
- 후반 하강률이 크며
- 압력 추종 오차도 조금 크면
- 종합적으로 `review`로 보자

이 조합 판단은 트리 모델이나 선형 모델에서 자연스럽게 다룰 수 있다.

## 딥러닝으로 올라갈 때 생기는 진짜 장벽

이 동작 로그 사례는 딥러닝의 가능성과 한계를 동시에 보여 주는 좋은 사례다.

### 가능성

- 원시 신호를 직접 다룰 수 있다
- 세그먼트 규칙에 덜 의존할 수 있다
- 복잡한 시계열 상호작용을 포착할 가능성이 있다

### 장벽

- 라벨이 충분한가
- 검증 세트가 믿을 만한가
- 설명 가능한가
- 운영자가 받아들일 수 있는가

즉 딥러닝은 기술적으로 매력적이지만, 항상 가장 먼저 선택할 단계는 아니다.

## LLM은 왜 맨 위층이 아니라 옆층처럼 다뤄야 하는가

이 동작 로그 사례에서 LLM은 센서 패턴을 직접 읽는 핵심 예측기가 아니라, 결과 설명과 문서화 보조에 더 어울린다.

예:

- 구조화된 결과를 3줄 요약으로 바꾸기
- 운영자가 읽을 점검 메모 초안 만들기
- 최근 구간과 기준선 차이 요약하기

즉 LLM은 `판단 모델`이라기보다 `설명 인터페이스`에 가깝게 쓰는 편이 안전하다.

이 점은 책에서 매우 중요하다.

왜냐하면 모든 문제를 LLM으로 풀려는 오해를 줄여 주기 때문이다.

## 장난감 표: 층위별 요구 조건 비교

| 층위 | 라벨 필요성 | 설명 가능성 | 구현 난도 | 운영 검증 난도 |
| --- | --- | --- | --- | --- |
| 규칙 기반 | 낮음 | 매우 높음 | 낮음 | 낮음 |
| 기준선 비교 | 낮음 | 높음 | 낮음~중간 | 낮음 |
| 특징 기반 ML | 중간 | 중간~높음 | 중간 | 중간 |
| 딥러닝 | 높음 | 낮음~중간 | 높음 | 높음 |
| LLM 설명 보조 | 예측 라벨보다 구조화 입력 필요 | 문장 설명은 높음 | 중간 | 중간 |

이 표는 독자에게 `왜 항상 위층으로 갈 필요가 없는가`를 명확히 보여 준다.

## 장난감 예시: 같은 문제를 층위별로 다시 쓰기

문제:

`최근 동작 상태가 평소와 달라졌는가`

### 규칙 기반 버전

- 후반 하강률이 0.25보다 크면 경고

### 기준선 비교 버전

- 최근 구간의 후반 하강률이 기준선보다 0.10 이상 크면 경고

### 특징 기반 ML 버전

- 중간 구간 평균, 후반 하강률, 추적 오차, 변동성, 사건 수를 입력으로 `review_needed` 예측

### 딥러닝 버전

- 원시 시계열 입력으로 상태 वर्ग을 예측

### LLM 보조 버전

- 위 결과를 사람이 읽을 점검 문장으로 요약

이 예시는 층위 차이를 한눈에 보여 준다.

## 기준 모델의 교육적 위치

Part 3에서 기준 모델은 성능 비교의 출발점으로 다룰 수 있다.

이 동작 로그 사례에서는 기준 모델 후보가 매우 분명하다.

- 단순 임계값 규칙
- 기준선 차이 규칙

이 점이 좋다.

초심자가 `baseline도 모델인가?`라는 질문에 예/아니오가 아니라, `작지만 분명한 판단 규칙도 기준 모델 역할을 할 수 있다`는 감각을 얻을 수 있다.

## 설명 가능성과 성능의 trade-off를 어떻게 다룰 것인가

이 주제는 과장하지 않되 정직하게 써야 한다.

### 설명 가능성이 높은 층위

- 규칙 기반
- 기준선 비교
- 일부 트리 모델

### 성능 확장 가능성이 큰 층위

- 복잡한 특징 기반 모델
- 딥러닝

하지만 이 둘은 단순히 반대말이 아니다.

좋은 실전 설계는 종종:

- 작은 설명 가능한 기준 모델을 먼저 만들고
- 더 복잡한 모델이 실제로 얼마나 더 나아지는지 비교하는 방식

으로 간다.

이 과정 자체가 책에서 강조할 가치가 있다.

## 코드 초안: 가장 단순한 규칙 기반 경고

문제 상황: 후반 하강률과 압력 오차만으로 가장 작은 경고 규칙을 만들고 싶다.

입력:

- 동작 단위 요약 표

기대 출력:

- `review_needed`

확인할 개념:

- 기준 모델은 단순한 규칙으로도 시작할 수 있다

```python
events = [
    {"event_id": "s1", "late_drop_rate": 0.18, "tracking_error_mean": 0.21},
    {"event_id": "s2", "late_drop_rate": 0.31, "tracking_error_mean": 0.36},
    {"event_id": "s3", "late_drop_rate": 0.12, "tracking_error_mean": 0.19},
]

for event in events:
    review_needed = (
        event["late_drop_rate"] > 0.25 or event["tracking_error_mean"] > 0.30
    )
    print(event["event_id"], "review" if review_needed else "normal")
```

이 예제는 지나치게 단순하지만 기준 모델 설명에는 오히려 좋다.

## 코드 초안: 특징 기반 모델로 다시 쓰기 위한 입력 표

문제 상황: 규칙 기반에서 쓰던 값을 특징 표로 바꿔 간단한 모델 실험 준비를 하고 싶다.

입력 열 예:

- `mid_segment_mean`
- `late_drop_rate`
- `tracking_error_mean`
- `pattern_diversity`
- `event_count_context`

확인할 개념:

- 규칙 기반에서 보던 값들이 ML 입력 특징으로 자연스럽게 넘어갈 수 있다

이 단계는 코드보다 표 설계 설명이 더 중요할 수 있다.

## 본문용 짧은 삽입 문단 초안

### 초안 A

동작 단위 센서 시계열 사례가 좋은 이유는 하나의 정답 모델을 강요하지 않기 때문입니다. 가장 단순한 규칙 기반 경고에서 시작해, 평소 대비 차이를 보는 기준선 비교로 올라가고, 필요하면 여러 특징을 함께 쓰는 머신러닝으로 확장할 수 있습니다. 즉 모델 선택은 알고리즘 이름 고르기가 아니라 문제에 맞는 층위를 고르는 일에 더 가깝습니다.

### 초안 B

이 과정에서 중요한 것은 항상 더 복잡한 모델로 올라가는 것이 아닙니다. 라벨이 적고 설명 가능성이 중요하다면 작은 규칙 모델이나 기준선 비교가 오히려 더 실용적일 수 있습니다. 반대로 충분한 데이터와 검증 체계가 있다면 더 복잡한 표현 학습도 검토할 수 있습니다.

## 다른 도메인과의 평행 비교

| 도메인 | 작은 기준 모델 | 중간 층위 | 큰 모델 |
| --- | --- | --- | --- |
| 추출 센서 | 임계값 경고 | 기준선 차이, 특징 기반 ML | 시계열 딥러닝 |
| 서버 모니터링 | CPU 90% 초과 경고 | 최근 5분 vs 기준선 비교 | 다변수 이상 탐지 |
| 검색 품질 | CTR 급락 규칙 | 질의군별 기준선 비교 | 랭킹 품질 예측 모델 |
| LLM 운영 | timeout 비율 규칙 | 최근 평가점수 변화 추세 비교 | 실패 유형 분류 모델 |

이 표는 이 동작 로그 사례가 특정 산업 예외가 아니라 일반 운영 문제의 축소판임을 보여 준다.

## 반론과 응답

### 반론 1

`작은 모델부터 시작하면 너무 느리지 않나?`

응답:

작은 모델은 검증이 빠르고 실패 원인을 읽기 쉽다. 문제 정의가 맞는지 확인하기 전에는 오히려 더 빠른 길이 될 수 있다.

### 반론 2

`딥러닝이 더 강력하면 처음부터 그걸 하면 되지 않나?`

응답:

### 반론 3

`LLM이 설명도 하고 분류도 하면 한 번에 끝나는 것 아닌가?`

응답:

가능한 부분도 있겠지만, 센서 구조 해석과 운영 경고는 먼저 구조화된 비교가 있어야 한다. LLM은 그 결과를 설명하는 보조 층으로 둘 때 더 안전하다.

## 특징 기반 모델에서 무엇을 목표 변수로 둘 수 있는가

특징 기반 ML은 입력 설계만이 아니라 목표 변수 설계도 중요하다.

가능한 목표 변수 예:

- `review_needed`
- `priority_level`
- `quality_risk`
- `repeat_check_needed`

즉 이 동작 로그 사례는 단순 0/1 분류보다 순위화(ranking)나 우선순위화에도 잘 어울린다.

## 트리 모델이 특히 잘 맞는 이유

입문 교재에서 트리 모델은 설명하기 좋고, 이 사례와도 잘 맞는다.

이유:

- 조건 분기 구조가 직관적이다
- 특징 중요도 해석이 가능하다
- 비선형 조합을 어느 정도 잡는다
- 작은 데이터에서도 baseline보다 나아질 수 있다

즉 Part 3의 결정트리나 앙상블 장에 이 사례를 붙이기 좋다.

## 선형 모델은 왜 여전히 가치가 있는가

초심자는 선형 모델을 너무 약하게 볼 수 있다.

하지만 이 동작 로그 사례에서는 다음 이유로 가치가 있다.

- 방향성과 가중치 해석이 쉽다
- 작은 데이터에서 과적합을 덜 일으킬 수 있다
- baseline으로 좋다

즉 `작고 해석 가능한 모델`을 무시하지 않는 태도를 심어 줄 수 있다.

## 딥러닝을 검토할 만한 시점

다음 조건이 어느 정도 갖춰질 때 검토 가치가 커진다.

- 원시 시계열이 충분히 많다
- 라벨이 비교적 안정적이다
- 세그먼트 특징만으로는 놓치는 패턴이 있다
- 검증 체계가 준비되어 있다

이 조건이 없으면 딥러닝은 가능성보다 비용이 더 커질 수 있다.

## 원시 시계열 모델의 장점과 질문

원시 시계열 모델은 다음을 기대하게 만든다.

- 사람이 고른 세그먼트 기준을 덜 강요한다
- 미세한 파형 관계를 더 잘 잡을 수 있다

하지만 동시에 질문도 커진다.

- 길이가 다른 시퀀스를 어떻게 넣을 것인가
- 결측과 노이즈를 어떻게 처리할 것인가
- 설명은 어떻게 붙일 것인가

즉 Part 4에서 이 사례를 언급할 때는 가능성과 함께 전처리 부담도 같이 적는 것이 좋다.

## 설명 보조로서 LLM의 안전한 위치를 더 구체화

LLM을 이 동작 로그 사례에 붙인다면 다음 정도가 안전하다.

- 최신 최근 구간과 기준선 차이 요약
- 경고 후보를 사람이 읽기 쉬운 문장으로 정리
- 여러 지표를 한 문단 메모로 묶기

반대로 조심할 것은 다음이다.

- 원시 센서 로그만 넣고 원인 진단을 확정하게 하기
- 근거 없이 부품 이상 종류를 단정하게 하기

즉 LLM은 구조화된 입력 위에서 보조 설명을 하는 편이 맞다.

## 본문용 더 짧은 문장 후보

- 가장 복잡한 모델이 항상 가장 좋은 첫걸음은 아닙니다.
- 작은 기준 모델은 성능보다 해석 기준을 먼저 만들어 줍니다.
- 큰 모델로 올라갈수록 검증과 설명 비용도 함께 커집니다.
- LLM은 센서 판단의 주체보다 설명 보조 층으로 둘 때 더 안전합니다.

## 초심자 FAQ

### Q1. 기준 모델(baseline model)을 꼭 만들어야 하나요?

A. 꼭은 아니지만, 만들면 큰 모델이 실제로 얼마나 나아졌는지 비교하기 쉬워진다. 또한 문제 정의 자체가 맞는지도 빨리 검증할 수 있다.

### Q2. 라벨이 적으면 ML을 포기해야 하나요?

A. 아니다. 기준선 비교, 이상 탐지, 군집화, 규칙 기반 모델 등 먼저 할 수 있는 일이 많다.

### Q3. 규칙 기반이면 AI가 아닌가요?

A. 이 책에서는 AI 전체 지형 속에서 규칙 기반 접근도 중요한 출발점으로 다룬다. 특히 학습 기반 접근과의 차이를 이해하는 데 필요하다.

## 층위별로 실패가 어떻게 다르게 보이는가

같은 운영 문제라도 실패 양상은 층위마다 다르다.

### 규칙 기반 실패

- 임계값이 너무 빡빡해 경고가 과도함
- 조건이 너무 단순해 중요한 조합을 놓침

### 기준선 비교 실패

- 기준선 기간이 잘못돼 평소를 잘못 정의함
- 집단이 섞여 gap 자체가 왜곡됨

### 특징 기반 ML 실패

- 특징 표가 문제를 충분히 표현하지 못함
- 라벨이 불안정해 모델이 애매한 경계를 배움

### 딥러닝 실패

- 데이터는 많아 보여도 실제 유효 라벨이 부족함
- 해석이 어려워 운영자가 수용하지 못함

이렇게 보면 `모델이 나쁘다`는 한 문장보다, `어느 층위에서 어떤 실패가 나오는가`를 적는 편이 훨씬 생산적이다.

## 층위별 산출물 비교

## 언제 사다리의 다음 층위로 올라갈 것인가

이 질문은 실무적으로 중요하다.

다음으로 올라갈 이유가 분명해야 한다.

### 규칙 기반에서 기준선 비교로

- 절대 임계값이 조건 그룹 차이를 못 흡수할 때
- 평소 대비 변화가 더 중요한 질문일 때

### 기준선 비교에서 특징 기반 ML로

- 여러 특징 조합을 함께 봐야 할 때
- 사람 규칙만으로 경계가 너무 복잡해질 때

### 특징 기반 ML에서 딥러닝으로

- 원시 시계열의 미세 구조를 잃는다고 판단될 때
- 데이터와 검증 체계가 충분할 때

즉 더 높은 층위는 `멋져 보여서`가 아니라, 아래 층위의 한계가 분명해졌을 때 선택해야 한다.

## 올라가지 않는 결정도 좋은 결정일 수 있다

교재에서는 이 점도 분명히 적는 편이 좋다.

어떤 문제는:

- 규칙 기반으로 충분하고
- 기준선 비교만으로 운영 가치가 크며
- 딥러닝까지 갈 비용이 합리적이지 않을 수 있다

1회 동작 센서 시계열 사례는 바로 이런 현실 판단을 설명하기 좋다.

`더 높은 모델로 가지 않기로 한 결정`도 기술적 후퇴가 아니라 적절한 범위 설정일 수 있다.

## 작은 기준 모델이 만드는 학습 효과

초심자에게는 기준 모델(baseline model)이 단순 비교 기준 이상이다.

작은 기준 모델을 만들면 다음을 배운다.

- 입력 열이 무엇을 뜻하는지
- 출력이 실제로 어떤 행동과 연결되는지
- false positive가 어떤 장면에서 생기는지
- feature를 추가할 이유가 어디서 생기는지

즉 기준 모델(baseline model)은 평가용이면서 동시에 학습용이다.

## 1회 동작 센서 시계열 사례에서 추천하는 기준 모델 묶음

### 기준 모델 1

- 단일 임계값 규칙

### 기준 모델 2

- 이중 조건 규칙

### 기준 모델 3

- 기준선 gap 규칙

### 기준 모델 4

- repeatability를 반영한 우선순위 규칙

이 네 단계만 잘 만들어도 Part 6 프로젝트는 충분히 풍부해질 수 있다.

## 트리 모델을 쓸 때 좋은 설명 포인트

트리 모델은 다음 이유로 입문 설명에 적합하다.

- 분기 규칙이 규칙 기반 모델과 닮아 있다
- feature importance로 어떤 열이 많이 쓰였는지 볼 수 있다
- 사람이 만든 특징이 실제로 쓸모 있는지 감을 잡기 쉽다

1회 동작 센서 시계열 사례에서는 `late_drop_rate`, `mid_segment_mean`, `tracking_error_mean`, `event_count_context` 같은 열이 어떻게 분기에 쓰이는지 예시를 만들 수 있다.

## 선형 모델을 쓸 때 좋은 설명 포인트

선형 모델은 성능 자랑보다 다음 감각에 좋다.

- 어떤 방향의 변화가 점수를 올리는가
- 가중치 부호가 어떤 해석을 주는가
- 작은 특징 표에서 과하게 복잡한 모델 없이도 어느 정도 분리가 되는가

이 점은 `복잡함이 곧 우월함은 아니다`라는 메시지와 잘 맞는다.

## 딥러닝으로 넘어갈 때 추가로 준비할 것

1회 동작 센서 시계열 사례를 Part 4나 Part 6에서 더 확장하려면 아래 준비가 필요하다.

- 길이가 다른 시퀀스를 다루는 입력 형식
- train/validation/test 시간 분할
- 결측과 노이즈 처리 규칙
- 해석을 위한 attention map 또는 보조 지표

즉 딥러닝은 모델만 바꾸는 것이 아니라 주변 평가 체계까지 더 크게 바꾸는 일이다.

## LLM 설명 보조의 실패 사례도 적어 두기

LLM 보조는 문장을 잘 만들 수 있지만 다음 실패가 있다.

- 구조화 입력보다 더 많이 추정해 버림
- 원인 확정처럼 과한 문장을 씀
- 숫자 차이를 과장된 언어로 요약함

그래서 템플릿 또는 제한된 문장 구조를 먼저 두는 편이 안전하다.

예:

- `최근 구간의 중반 유량 평균이 기준선보다 낮았습니다.`
- `동작 수가 적어 참고 신호로만 해석해야 합니다.`

이런 절제된 문장이 먼저 필요하다.

## 추가 FAQ

### Q4. 기준선 비교도 모델이라고 부를 수 있나요?

A. 학습된 파라미터 모델과는 다르지만, 운영 판단 규칙과 비교 프레임을 가진 해석 체계라는 점에서 기준 모델 역할을 분명히 할 수 있다.
