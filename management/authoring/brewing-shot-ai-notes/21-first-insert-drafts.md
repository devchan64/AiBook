## P3-8.2 기준 모델(baseline) 초안

### 넣을 문단 초안

`기준 모델(baseline)은 꼭 가장 단순한 알고리즘 이름만 뜻하지는 않습니다. 어떤 운영 문제에서는 최근 상태를 비슷한 조건의 평소 상태와 비교하는 기준선 자체가 baseline 역할을 할 수 있습니다. 이 비교 프레임이 있어야 뒤에서 보는 규칙 기반 경고나 학습 모델의 점수도, 실제로 얼마나 의미 있는 개선인지 더 분명하게 읽을 수 있습니다.`

### 넣을 표 초안

| 항목 | 최근 구간 | 평소 기준선 | 차이 | 읽기 |
| --- | ---: | ---: | ---: | --- |
| 중간 구간 평균 | 2.10 | 2.34 | -0.24 | 최근 값이 평소보다 낮다 |
| 후반 하강률 | -0.42 | -0.28 | -0.14 | 후반 하강이 더 가파르다 |
| 동작 수 | 18 | 20 | -2 | 비교 가능하지만 표본 수는 함께 본다 |

### 표의 역할

- baseline이 단순 분류기만이 아니라 비교 프레임일 수 있음을 보여 준다
- 숫자 비교 뒤에 해석이 붙어야 함을 보여 준다
- 다음에 규칙 기반 경고나 모델 예측을 이 위에 얹을 수 있게 만든다

### 넣지 않을 것

- 실제 임계값 설명
- 구체 도메인 원인 진단
- 긴 원시 로그 설명

## P2-12.2 선택, 필터링, 집계 초안

### 넣을 문단 초안

`표를 읽을 때는 한 행이 곧바로 하나의 완성 사례가 아닐 수도 있습니다. 예를 들어 동작 중 기록된 원시 로그에서는 여러 행이 함께 하나의 동작 1건을 이루기도 합니다. 이때는 먼저 동작 식별자 열로 묶고, 그 안에서 길이, 구간 평균, 기울기 같은 값을 요약해 동작 단위 표를 다시 만드는 편이 더 자연스럽습니다.`

### 넣을 표 초안

| event_id | elapsed_seconds | progress_fraction | signal_a |
| --- | ---: | ---: | ---: |
| A-01 | 0.0 | 0.00 | 0.8 |
| A-01 | 1.0 | 0.20 | 1.4 |
| A-01 | 2.0 | 0.40 | 1.9 |
| B-02 | 0.0 | 0.00 | 0.7 |
| B-02 | 1.0 | 0.25 | 1.3 |
| B-02 | 2.0 | 0.50 | 1.5 |

### 이어서 보여 줄 요약 표 초안

| event_id | total_duration_seconds | mid_segment_mean | end_signal_a |
| --- | ---: | ---: | ---: |
| A-01 | 5.0 | 1.9 | 1.1 |
| B-02 | 4.0 | 1.5 | 0.9 |

### 코드 예시 방향

```python
summary = (
    df.groupby("event_id")
      .agg(
          total_duration_seconds=("elapsed_seconds", "max"),
          mid_segment_mean=("signal_a", "mean"),
          end_signal_a=("signal_a", "last"),
      )
      .reset_index()
)
```

### 표의 역할

- 여러 행이 한 동작으로 묶이는 구조를 보여 준다
- `groupby`가 왜 필요한지 설명한다
- Part 3의 특징 공학이나 Part 6의 작은 프로젝트 표로 다시 이어질 수 있게 만든다

### 넣지 않을 것

- 기준선 비교 해석
- 거짓 경보 설명
- 모델 입력 특징 후보 토론
