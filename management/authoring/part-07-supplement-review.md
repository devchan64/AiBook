# Part 7 내용 개선 및 Section 보충 검토

작성일: 2026-07-23

## 목적

이 메모는 Part 7의 예제와 연습을 점검해, 실제 모델, 실제 라이브러리, 벡터 데이터베이스를 붙이면 학습밀도가 올라가는 위치와 보류할 위치를 정리한다.

검토 기준은 다음 세 가지다.

- Section의 중심 질문이 실제 입력, 모델 출력, 후보 순위, 오류 샘플 변화로 더 잘 드러나는가
- 새 라이브러리 사용이 설치, API, 제품 사용법보다 학습 목표를 더 선명하게 만드는가
- 기존 수작업 예제의 교육적 역할을 없애지 않고 프로젝트 실행 감각을 보강하는가

## 보류하거나 낮은 우선순위로 둔 후보

| Section | 후보 | 보류 이유 |
| --- | --- | --- |
| P7-3.1 | `MLPClassifier` 또는 CNN 이미지 패치 분류 | `P7-3.3`에서 실제 `LogisticRegression` 비교를 별도 Section으로 추가했으므로, 더 큰 모델 계열은 현재 Section 경계를 넘길 가능성이 크다 |
| P7-4.2 | `TfidfVectorizer` 기반 coverage 비교 | P7-4.1에 실제 TF-IDF 보충을 추가했으므로, 바로 이어지는 P7-4.2까지 같은 라이브러리 예제를 반복하면 역할이 겹칠 수 있다 |
| P7-5.1 | 단순 `TfidfVectorizer` 검색 보강 | P7-5.5에서 검색 평가셋과 cosine similarity mismatch 실험을 별도 Section으로 추가했으므로, P7-5.1은 현재의 근거 선택 기록 흐름을 유지하는 편이 낫다 |
| P7-6.x | 실제 LLM API 또는 tool-calling 모델 | 권한, 승인, blocked 상태가 중심이다. 실제 LLM/API를 붙이면 네트워크, 키, 비용, 출력 비결정성이 중심 질문을 흐릴 위험이 크다 |
| P7-7.x | 운영 신호 분류 모델 | 운영 판단은 규칙, 근거, 우선순위 기록이 중심이다. 작은 분류 모델을 붙일 수는 있지만, 규칙 기반 판단보다 학습 효과가 뚜렷하지 않다 |

## 현재 결론

Part 7에서 실제 모델과 라이브러리를 붙일 때의 우선순위는 `프로젝트 실행 감각이 생기는가`로 판단해야 한다. 이번 보강에서는 전처리 파이프라인, 이미지 입력 표현별 분류기 비교, 텍스트 벡터화와 분류기, 벡터 DB 검색 설정, 검색 평가셋, 재현 가능한 프로젝트 패키지를 반영했다.
