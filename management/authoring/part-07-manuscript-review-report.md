# Part 7 원고 대조 리포트

> 작성일: 2026-07-30
> 범위: `management/authoring/part-07-open-checklist.md`와 Part 7 한국어 원고

## 요약 판단

Part 7은 체크리스트가 요구한 `실행 -> 비교 -> 실패 해석 -> 운영 회고` 흐름을 원고 전반에서 유지한다. 각 Section이 설명, 코드 실행, 출력 비교, 해석, 회고로 이어지는 실습 단위로 설계되어 있고, Part 4-6의 개념을 다시 실행하는 프로젝트 Part라는 성격도 분명하다.

수정 후보는 구조 결손보다 관리 표기다. 모든 Section에 `## 판단 기준` 제목이 반복되지만, Part 7은 이미 실습 단위로 잘 설계되어 있으므로 소제목 구체화를 필수 작업으로 두지는 않는다. Section 메타데이터 표기 차이는 관리 예외가 될 수 있어 확인 대상이다.

## 수정 필요 항목

### 1. 모든 Section의 `판단 기준` 제목 유지 가능 여부

- 대상: `docs/parts/part-07/chapter-*/*.md`
- 확인된 원고 근거: Part 7의 26개 Section 모두 `## 판단 기준` 제목을 사용한다. 예를 들어 `docs/parts/part-07/chapter-01/section-01.md:19`, `docs/parts/part-07/chapter-05/section-01.md:18`, `docs/parts/part-07/chapter-07/section-05.md:18`에서 확인된다.
- 검토 의견: Part 7은 Section마다 실습 산출물이 달라야 한다. 동일한 `판단 기준` 제목이 반복되지만, 현재 본문은 질문, 실행, 비교, 실패 해석, 회고 흐름을 이미 갖고 있다.
- 수정 방향: 필수 수정 없음. 제목 교체보다 각 Section의 실습 산출물과 회고 기준이 실제로 남는지 유지 점검한다.

### 2. Part 7 메타데이터 표기 일관성 점검

- 대상 예:
  - `docs/parts/part-07/chapter-01/section-01.md:3`, `:4`
  - `docs/parts/part-07/chapter-05/section-01.md:3`, `:4`
  - `docs/parts/part-07/chapter-07/section-05.md:3`, `:4`
- 확인된 원고 근거: Part 7 Section들은 `Section ID`, `Version`을 blockquote 없이 일반 문단으로 둔다. Part 2-6 원고는 대체로 `> Section ID`, `> Version` 형식을 쓴다.
- 수정 필요 이유: Section 메타데이터는 Section ID 기반 추적의 기준이다. 표기 차이가 빌드 오류를 만들지는 않더라도, 관리 문서와 다국어 동기화에서 불필요한 예외가 된다.
- 수정 방향: Part 7 전체의 Section ID/Version 표기를 다른 Part와 같은 blockquote 형식으로 맞출지 결정하고, 맞춘다면 일괄 수정한다.

### 3. 실습 리듬 유지 확인

- 대상: Part 7 전체
- 확인된 원고 근거: 예를 들어 P7-5.1은 `질문 -> 검색 후보 비교 -> 선택 근거 -> 답변 구성` 흐름을 제시하고, P7-7.5는 질문, 입력, 코드, 환경, 실행 명령, 출력, 한계, 다음 조치를 묶어 재현 패키지를 점검한다.
- 수정 필요 이유: 현재 구조는 적절하다. 다만 후속 개정에서 설명이 늘어나면 Part 7이 다시 요약 문서처럼 변할 수 있다.
- 수정 방향: 각 Section마다 `입력 또는 조건 변경`, `출력 비교`, `실패 해석`, `다음 수정 또는 회고`가 실제로 남는지 유지 점검한다.

## 유지 확인 항목

- P7-1부터 P7-2는 질문, 샘플 단위, baseline, 점수와 오류 사례를 실습 기록으로 연결한다.
- P7-3부터 P7-4는 입력 구조, 학습 곡선, 오류 샘플, 표현 손실을 비교한다.
- P7-5는 RAG의 검색 후보, 선택 근거, 답변, 검색 실패와 답변 실패를 나눈다.
- P7-6은 agent 실행을 승인 경계, blocked 상태, 권한, 로그와 연결한다.
- P7-7은 배포 확인, 운영 회고, 운영 신호 분류, 재현 가능한 프로젝트 패키지로 Part를 닫는다.

## 검토 의견과 대안

### A안. 실습 리듬 유지 점검

- 의견: Part 7의 본문 구조는 좋다. 제목을 바꾸기보다 각 Section이 입력, 실행, 출력 비교, 실패 해석, 다음 조치를 남기는지 확인한다.
- 장점: 실습형 Part의 핵심 품질을 직접 지킨다.
- 단점: 표면 제목의 반복은 그대로 남는다.
- 채택 기준: 독자 실습 경험을 우선하면 이 안을 먼저 적용한다.

### B안. 메타데이터 표기만 통일

- 의견: Part 7은 Section ID/Version 표기가 다른 Part와 달라 관리 예외가 된다. 소제목을 건드리지 않고 메타데이터만 blockquote 형식으로 맞출 수 있다.
- 장점: Section 관리 일관성이 좋아진다.
- 단점: 변경 파일 수가 Part 7 전체로 커진다.
- 채택 기준: Part 7 전체 파일을 한 번에 만질 수 있을 때 선택한다.

### C안. 실습 리듬 점검표를 추가

- 의견: 각 Section이 이미 실습 리듬을 갖고 있지만, 후속 개정에서 설명문이 늘어날 위험이 있다. 리포트나 체크리스트에 `입력 변경`, `출력 비교`, `실패 해석`, `다음 조치` 점검표를 두는 대안이 있다.
- 장점: 이후 개정의 품질 기준이 명확해진다.
- 단점: 원고 자체 수정은 아니므로 독자 화면 개선 효과는 간접적이다.
- 채택 기준: Part 7을 계속 확장할 예정이면 적용한다.

### 권장안

A안을 먼저 적용하고, 실제 관리 예외가 크면 B안을 적용한다. Part 7은 원고 구조가 이미 실습형으로 잡혀 있으므로, 제목 일괄 교체보다 사례·연습·회고 리듬을 유지하는 편이 더 중요하다. C안은 체크리스트 보강 작업으로 별도 처리한다.
