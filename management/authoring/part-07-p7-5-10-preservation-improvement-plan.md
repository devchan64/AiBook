## 3. 우선순위 1 — 재학습 없이 적용 강도 비교

첫 비교는 **12개 입력 × 두 가중치 × 강도 0.5·0.75**로 제한한다. 강도 1.0의 기존 결과 24장은 재사용하고, 같은 프롬프트의 미적용 결과 12장을 공통 기준으로 둔다. 미적용도 조건·해시가 일치하는 기존 결과가 있으면 재사용한다. 0.5와 0.75는 효과가 입증된 최적값이 아니라 넓게 차이를 보기 위한 탐색값이다.

| 입력 묶음 | 관리번호 끝 세 자리 | 선택 이유 |
| --- | --- | --- |
| 남성 4개 | 006·009·010·015 | 방향·인물 크기, 기존 오류 개선, 셔츠 구조 소실 |
| 여성 4개 | 017·023·026·028 | 단추 추가, 상의 길이, 목선·자세, 시선 변화 |
| 유아 4개 | 037·038·041·043 | 웃음 개선, 비교적 안정적인 정면, 의상·몸 비율 변화 |

신규 생성은 최대 60장(강도 비교 48장 + 미적용 12장)이다. 기존 3200 결과의 한 장 약 4분 수준을 적용하면 약 4시간 규모의 추론이지만 로딩·GPU 대기·실제 속도에 따라 달라진다. 추가 시드·중간 가중치·다른 프롬프트를 이 첫 비교에 섞지 않는다.

### 실행 전 필요한 코드 보완

[현재 평가기](../../docs/assets/part-07/chapter-05/sec-12/p7_5_12_evaluate_bfs.py)는 `--scales`를 정수 0·1만 허용하고 출력 키도 `-base`·`-lora`로만 나눈다. 따라서 0.5·0.75를 지금 CLI에 넣어 실행할 수 없다.

1. 유한한 실수 강도를 받도록 수정하고 이 실험의 허용 범위를 0~1로 제한한다. 중복값을 차단한다.
2. 출력명·상태 키에 정규화한 강도를 넣어 0.5와 0.75가 덮어쓰이지 않게 한다. 과거 파일명과 결과 JSON은 유지한다.
3. 관리번호 12개 선택, `--dry-run`의 선택 수·재사용 수·신규 수 확인을 지원한다. 생성 조건·선택 JSON을 중복 신설하지 않고 기존 입력 목록을 참조한다.
4. 재개 검증에 가중치·입력·프롬프트·강도·전처리·코드 해시를 포함한다. 미적용은 어댑터를 실제 비활성화하고, 다음 결과에서는 올바른 강도로 다시 활성화한다.
5. GPU 실행 전 강도 파싱, 출력 충돌 방지, 항목 선택, 재개 지문 변경 감지를 확인한다. 원본 결과와 같은 조건은 다시 생성하지 않는다.

Hugging Face 공식 문서는 LoRA 강도로 기여도를 조절하는 방법을 제공한다. 로컬 평가기도 `set_adapters(..., adapter_weights=scale)`를 사용한다. 강도 저하가 이 데이터의 보존 품질을 높인다는 부분은 아직 실험 가설이다.[1]

## 4. 우선순위 2 — 학습 쌍의 지시·목표 일치 점검

추가 학습 전에 학습 347쌍과 검증 19쌍을 구분해 원본 입력·목표를 대조한다. 46개 목표를 먼저 묶어 보고, 같은 목표에 연결된 각각의 입력까지 확인한다. 이번 계획에서는 원본 쌍 전체의 시각 점검을 아직 수행하지 않았다.

| 점검 축 | 기록할 구체적 차이 |
| --- | --- |
| 의상 | 칼라, V/둥근 목선, 단추, 포켓, 소매·밑단·바지 길이 |
| 방향·표정 | 머리 좌우 방향, 위아래 방향, 시선, 열린 입·웃음 |
| 몸·구도 | 어깨 폭, 목·몸통 길이, 인물 크기·중심 위치 |
| 손·소품 | 동작, 주머니 자세, 책의 닫힘·펼침, 컵 위치 |
| 화풍·배경 | 형태 보존과 의도한 질감 변경을 구분 |

각 행에 쌍 ID·입력/목표 해시·관찰 차이·사용 범위·보완 사유를 남긴다. 새 승인 상태나 자동 차단 절차를 추가하지 않는다. 실제 이미지가 다르면 캡션에 “보존” 문장을 더 붙여 해결된 것으로 취급하지 않는다.

보완 순서는 **기존 적합 목표 재사용 → 불일치 쌍을 제외한 학습 비교 → 부족한 조건만 목표 보완**이다. 같은 방향이라는 이유만으로 다른 의상·몸 비율의 목표를 재사용하지 않는다. 기존 원본과 과거 실행 목록은 보존하고 새 실험의 데이터 버전·제외 ID·이유·해시로 추적한다. 생성이 필요해도 기존 통합 생성 JSON의 해당 ID만 대상으로 한다.

목표별 반복 수를 줄이거나 가중치를 조절하는 실험은 쌍 불일치 수정과 별도 비교한다. 동일 목표·그 목표에서 파생한 유사 입력은 같은 분할에 유지한다. 해시가 다른 근접 이미지도 확인한다. 현재 목표 해시 중복 0개는 바이트 중복에 관한 사실이며 의미상 누수까지 부정하지 않는다. 그룹 분할 원칙은 공식 교차검증 문서에 근거한다.[2]

## 5. 우선순위 3 — 필요한 경우에만 학습 비교

강도 비교에서 정체성·화풍을 유지하면서 보존 차이가 줄면 그 조합을 45장으로 확장한다. 낮은 강도에서 Mira 특징도 함께 사라지거나 의상 오류가 지속되면 데이터 대응 점검 결과를 다음 학습 설계에 사용한다.

- **기존 중간 가중치:** 첫 비교에서 선정한 강도를 고정하고 원래 학습 1200스텝 또는 재개 400스텝(누적 2000)의 최대 두 후보를 12장에 비교한다. 모두 로컬에 존재한다. 재개 파일의 `step00000400`을 누적 400으로 오기하지 않는다. 전 가중치·전 강도 조합을 무차별 탐색하지 않는다.
- **데이터 수정 비교:** 쌍 불일치가 확인되면 원래 기반 모델에서 새 LoRA를 초기화하고, 기존 rank/alpha·학습률·해상도·시드·1600 업데이트를 고정한 데이터 수정 실험을 먼저 한다. 기존 3200에서 이어 학습하면 기존 오류 영향과 데이터 수정 효과를 분리하기 어렵다. 쌍 수가 줄면 이미지당 노출 횟수도 바뀐다는 한계를 기록한다.
- **학습률 비교:** 데이터 수정 결과에도 문제를 재현할 때 같은 새 데이터와 초기화 방식에서 `1e-4` 대 `5e-5`만 비교한다. 후자는 탐색 후보이며 최적값 주장이 아니다. rank·해상도·캡션·반복 수를 동시에 바꾸지 않는다.
- **보류할 확장:** 무조건 4800·6400스텝 연장, 전체 목표 재생성, 근거 없는 rank 확대, 다른 기반 모델 혼합은 우선안에 넣지 않는다. 얼굴만 국소 편집하는 대안은 전체 화풍 변환 요구가 남아 있으므로 별도 과제다.

## 6. 비교표와 선택 기준

각 항목은 입력, 방향에 맞는 기존 Mira 얼굴 기준, 기존 1600·3200 결과, 신규 결과를 함께 본다. 합성 시트 대신 원본 이미지 링크를 사용한다. 다음 열을 분리해 기록한다.

`관리번호 / 조건·해시 / 얼굴·헤어 일치 / 전체 화풍 / 의상 / 방향·시선 / 표정 / 몸 비율·구도 / 동작·소품 / 배경 / 1600 대비 변화 / 3200 대비 변화 / 근거`

얼굴·헤어·화풍은 `일치·부분 일치·불일치·판단 어려움`, 보존 축은 `보존·세부 차이·구조 변경·판단 어려움`으로 적는다. 종합 점수 하나로 합치지 않는다. 예를 들어 주름 단순화는 세부 차이, 포켓 신설·상의 길이 변경은 구조 변경으로 구분한다. 판단 어려움은 통과로 세지 않는다.

후속 확대 후보는 다음 근거로 선택한다. 이는 이번 프로젝트의 비교 규칙이며 일반 성능 기준이 아니다.

1. 12장 중 의상 구조 변경이 있는 항목 수가 1600·강도 1.0보다 줄고, 기존에 없던 구조 변경이 생기지 않는다.
2. 얼굴·헤어 및 전체 화풍의 비교 등급이 항목별로 낮아지지 않는다. 보존 개선을 위해 변환 목적을 잃은 결과는 개선 후보로 설명하지 않는다.
3. 방향·몸 비율·동작의 새로운 악화가 없다. 개선된 009·010·037과 안정적인 038도 함께 확인한다.
4. 조건을 만족하지 못하면 “강도만으로 개선 불충분”으로 기록하고 데이터 점검으로 이동한다. 평균 수치가 좋다는 이유로 041 같은 큰 의상 변화를 묻지 않는다.

후보 하나를 45장으로 확장할 때 첫 12장은 재사용해 같은 시드에서는 최대 33장만 추가한다. 이후 후보와 1600 기준선을 새 시드 62295·62296에서 같은 12장에 비교한다(최대 48장). 전체 신규량은 첫 실험 이후 관찰로 결정한다.

45장은 이미 원인 탐색과 설정 선택에 사용했으므로 최종 독립 테스트로 부르지 않는다. 최종 일반화 확인은 설정 선택에 사용하지 않은 별도 입력으로 한다. 새 입력의 필요성과 재사용 가능 여부는 그 단계에서 정하며 지금 대량 생성하지 않는다. 검증 19쌍도 설정 선택에 쓰면 검증 용도로 남기고 독립 테스트로 재명명하지 않는다.

## 7. 실행 순서와 산출물

1. 평가기 강도·출력명·선택·재개 검증 보완, GPU 없이 실행 범위 확인.
2. 12개 입력의 미적용·0.5·0.75 결과 비교. 기존 1.0 결과 재사용.
3. 원본 쌍의 지시·목표 일치 점검과 목표 반복 분포 기록.
4. 관찰에 따라 45장 확대 또는 데이터 수정 학습 중 다음 실험 선택.
5. 다중 시드와 독립 입력에서 재확인한 뒤 사용 조건·남은 한계 기록.

새 결과는 가중치 해시, 누적 학습 스텝, 데이터 해시, 입력·프롬프트·강도·시드·전처리, 코드·실행환경을 함께 기록한다. 과거 `pending_visual_review` 결과 JSON은 당시 실행 기록이므로 덮어쓰지 않고 현재 의견은 검수표에 남긴다. 모델·이미지의 공개 교체와 원고 수치 갱신은 실험 결과가 나온 뒤 별도 변경으로 다룬다.
