# Part 6 체크포인트 노트

이 문서는 Part 6을 목차 순서대로 읽을 때 각 Section이 담아야 할 중심 주제를 개괄식으로 정리한 체크포인트 노트입니다.

## 사용 원칙

- 이 노트는 `docs/table-of-contents.md`를 기준으로 Part 6의 시작/마무리 페이지, Chapter, Section을 같은 순서로 훑기 위한 개요 문서입니다.
- 이 노트는 작업 상태표가 아니라 Part 6 원고가 유지해야 할 중심선 문서입니다.
- 순차 점검 기록, 품질 상태 메모, 개편 작업 로그, 배포 전 빌드 체크는 이 문서에서 운영하지 않습니다.
- 체크포인트는 `생성형 AI 산출물 -> LLM 대표 경로 -> 입력 표현 -> 다음 후보 생성 -> 학습과 조정 -> 근거 보강 -> 도구 실행 -> 평가와 운영 -> 배경 지도` 흐름을 각 Section이 어떻게 지지하는지 확인하는 데 목적을 둡니다.
- `학습 관점 누락 점검`은 Part 원고가 잃기 쉬운 설명 흐름을 점검하고, `목차 기준 체크포인트`는 Part 원고가 유지해야 할 구조 흐름을 관리합니다.
- Section ID 기반 자동 대조는 문서 전체가 아니라 `목차 기준 체크포인트` 이후 구간을 기준으로 삼습니다.
- 체크포인트 문장은 집필 기준이며, 본문에는 `오픈체크리스트`, `중심축` 같은 관리 표현으로 노출하지 않습니다. 본문 보강은 문제 장면, 개념 대비, 독자용 판단 문장으로 풀어 씁니다.

## 학습 관점 누락 점검

- 각 Chapter를 볼 때 기술 이름보다 `생성형 AI 사용 장면에서 어떤 판단을 가능하게 하는가`가 먼저 보이는지 확인합니다.
- 각 Section을 볼 때 비교, 구분, 판정, 기록 읽기 가운데 하나의 학습 산출물이 남는지 확인합니다.
- LLM을 생성형 AI 전체와 동일시하지 않고, 생성형 AI를 읽는 중심 사례로만 두는지 확인합니다.
- 토큰, token ID, 임베딩, Transformer, GPT, next-token prediction이 서로 다른 층위의 설명으로 유지되는지 확인합니다.
- 프롬프트, RAG, 벡터 데이터베이스, 도구 사용, AI 에이전트, MCP, 하네스가 제품 기능 목록이 아니라 `검토 가능성`, `근거`, `실행`, `기록` 문제로 연결되는지 확인합니다.
- 평가와 운영 장에서는 자연스러운 답변, 품질 기준, 자동 평가, 사람 평가, 비용, 지연 시간, 실패 대응, 실행 기록이 서로 다른 판단 축으로 보이는지 확인합니다.
- 발전사와 BERT 계열은 본류를 대체하지 않고, GPT 중심 설명을 과장하지 않기 위한 배경 지도와 비교 축으로 남는지 확인합니다.
- 다국어 본문이 이미 함께 있으므로, 한국어 원문에서 Section 경계나 소제목을 바꾸면 영어·중국어 번역본도 같은 `Section ID` 기준으로 후속 동기화 대상에 올려야 합니다.

## Section 경계 정리

- Part 6 전체 경계는 생성형 AI 산출물에서 출발해 `요청 -> 입력 단위 -> 표현 -> 다음 후보 생성 -> 학습과 조정 -> 근거 보강 -> 도구 실행 -> 평가와 운영 -> 작은 기능 기록 -> 배경 지도`로 이어지는 서비스 구조를 읽게 하는 데 둡니다.
- Part 6은 대규모 모델을 직접 학습시키는 구현서가 아닙니다. 모델 내부 계산의 기본 구조는 Part 5에서 닫고, Part 6에서는 그 구조가 LLM 서비스 경험과 시스템 판단으로 어떻게 드러나는지에 집중합니다.
- P6-1.1~P6-1.3은 생성형 AI를 결과물 검토 문제로 열고, LLM을 대표 사례로 두며, 후보 분포와 선택 반복을 Part 5에서 회수합니다. 생성형 AI 전체를 LLM으로 환원하거나, 토큰·Transformer 설명을 입구에서 앞당기지 않습니다.
- P6-2와 P6-3은 텍스트가 모델 입력으로 바뀌는 구간입니다. 토큰, token ID, 토큰화, 비용, 청크, 임베딩, 가까운 벡터, ANN 검색을 나누어 설명하되, 벡터 데이터베이스 구현과 RAG 파이프라인은 P6-11~P6-12로 넘깁니다.
- P6-4~P6-6은 LLM이 다음 후보를 만드는 구조를 닫습니다. Transformer 복습은 Part 5의 블록 설명을 반복하지 않고, LLM 안에서 문맥 반영, 참조 범위, KV cache, 긴 문맥, GPT 계열, 다음 토큰 예측, 출력 선택 규칙이 어떻게 이어지는지만 잡습니다.
- P6-4.3~P6-4.5는 보충학습으로 유지합니다. attention head, 위치 표현, KV cache, 긴 문맥, 희소 attention을 처음 구분하는 지도에 머물고, 논문별 attention 변형이나 추론 최적화 구현 세부로 확장하지 않습니다.
- P6-7~P6-9는 응답 습관을 만드는 학습과 조정의 경계입니다. 사전학습, 스케일, 파인튜닝, LoRA, 지시 튜닝, 정렬, 실패 진단을 `무엇을 배우고 무엇을 맞추는가` 기준으로 나누며, 학습 코드나 최신 학습 기법 비교표로 흐르지 않게 합니다.
- P6-9.3은 형식, 근거, 실행, 지속 적응 부족을 진단하는 분기점입니다. 이후 프롬프트, RAG, 도구 사용, 평가·운영 장으로 넘어가기 위한 문제 분류 역할을 맡기고, 실패 사례 목록으로만 끝내지 않습니다.
- P6-10은 프롬프트를 입력 설계로 다루되, 최신성, 근거성, 계산, 실행, 재현성 문제를 프롬프트 밖 시스템 구조로 넘기는 경계를 분명히 둡니다. CoT와 self-consistency는 답변 경로 관찰 전략이지 근거 보장이나 실행 보장이 아닙니다.
- P6-11~P6-12는 RAG와 벡터 데이터베이스의 경계를 나눕니다. P6-11은 외부 근거를 답변 전에 붙이는 구조와 검색 실패·생성 실패 구분을 닫고, P6-12는 임베딩·원문·메타데이터 저장, payload 반환, 인덱스와 검색 품질 점검을 본격화합니다.
- P6-13~P6-15는 도구와 에이전트 실행 구조입니다. 도구 사용은 조회·계산·실행을 모델 밖으로 넘기는 문제, 함수 호출은 자연어 요청을 이름과 인자로 구조화하는 문제, 에이전트는 관찰 결과에 따라 다음 작업을 바꾸는 문제, MCP와 하네스는 연결 형식과 재현 가능한 실행 기록 문제로 나누어 둡니다.
- P6-13~P6-15는 제품 기능 소개가 아닙니다. 특정 API 사용법이나 플러그인 목록보다, 어떤 일을 모델이 직접 답하고 어떤 일을 도구·승인·로그·재현 환경으로 넘겨야 하는지 판단하게 해야 합니다.
- P6-16~P6-17은 좋은 답변과 서비스 가능한 답변을 분리하는 구간입니다. 평가는 LLM 내부 알고리즘이 아니라 실제 출력물을 대상으로 삼고, 운영 제약은 품질 점수와 별도로 비용, 지연, 사용량, 복구 가능성으로 다시 거릅니다.
- P6-18은 Part 6의 종합이지만 Part 7 프로젝트 본편은 아닙니다. 질문, 근거, 답변, 상태, 기록을 묶는 최소 기능으로 Part 7에서 만들 산출물의 판단 기준을 열고, 완성형 제품 구현이나 배포 절차로 확장하지 않습니다.
- P6-19~P6-20은 본류 뒤의 배경 지도와 비교 축입니다. 발전사는 직접 계보와 주변 근거를 분리해 읽고, BERT 계열은 GPT 생성 계열과 대비되는 이해 중심 Transformer로 다룹니다. 최신 모델 연표나 제품별 성능 비교로 확장하지 않습니다.
- Part 6의 긴 Section은 실행 예제, 표, 그래프가 많아질 수 있지만 중심 질문은 하나로 유지합니다. 예제가 검색, 생성, 평가, 운영 상태 중 서로 다른 질문을 동시에 열면 분리 후보로 봅니다.
- 다국어 확장 시에도 Section ID를 기준 단위로 유지합니다. token, embedding, generation, inference, reasoning, alignment, tool use, agent, harness, evaluation은 번역어가 Part 5·Part 7의 용어 경계와 어긋나지 않게 맞춥니다.

## 흐름 왜곡 방지 기준

- Part 6을 토큰 장 개편의 잔여 작업표로 읽지 않습니다. 첫 판단 기준은 항상 `생성형 AI 산출물은 왜 검토 대상인가`이고, 토큰·임베딩·Transformer는 그 산출물이 만들어지고 검토되는 과정을 설명하기 위한 중간 층위입니다.
- P6-11과 P6-12를 함께 볼 때는 RAG와 벡터 데이터베이스를 합치지 않습니다. P6-11은 외부 근거를 답변 전에 붙이는 흐름, P6-12는 검색 저장소가 원문·메타데이터·검색 품질을 어떻게 남기는지에 집중합니다.
- P6-16과 P6-17을 함께 볼 때는 품질 평가와 운영 가능성을 합치지 않습니다. P6-16은 결과물이 평가 가능한가를 묻고, P6-17은 평가를 통과한 결과도 비용·지연·사용량·복구 경로 기준으로 다시 걸러야 함을 묻습니다.
- P6-18은 Part 6의 종합 기준을 Part 7 프로젝트로 넘기는 다리입니다. 작은 기능의 완성도보다 `요청, 근거, 답변, 상태, 기록`이 함께 남는지가 먼저 확인되어야 합니다.

## 목차 기준 체크포인트

- `P6-index`: Part 6이 토큰이나 Transformer 세부 구현이 아니라 생성형 AI 산출물 검토에서 시작한다는 점을 분명히 해야 합니다.
- Part 흐름: Module 1~3은 `산출물 -> LLM 대표 경로 -> 입력 표현 -> 다음 후보 생성`을 하나의 전개로 이어야 합니다.
- Part 흐름: Module 4~5는 `응답 습관을 만드는 학습과 조정`에서 `프롬프트와 근거 보강`으로 넘어가는 이유가 보여야 합니다.
- Part 흐름: Module 6~7은 도구 실행, AI 에이전트, MCP, 하네스, 평가, 운영 제약을 `검토 가능한 서비스 상태`로 묶어야 합니다.
- Part 흐름: Module 8은 본류 뒤에서 발전사와 BERT 비교 축을 제공하되, 앞선 서비스 구조 흐름을 다시 덮지 않아야 합니다.
- `P6-summary`: Part 6에서 닫은 판단 기준을 Part 7의 프로젝트 기록, RAG 검증, agent 실행, 운영 회고로 넘겨야 합니다.

### Module 1. 생성형 AI를 LLM 중심으로 읽는 입구

#### Chapter 1. 생성형 AI와 LLM의 위치 `LLM 핵심`

- 중심축: 생성형 AI 산출물을 검토 대상 결과물로 먼저 보고, LLM을 대표 경로로 삼되 전체와 동일시하지 않습니다.
- `P6-1.1`: 생성형 AI 출력이 분류값이나 수치 예측이 아니라 근거, 형식, 위험을 함께 검토해야 하는 산출물이라는 점을 잡아야 합니다.
- `P6-1.2`: LLM을 생성형 AI 전체가 아니라 텍스트 생성과 대화형 사용 구조를 읽는 중심 사례로 세워야 합니다.
- `P6-1.3`: 생성이 완성 답을 한 번에 꺼내는 일이 아니라 후보 분포와 선택 반복이라는 점을 Part 5의 생성 모델 감각과 연결해야 합니다.

### Module 2. 텍스트 생성의 입력 단위와 표현

#### Chapter 2. 토큰과 토큰화 `LLM 핵심`

- 중심축: 텍스트가 모델 입력으로 바뀌는 단위를 토큰, token ID, 토큰화 영향, 운영 판단으로 나누어 읽게 합니다.
- `P6-2.1`: 입력과 출력이 비용, 길이 제한, 문맥 보존에서 토큰 단위로 제한되는 이유를 보여 주어야 합니다.
- `P6-2.2`: 문자열, 토큰, token ID, 순서와 위치를 서로 다른 층위로 구분해야 합니다.
- `P6-2.3`: 토큰화 절차가 길이, 비용, 청크, 출력 해석 판단으로 자연스럽게 이어져야 합니다.
- `P6-2.4`: 프롬프트 길이, RAG 청크, 비용 예산, 출력 형식 설계에 토큰 기준을 적용하게 해야 합니다.
- `P6-2.5`: BPE, WordPiece, SentencePiece를 이름 암기가 아니라 절단 기준과 운영 관찰값 차이로 읽게 해야 합니다.

#### Chapter 3. 임베딩 `LLM 핵심`

- 중심축: token ID 번호와 비교 가능한 벡터 표현을 분리하고, 가까운 벡터를 정답이 아니라 후보 신호로 읽게 합니다.
- `P6-3.1`: token ID가 의미 자체가 아니라 임베딩을 통해 계산 가능한 벡터 표현으로 바뀐다는 점을 잡아야 합니다.
- `P6-3.2`: 가까운 벡터가 최종 정답이 아니라 후보를 좁히는 신호라는 점을 사례와 함께 보여 주어야 합니다.
- `P6-3.3`: 임베딩 학습을 가까운 표현과 먼 표현을 조정하는 문제로 보충해야 합니다.
- `P6-3.4`: ANN 검색의 속도 이득과 후보 누락 위험을 함께 읽는 기준을 보충해야 합니다.

### Module 3. 다음 후보를 만드는 LLM 구조

#### Chapter 4. Transformer 구조 복습 `딥러닝 구조`

- 중심축: Transformer를 Part 5의 구조 반복이 아니라 LLM 안에서 다음 후보 점수로 이어지는 계산 흐름으로 다시 읽게 합니다.
- `P6-4.1`: LLM 안의 Transformer 계산을 문맥 반영, 표현 갱신, 다음 후보 점수 흐름으로 설명해야 합니다.
- `P6-4.2`: attention의 참조 범위가 무한하지 않으며, 제한된 범위 안에서 관계를 계산한다는 점을 잡아야 합니다.
- `P6-4.3`: attention head와 위치 표현을 여러 관계 축과 순서 정보의 보충학습으로 다루어야 합니다.
- `P6-4.4`: KV cache를 반복 생성에서 이미 계산한 key/value 재사용 문제로 보충해야 합니다.
- `P6-4.5`: 긴 문맥과 희소 attention을 연결 수 조절과 장문맥 유지의 절충으로 보충해야 합니다.

#### Chapter 5. GPT 계열 `LLM 핵심`

- 중심축: GPT 계열을 decoder 기반 자기회귀 생성 구조와 대화형 지시 따르기 층으로 나누어 읽게 합니다.
- `P6-5.1`: GPT 계열을 decoder 중심 누적 생성 구조로 설명하고, BERT식 이해 중심 구조와 섞지 않아야 합니다.
- `P6-5.2`: 생성 구조 위에 instruction following과 대화 인터페이스가 더해지며 사용 경험이 달라진다는 점을 보여 주어야 합니다.

#### Chapter 6. 다음 토큰 예측과 생성 `LLM 핵심`

- 중심축: 긴 답변을 다음 토큰 후보 분포의 반복 선택 결과로 읽고, 출력 선택 규칙이 안정성과 다양성을 바꾸는 지점을 닫습니다.
- `P6-6.1`: 다음 토큰 예측이라는 국소 목표가 긴 생성으로 누적되는 이유를 설명해야 합니다.
- `P6-6.2`: greedy, sampling, temperature 같은 출력 선택 규칙이 답변 안정성과 다양성을 어떻게 바꾸는지 보여 주어야 합니다.

### Module 4. 응답 습관을 만드는 학습과 조정

- `P6-7.1`: 사전학습이 대규모 텍스트에서 일반 언어 기반을 만드는 과정이라는 점을 잡아야 합니다.
- `P6-7.2`: 모델 규모가 능력뿐 아니라 비용, 지연, 배포 부담도 함께 키우는 축임을 보여 주어야 합니다.

#### Chapter 8. 파인튜닝 `학습 원리`

- 중심축: 기반 모델을 목적과 도메인에 맞게 조정하되, 전체 조정과 효율적 조정의 부담 차이를 읽게 합니다.
- `P6-8.1`: 파인튜닝을 특정 목적과 도메인에 맞춘 응답 습관 조정으로 설명해야 합니다.

#### Chapter 9. 지시 튜닝과 정렬 `LLM 핵심`

- 중심축: 잘 생성하는 모델과 사용자가 요청한 방식으로 안전하게 답하는 모델을 구분하고, 실패 원인을 후속 보강 경로로 나눕니다.
- `P6-9.1`: 지시 튜닝이 사용자 지시 형식에 맞는 응답 습관을 만든다는 점을 보여 주어야 합니다.
- `P6-9.2`: 정렬을 유용성, 안전성, 사실성, 거절 기준을 함께 맞추는 문제로 설명해야 합니다.
- `P6-9.3`: LLM 실패를 형식, 근거, 실행, 지속 적응 부족으로 나누어 프롬프트, RAG, 도구 사용, 평가·운영 장으로 이어야 합니다.
- `P6-9.4`: LoRA의 low-rank를 큰 변경 전체가 아니라 작은 조정분을 표현하는 관점으로 보충해야 합니다.
- `P6-9.5`: 효율적 조정 방식의 비용, 구조, 메모리 제약을 이름 목록이 아니라 운영 제약으로 보충해야 합니다.

### Module 5. 프롬프트와 근거 보강

#### Chapter 10. 프롬프트 엔지니어링 `LLM 핵심`

- 중심축: 프롬프트를 입력 설계 장치로 읽고, 프롬프트 밖 시스템 구조가 필요한 경계를 분리합니다.

- `P6-10.2`: 최신성, 근거성, 계산, 실행, 재현성 문제는 프롬프트만으로 닫히지 않는다는 경계를 세워야 합니다.
- `P6-10.3`: CoT와 self-consistency를 근거 보장이나 실행 보장이 아니라 답변 경로 관찰과 후보 비교 전략으로 보충해야 합니다.
- `P6-10.4`: automatic prompt optimization을 자동화 마법이 아니라 후보 프롬프트, 평가 기준, 검증 세트, 실패 누락 위험의 반복 루프로 보충해야 합니다.

#### Chapter 11. RAG `서비스 구조`

- 중심축: RAG를 문서 붙이기 요령이 아니라 답변 전에 외부 근거 후보를 회수해 입력 문맥으로 붙이는 구조로 읽게 합니다.
- `P6-11.1`: 모델 내부 기억 대신 검색 저장소에서 외부 근거를 붙이는 구조를 설명하고, 벡터 DB는 대표 저장소로만 짧게 언급해야 합니다.
- `P6-11.2`: 검색 실패와 생성 실패를 분리해, 붙은 문서가 틀린 문제와 문서는 맞지만 답변이 과장되거나 빠뜨리는 문제를 구분해야 합니다.
