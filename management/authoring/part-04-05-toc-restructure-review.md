# Part 4, Part 5 목차 재구성 검토 메모

## 검토 질문

- Part 4와 Part 5는 정말 `챕터 재배치`가 필요한가?
- 아니면 현재 순서를 유지하되, 개요 문서와 연결 절만 보강해도 충분한가?

## 검토 기준

이번 검토에서는 다음 두 기준을 분리해서 봤다.

1. 섹션 내부의 `다음 절/다음 장 연결`이 이미 자연스러운가
2. 현재 `목차 순서`가 그 자연스러운 연결을 오히려 가리고 있는가

즉, 본문 연결과 목차 배열을 같은 문제로 보지 않는다.

## 결론 요약

| 파트 | 결론 | 이유 |
| --- | --- | --- |
| Part 4 | 전면 재배치까지는 불필요, `그룹 재구성`과 `연결 절 추가`가 필요 | 섹션 간 선형 흐름은 대체로 살아 있으나, 목차가 학습 루프를 분리해 보이게 만든다 |
| Part 5 | 실제 `챕터 재배치`가 필요 | 본류보다 배경 축이 앞에 나와 LLM 핵심 설명이 늦게 시작되는 인상을 준다 |

## Part 4 판단

### 1. 현재 선형 흐름 자체는 비교적 자연스럽다

Part 4는 대체로 다음 흐름을 이미 갖고 있다.

- 퍼셉트론
- 다층 구조
- 활성화 함수
- 손실 함수
- 역전파
- 학습과 모델 실행
- 옵티마이저
- 정규화
- GPU와 배치
- 표현 학습
- CNN
- RNN
- Attention
- Transformer
- 생성과 샘플링

즉, `계산 구조 -> 학습 절차 -> 구조 분기 -> 생성`이라는 큰 줄기는 이미 존재한다.

### 2. 문제는 `학습 루프가 목차에서 찢어져 보인다`는 점이다

손실, 역전파, 학습 모드, 옵티마이저, 정규화는 실제로 하나의 학습 루프로 읽혀야 한다. 하지만 현재 목차에서는 각각 독립 장으로 흩어져 있어, 독자가 `각 장은 이해했지만 한 번에 묶이지 않는다`는 상태로 남기 쉽다.

### 3. 따라서 Part 4는 `전면 순서 변경`보다 `그룹 재구성`이 더 적합하다

권장 방향:

- `신경망의 출발점`
- `출력, 손실, 역전파`
- `학습 루프와 안정화`
- `계산 환경과 표현 학습`
- `공간 구조와 CNN`
- `순차 구조와 RNN 계열`
- `Attention에서 Transformer로`
- `생성 모델과 샘플링`

즉, Part 4는 기존 섹션 순서를 크게 뒤집기보다 `독서 경로를 다시 묶는 편`이 더 효과적이다.

## Part 5 판단

### 1. 현재 목차는 본류보다 배경 축이 먼저 눈에 띈다

Part 5의 실제 핵심은 다음과 같다.

- 토큰과 토큰화
- 임베딩
- Transformer를 LLM 관점에서 읽기
- GPT
- 다음 토큰 예측
- 사전학습, 파인튜닝, 지시 튜닝, 정렬
- 프롬프트, RAG, 벡터 검색
- 도구 사용, 에이전트, MCP, 하네스
- 평가, 운영, 통합 미니 실습

그런데 현재 순서에서는:

- LLM 발전사
- BERT 계열

이 본류 중간에 강하게 들어와, `이제부터 LLM을 설명한다`는 감각을 늦춘다.

### 2. Part 5는 `읽는 순서`가 실제 이해 순서와 어긋난다

본문 내부 연결만 보면:

- GPT -> next-token -> 생성 과정 -> 사전학습/조정 -> 프롬프트 -> RAG -> tool use -> agent

가 더 자연스럽다.

따라서 Part 5는 목차가 본문의 이해 흐름을 충분히 반영하지 못하고 있다.

### 3. 따라서 Part 5는 실제 재배치가 필요하다

권장 방향:

- `입력 단위와 표현`
- `LLM 핵심 구조`
- `학습과 조정`
- `프롬프트와 근거 연결`
- `실행 구조`
- `평가, 운영, 통합 실습`
- `배경 지도: LLM 발전사`
- `배경 비교: BERT 계열`

즉, Part 5는 `배경 축을 뒤로 보내고 본류를 앞당기는 재배치`가 필요하다.

## 섹션 추가 판단

### Part 4

추가가 필요한 섹션:

- `P4-8.3 학습 루프를 한 번에 다시 묶기`

이유:

- 손실, 역전파, optimizer, regularization, mode 전환을 하나의 반복 구조로 회수해야 하기 때문

### Part 5

추가가 필요한 섹션:

- `P5-10.3 프롬프트, 파인튜닝, RAG, 도구 사용을 언제 고를까`

이유:

- 후반 장들이 각각 따로 설명되기 전에, 문제 유형과 해결 수단의 선택 기준을 먼저 묶어 줄 필요가 있기 때문

## 최종 결론

- Part 4는 `전면 순서 변경`보다 `목차 그룹 재구성 + 연결 섹션 추가`가 적합하다.
- Part 5는 `실제 챕터 재배치 + 연결 섹션 추가`가 필요하다.

한 줄로 줄이면 다음과 같다.

`Part 4는 같은 순서를 더 잘 읽히게 다시 묶고, Part 5는 본류를 앞당기기 위해 실제로 재배치한다.`
