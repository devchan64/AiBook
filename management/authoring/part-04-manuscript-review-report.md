# Part 4 원고 대조 리포트

> 작성일: 2026-07-30
> 범위: `management/authoring/part-04-open-checklist.md`와 Part 4 한국어 원고

## 요약 판단

Part 4는 머신러닝을 알고리즘 목록이 아니라 `문제 구조 -> 데이터 분리 -> 평가 기준 -> baseline -> 알고리즘 선택` 흐름으로 설명하려는 중심선이 뚜렷하다. 여러 Section에 `주요 학습내용`, `세부 학습내용`, `읽기 순서` 같은 진행 메타 제목이 남아 있지만, 소제목 관리 자체를 별도 수정 원칙으로 둘 필요는 낮다.

가장 우선 수정할 부분은 P4-7.1/P4-7.2의 절차 설명이 유지되는지, 그리고 도구 이름 소개가 판단 흐름을 압도하지 않는지 점검하는 일이다. 알고리즘 장은 제목 통일보다 baseline 비교 흐름과 사례·예제가 실제 판단을 보여 주는지가 중요하다.

## 수정 필요 항목

### 1. Part 4 전반의 진행 메타형 제목 유지 가능 여부

- 대상 예:
  - `docs/parts/part-04/chapter-01/section-01.md:30`
  - `docs/parts/part-04/chapter-04/section-01.md:56`, `:219`
  - `docs/parts/part-04/chapter-05/section-01.md:59`, `:188`
  - `docs/parts/part-04/chapter-06/section-01.md:60`, `:147`
  - `docs/parts/part-04/chapter-07/section-01.md:55`, `:436`, `:837`
  - `docs/parts/part-04/chapter-10/section-01.md:56`, `:202`
  - `docs/parts/part-04/chapter-11/section-01.md:54`, `:210`
- 확인된 원고 근거: Part 4 여러 Section에 `## 읽기 순서`, `## 주요 학습내용`, `## 세부 학습내용`, `## 세부 학습내용 보충`이 반복된다.
- 검토 의견: Part 4 체크리스트는 진행 메타 제목을 개념 중심 제목으로 정리할 후보라고 명시한다. 다만 현재 개정 기준에서는 제목 교체보다 문제 구조와 평가 질문이 사례·예제 속에서 따라오는지가 더 중요하다.
- 수정 방향: 필수 수정 없음. 소제목은 실제 독해 문제나 목차 혼선이 확인될 때만 제한적으로 조정한다.

### 2. P4-7.1/P4-7.2의 전처리·특징 선택 절차 유지 점검

- 대상:
  - `docs/parts/part-04/chapter-07/section-01.md:837`
  - `docs/parts/part-04/chapter-07/section-02.md:527`, `:892`
- 확인된 원고 근거: P4-7.1과 P4-7.2는 한국어 원고 기준 각각 869줄, 924줄이며, 본문 뒤에 `세부 학습내용 보충`으로 scikit-learn 도구 이름과 전처리 도구 이름을 추가한다.
- 수정 필요 이유: 체크리스트는 P4-7을 Part 3의 데이터 구조화와 Part 5의 표현 학습 사이에 놓인 입력 문제 정리 구간으로 제한한다. 도구 이름 소개가 필요하더라도 레시피나 도구 매뉴얼처럼 커지면 경계가 흐려질 수 있다.
- 수정 방향: `입력 문제를 어떤 가설로 정리할 것인가`를 본문 중심에 두고, 도구 이름 표는 짧은 보충으로 유지한다. 반복 예제가 절차 설명을 돕는다면 유지하고, 같은 결론만 되풀이하는 문장만 제한적으로 줄인다.

### 3. 알고리즘 장의 baseline 비교 흐름 확인

- 대상 예:
  - `docs/parts/part-04/chapter-10/section-01.md:56`
  - `docs/parts/part-04/chapter-10/section-02.md:82`, `:252`, `:308`
  - `docs/parts/part-04/chapter-11/section-01.md:54`
  - `docs/parts/part-04/chapter-14/section-01.md:76`, `:144`
  - `docs/parts/part-04/chapter-15/section-01.md:87`, `:241`
- 확인된 원고 근거: 선형회귀, 로지스틱 회귀, 결정트리, 랜덤포레스트 등 알고리즘 장에도 `주요 학습내용`, `세부 학습내용`이 남아 있다.
- 수정 필요 이유: 체크리스트는 각 알고리즘을 공식 중심 설명보다 기준선과 비교 렌즈로 쓰라고 한다. 이 기준은 소제목 통일보다 본문 사례와 예제가 기준선 대비 판단을 실제로 보여 주는지로 확인한다.
- 수정 방향: 제목 교체를 필수로 두지 않는다. 각 Section이 `baseline 대비 언제 남고 언제 빠지는가`를 사례·예제 안에서 보여 주는지 점검한다.

## 유지 확인 항목

- P4-4부터 P4-6은 알고리즘 설명 전에 데이터 분리, 일반화, 평가 지표를 닫는 흐름을 갖고 있다.
- P4-8부터 P4-9는 모델 후보, 기준 모델, 하이퍼파라미터, 검증 비용을 실험 루프로 묶는다.
- P4-17부터 P4-19는 비지도 학습, 차원 축소, 강화학습을 과잉 해석하지 않도록 제한한다.

## 검토 의견과 대안

### A안. P4-7.1/P4-7.2 절차 설명을 먼저 점검

- 의견: 특징 선택과 전처리는 Part 3과 Part 5 사이의 핵심 연결부다. 이 두 Section에서 절차 설명이 충분히 살아 있어야 뒤 Part의 표현 학습으로 넘어갈 수 있다.
- 장점: 가장 긴 구간의 학습 손잡이를 보존한다.
- 단점: 표면 제목의 오래된 형식은 그대로 남는다.
- 채택 기준: 독자 이해를 우선하면 이 안을 먼저 택한다.

### B안. 도구 이름 보충만 제한적으로 정리

- 의견: P4-7.1/P4-7.2가 길어 보이는 주된 이유가 도구 이름 보충이라면, 본문 절차는 유지하고 보충 표의 목적만 더 분명히 하면 된다.
- 장점: 압축으로 절차 설명이 약해지는 위험을 줄인다.
- 단점: 본문 길이는 크게 줄지 않는다.
- 채택 기준: 수정 범위를 줄이면서 효과를 보고 싶다면 이 안을 먼저 택한다.

### C안. 알고리즘 장의 예제 흐름을 baseline 비교 틀로 점검

- 의견: 선형회귀, 로지스틱 회귀, 트리, 앙상블 장의 사례와 예제가 baseline 비교 렌즈를 보여 주는지 확인하면 Part 4의 카탈로그화 위험을 줄일 수 있다.
- 장점: Part 4의 핵심 메시지인 `비교 기준으로 알고리즘을 읽기`가 살아난다.
- 단점: P4-7의 길이 문제는 별도로 남는다.
- 채택 기준: 알고리즘 장 독해 흐름을 먼저 개선하려면 이 안이 적합하다.

### 권장안

A안을 먼저 처리한 뒤 필요하면 B안과 C안을 적용한다. Part 4는 범위가 넓으므로 한 번에 전체 제목을 바꾸기보다 핵심 연결부와 알고리즘 장의 사례·예제 흐름을 나누어 확인하는 편이 안전하다.

## 다음 작업 순서 제안

1. P4-7.1/P4-7.2의 사례와 예제가 전처리 판단 절차를 실제로 돕는지 확인한다.
2. 도구 이름 보충이 본문 흐름을 압도하는 부분만 제한적으로 정리한다.
3. 알고리즘 장의 예제가 baseline 비교 판단을 보여 주는지 확인한다.
4. 변경 뒤 다국어 원고를 Section ID 기준으로 동기화한다.
