# 범위 안내 분리 리포트

작성일: 2026-07-17
검토 기준: `AGENTS.md`, `management/guidelines/manuscript-writing-workflow.md`

## 목적

원고의 범위 안내 문장에서 다음 두 부류를 분리해 판단하기 위한 운영 기준을 정리한다.

- 회수하는 것이 독자에게 도움이 되는 것
- 언급하지 않는 것이 독자에게 도움이 되는 것

핵심은 `무엇을 안 다룬다`를 많이 적는 일이 아니라, 독자의 다음 이해를 실제로 돕는 문장만 남기는 것이다.

이번 리포트는 특정 Part만이 아니라 `Part 1`부터 `Part 7`까지 전체 본편을 대상으로 본다.

## 기준 문장

- 뒤에서 실제로 회수할 내용이면 `범위 밖`보다 `어디서 이어지는가`를 보여 주는 편이 낫다.
- 뒤에서 회수하지 않을 내용이면, 그 사실을 적는 것 자체가 현재 절의 중심 질문을 흐리면 아예 언급하지 않는 편이 낫다.
- 따라서 범위 안내는 `회수할 것`과 `굳이 꺼내지 않을 것`을 같은 문단에서 섞지 않는다.

## 리포트 갱신 규칙

이 문서를 이후에도 작업 큐로 유지하려면, 실제 본문을 수정한 뒤 다음 네 가지를 가능하면 같은 작업 안에서 함께 갱신한다.

1. `전체 Part 관찰`의 검색 건수
2. `삭제 쪽으로 먼저 정리할 축`과 `회수 문장으로 남겨야 할 축`
3. `이미 정리한 축`
4. `다음 실행 순서`

특히 어떤 Part를 한 묶음으로 정리했다면, 건수만 줄이고 우선 대상 목록을 그대로 두지 않는다. 반대로 검색 건수는 남아 있어도, 사람이 다시 읽어 `실제 수정 필요가 낮다`고 판단한 절은 우선 대상에서 뺄 수 있다.

## 1. 회수하는 것이 독자에게 도움이 되는 것

이 부류는 독자가 현재 절을 읽으며 자연스럽게 떠올릴 다음 질문이고, 그 질문이 실제 본문이나 보충학습에서 다시 이어질 때 해당한다.

### 판단 기준

- 바로 다음 Section이나 같은 Chapter의 후속 Section에서 실제로 이어진다.
- 현재 절의 핵심 개념이 뒤 절의 핵심 질문으로 직접 확장된다.
- 이 연결을 적지 않으면 독자가 `설명이 끊겼다`고 느낄 가능성이 높다.
- 실제 회수 위치를 `Section ID`로 적을 수 있다.

### 이런 항목은 남기는 편이 좋다

- 현재 절의 개념이 바로 다음 절에서 구조적으로 확장되는 경우
- 같은 Part 안에서 독자가 곧 다시 만나게 될 핵심 질문
- 보충학습으로 보내더라도, 그 보충학습이 현재 절 이해를 보완하는 실제 경로일 때

### 대표 예

- `P5-12.1 -> P5-12.2`
  - RNN/LSTM/GRU의 필요성을 본 뒤 장기 의존성 문제로 넘어가는 연결
- `P5-13.1 -> P5-13.2 -> P5-14.1`
  - attention에서 self-attention, Transformer 블록으로 확장되는 연결
- `P6-12.1 -> P6-12.2 -> P6-13.1`
  - tool use에서 function calling, agent 구조로 이어지는 연결

### 권장 문장 형태

- `이번 절은 X까지를 닫고, 다음 절 Pn-n.n에서는 Y를 이어서 본다.`
- `여기서 잡은 기준은 보충학습 Pn-n.n에서 Z를 읽을 때 다시 쓴다.`

## 2. 언급하지 않는 것이 독자에게 도움이 되는 것

이 부류는 뒤에서 회수하지 않거나, 회수 여부와 무관하게 현재 절의 중심 질문을 읽는 데 필요하지 않은 항목이다. 이런 내용은 `범위 밖`이라고 친절하게 적어도 독자에게는 대개 불필요한 인지 부하로 작동한다.

### 판단 기준

- 뒤에서 다시 다루는 위치가 없다.
- 현재 절의 중심 질문을 이해하는 데 없어도 된다.
- 적는 순간 독자의 시야가 본문 핵심보다 `빠진 것 목록`으로 이동한다.
- 최신 구현 경쟁, 벤치마크, 제품 스펙, 상세 증명처럼 현재 책의 설명 책임과 거리가 있다.

### 이런 항목은 빼는 편이 좋다

- 최신 벤치마크 경쟁, 구현 최적화 경쟁
- 특정 프레임워크 내부 구조 세부
- 엄밀한 수식 증명 전체를 이번 책에서 끝까지 추적하지 않는 경우
- 제품별 가격표, API 스펙 전체, 세부 튜닝 노하우처럼 빠르게 변하는 항목

### 대표 예

- `P5-9.1`
  - CUDA 내부 최적화, TPU/NPU 상세 비교
- `P5-10.1`
  - disentanglement, 최신 self-supervised representation 세부 기법
- `P5-14.2`
  - long-context 최적화의 최신 벤치마크 경쟁
- `P6-16.1`
  - 구체적 클라우드 가격표, GPU 인프라 수치 설계 전부

### 편집 원칙

- 이런 항목은 가능하면 문장째 삭제한다.
- 삭제 후 빈자리는 `이번 절에서 닫을 질문`과 `바로 이어질 질문`으로 채운다.
- `현재 본편 범위 밖에 둡니다`라는 한 문장으로 남기지 않는다.

## 3. 실제 편집 규칙

Section의 범위 안내를 고칠 때는 아래 순서로 판단한다.

1. 이 항목은 뒤에서 실제로 회수되는가?
2. 회수된다면, 그 연결을 적는 것이 현재 절 이해를 돕는가?
3. 회수되지 않는다면, 굳이 적지 않는 편이 현재 절 집중도를 높이는가?

판정은 다음처럼 단순화한다.

- `예, 회수되고 독자에게 도움 됨` -> 남긴다. `Section ID`로 연결한다.
- `아니오, 회수되지 않음` -> 원칙적으로 쓰지 않는다.
- `회수는 되지만 지금 적으면 산만함` -> 현재 절에서는 지우고, 실제 회수 절에서만 다시 잡는다.

### 자주 쓰는 문장 전환 패턴

아래 패턴은 실제 편집에서 자주 나오는 문장을 어떤 방향으로 바꿀지 보여 주는 최소 예시다.

1. `이 절에서는 A, B, C를 깊게 다루지 않습니다.`
   -> `이번 절은 X를 이해하는 데 필요한 기준까지를 먼저 닫는다. A는 Pn-n.n에서 이어서 보고, B와 C는 여기서 먼저 꺼내지 않는다.`
2. `A, B, C는 현재 본편 범위 밖에 둡니다.`
   -> `이번 절은 X에 집중한다.`
3. `A는 다음 절에서, B는 보충학습에서, C는 범위 밖입니다.`
   -> `이번 절은 X까지를 다루고, 다음 절 Pn-n.n에서는 A를 이어서 본다. B가 현재 이해에 꼭 필요하면 보충학습 Pn-n.n으로 연결하고, C는 문장째 덜어낸다.`
4. `여기서는 자세한 구현을 다루지 않습니다.`
   -> `여기서는 X가 왜 필요한지와 어떻게 읽는지만 먼저 잡는다.`

핵심은 `안 다룬다`를 덜 말하는 것이 아니라, 그 자리를 `이번 절에서 닫을 질문`과 `실제 다음 읽기 경로`로 바꾸는 데 있다.

## 4. 전체 Part 관찰

현재 시점 전수 검색 기준으로 범위 안내 관련 표현은 다음처럼 줄어든 상태다.

- `Part 1`: 1건
- `Part 2`: 0건
- `Part 3`: 0건
- `Part 4`: 2건
- `Part 5`: 0건
- `Part 6`: 0건
- `Part 7`: 6건

이 숫자는 `정규식에 걸린 잔여 표현 수`이지, 곧바로 `모두 수정해야 하는 문제 수`를 뜻하지는 않는다. 같은 표현이라도 어떤 곳은 실제 handoff로 유효하고, 어떤 곳은 삭제 대상이며, 어떤 곳은 이미 충분히 무해한 맥락일 수 있다. 따라서 이 리포트의 후반부 우선 대상 목록은 단순 검색 건수가 아니라 직접 읽고 다시 판정한 후보 목록으로 봐야 한다.

양이 많다고 항상 문제가 큰 것은 아니다. 중요한 것은 각 Part가 `다음 학습으로 실제 이어지는 질문`을 남기는지, 아니면 `지금 안 다루는 목록`을 독자 앞에 먼저 세우는지다.

특히 `Part 5`와 `Part 6`은 이번 정리 작업으로 검색 기준 0건까지 내려왔다. 다만 이는 `정규식 기준 1차 정리 완료`를 뜻하며, 이후에도 handoff 문장이 실제로 유효한지 내용 검토는 별도로 이어질 수 있다.

### 이 리포트 사용 순서

1. 먼저 위 건수 표로 `어느 Part에 잔여 표현이 많은가`를 본다.
2. 그다음 `현재 원고에 바로 적용할 우선 대상`에서 실제 수정 후보만 다시 본다.
3. 작업을 시작하기 전에는 `이미 정리한 축`에 같은 Section이 들어 있는지 확인해 중복 수정을 피한다.
4. 실제 집행 순서는 `다음 실행 순서`를 기본 큐로 삼되, 같은 Chapter를 묶어 효율적으로 처리할 수 있으면 그 안에서 순서를 조정한다.

### Part 1

`Part 1`은 입문 Part라서 뒤 Part로 연결하는 예고가 자주 필요하다. 이 Part에서는 `회수형 안내`가 실제로 도움이 되는 경우가 많다.

회수로 남길 것이 많은 대표 예:

- `P1-10.2 -> P1-10.3`
- `P1-12.1 -> P1-12.2, P1-12.3`
- `P1-14.4 -> P1-14.5 -> P1-14.6`

이유:

- 입문 Part의 목적상 `지금은 기본 구분만 잡고, 다음 절에서 무엇을 더 분리하는가`를 알려 주는 것이 독자의 길찾기에 직접 도움 된다.
- 현재 검색 기준 잔여 1건은 `P1-7.2` 표 안의 `범위 밖 문장` 같은 일반 용례라서, 범위 안내 문장 정리 작업은 사실상 1차 마감 상태로 본다.

언급하지 않는 편이 더 나은 대표 예:

- `P1-14.5`의 `에이전트 하네스의 엄밀한 학술 정의 논쟁`
- `P1-14.6`의 `사업자별 가격표와 인프라 설계 비교`
- `P1-13.4`의 `HNSW`, `FAISS`, `product quantization` 내부 구현

이유:

- 이런 항목은 뒤에서 본격 회수되지 않거나, 현재 절의 입문 질문보다 더 큰 외부 맥락을 불러온다.

### Part 2

`Part 2`는 선행지식 복구 Part라서 `지금은 읽기 감각만 잡고, 계산·구현·설치 세부는 뒤로 넘긴다`는 문장이 많다. 전체적으로는 `회수형 안내`와 `삭제형 안내`가 가장 강하게 섞인 Part다.

회수로 남길 것이 많은 대표 예:

- `P2-3.1 -> P2-3.2 -> P2-3.3`
- `P2-7.5 -> P2-7.7 -> P2-7.8 -> P2-7.9`
- `P2-11.1 -> P2-11.2 -> P2-11.4`
- `P2-12.1 -> P2-12.2 -> P2-12.3`

이유:

- 이 Part는 독자가 실제로 같은 Chapter 안에서 막히기 쉬워서, 바로 다음 절이나 보충학습으로의 회수 경로가 실제 학습 보조 역할을 한다.

언급하지 않는 편이 더 나은 대표 예:

- 운영체제별 설치 화면 비교 전체
- PATH 수동 수정 절차의 세부 분기
- NumPy 내부 메모리 배치와 GPU 계산 세부
- Matplotlib의 출판용 스타일링 전체

이유:

- 이런 항목은 초심자에게 `당장 배워야 할 것처럼 보이게` 만들기 쉽고, 현재 절의 기본 문해 목표와 직접 연결되지 않는다.

### Part 3

`Part 3`은 범위 생략 문장 자체가 매우 적다. 실제로는 `회수`보다 `현재 질문을 끝까지 닫는 방식`이 더 안정적인 Part다.

회수로 남길 것이 많은 대표 예:

- `P3-1.1 -> P3-1.2`
- `P3-2.* -> P3-5.*`

이유:

- Part 3은 샘플, 특징, 기준선, 출력 구조가 순서대로 이어지는 설계 Part라서, 범위 공지보다 구조적 handoff만 남겨도 충분한 경우가 많다.

언급하지 않는 편이 더 나은 대표 예:

- 별도 범위 밖 주제 열거 전반

이유:

- Part 3은 이미 현재 질문 중심으로 잘 닫히는 편이라, 불필요한 생략 공지를 넣으면 오히려 밀도가 떨어질 가능성이 높다.

### Part 4

`Part 4`는 모델·평가·튜닝·해석을 다루면서 수식 증명, 고급 최적화, 구현 세부를 자주 밀어내고 있다. 이 Part는 `회수형`과 `삭제형`을 가장 세밀하게 구분해야 한다.

회수로 남길 것이 많은 대표 예:

- `P4-9.1 -> P4-9.2 -> P4-9.3`
- `P4-11.1 -> P4-11.2 -> P4-11.3 -> P4-11.4 -> P4-11.5`
- `P4-13.1 -> P4-13.2`

이유:

- 같은 모델을 `출력`, `경계`, `학습 목적`, `다중 클래스`, `설정값`으로 나눠 읽는 구조이므로, 실제 회수 경로를 남겨 주는 것이 독자에게 유리하다.

언급하지 않는 편이 더 나은 대표 예:

- convex optimization 일반론
- solver 내부 알고리즘 증명
- plot 구현 세부
- 고차원 초평면의 엄밀한 기하 전개

이유:

- 이런 항목은 현재 절에서 `판단 기준을 읽는 일`보다 `수학 외연`을 먼저 떠올리게 한다.

### Part 5

`Part 5`는 후반 구조 전환이 많아서 회수 경로를 남기는 일이 중요하지만, 동시에 최신 구현 경쟁과 고급 수식 전개를 자주 언급해 시야를 분산시키는 문제도 크다.

회수로 남길 것이 많은 대표 예:

- `P5-12.1 -> P5-12.2 -> P5-13.1 -> P5-13.2 -> P5-14.1 -> P5-14.2`
- `P5-11.1 -> P5-11.2 -> P5-11.3`
- `P5-15.1 -> P5-15.2`

이유:

- 이 구간은 `상태 전달 -> 직접 참조 -> 블록 구조 -> 생성`으로 손잡이가 실제로 이동하므로 handoff 문장이 학습 구조 자체를 만든다.

언급하지 않는 편이 더 나은 대표 예:

- 최신 vision architecture 상세 비교
- long-context 최적화의 최신 벤치마크 경쟁
- diffusion, GAN, VAE 전체 비교
- 구현 최적화와 세부 수식 전개 전반

이유:

- 이 항목들은 대개 본문 책임보다 바깥의 비교 경쟁을 불러오고, 현재 절의 핵심 질문을 흐린다.

### Part 6

`Part 6`은 서비스 구조 Part라서 `다음 절에서 구조가 어떻게 커지는가`를 남기는 것은 유익하지만, 빠르게 변하는 제품·운영 세부를 굳이 범위 공지로 드러내는 것은 대체로 손해다.

회수로 남길 것이 많은 대표 예:

- `P6-10.* -> P6-11.* -> P6-12.* -> P6-13.*`
- `P6-14.2 -> P6-15.* -> P6-16.*`
- `P6-18.* -> P6-19.*`

이유:

- 검색, 도구 사용, 에이전트, 하네스, 평가, 운영은 실제로 연속된 서비스 층위라서, handoff를 분명히 적는 편이 구조 이해에 도움이 된다.

언급하지 않는 편이 더 나은 대표 예:

- 특정 API 스펙 전체
- 상용 모델 벤치마크 경쟁
- 클라우드 가격표와 GPU 수치 설계 전부
- 프레임워크별 SDK 구현 세부

이유:

- 이런 항목은 시간에 민감하고, 현재 절의 구조 설명보다 도구 비교나 제품 선택 쪽으로 시선을 빼앗는다.

### Part 7

`Part 7`은 프로젝트 Part라서 `다음 절에서 어떤 검토를 이어 할 것인가`를 남기는 문장이 실제 과제 흐름에 도움이 된다. 반면 거대한 운영 인프라 외연은 거의 모두 삭제 쪽이 맞다.

회수로 남길 것이 많은 대표 예:

- `P7-1.1 -> P7-1.2 -> P7-2.*`
- `P7-3.1 -> P7-3.2`
- `P7-6.1 -> P7-6.2 -> P7-7.1 -> P7-7.2`

이유:

- 프로젝트 Part는 `이번 실행 결과를 다음 검토 대상으로 넘기는가`가 핵심이라, handoff 자체가 학습 활동의 일부다.

언급하지 않는 편이 더 나은 대표 예:

- 대규모 학습 인프라
- 상용 서비스 수준의 전체 보안 설계
- 세부 배포 자동화 인프라 전반

이유:

- 이 Part의 목표는 프로젝트 입문과 검토 기록 훈련이지, 운영 조직 전체 설계를 열거하는 데 있지 않다.

## 5. Part 시작 페이지와 범위 안내

Part 시작 페이지는 Section보다 예외를 조금 더 허용할 수 있다. 다만 여기서도 기준은 같다.

- 뒤 Chapter 전반의 읽기 경로를 잡아 주는 범위 안내는 남길 수 있다.
- 단지 `이 Part는 이것저것 다 안 다룬다`는 목록은 줄이는 편이 낫다.

Part별 판단은 다음처럼 정리할 수 있다.

- `Part 1`, `Part 2`, `Part 4`, `Part 5`, `Part 6`, `Part 7`
  - 시작 페이지에서 큰 handoff는 유효하다.
- `Part 3`
  - 이미 설계 흐름이 선명하므로 과도한 생략 목록은 특히 불필요하다.

### 정리 완료로 보는 기준

이 작업은 검색 건수가 `0`이 되는 순간으로 끝나지 않는다. 반대로 검색 건수가 조금 남아 있어도, 아래 조건을 만족하면 이 리포트 기준의 1차 정리는 끝난 것으로 본다.

1. 잔여 표현을 다시 읽었을 때, 대부분이 `실제 다음 Section이나 보충학습으로 이어지는 handoff`다.
2. `mixed precision`, `quantization`, `inference serving 인프라`처럼 현재 절의 직접 질문과 무관한 고급 실무 항목을 범위 안내에 나열한 문장은 우선 정리돼 있다.
3. `현재 본편 범위 밖` 문장이 남아 있더라도, 정말로 현재 책 범위 경계를 짚어야 하는 드문 경우로 제한돼 있다.
4. `현재 원고에 바로 적용할 우선 대상`과 `이미 정리한 축`이 최신 상태라서, 같은 절을 반복 점검하지 않게 되어 있다.
5. 검색 건수와 우선 대상 목록이 서로 어긋나지 않고, 다음 작업 큐가 실제 잔여 문제를 반영한다.

즉 이 리포트의 완료 판정은 `표현이 남아 있는가`보다 `남아 있는 표현이 왜 남아 있는가`를 설명할 수 있는가에 가깝다.

## 7. 결론

범위 안내의 목표는 `생략 사실 통보`가 아니라 `독자의 읽기 경로 관리`다. 따라서 앞으로는 다음처럼 나눈다.

- 실제로 이어질 내용은 회수 문장으로 남긴다.
- 실제로 이어지지 않거나, 적는 편이 산만한 내용은 아예 언급하지 않는다.

전체 Part를 놓고 보면 차이는 더 분명하다.

- `Part 1`, `Part 2`, `Part 4`, `Part 5`, `Part 6`, `Part 7`은 회수형 안내가 실제 학습 경로를 돕는 경우가 많다.
- `Part 3`은 범위 안내보다 현재 질문을 닫는 밀도 자체가 더 중요하다.
- 모든 Part에서 공통으로, `회수되지 않는 고급 외연`은 친절하게 적기보다 지우는 편이 독자 집중도에 유리하다.

이 원칙을 적용하면 범위 안내는 짧아지지만, 오히려 각 Section과 Part의 학습 책임은 더 선명해진다.
