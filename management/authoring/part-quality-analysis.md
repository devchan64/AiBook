# 파트별 교재 품질 분석

## 목적

이 문서는 현재 원고를 `교재로서 얼마나 읽히는가`라는 기준으로 Part 단위로 점검한 관리 문서입니다.
Section별 근거 메모는 이미 많이 존재하므로, 여기서는 더 큰 층위에서 다음 질문에 답합니다.

- 각 Part의 역할이 독자에게 분명한가
- 초심자가 따라갈 수 있는 학습 흐름이 유지되는가
- 근거, 예시, 실습, 회고가 교재 수준으로 연결되는가
- 지금 상태에서 무엇이 가장 큰 품질 리스크인가
- 다음 보강 우선순위는 무엇인가

분석 기준일: 2026-07-01

## 분석 기준

Part별 평가는 다음 여섯 기준으로 봅니다.

| 기준 | 질문 |
| --- | --- |
| 역할 선명도 | 이 Part가 왜 필요한지, 앞뒤 Part와 어떻게 연결되는지가 분명한가 |
| 초심자 적합성 | 용어 밀도, 설명 흐름, 예시 크기가 초심자 기준에 맞는가 |
| 교재 구조 완성도 | index, chapter, section, summary가 한 학습 흐름으로 닫히는가 |
| 근거와 검증 | 핵심 주장에 대응하는 evidence 메모와 출처 체계가 충분한가 |
| 실습/산출물 연결 | 예시, 코드, 출력, 프로젝트 산출물이 실제 학습 행동으로 이어지는가 |
| 잔여 리스크 | 현재 상태에서 독해 혼란이나 보강 필요성이 큰 지점은 어디인가 |

평가 표현은 `강함`, `보통`, `취약`으로만 단순 표기합니다.

### 확인한 대표 파일

- `management/authoring/part-01-open-checklist.md`

### 판정

| 항목 | 평가 | 메모 |
| --- | --- | --- |
| 역할 선명도 | 강함 | AI 전체 지형을 먼저 잡는 이유가 index에서 잘 드러납니다. |
| 초심자 적합성 | 보통 | 용어 구분은 좋지만 다루는 범위가 넓어 첫 독해 부담이 큽니다. |
| 교재 구조 완성도 | 강함 | 역사, 규칙, 학습, LLM, 서비스, 윤리까지 큰 흐름이 살아 있습니다. |
| 근거와 검증 | 강함 | Section evidence 메모가 가장 촘촘한 Part입니다. |
| 실습/산출물 연결 | 보통 | 개념 중심 Part라 실습 밀도는 의도적으로 낮지만, 일부 예시가 더 작아질 수 있습니다. |
| 잔여 리스크 | 보통 | 범위가 넓어 `개론이 너무 많은 것을 약속한다`는 인상을 줄 수 있습니다. |

### 강점

- 책 전체의 용어 경계와 학습 지도를 세우는 역할이 분명합니다.
- `AI = LLM` 혼동을 초반에 끊어 주는 구조가 교재 전체를 안정시킵니다.
- 규칙 기반 접근, 확률, 학습, 딥러닝, 서비스 구조를 한 지도 안에 두려는 편집 의도가 일관됩니다.

### 리스크

- 17개 Chapter 구성은 개론 Part로는 밀도가 높습니다.
- 초심자가 Part 1에서 너무 오래 머물면 `아직 아무것도 직접 해 보지 못했다`고 느낄 수 있습니다.
- open checklist가 13개로 가장 많아, 아직 저자 판단이 완전히 닫히지 않은 영역이 많습니다.

### 우선 보강점

1. `추천/순위화`, `제어/행동`, 검색 서비스 예시를 더 짧은 업무 장면으로 압축합니다.
2. 역사와 용어 구분 문단에서 `지금은 이 정도만 기억하면 충분하다`에 해당하는 최소 기억점을 더 분명히 남깁니다.
3. Part 3, Part 4, Part 5에서 실제로 회수되는 지점을 더 자주 명시해 개론 과밀감을 줄입니다.

| 초심자 적합성 | 보통 | 친절한 편이지만 범위가 넓어 수학/코드/도구가 다시 흩어질 위험이 있습니다. |
| 교재 구조 완성도 | 강함 | 수식, Python, NumPy, Pandas, Matplotlib, Git이 하나의 흐름으로 배치되어 있습니다. |
| 근거와 검증 | 보통 | Section evidence는 넓게 있으나, 교재 품질의 핵심은 연결 문장의 자연스러움입니다. |
| 실습/산출물 연결 | 강함 | 실행 환경, 코드, 출력, 도구 사용이 실제 학습 행동으로 이어지기 쉽습니다. |
| 잔여 리스크 | 보통 | 초심자에게는 `도구가 너무 많다`는 피로를 줄 수 있습니다. |

### 강점

- 책 전체에서 가장 실용적인 진입 장치 역할을 합니다.
- `수학은 증명 과목이 아니라 계산 언어`라는 방향이 교재 목적과 잘 맞습니다.
- Part 3로 넘어가기 위한 사전 조건을 명시적으로 정리하고 있습니다.

### 리스크

- Chapter 수와 Section 수가 많아 Part 2 자체가 하나의 긴 코스처럼 느껴질 수 있습니다.
- 보충학습과 본문 연결 문장이 약하면 초심자가 본류와 보강 절을 따로 읽게 됩니다.
- Git까지 포함한 구성은 장점이지만, AI 학습 기초로 왜 필요한지 계속 회수하지 않으면 외삽처럼 보일 수 있습니다.

### 우선 보강점

1. 각 도구 장 앞머리에서 `왜 지금 필요한가`를 더 짧고 반복적으로 고정합니다.
2. 보충학습 절과 본문 Section 사이의 왕복 링크 문장을 늘립니다.
3. Part 2의 끝에서 Part 3 진입 전 체크포인트를 더 실전형 질문으로 바꿉니다.

| 초심자 적합성 | 강함 | 문제 정의, 데이터 분리, 평가 지표를 먼저 두는 편집이 안정적입니다. |
| 교재 구조 완성도 | 강함 | 지도/비지도/강화학습과 평가·일반화 흐름이 잘 닫힙니다. |
| 근거와 검증 | 강함 | evidence 메모가 넓고, 교재 핵심 주장도 비교적 안정적입니다. |
| 실습/산출물 연결 | 보통 | 모델 직관은 충분하지만, 오류 사례 비교와 baseline 강조를 더 밀어도 됩니다. |
| 잔여 리스크 | 보통 | 후반의 강화학습, calibration 계열은 아직 경계 정리가 더 필요합니다. |

### 강점

- 현재 원고 전체에서 교재 구조가 가장 안정적인 Part 중 하나입니다.
- `문제-데이터-학습-평가-적용` 흐름이 잘 살아 있습니다.
- Part 4로 넘어갈 이유가 자연스럽습니다.

### 리스크

- 전통 모델 장에서 알고리즘 수가 많아지면 다시 `모델 카탈로그`로 보일 수 있습니다.
- calibration, reliability, log loss 같은 품질 주제가 어디까지 본편인지 아직 덜 닫혀 있습니다.
- 강화학습 수학 보강을 별도 절로 뺄지 여부가 남아 있습니다.

### 우선 보강점

1. baseline, 오류 사례, confusion 사례를 더 눈에 보이게 정리합니다.
2. 대표 모델 간 선택 기준을 작은 표와 작은 데이터 장면으로 더 자주 대비합니다.
3. calibration 계열은 본편/보충학습 경계를 조기에 확정합니다.

### 확인한 대표 파일

- `docs/parts/part-04/index.md`
- `docs/parts/part-04/summary.md`
- `management/authoring/part-04-open-checklist.md`

### 판정

| 항목 | 평가 | 메모 |
| --- | --- | --- |
| 역할 선명도 | 강함 | Part 1~3에서 미룬 딥러닝 본문 설명을 회수하는 책임이 분명합니다. |
| 초심자 적합성 | 보통 | 계산 구조 밀도가 높아질 수밖에 없어 설명의 호흡 관리가 중요합니다. |
| 교재 구조 완성도 | 보통 | 큰 축은 좋지만, 구조 설명과 예고 설명이 섞이면 약해질 위험이 있습니다. |
| 근거와 검증 | 강함 | 핵심 구조별 evidence 메모가 넓게 구축되어 있습니다. |
| 실습/산출물 연결 | 보통 | 구조 이해는 강하지만, 독자가 직접 확인할 수 있는 최소 실험 감각은 더 보강 여지가 있습니다. |
| 잔여 리스크 | 보통 | CNN, RNN, Attention, Transformer가 `이름 소개`처럼 보일 위험이 남아 있습니다. |

### 강점

- Part 5를 떠받치는 핵심 구조 Part라는 자기 역할 인식이 분명합니다.
- 표현 학습, 역전파, optimizer, GPU, Attention을 같은 흐름으로 묶으려는 설계가 좋습니다.
- 단순 유행어 나열을 피하려는 의도가 선명합니다.

### 리스크

- open checklist가 지적하듯, `뒤에서 다시 본다`는 유예 문장이 많아지면 Part 4 자체 설명이 약해집니다.
- 초심자는 구조 문제와 학습 절차 문제를 쉽게 섞습니다.
- Transformer 이전 구조가 단지 전사(前史)처럼 읽히면 교재 완성도가 떨어집니다.

### 우선 보강점

1. 각 구조 장에서 `어떤 데이터 구조 문제 때문에 나왔는가`를 첫 문단에서 고정합니다.
2. 같은 절 안에서 구조 설명과 학습 절차 설명이 섞이면 표로 분리합니다.
3. CNN, RNN, LSTM, Transformer를 `대체 역사`가 아니라 `문제 구조별 선택`으로 더 명확히 닫습니다.

| 초심자 적합성 | 보통 | 서비스 경험과 구조 용어가 함께 나와 독해 난도가 높습니다. |
| 교재 구조 완성도 | 보통 | 범위는 탄탄하지만, 순서 재배치와 배경 축 압축이 아직 남아 있습니다. |
| 근거와 검증 | 강함 | 토큰, 임베딩, RAG, 평가, 운영까지 evidence 기반이 넓습니다. |
| 실습/산출물 연결 | 강함 | RAG, tool use, agent, evaluation을 Part 6 산출물과 연결하려는 방향이 좋습니다. |
| 잔여 리스크 | 취약 | 현재 전체 책에서 구조 재배치 필요성이 가장 큰 Part입니다. |

### 강점

- 최근 독자의 관심사와 직접 연결되는 핵심 Part입니다.
- 모델 내부 원리와 서비스 연결 구조를 함께 설명하려는 편집 방향이 좋습니다.
- Part 6 프로젝트 문서와 연결되는 산출물 언어가 이미 제시되어 있습니다.

### 리스크

- open checklist 9개가 말하듯, 순서와 본류/배경 축이 아직 완전히 고정되지 않았습니다.
- 역사, 계보, BERT 배경, 임베딩, RAG, 운영 설명이 서로 좋은 내용이지만 흐름상 경합하고 있습니다.
- 독자는 챗봇 경험 때문에 쉽게 읽기 시작하지만, 실제로는 개념 난도가 높아 중도 피로가 생길 수 있습니다.

### 우선 보강점

1. 본류를 `토큰 -> Transformer -> GPT -> 조정 -> RAG -> 도구/agent -> 평가/운영`으로 더 강하게 고정합니다.
2. 역사/배경 장은 본류 설명을 방해하지 않도록 압축하거나 보충학습으로 재배치합니다.
3. 토큰 비용, 지연, 문맥 길이 같은 운영 감각은 더 작은 예제로 보강합니다.

| 실습/산출물 연결 | 강함 | 책 전체를 실제 산출물로 닫아 주는 역할이 뚜렷합니다. |
| 잔여 리스크 | 보통 | 프로젝트 문서 형식이 선언에 비해 예시 밀도가 약하면 추상적으로 남을 수 있습니다. |

### 강점

- 많은 AI 입문서가 약한 `기록과 회고`를 전면에 둡니다.
- 분석 프로젝트, 모델 프로젝트, RAG/agent 프로젝트를 다른 산출물 구조로 보게 하는 점이 좋습니다.
- Part 1~5에서 배운 것을 실제 학습 행동으로 회수하는 마감 Part 역할이 분명합니다.

### 리스크

- 템플릿과 예시가 충분하지 않으면 좋은 원칙 문서로만 남을 수 있습니다.
- Part 6의 산출물 이름들이 강점이지만, 초심자에게는 낯선 메타 용어처럼 보일 수 있습니다.

### 우선 보강점

1. 실패 기록과 회고 템플릿을 더 짧고 바로 따라 쓸 수 있게 만듭니다.
2. 각 프로젝트 축마다 최소 1개씩 `나쁜 기록`과 `좋은 기록` 예시를 대비합니다.
3. Part 5 산출물 언어와 Part 6 템플릿이 실제로 같은 용어를 쓰는지 맞춥니다.
