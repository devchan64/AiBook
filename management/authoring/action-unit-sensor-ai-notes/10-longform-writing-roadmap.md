# 10개 노트를 1000라인급 장문 원고로 키우기 위한 작성 로드맵

## 이 노트의 목적

이 노트는 이번에 만든 10개 노트를 앞으로 어떻게 장문 원고로 확장할지 정리한다.

현재 본문 반영 기준은 `../action-unit-sensor-aibook-update-preparation.md`를 따른다.

동작 단위 센서 사례는 Part 7 연습 Section에만 작성하며, 다른 Part에 분산 배치하는 아이디어는 현재 실행 계획에서 제외한다.

현재 상태는 `주제와 구조를 잡은 준비 초안`이다.

사용자 목표인 `노트 1개당 1000라인 수준`에 가까워지려면, 단순히 설명을 늘리는 것이 아니라 각 노트 안에 실습, 표, 도식, 질문, 비교, 용어 정리, Part 연결을 체계적으로 채워 넣어야 한다.

## 먼저 분명히 할 점

이번 단계의 산출물은 10개 노트의 뼈대를 세우고, 책을 풍부하게 만들 수 있는 주제 축을 안전하게 정리한 것이다.

아직 각 노트가 1000라인급 장문은 아니다.

하지만 1000라인으로 키울 수 있도록 다음 요소를 미리 넣었다.

- 중심 질문
- 책 연결 위치
- 공개 안전 원칙
- 실습 후보
- 시각화 후보
- 확장 체크리스트

## 1000라인을 채우는 안전한 방법

길이를 늘리기 위해 같은 말을 반복하면 안 된다.

대신 다음 재료를 층위별로 추가한다.

- 개념 설명을 `왜`, `어떻게`, `무엇이 달라지나`로 분해
- 같은 개념의 다른 예시 3개
- 반례 2개
- Python 코드 2개
- 코드 출력 해석 2개
- 표 2개
- 도식 1~2개
- 책 연결 메모
- 생략 범위 메모

이렇게 하면 1000라인이 단순 분량이 아니라 실제로 읽을 가치가 있는 장문이 된다.

## 대외비 방지 체크리스트

장문 확장 전마다 아래를 확인한다.

- 구현 전용 경로나 식별 표기가 들어갔는가
- 버전 문자열이나 내부 분류 체계를 직접 옮겼는가
- 장비 식별 규칙, 시간 규칙, 운영 규칙 세부를 그대로 옮겼는가
- 제품 내부 명칭이나 조직 맥락을 암시하는 표현이 남았는가
- 실제 로그 형태를 재구성할 만큼 상세한 샘플이 들어갔는가

하나라도 걸리면 일반화한다.

## 왜 관리형 노트도 1000라인이 될 수 있는가

관리형 노트가 짧아야 한다는 법은 없다.

오히려 장기 프로젝트에서는 다음 정보가 누적되며 장문이 된다.

- 결정 이유
- 기각한 대안
- 삽입 후보 문단
- 예상 리스크
- 용어 충돌 메모
- 일정 변경 메모
- 자산 제작 순서

즉 길이의 문제라기보다 정보 종류의 문제다.

## 장문 확장 시 품질 기준

분량이 늘수록 오히려 품질 기준이 더 필요하다.

### 기준 1. 줄 수보다 질문 밀도

각 섹션이 새로운 질문이나 결정을 추가해야 한다.

### 기준 2. 재사용 가능성

한 번 쓴 메모가 본문, 실습, 도식, 관리 판단 중 최소 하나에 재사용되어야 한다.

### 기준 3. 안전성

길어질수록 내부 문서의 흔적이 들어갈 위험이 커진다.

### 기준 4. 구조

나중에 검색과 재배치가 쉬워야 한다.

### 기준 5. 실제 작업 연결

로드맵 노트는 읽고 끝나는 문서가 아니라, 다음 행동으로 연결되어야 한다.

장문 노트는 그대로 책에 들어가지 않는다.

장문 노트의 기능은 다음과 같다.

- 본문 후보 문단의 저장소
- 예시와 반례의 저장소
- 실습 자산 설계서
- 편집 판단 기록

즉 장문 노트는 `본문 원천 재료`다.

## 본문 반영 전에 해야 할 축약 작업

노트가 길어질수록 그대로 본문에 넣고 싶은 유혹이 생긴다.

하지만 본문 반영 전에는 반드시 축약해야 한다.

### 축약 기준

- 현재 Section의 중심 질문과 직접 연결되는가
- 앞뒤 Section과 중복되지 않는가
- 관리 메모 문장이 아닌가
- 공개형 설명으로 충분히 일반화되었는가

## 근거 검토 메모와의 연결 방식

이 노트들은 아이디어 정리 문서이므로, 나중에 근거 검토 메모와 연결될 수 있어야 한다.

예를 들면 다음 연결이 가능하다.

- 동작 단위 사례를 통한 시계열 일반화 근거
- 기준선과 변화 추세 설명의 표준 자료
- 설명 가능한 특징 공학의 일반 자료
- 운영 모니터링과 false alarm 관련 자료

## 문체 기준

관리형 장문도 문체가 중요하다.

권장 문체는 다음과 같다.

- 선언형
- 비교 중심
- 메모이지만 검색 가능한 제목 사용
- 불필요한 감탄과 수사 배제

## 라인 수 목표를 다루는 태도

1000라인은 품질의 보장이 아니라 작업 밀도의 목표다.

따라서 다음을 동시에 봐야 한다.

- 줄 수가 늘었는가
- 새로운 정보가 늘었는가
- 재사용 가능한 구조가 생겼는가

즉 1000라인은 결과 지표이지, 작성 원리가 아니다.

- 분량 목표가 내용 품질을 압박할 수 있다

## 노트별 상태 추적 방식 제안

장문 노트가 많아지면 상태 추적 방식이 필요하다.

다음 정도의 상태 표기를 둘 수 있다.

- `seed`: 뼈대만 있음
- `growing`: 장문 확장 중
- `usable`: 본문/실습 전환 가능
- `linked`: Part 연결까지 반영됨

## 상태 판정 기준

### seed

- 중심 질문만 있다
- 섹션 수가 적다
- 실습/표/도식이 아직 부족하다

### growing

- 개념 설명이 생겼다
- 확장용 질문과 체크리스트가 있다
- 일부 실습 또는 표 후보가 있다

### usable

- 본문 후보 문단이 있다
- 실습 또는 도식 후보가 충분하다
- 비식별화 검토가 이루어졌다

### linked

- 실제 Part/Section 후보와 연결되었다
- 관리 메모 간 링크가 정리되었다

## 개념 노트 확장과 관리 노트 확장의 균형

개념 노트만 키우면 배치와 운영 판단이 약해진다.

관리 노트만 키우면 실제 본문 재료가 빈약해진다.

따라서 한 세션에서 다음 조합을 권장할 수 있다.

- 개념 노트 1개
- 관리 노트 1개

이 조합은 균형이 좋다.

## 내용 중복을 줄이는 규칙

### 규칙 1

같은 정의를 세 파일에서 반복하지 않는다.

### 규칙 2

반복이 필요하면 표현 층위를 바꾼다.

### 규칙 3

관리 노트의 문장은 본문 후보 문장과 구분한다.

### 규칙 4

실습 노트는 실행 산출물 중심으로 쓴다.

- 07은 모델링 사다리를 맡는다.
- 08은 Part 배치를 맡는다.
- 09는 실습과 자산 설계를 맡는다.
- 10은 전체 운영과 순서를 맡는다.

## 세션 종료 후 남길 수 있는 짧은 기록 항목

- 오늘 확장한 파일
- 새로 추가한 섹션 종류
- 민감 정보 점검 여부
- 다음 세션 첫 작업

## 운영용 한 줄 카드

- 먼저 역할을 본다.
- 그다음 분량을 본다.
- 마지막에 안전성을 본다.
- 그리고 다음 작업을 남긴다.

## 마지막 운영 정리

- 장문 노트는 원천 재료다.
- 관리 노트는 의사결정 기록이다.
- 실습 노트는 자산 설계서다.
- 로드맵 노트는 작업 시스템이다.

## 상태 관리용 짧은 표기 예시

- `draft`: 뼈대만 있는 상태
- `expanded`: 장문 확장 중인 상태
- `ready-for-reuse`: 본문이나 실습으로 옮길 준비가 된 상태
- `needs-review`: 중복 또는 안전성 검토가 더 필요한 상태

## 다음 단계 분기 기준

### 본문 반영으로 갈 때

- 본문 후보 문단이 충분히 쌓였을 때
- Part 배치가 어느 정도 정리되었을 때

### 실습 자산 제작으로 갈 때

- 공개형 데이터 구조가 안정되었을 때
- 시각화 질문이 명확해졌을 때

### 추가 장문 확장으로 갈 때

- 아직 반례나 실습이나 체크리스트가 부족할 때
- 다른 노트와의 연결이 약할 때

## 세션 로그에 남기기 좋은 항목

- 오늘 줄 수 변화
- 오늘 확장한 정보 유형
- 오늘 발견한 중복 위험
- 오늘 확인한 재사용 후보

## 운영 판단용 마지막 질문

- 다음 작업이 본문 초안인가
- 다음 작업이 CSV/도식 자산 생성인가
- 다음 작업이 근거 검토 메모 연결인가
- 다음 작업이 중복 제거 편집인가

## 로드맵 파일의 마지막 역할 정리

이 파일은 동작 단위 사례 묶음이 어디까지 왔는지 기록하고, 다음에 무엇을 해야 하는지 잊지 않게 만드는 작업 관제판 역할을 한다.

그리고 각 노트의 역할이 서로 겹치지 않도록 마지막에 다시 조정하는 기준 문서이기도 하다.
