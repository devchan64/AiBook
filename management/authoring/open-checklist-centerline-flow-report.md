# 오픈체크리스트 중심선 흐름 검토 리포트

작성일: 2026-07-29

## 검토 범위

- 대상 문서: `management/authoring/part-01-open-checklist.md`부터 `management/authoring/part-07-open-checklist.md`
- 대조 기준: `docs/table-of-contents.md`, `docs/parts/part-06/index.md`, `docs/parts/part-06/summary.md`, `management/guidelines/manuscript-writing-workflow.md`
- 검토 질문: 오픈체크리스트에 작성된 Section의 중심선이 실제 내용 전개로서 유의미한 전달력을 갖는가, 누락된 흐름이나 의도가 왜곡될 수 있는 순서가 있는가

## 요약 판정

- Part 1~5와 Part 7 체크포인트 노트는 대체로 `학습 관점 누락 점검 -> Section 경계 정리 -> 목차 기준 체크포인트` 구조를 유지한다.
- Part 1~5와 Part 7의 앞부분에는 특정 Section ID가 선행 점검 후보로 먼저 등장하므로 단순 ID 순서 검사는 흔들릴 수 있다. 그러나 `목차 기준 체크포인트` 본문은 목차 순서를 따르는 구조다.
- Part 6 체크포인트 노트는 가장 큰 보완 대상이었다. 개편 작업 완료표, 사라진 기준 문서 참조, 일부 Module 정밀검토 표가 섞여 있어 전체 Section 중심선 관리 문서로 읽기 어려웠다.
- 이번 정리에서 Part 6 체크포인트 노트를 다른 Part와 같은 구조로 재작성하고, 모든 현재 Section ID의 중심축을 목차 순서대로 보강했다.
- Part 1~7의 `목차 기준 체크포인트` 구간은 현재 원고의 Part 시작/마무리 페이지와 본문 Section ID를 빠짐없이 추적한다.

## 보완 완료 항목

- 기존 문제: `management/authoring/part-06-open-checklist.md`가 `part-06-restructure-proposal.md`를 기준 문서로 언급했지만, 현재 작업트리에는 해당 기준 문서가 없다.
- 기존 문제: `구조 적용 체크`에 배포 전 strict build 같은 작업 상태 항목이 남아 있어, 체크포인트 노트가 중심 주제 관리 문서인지 작업 로그인지 흐려졌다.
- 기존 문제: P6-3, P6-5~P6-9, P6-13~P6-15, P6-18~P6-20의 개별 Section 중심축이 목차 기준 체크포인트로 빠져 있었다.
- 기존 문제: 과거 개편 전 Section ID인 `P6-1.4`, `P6-1.5`, `P6-1.6`, `P6-1.7`, `P6-1.8`이 현재 체크리스트 본문에 남아 있어, 현재 목차의 중심선과 이전 아카이브 회수 기준이 섞일 수 있었다.
- 반영 내용: Part 6 체크포인트 노트를 `사용 원칙`, `학습 관점 누락 점검`, `Section 경계 정리`, `목차 기준 체크포인트` 구조로 재작성했다.
- 반영 내용: `P6-index`, `P6-summary`, `P6-1.1`부터 `P6-20.2`까지 현재 목차 기준 흐름을 모두 포함하도록 중심축을 보강했다.

### Section ID 기반 추적 보강

- 기존 문제: Part 1~5와 Part 7 일부 체크포인트에서 시작/마무리 페이지를 `index.md`, `summary.md`로만 적어 Section ID 기반 자동 대조에서는 `P*-index`, `P*-summary`가 누락처럼 보였다.
- 기존 문제: Part 5의 Transformer 장 일부 항목은 Section ID와 제목을 한 backtick 안에 함께 넣어, Section ID 추출 기준이 약했다.
- 기존 문제: Part 7의 P7-3.3, P7-5.4, P7-5.5, P7-7.5는 Section 경계 정리에는 언급되었지만 `목차 기준 체크포인트` 안의 개별 Section 중심축으로는 빠져 있었다.
- 반영 내용: Part 1~5와 Part 7의 시작/마무리 페이지를 `P*-index`, `P*-summary` 형식으로 명시했다.
- 반영 내용: Part 5의 P5-14.1~P5-14.8 항목을 Section ID만 backtick으로 감싸는 형식으로 정리했다.
- 반영 내용: Part 7의 누락 Section 중심축을 `목차 기준 체크포인트` 안에 추가했다.

## 누락 흐름 및 왜곡 위험

### Part 6

- 위험: Part 6을 토큰 장 개편의 잔여 작업표로 읽으면, 현재 Part 6의 실제 출발점인 `생성형 AI 산출물 검토`가 약해진다.
- 위험: P6-11 RAG와 P6-12 벡터 데이터베이스를 동시에 정밀검토 표로만 보면, `외부 근거를 붙이는 구조`와 `검색 저장소·payload·검색 품질 점검`의 경계가 흐려질 수 있다.
- 위험: P6-16~P6-17을 평가·운영 후속 검토 표로만 두면, 좋은 답변과 서비스 가능한 답변을 분리하는 Part 6 후반 중심선이 약해진다.
- 보완: 현재 체크포인트 노트에서 Module 1~8 전체를 목차 순서로 재배치하고, 각 Chapter와 Section이 닫아야 할 중심 질문을 한 줄씩 고정했다.

### Part 1~5, Part 7

- 관찰: 앞부분의 `Section 경계 정리`에는 특정 Section ID가 먼저 등장한다. 이 때문에 기계적으로 Section ID를 추출하면 실제 목차보다 앞서 나온 보류 후보가 순서를 흔드는 것처럼 보인다.
- 판단: 현재 문서 구조상 이는 치명적 왜곡은 아니다. 해당 ID들은 본문 개정 시 주의할 후보를 먼저 적은 것이고, 아래 `목차 기준 체크포인트`는 목차 흐름을 유지한다.
- 남은 주의: 후속 자동 점검 스크립트를 만든다면 문서 전체에서 ID를 추출하지 말고 `## 목차 기준 체크포인트` 이후 구간만 기준으로 삼아야 한다.

## 후속 검토 기준

- 오픈체크리스트는 작업 완료표가 아니라 현재 원고가 유지해야 할 중심선 문서로 유지한다.
- 오래된 개편 전 Section ID는 현재 목차 기준 체크포인트 안에 직접 남기지 않는다. 필요하면 별도 아카이브 회수 메모나 리포트에서만 언급한다.
- 누락된 흐름을 찾을 때는 `Part 시작 페이지 -> 목차 설명 -> Section 본문 -> Part 마무리` 순서로 보며, 특정 Section 하나의 품질보다 Part 전체 중심선이 끊기는 지점을 우선 기록한다.
- 실제 원고를 수정할 때는 해당 Section의 `Version`과 릴리즈노트를 함께 갱신하고, 영어·중국어 번역본도 같은 `Section ID` 기준으로 후속 동기화 대상으로 올린다.
