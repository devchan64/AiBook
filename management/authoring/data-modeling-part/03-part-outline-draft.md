# 데이터 모델링 Part 설계안 초안

## Part 목표

이 Part의 목표는 독자가 원천데이터를 바로 모델에 넣는 대신, 먼저 샘플 단위, 요약 구조, 특징, 비교 기준, 해석 경계를 설계해야 한다는 감각을 갖게 만드는 데 있다.

이 Part를 읽고 나면 독자는 다음을 설명할 수 있어야 한다.

- 한 시점 측정값과 한 건의 샘플이 어떻게 다른가
- 원시 로그를 요약 표로 바꾸는 이유가 무엇인가
- 특징이 단순 열 선택이 아니라 표현 설계라는 뜻이 무엇인가
- 절대값 판단과 기준선 비교가 어떻게 다른가
- 경고 후보와 진단 확정을 왜 구분해야 하는가
- 어떤 문제는 아직 분류기가 아니라 비교 리포트로 다루는 편이 더 현실적인가
- 데이터 정리, 특징 공학, 통계적 해석, 모델링 문제 설정이 왜 한 흐름으로 이어지는가

## 커리큘럼 재구성 원칙

이번 구조는 외부 커리큘럼의 다음 반복 항목을 현재 책 흐름에 맞게 재배치해 만든다.

- 데이터 생애주기와 문제 정식화
- data wrangling과 analysis-ready table
- feature engineering과 representation
- sampling, bias-variance, inference의 보수적 읽기
- regression/classification 이전의 문제 설정 점검

즉 외부 커리큘럼의 표준 순서를 그대로 옮기지 않고, 현재 책 사례에 필요한 순서로 다음과 같이 고정한다.

1. 샘플 단위 정의
2. 원천데이터와 데이터셋의 차이 보기
3. 원시 로그와 요약 표 구분
4. 특징 만들기
5. 최근 구간과 기준선 비교
6. 표본 수와 해석 경계
7. 문제 유형 구분
8. 머신러닝 handoff 정리

이 순서를 뒤집으면 다음 오해가 쉽게 생긴다.

- baseline이 단지 평가 절의 용어처럼 보인다.
- feature가 데이터셋 열 이름 정도로 축소된다.
- 데이터셋이 원시 로그를 조금 정리한 표 정도로 읽힌다.
- 통계적 보수성이 모델 평가 절의 뒷부분 이야기로 밀려난다.

## 이 Part의 대표 사례 방향

대표 사례는 특정 산업이나 장비 이름보다 다음 구조를 기준으로 잡는다.

- 자동으로 실행되는 동작 1회
- 그 동작에서 사용한 제어 파라미터 시계열
- 동작 중 관측된 센서 데이터 시계열
- 여러 동작을 묶어 비교하는 최근 구간과 기준선

이 구조는 특정 에스프레소 머신에 묶이지 않고, 자동화 장비 일반으로 확장 가능하다.

대표 사례는 다음 질문 축으로도 다시 변형할 수 있어야 한다.

- 정상 범위에서 벗어났는가
- 최근 구간이 평소와 달라졌는가
- 같은 평균인데 패턴이 달라졌는가
- 반복성이 줄어들고 있는가
- 사람이 검토해야 할 건은 무엇인가

## 다음 Part로 넘기는 질문

이 Part가 끝나면 다음 질문을 Part 4에서 이어받는다.

- 이렇게 설계된 feature와 label을 어떤 모델이 학습하는가
- train/validation/test는 이 구조 위에서 어떻게 나뉘는가
- baseline과 evaluation metric은 어떤 관계를 갖는가

즉 이 Part는 머신러닝을 대신하지 않고, 머신러닝 Part가 기대는 데이터 표현 전제를 먼저 세운다.

## 현재 결론

새 Part는 `역할 지도 -> 데이터셋 환상 깨기 -> 샘플 -> 요약 표 -> 특징 -> 기준선 비교 -> 해석 경계 -> 문제 유형 -> handoff`의 순서로 구성하고, 각 Chapter에서 표 자산, Python 예제, 공통 어휘, 과장 방지 문장을 함께 흡수하는 편이 가장 안정적이다.
