# 왜 데이터 모델링은 독립 Part가 되어야 하는가

## 문제 재정의

기존 문서군은 데이터 모델링을 `공통 모듈`로 보고, 여러 Part 안에서 필요한 만큼 다시 호출하는 구조를 전제로 삼았다.

이 접근은 집필자 입장에서는 유연해 보이지만, 독자 입장에서는 다음 문제가 생긴다.

- Part 1에서는 샘플 단위를 맛보기로 본다.
- Part 2에서는 원시 로그와 요약 표를 다시 본다.
- Part 3에서는 특징과 기준선을 다시 본다.
- Part 6에서는 리포트와 경고 해석으로 다시 본다.

즉 같은 개념이 여러 번 등장하지만, 그때마다 `왜 이것이 데이터 모델링인가`를 다시 설명해야 한다.

## 왜 복잡도가 커지는가

데이터 모델링은 단순 보조 개념이 아니다.

이 주제는 실제로 다음을 한 묶음으로 다룬다.

- 샘플 단위를 어떻게 정하는가
- 원시 시계열을 어떤 행 구조로 다시 묶는가
- 어떤 요약값과 특징을 남길 것인가
- 최근 구간과 평소 기준선을 어떻게 비교할 것인가
- 경고 후보와 진단 확정을 어떻게 구분할 것인가
- 어떤 문제는 라벨 예측으로 만들 수 있고 어떤 문제는 아직 아닌가

이 묶음이 선행되지 않으면 Part 3의 머신러닝 설명도 흔들린다. feature, label, baseline, evaluation을 설명할 때 독자는 이미 데이터 모델링을 알고 있다고 가정되기 쉽기 때문이다.

## 독립 Part로 둘 때 생기는 장점

### 1. 개념 선행 순서가 분명해진다

독자는 먼저 `데이터를 문제에 맞게 다시 표현하는 일`을 배운 뒤, 그 다음 `그 표현 위에서 모델이 무엇을 학습하는가`로 넘어간다.

즉 흐름이 다음처럼 바뀐다.

`수학과 표 읽기 -> 데이터 모델링 -> 머신러닝 -> 딥러닝 -> 생성형 AI -> 프로젝트`

### 2. Part 3가 더 단단해진다

머신러닝 Part는 더 이상 데이터 모델링 입문 설명을 반복하지 않고 다음 질문에 집중할 수 있다.

- 어떤 문제가 지도학습인가
- feature와 target을 어떻게 학습시키는가
- train/validation/test를 왜 나누는가
- 점수와 일반화를 어떻게 읽는가

즉 Part 3의 중심이 `표현 설계 입문`이 아니라 `학습과 평가`로 더 선명해진다.

### 3. Part 6도 설명이 가벼워진다

프로젝트 Part는 데이터 모델링을 처음 가르치는 자리가 아니라, 이미 배운 데이터 모델링을 실제 산출물 구조로 재사용하는 자리로 정리된다.

그러면 Part 6은 다음 질문에 더 집중할 수 있다.

- 어떤 비교표를 남길 것인가
- 어떤 run record를 남길 것인가
- 어떤 실패를 incident로 남길 것인가

### 4. 사례 일반화가 더 자연스러워진다

동작 단위 원천데이터 사례는 자동화 머신의 한 사례일 뿐이다. 독립 Part를 두면 특정 장비 설명처럼 읽히지 않게 하면서도, 데이터 모델링의 일반 원리를 먼저 고정할 수 있다.

## 어떤 독자에게 특히 필요한가

이 Part는 다음 독자에게 특히 중요하다.

- 표와 그래프는 읽을 수 있지만 샘플 단위를 아직 구분하지 못하는 독자
- 머신러닝에서 feature라는 말을 들었지만 그것이 설계 대상인지 모르는 독자
- 실제 로그를 보면 무엇을 한 건의 데이터로 만들어야 하는지 막막한 독자
- 경고와 진단, 기준선과 절대값 판단을 자주 혼동하는 독자

## 현재 결론

데이터 모델링은 흐름 보조용 보충 설명으로 두기보다, 머신러닝 이전에 먼저 배우는 독립 Part로 세우는 편이 더 교육적이다.
