# 기존 모듈 문서군에서 독립 Part 설계로 전환하는 규칙

## 전환 목적

기존 모듈 문서군은 유용한 자산을 많이 갖고 있었지만, 배치 전제가 `공통 모듈`에 머물러 있었다.

이 문서는 그 자산을 버리지 않고, 독립 Part 설계 재료로 재분류하는 기준을 적는다.

## 그대로 가져올 수 있는 자산

다음 자산은 독립 Part로 전환해도 거의 그대로 활용할 수 있다.

- 샘플 단위, 원시 로그, 특징, 기준선, 표본 수에 대한 개념 메모
- 공통 표 초안
- 공통 Python 예제 초안
- 과장 방지 문장 세트
- 참조 노트에서 일반화한 어휘 기준

즉 `내용 자산`은 유지할 수 있다.

## 다시 써야 하는 전제

반대로 다음 전제는 바뀌어야 한다.

- `여러 Part에서 반복 호출하는 모듈`
- `독립 Part보다 모듈 배치가 더 낫다`
- `새 Part를 만드는가보다 어떤 모듈을 어디에 호출할 것인가`

이 문장들은 이제 독립 Part 설계 관점에서 다시 써야 한다.

## 기존 문서군을 새 관점으로 읽는 법

### 1. 개념 문서는 Chapter 후보로 읽는다

- `01`, `02`, `03`, `06`은 Part의 개념 골격 문서로 재사용한다.

### 2. 배치 문서는 새 구조 근거로 다시 쓴다

- 기존 배치 문서의 판단은 `모듈 분산 배치`가 아니라 `독립 Part 배치` 관점으로 다시 정리해야 한다.

### 3. 자산 문서는 루트 기준 문서로 흡수한다

- 공통 표, Python 예제, 공통 어휘, 과장 방지 문장은 `14-shared-assets-and-guards.md`로 흡수한다.
- 원고 반영 체크리스트는 `15-manuscript-application-checklist.md`로 흡수한다.

### 4. 로그와 감사 문서는 흡수 대상에서 제외한다

- 실행 라운드 로그, 감사 기록, 상태 추적 문서는 현재 `data-modeling-part`의 기준 계획 문서로 다시 가져오지 않는다.
- 남겨 둘 것은 개념 설계, 자산 문서, 원고 반영 체크리스트 수준의 계획 문서다.
