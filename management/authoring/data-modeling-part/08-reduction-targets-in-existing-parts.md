# 기존 Part에서 덜어낼 데이터 모델링 입문 설명 후보

## 목적

새 데이터 모델링 Part를 독립적으로 두면, 기존 Part 4와 Part 7에 흩어져 있던 데이터 모델링 입문 설명 일부는 줄이거나 역할을 바꿀 수 있다.

이 문서는 이후 실제 `docs/` 편집 단계에서 어떤 종류의 설명을 새 Part로 옮기고, 기존 Part에서는 무엇만 남길지 판단하기 위한 관리 메모다.

## Part 4에서 줄일 후보

### 1. feature가 무엇인지 처음부터 길게 다시 정의하는 문단

새 Part에서 이미 다룬다면 Part 4에서는 다음 정도만 짧게 회수하면 된다.

- feature는 데이터 모델링 Part에서 설계한 입력 표현이다
- 여기서는 그 feature를 모델이 어떻게 학습하는지에 집중한다

### 2. baseline의 의미를 데이터셋 표현 수준부터 다시 길게 푸는 문단

Part 4에서는 baseline을 `비교 기준`으로 회수하되, 기준선 자체를 설계하는 입문 설명은 새 Part로 이동하는 편이 낫다.

### 3. 샘플 단위 혼동을 처음부터 자세히 푸는 문단

Part 4에서는 샘플 단위를 다시 정의하기보다, 이미 정해진 샘플 단위 위에서 train/test split과 evaluation unit을 설명하는 편이 더 곧다.

## Part 7에서 줄일 후보

### 1. 프로젝트 문서 안에서 원시 로그와 요약 표의 차이를 처음 가르치는 문단

Part 6에서는 그 차이를 다시 입문 설명으로 풀기보다, 이미 정리된 구조를 어떤 산출물로 남길지를 다루는 편이 낫다.

### 2. 기준선 비교를 왜 해야 하는지 처음부터 길게 설명하는 문단

Part 6에서는 `어떻게 비교 리포트를 남길 것인가`에 초점을 맞추고, 기준선 입문 설명은 새 Part에서 먼저 끝내는 편이 좋다.

### 3. 경고와 진단의 차이를 처음 배우는 수준으로 푸는 문단

Part 6에서는 운영 리포트, review summary, incident 기록에 집중하고, 경고와 진단의 개념 정의는 새 Part가 담당하는 편이 자연스럽다.

## 기존 Part에서 계속 남겨야 하는 것

### Part 4

- feature가 모델 입력으로 어떻게 작동하는가
- label과 target이 학습 문제에서 어떻게 쓰이는가
- baseline과 metric을 함께 읽는 법
- evaluation unit이 왜 중요한가

### Part 7

- 비교표를 어떤 문서 산출물로 남길 것인가
- run record, review summary, incident record를 어떻게 구성할 것인가
- 경고 후보를 운영 검토 흐름에 어떻게 연결할 것인가

## 실제 편집 시 판단 기준

- 이 문단이 데이터 모델링 입문 설명인가
- 아니면 이미 설계된 데이터 표현을 학습, 평가, 프로젝트에 적용하는 설명인가

앞 문장에 더 가깝다면 새 Part로 이동 후보로 보고, 뒤 문장에 더 가깝다면 기존 Part에 남긴다.

## 현재 결론

새 데이터 모델링 Part가 들어오면 Part 4와 Part 7은 더 짧고 또렷해질 수 있다. 핵심은 설명을 삭제하는 것이 아니라, `입문 설명`과 `활용 설명`의 자리를 분리하는 데 있다.
