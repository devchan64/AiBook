# Part 7 학습밀도 검토 및 개선 사항 리포트

작성일: 2026-07-19

## 목적

이 리포트는 Part 7 원고가 `진행 메타`가 아니라 설명, 해설, 사례, 예제, 보조자료로 학습밀도를 만들고 있는지 점검하고, 다음 보강 때 우선 적용할 개선 후보를 정리한다.

검토 대상은 다음 범위다.

- `docs/parts/part-07/index.md`
- `docs/parts/part-07/chapter-*/*.md`
- `docs/parts/part-07/summary.md`
- `management/authoring/part-07-open-checklist.md`
- `management/authoring/action-unit-sensor-part-07-material-report.md`

## 검토 기준

기준 문서는 `AGENTS.md`와 `management/guidelines/manuscript-writing-workflow.md`다.

핵심 기준은 다음처럼 정리한다.

- 학습밀도는 `이번 절의 목표`, `이 절을 읽는 순서`, `이 절에서 직접 할 일` 같은 진행 메타를 늘려서 올리지 않는다.
- 보강은 현재 본문 안에서 설명, 해설, 사례, 예제, 보조자료, 비교표, 출력 해석, 직접 바꿔 볼 값, 판단 기준으로 처리한다.
- 연습은 행동 목록이 아니라 `값을 바꾸면 무엇이 달라지는가`, `그 변화가 어떤 판단으로 이어지는가`를 보여 주어야 한다.
- 예제는 단순 실행 결과가 아니라 입력, 중간 산출물, 최종 출력, 실패 사례, 다음 수정이 이어지는 구조여야 한다.
- 질문을 던진 연습 항목은 바로 뒤에서 답을 비교할 기준이나 해설로 닫아야 한다.

## 현재 상태 요약

Part 7은 전반적으로 학습밀도 기준을 충족한다.

각 본문 Section에는 공통적으로 다음 요소가 들어 있다.

- 중심 질문 또는 판단 기준
- Python 예제
- 입력 파일 또는 예제 데이터
- 실행 기록 기준
- 결과를 읽는 해설
- 결과 해석 기준
- 프로젝트 기록 예시
- 직접 바꿔 볼 값과 관찰 질문
- 체크리스트

22개 본문 Section을 기준으로 확인한 구조 상태는 다음과 같다.

| 항목 | 상태 |
| --- | --- |
| Python 예제 | 모든 본문 Section에 있음 |
| 직접 바꿔 볼 값 | 모든 본문 Section에 있음 |
| 체크리스트 | 모든 본문 Section에 있음 |
| 결과 해석 기준 | 모든 본문 Section에 있음 |
| 프로젝트 기록 예시 | 모든 본문 Section에 있음 |
| 진행 메타 제목 | 최근 정리 뒤 본문 Section에서는 제거됨 |

따라서 지금 필요한 작업은 새 연습 Section을 급히 늘리는 것보다, 이미 있는 예제와 해설의 연결 강도를 더 고르게 만드는 것이다.

## 강한 지점

### 1. 실행과 해석의 연결이 분명함

Part 7의 대부분 Section은 `코드 실행 -> 출력 -> 결과 해석 -> 프로젝트 기록` 흐름을 갖춘다. 특히 다음 Section은 학습밀도가 높다.

| Section | 강한 이유 |
| --- | --- |
| `P7-1.2` | baseline, 사실, 해석, 다음 질문을 회고 문장으로 옮기는 구조가 구체적이다. |
| `P7-2.2` | 전처리 전후 비교가 정확도 변화와 샘플별 변화로 이어진다. |
| `P7-3.2` | 한 오류 사례를 데이터, 입력 표현, 구조 계열 질문으로 나누어 다음 조치까지 닫는다. |
| `P7-4.1` | loss, accuracy, 오류 샘플을 함께 읽어 학습 로그 해석을 단순 점수 비교에서 끌어낸다. |
| `P7-5.2` | 검색 실패, 문서 범위 밖, 답변 과장 위험을 같은 RAG 실패로 뭉개지 않는다. |
| `P7-6.2` | blocked와 failure를 권한, 승인, 로그, 다음 행동 기준으로 나누어 설명한다. |
| `P7-7.4` | gap, 표본 수, 반복성, 최근성을 경고 등급 판단으로 묶어 운영 해석을 강화한다. |

### 2. 연습 Section 추가 효과가 이미 반영됨

동작 단위 센서 소재는 새 Part를 열지 않고 기존 Part 7 흐름 안의 보강 소재로 잘 들어가 있다.

| 소재 | 반영 위치 | 판단 |
| --- | --- | --- |
| 기준선 재설계 | `P7-1.3` | 같은 원시 데이터도 질문과 기준선에 따라 회고가 달라진다는 점을 보강한다. |
| 절대 시간축 vs 진행도축 | `P7-2.3` | 비교 실험의 확장 질문으로 적정 수준이다. |
| 같은 평균, 다른 패턴 | `P7-4.4` | 평균만으로 사라지는 정보 손실을 초심자에게 보여 주기 좋다. |
| 운영 신호 분류 | `P7-7.3` | 즉시 수정, 재현 확인, 다음 반복 개선을 행동 구간으로 연결한다. |
| 경고 등급 설계 | `P7-7.4` | watch, review, action을 운영 판단으로 닫는다. |

### 3. 진행 메타 대신 내용 표지가 자리 잡음

최근 정리 뒤 `이 절에서 직접 할 일`, `관찰 포인트`, `기록 템플릿` 같은 진행 표지는 `실행 기록 기준`, `결과 해석 기준`, `프로젝트 기록 예시`, `판단 기준`처럼 내용 중심 표지로 바뀌었다.

이 방향은 현재 원칙과 맞다.

## 개선 후보

### 우선순위 1. 짧은 연습 Section의 시각 보조자료 보강

`P7-4.4`, `P7-7.4`는 학습 효과가 높지만 Mermaid 또는 SVG 시각 보조자료가 없다.

| Section | 현재 상태 | 개선 제안 |
| --- | --- | --- |
| `P7-4.4` | 평균과 shape token 비교는 있으나 도식 없음 | 같은 평균을 가진 3개 패턴을 `평균 -> shape token -> 회고 문장` 흐름도로 압축한다. |
| `P7-7.4` | 경고 등급 표와 코드 예제는 있으나 도식 없음 | `gap/event_count/repeatability/recency -> watch/review/action` 판단 흐름도를 추가한다. |

기대 효과:

- 독자가 표를 읽기 전에 판단 흐름을 먼저 붙잡을 수 있다.
- 평균, 반복성, 최근성처럼 추상적인 비교 기준을 한눈에 다시 확인할 수 있다.
- 진행 메타를 늘리지 않고 보조자료로 학습밀도를 올릴 수 있다.

### 우선순위 2. 긴 Section의 해설 밀도 재배치

일부 Section은 350줄 이상이고, 사례, 코드, 결과 해석, 회고가 모두 들어 있어 학습밀도는 높지만 읽는 압력이 크다.

| Section | 관찰 | 개선 제안 |
| --- | --- | --- |
| `P7-1.2` | baseline, 회고 템플릿, 나쁜/좋은 회고까지 풍부하지만 길다. | `바로 쓰는 회고 템플릿` 앞에 사실/해석/다음 질문의 차이를 3행 표로 한 번 더 압축한다. |
| `P7-3.1` | 이미지 입력, 학습 루프, Mermaid가 모두 들어 있다. | 학습 루프 보강은 유지하되 `입력 구조`와 `학습 루프`의 역할 차이를 짧은 연결 문장으로 더 분명히 한다. |
| `P7-7.1` | 배포 경로, 확인표, Python 예제, 템플릿이 모두 있다. | `빌드 성공`, `배포 완료`, `공개 확인 완료`의 차이를 최종 기록 예시 앞에 3칸 비교표로 한 번 더 닫는다. |

주의:

- 이 후보들은 새 Section으로 나누기보다 현 Section 안의 해설 재배치가 낫다.
- 지금도 구조 결함은 아니므로 우선순위 1보다 낮다.

### 우선순위 3. 직접 바꿔 보기 뒤 해설의 즉시성 강화

대부분 Section의 `직접 바꿔 보며 확인할 것`은 관찰 질문이 좋다. 다만 일부는 독자가 바꾼 뒤 어떤 방향으로 해석해야 하는지 바로 대조할 짧은 기준 문장이 더 있으면 좋다.

보강 방식:

- 목록 뒤에 `판단 기준은 ...` 한 문장을 붙인다.
- 정답을 단정하지 말고, 어떤 상태 변화가 어떤 해석 후보를 여는지 적는다.
- 체크리스트와 중복되지 않게 한다.

우선 적용 후보:

| Section | 보강할 문장 방향 |
| --- | --- |
| `P7-2.3` | 정규화로 풀리는 실패와 데이터 경계 부족으로 남는 실패를 다시 구분하는 기준 |
| `P7-4.3` | 정규화가 실제 오답을 고친 경우와 단지 coverage만 올린 경우의 우선순위 차이 |
| `P7-5.3` | 질문 재작성으로 해결되는 문제와 문서 자체를 늘려야 하는 문제의 경계 |
| `P7-6.3` | 보류가 사라진 경우에도 변경 단계의 위험이 남는지 확인하는 기준 |

### 우선순위 4. Part 시작/마무리 페이지와 본문 Section의 연결 약화 방지

Part 시작 페이지와 마무리 페이지는 오버뷰 문서이므로 어느 정도 목표, 범위, 완료 기준을 가질 수 있다. 다만 본문 Section들이 강해진 만큼 시작/마무리 페이지도 다음 연결을 더 분명히 유지할 필요가 있다.

개선 후보:

- `index.md`: `실습 기록의 공통 요소` 표가 각 Chapter에서 실제로 어떻게 반복되는지 대표 Section ID를 더 직접 연결한다.
- `summary.md`: `프로젝트 문서에 남는 최소 절차`가 Part 7의 대표 Section으로 되돌아가는 재진입 지도처럼 읽히게 한다.

주의:

- 오버뷰 문서에서는 진행 안내가 완전히 금지되는 것은 아니다.
- 다만 학습밀도를 올리기 위해 절차 목록을 더 늘리는 방식은 피하고, 대표 Section 링크와 판단 기준으로 연결한다.

## 결론

Part 7은 현재 학습밀도 기준에서 통과 상태다. 모든 본문 Section이 실행, 출력, 해석, 프로젝트 기록, 직접 바꿔 보기, 체크리스트를 갖추고 있고, 최근 정리로 진행 메타 의존도도 낮아졌다.

다음 개선은 새 Section을 늘리는 방향보다 `짧은 판단 흐름도`, `직접 바꿔 보기 뒤 즉시 해설`, `긴 Section의 압축 비교표`를 추가하는 방향이 적절하다. 이렇게 보강하면 원칙을 어기지 않고, 설명과 해설, 보조자료를 통해 학습밀도를 더 올릴 수 있다.
