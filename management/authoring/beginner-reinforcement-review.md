# 초심자 보강 적용 검토

이 문서는 `management/authoring/beginner-reinforcement-guidelines.md`의 기준을 현재 목차와 본문 구조에 적용한 검토 메모입니다. 목적은 모든 Section을 즉시 수정하는 것이 아니라, 어떤 Part에서 `현재 Section 보강`을 우선하고 어떤 항목을 `보충학습` 후보로 분리할지 정리하는 것입니다.

## 검토 기준 요약

- 초심자는 대학 학사 교육을 받지 않았을 수 있는 독자를 기준으로 판단합니다.
- 현재 Section의 중심 질문에 직접 필요한 설명은 본문 안에서 보강합니다.
- 선행 과목 복구, 설치, 운영체제별 절차, 공통 수학·문법처럼 재사용 범위가 넓은 항목은 보충학습 후보로 분리합니다.
- 전체 Part에서 초심자 기준을 유지하므로, 알고리즘 본문과 개념 본문 안에 작은 예시·표·도식·실행 결과를 먼저 넣는 방향을 우선합니다.

## Part 1. AI 개론과 지형도

### 기본 판단

- 기본 선택: `현재 Section 보강`
- 이유: Part 1의 역할은 전체 지도를 잡는 것이므로, 개념의 큰 흐름이 자주 끊기면 초심자가 오히려 길을 잃기 쉽습니다.

### 본문 보강 우선 항목

- AI, 머신러닝, 딥러닝, 생성형 AI의 범위 비교 표
- 규칙 기반, 확률 기반, 학습 기반 접근을 한 문단과 작은 비교 사례로 다시 묶는 설명
- LLM, RAG, 에이전트, 도구 사용을 같은 말로 오해하지 않게 하는 구분 표
- 전망, 윤리, 저작권, 보안은 `왜 지금 독자가 알아야 하는가`를 먼저 말하는 도입 문장 보강

### 보충학습 후보

- 한국 저작권법 세부 논점
- 학술 용어 번역의 세부 차이
- 검색·프롬프트·에이전트의 구현 수준 세부 절차

### 현재 구조 평가

- Part 1은 현재도 `본문 보강 중심` 전략이 적절합니다.
- 새 보충학습을 늘리기보다, 각 절 안에서 역사적 배경과 생활/업무 예시를 더 보강하는 쪽이 안전합니다.

## Part 2. 기초 복구

### 기본 판단

- 기본 선택: `현재 Section 보강 + 보충학습 적극 사용`
- 이유: Part 2는 선행 지식 공백을 메우는 파트이므로, 초심자가 반복적으로 막히는 기초를 따로 분리할 가치가 큽니다.

### 본문 보강 우선 항목

- 수식 표기와 코드 값의 대응
- 평균, 분산, 기울기, 행렬 곱의 작은 값 예시
- Python 리스트, 딕셔너리, 반복 구조의 출력 결과 해석
- NumPy, Pandas, Matplotlib의 `왜 필요한가`를 실제 머신러닝 전 단계와 연결하는 문장

### 보충학습 유지·확장 후보

- P2-4.5 그래디언트 보충학습
- P2-7.6 운영체제별 터미널
- P2-7.7 Python 설치 시점
- P2-8.6 클래스와 객체
- P2-9.4 전통 자료구조 입문

### 현재 구조 평가

- Part 2는 이미 보충학습 분리 전략이 잘 작동하고 있습니다.
- 앞으로는 새로운 보충학습을 무분별하게 늘리기보다, 현재 보충학습 문서를 재사용하는 방향이 좋습니다.

## Part 3. 머신러닝

### 기본 판단

- 기본 선택: `현재 Section 보강`
- 이유: 전체 Part가 초심자 기준을 따르므로, 알고리즘을 읽는 순간 바로 이해 손잡이가 있어야 합니다.

### 본문 보강 우선 항목

- P3-4 데이터 분리와 검증:
  - 학습/검증/테스트를 실제 표본 분리 표로 반복 확인
- P3-5 과적합과 일반화:
  - 새 데이터가 왜 중요한지 사회현상/업무 사례 재보강
- P3-8 모델 선택, 기준 모델:
  - `왜 baseline이 필요한가`를 더 작은 비교 예시로 보강
- P3-9 하이퍼파라미터:
  - 학습 파라미터와 하이퍼파라미터의 차이를 출력 예시와 함께 더 반복
- P3-10~P3-16 알고리즘 절:
  - 입력, 라벨, 예측, 출력 해석을 같은 패턴으로 더 통일
- P3-17~P3-18 구조 찾기:
  - 클러스터링 결과와 차원 축소 결과가 `정답`이 아님을 더 자주 경고

### 보충학습 후보

- P3-12 k-NN:
  - 거리 함수의 수학적 차이와 거리 공간 가정은 보충학습 후보
- P3-13 SVM:
  - 커널의 수학적 전개, RKHS, gamma/degree 세부 감각은 보충학습 후보
- P3-19 강화학습:
  - MDP, 상태-행동 전이, 할인율의 수학적 정의는 보충학습 후보

### 현재 구조 평가

- Part 3는 새 보충학습을 대량 추가하기보다, 각 알고리즘 절의 본문 예시를 더 정교하게 맞추는 것이 우선입니다.
- 현재 명시된 보충학습은 P3-6.3 하나뿐인데, 이 구조 자체는 나쁘지 않습니다. 다만 SVM과 강화학습처럼 수학 밀도가 높은 절은 장기적으로 보충학습 후보가 될 수 있습니다.

## Part 4. 딥러닝

### 기본 판단

- 기본 선택: `현재 Section 보강`
- 이유: 딥러닝은 용어보다 계산 흐름에서 막히는 경우가 많으므로, 본문 안에서 입력-출력-손실-업데이트 연결을 바로 보여 주는 것이 우선입니다.

### 본문 보강 우선 항목

- P4-1~P4-3:
  - 입력, 가중치, 선형 결합, 활성화가 어떤 순서로 흐르는지 더 통일된 도식 사용
- P4-4~P4-7:
  - 손실, 역전파, 옵티마이저가 각각 무엇을 담당하는지 역할 비교 보강
- P4-9 GPU와 병렬 처리:
  - 배치와 텐서 계산이 왜 딥러닝 확산과 연결되는지 작은 사례 보강
- P4-13~P4-14:
  - attention과 Transformer는 `무엇을 더 잘 보게 하는가`를 예시 문장으로 반복
- P4-15:
  - 생성 모델과 분류 모델 차이를 표와 예시로 한 번 더 고정

### 보충학습 후보

- 역전파의 엄밀한 미분 전개
- 배치 정규화(batch normalization)의 수학적 계산
- self-attention의 행렬 식 전개
- GPU 메모리, CUDA, 병렬 커널 실행 세부 구현

### 현재 구조 평가

- Part 4는 현재 목차 안에서 충분히 설명이 가능합니다.
- 초심자용 추가는 본문 예시와 도식 보강이 우선이며, 수학 전개가 길어질 때만 보충학습을 검토하는 것이 적절합니다.

## Part 5. LLM과 생성형 AI

### 기본 판단

- 기본 선택: `현재 Section 보강`
- 이유: 초심자는 LLM을 먼저 제품 경험으로 접하므로, 서비스 경험과 내부 개념을 같은 Section 안에서 바로 연결해야 합니다.

### 본문 보강 우선 항목

- P5-1 토큰화:
  - 토큰 수가 비용, 지연, 문맥 길이와 왜 연결되는지 더 작은 입력 예시 보강
- P5-2 임베딩:
  - 의미와 거리를 실무 검색 사례와 더 자주 연결
- P5-3~P5-6 계보:
  - 직접 계보와 주변 근거를 더 명확한 비교 표로 유지
- P5-7~P5-10 학습과 정렬:
  - 사전학습, 파인튜닝, 지시 튜닝, 정렬의 역할을 같은 도식 언어로 통일
- P5-11~P5-16 서비스 구조:
  - 프롬프트, RAG, 벡터DB, 도구 사용, 에이전트, MCP, 하네스를 같은 요청 흐름으로 반복 설명
- P5-17~P5-18 평가와 운영:
  - 자동 평가와 사람 평가, 운영 제약과 실패 대응을 현실 서비스 체크리스트로 더 보강

### 보충학습 후보

- 토큰화 알고리즘(BPE, SentencePiece) 세부 비교
- LoRA 수학과 파라미터 절감 공식
- 정렬의 세부 학습 절차(RLHF, preference optimization)의 엄밀한 훈련 단계
- 벡터 인덱스의 근사 최근접 탐색 내부 구조

### 현재 구조 평가

- Part 5는 새 보충학습 없이도 현재 본문 확장만으로 초심자 설명을 상당 부분 해결할 수 있습니다.
- 다만 구현 내부 수학과 인덱스 구조로 깊게 들어가면 보충학습 분리가 필요합니다.

## Part 6. 프로젝트

### 기본 판단

- 기본 선택: `현재 Section 보강`
- 이유: 프로젝트 파트는 실행 흐름과 산출물 읽기가 핵심이므로, 별도 보충학습보다 본문 안의 명령, 출력, 회고 예시가 더 유익합니다.

### 본문 보강 우선 항목

- 프로젝트 목표와 평가 기준을 표로 먼저 제시
- 실행 명령과 출력 결과를 같은 패턴으로 반복
- 실패 기록과 회고 문장을 실제 독자가 따라 쓸 수 있는 형태로 보강
- `다음 개선 계획`을 알고리즘/서비스 관점으로 분리

### 보충학습 후보

- 공통 배포 템플릿
- 반복되는 평가표 작성법
- 운영 점검 체크리스트 공통판

### 현재 구조 평가

- Part 6은 보충학습보다 현재 문서 안에서의 예시 보강이 훨씬 중요합니다.
- 프로젝트별 차이를 유지해야 하므로, 공통 절차만 지나치게 분리하지 않는 편이 좋습니다.

### 1차 우선순위: 본문 보강

- P3-9.1 하이퍼파라미터
- P4-4.1, P4-5.1, P4-7.1 손실-역전파-옵티마이저 연결
- P5-7.1, P5-9.1, P5-10.1 사전학습-파인튜닝-지시 튜닝 연결
- P5-11~P5-16 서비스 구조 절들의 공통 요청 흐름 정리

### 2차 우선순위: 보충학습 후보 검토

- Part 3 SVM 수학 보충학습
- Part 3 강화학습 수학 보충학습
- Part 4 self-attention/역전파 수학 보충학습
- Part 5 토큰화 내부 알고리즘 보충학습

## 작업 방식 제안

다음 수정은 한 번에 모든 Part를 손보지 않고, 다음 순서로 진행하는 편이 안전합니다.

1. Part 3에서 `본문 보강 우선 항목`만 먼저 수정
2. 같은 기준으로 Part 4를 점검
3. 같은 기준으로 Part 5를 점검
4. 그다음 실제로 필요한 보충학습 후보만 별도 문서로 분리

즉, 초심자 보강은 `새 문서부터 늘리는 작업`이 아니라, `현재 Section이 정말 필요한 설명을 이미 담고 있는지 먼저 확인하는 작업`으로 진행합니다.
