# 데이터 모델링 모듈과 기존 노트의 통합 우선순위 지도

## 목적

이 문서는 `data-modeling-for-ai-modules`와 `brewing-shot-ai-notes`를 어떻게 연결해 실제 원고 편집 순서를 잡을지 정리한다.

핵심은 모든 노트를 한꺼번에 확장하는 것이 아니라, 데이터 모델링 관점에서 먼저 흡수해야 할 노트와 나중에 다룰 노트를 구분하는 데 있다.

## 우선 연결 대상

가장 먼저 연결해야 할 노트는 다음 네 묶음이다.

1. 샘플 단위와 문제 정의
2. 원시 시계열과 요약 구조
3. 특징과 중간 표현
4. 최근 구간, 기준선, 해석 한계

이 순서가 먼저 고정되어야 뒤의 모델링 사다리나 장기 집필 로드맵도 흔들리지 않는다.

## 1차 우선순위 노트

### 01-domain-opportunity-and-boundaries.md

연결 이유:

- 사례를 특정 장비 설명이 아니라 문제 구조 설명으로 다시 잡는 출발점이 된다.
- `자동으로 실행되는 동작 1회`라는 샘플 관점을 도입하기 좋다.

모듈 연결:

- 모듈 1. 샘플 단위 정의
- 모듈 6. 모델링 사다리의 아주 얕은 도입

### 02-problem-framing-from-shot-to-dataset.md

연결 이유:

- 동작 1회에서 데이터셋으로 넘어가는 흐름을 직접 다루기 때문이다.
- 샘플과 행의 차이를 설명하기 좋다.

모듈 연결:

- 모듈 1. 샘플 단위 정의
- 모듈 2. 원시 로그와 요약 표

### 03-time-series-normalization-and-segmentation.md

연결 이유:

- 원시 시계열을 그대로 두지 않고 정렬, 분할, 비교 가능한 구조로 바꾸는 핵심 노트다.

모듈 연결:

- 모듈 2. 원시 로그와 요약 표
- 모듈 3. 특징과 중간 표현

### 04-sensor-tokenization-and-explainable-features.md

연결 이유:

- 특징과 표현 설계를 직접 다루기 때문이다.
- `토큰화`를 과장하지 않고 설명 가능한 입력 표현이라는 관점으로 다시 풀 수 있다.

모듈 연결:

- 모듈 3. 특징과 중간 표현

### 05-window-aggregation-baseline-drift.md

연결 이유:

- 최근 구간, 집계, 기준선 비교를 묶어서 다루는 중심 노트다.
- 다만 `drift`라는 표현은 일반화해 다시 써야 한다.

모듈 연결:

- 모듈 4. 최근 구간과 기준선 비교
- 모듈 5. 표본 수, 반복성, 경고 해석의 도입

## 통합 순서 제안

1. `01`, `02`를 샘플 단위와 문제 정의 관점으로 재독한다.
2. `03`, `04`를 원시 시계열과 특징 설계 관점으로 재독한다.
3. `05`, `06`을 기준선 비교와 경고 해석 관점으로 재독한다.
4. `07`을 모델링 사다리 관점으로 연결한다.
5. 마지막에 `08`, `09`, `10`을 집필 배치와 연습 계획으로 갱신한다.

## 현재 결론

기존 노트는 모두 동등하게 다루기보다, 샘플 정의와 데이터 표현 구조를 먼저 고정하는 노트부터 재편집하는 편이 안정적이다.
