# 노트 02 문제 정의 정리 커밋 로그

## 목적

이 문서는 `management/authoring/brewing-shot-ai-notes/02-problem-framing-from-shot-to-dataset.md`에 반영한 수정의 이유를 관리 근거로 남긴다.

이번 정리는 책원고 `docs/`를 건드리지 않고, 문제 정의 노트 한 파일의 표현 축만 바로잡는 작업으로 제한했다.

## 수정 대상

- `management/authoring/brewing-shot-ai-notes/02-problem-framing-from-shot-to-dataset.md`

## 핵심 수정

- `shot`을 기본적으로 `동작 1회`로 다시 읽게 하는 기준을 도입부에 명시했다.
- `세그먼트별 방향 토큰`을 `세그먼트별 방향 코드 또는 구간 표현`으로 바꿔 자연어 토큰과의 직접 혼동을 줄였다.
- `고장 분류기` 축을 `원인 분류기`로 옮겨, 이 노트의 기본 질문이 원인 확정보다 문제 정의와 비교 구조 설계라는 점을 더 분명히 했다.
- `이상 탐지` 일부를 `변화 신호 탐지`로 바꿔, 경고 후보와 검토 우선순위 중심의 읽기와 더 잘 맞추었다.
- 나쁜 예시와 더 나은 예시에서도 `추출 패턴`보다 `동작 패턴`, `고장 종류`보다 `원인 종류`를 앞세우도록 조정했다.

## 수정 이유

이 노트는 데이터셋과 문제 정의의 층위를 설명하는 문서이므로, 특정 원인 분류 문제를 대표 목표처럼 두면 전체 흐름이 너무 빨리 좁아진다.

특히 입문 독자에게는 다음 순서가 먼저 보여야 한다.

1. 무엇을 샘플 1건으로 볼 것인가
2. 무엇을 비교할 것인가
3. 어떤 출력을 사람이 실제로 쓸 수 있는가
4. 그 뒤에야 분류, 회귀, 변화 탐지 같은 기술 이름이 자리를 찾는다

이번 수정은 이 순서를 더 선명하게 만들기 위한 것이다.
