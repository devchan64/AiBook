# 데이터 모델링 모듈 공통 어휘와 사용 맵

## 목적

이 문서는 `data-modeling-for-ai-modules` 아래 문서와 실제 책 원고에서 반복 사용할 공통 어휘를 고정한다.

핵심은 특정 장비나 특정 도메인 이름을 지우는 데 있지 않다. 독자가 어떤 사례를 보더라도 `샘플 단위`, `원시 데이터`, `요약 구조`, `비교 기준`, `해석 경계`를 같은 말로 따라가게 만드는 데 있다.

## 기본 원칙

- 용어는 가능한 한 역할이 드러나는 일반 명칭을 쓴다.
- 특정 장비를 아는 사람만 이해할 표현은 피한다.
- 원인 확정처럼 과장되기 쉬운 단어보다 관찰과 해석의 구분이 드러나는 단어를 우선한다.
- 본문에서 같은 층위를 가리키는 말은 가능한 한 한 가지 표현으로 유지한다.

## 공통 어휘표

| 권장 표현 | 뜻 | 피할 표현 또는 주의점 | 본문에서 주로 쓰는 위치 |
| --- | --- | --- | --- |
| 자동으로 실행되는 동작 1회 | 제어 명령 하나가 시작되어 종료될 때까지의 1건 | `추출기록`, `샷 기록`을 일반 독자 기준의 표준어처럼 쓰지 않는다 | 사례 도입, 샘플 단위 설명 |
| 샘플 1건 | 모델이나 비교 표에서 한 행으로 다룰 분석 단위 | 한 행이 항상 샘플 1건이라고 가정하지 않는다 | Part 1, Part 2, Part 3 |
| 원시 시계열 | 제어 파라미터와 센서 관측이 시간 순서로 쌓인 원천 데이터 | `원본값`처럼 범위가 모호한 말만 단독으로 쓰지 않는다 | Part 2, Python 예제 |
| 동작 1회 요약 행 | 원시 시계열 여러 행을 하나의 분석용 행으로 묶은 결과 | `집계값`만 쓰면 샘플 의미가 사라질 수 있다 | 표 세트, Part 2, Part 3 |
| 특징 | 요약 행이나 원시 구간에서 계산해 남긴 설명용 값 | `토큰`은 실제로 이산화 규칙을 설명할 때만 제한적으로 쓴다 | Part 3, 특징 설계 설명 |
| 최근 구간 | 지금 검토 대상이 되는 최근 몇 건의 동작 묶음 | `실시간 이상`처럼 의미를 넓혀 단정하지 않는다 | Part 3, Part 6 |
| 기준선 | 비교를 위해 남겨 둔 평소 구간, 기준 집단, 또는 기본 모델 값 | baseline을 모델 이름처럼 오해하게 두지 않는다 | 평가, 비교 표, 회고 |
| 변화 신호 | 최근 구간과 기준선 차이에서 먼저 보인 변화 | `드리프트`는 맥락 없이 일반 표제로 쓰지 않는다 | 변화 해석, 경고 전 단계 |
| 경고 | 사람의 검토 우선순위를 올리기 위한 신호 | 자동 진단 확정처럼 쓰지 않는다 | 리포트, 운영 해석 |
| 검토 필요 | 추가 확인이 필요하다는 보수적 판단 | `이상 확정`, `원인 규명`으로 바로 건너뛰지 않는다 | 리포트 문장, 결론 |

## 자주 쓰는 연결 문장

다음 문장은 여러 Part에서 같은 의미로 재사용하기 좋다.

- 원시 시계열의 한 행은 측정 시점 하나일 뿐이고, 비교 대상은 그 행들이 모인 동작 1회다.
- 동작 1회 요약 행은 여러 시점을 모델과 사람이 함께 읽기 쉬운 한 행으로 바꾼 결과다.
- 최근 구간과 기준선을 나란히 두어야 변화가 보이고, 그 뒤에야 검토 우선순위를 정할 수 있다.
- 변화는 관찰되었지만 원인은 아직 확정되지 않았다.
- 경고는 자동 진단 결과라기보다 사람이 먼저 볼 대상을 좁히는 신호에 가깝다.
- 같은 평균이라도 구간 패턴과 변동성은 다를 수 있다.

## 표현 치환 가이드

| 기존에 나오기 쉬운 표현 | 우선 검토할 대체 표현 | 대체 이유 |
| --- | --- | --- |
| 추출기록 | 자동으로 실행되는 동작 1회, 동작 1회 기록 | `추출`이 무엇인지 설명 없이 남지 않게 하기 위해 |
| 샷 | 동작 1회, 자동 동작 1건 | 특정 도메인 지식을 몰라도 읽히게 하기 위해 |
| 토큰화 | 특징 설계, 구간 표현 설계 | 자연어 토큰과 혼동되는 범위를 줄이기 위해 |
| 드리프트 | 변화 신호, 기준선 대비 변화, 장기 변화 | 문맥 없이 너무 넓거나 좁게 읽히는 문제를 줄이기 위해 |
| 이상 탐지 결과 | 경고, 검토 필요 신호 | 원인 확정과 우선순위 신호를 구분하기 위해 |

## 편집 체크리스트

- 이 문단은 `한 행`, `한 동작`, `한 구간` 중 무엇을 설명하는지 분명한가
- 특징이라는 말이 실제로 어떤 계산값을 가리키는지 바로 이어서 보이는가
- 기준선이 무엇과 무엇을 비교하는 기준인지 문맥 안에서 설명되는가
- 경고와 원인 확정을 섞어 쓰지 않았는가
- 도메인 배경지식이 없어도 용어의 역할이 드러나는가

## 현재 결론

이 어휘표는 단어를 단순 치환하기 위한 목록이 아니라, 데이터 모델링 설명이 어느 층위를 다루는지 고정하는 기준으로 써야 한다.
