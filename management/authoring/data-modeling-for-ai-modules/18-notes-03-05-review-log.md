# `brewing-shot-ai-notes` 03-05 재편집 검토 메모

## 목적

이 문서는 `03-time-series-normalization-and-segmentation.md`, `04-sensor-tokenization-and-explainable-features.md`, `05-window-aggregation-baseline-drift.md`를 데이터 모델링 모듈 기준으로 재검토하면서 반영한 판단을 기록한다.

## 이번 검토에서 본 핵심 기준

### 1. `샷`과 `버킷`이 일반 독자에게 설명 없이 전달되는가

판단:

- 아니다.
- `샷`은 `동작 1회`, `버킷`은 `최근 구간` 또는 `최근 N건`으로 바꾸는 편이 더 직접적이다.

### 2. `토큰화`가 표현 설계보다 앞세워져 있는가

판단:

- 일부 문단에서는 그렇다.
- 이 노트의 중심은 `토큰화라는 용어`보다 `설명 가능한 중간 표현`이어야 한다.

### 3. `drift` 같은 용어를 그대로 전면에 둘 필요가 있는가

판단:

- 없다.
- 책에서는 `변화 추세`, `기준선 대비 변화`, `최근 구간 비교` 같은 표현이 더 안전하다.

## 파일별 반영 방향

### 03 노트

- 절대 시간축과 진행도축 비교 설명에서 `샷` 잔여 표현을 `동작` 기준으로 정리했다.
- 특정 도메인 언급보다 `길이가 다른 동작 시계열 비교`라는 문제 구조가 먼저 보이게 다듬었다.

### 04 노트

- 제목과 도입에서 `토큰화`를 독립 기술처럼 세우기보다 `설명 가능한 특징 표현의 한 방식`으로 낮췄다.
- `샷`, `버킷`, `브루잉` 잔여 표현을 `동작`, `최근 구간`, `이 사례` 중심으로 다시 썼다.
- 토큰화가 집계와 설명으로 이어지는 흐름을 더 일반화된 표현으로 정리했다.

### 05 노트

- `버킷` 중심 표현을 `최근 구간` 중심으로 바꿨다.
- `baseline`은 영어 병기를 남기되 본문 흐름은 `기준선` 중심으로 유지했다.
- 사례/상태 구분 문장을 `동작 1회`와 `최근 구간 상태` 구조로 더 분명히 정리했다.
