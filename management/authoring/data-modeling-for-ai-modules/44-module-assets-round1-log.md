## 판단과 수정 이유

### 1. 공통 어휘가 별도 문서로 분리되어 있지 않았다

기존 문서들에도 `동작 1회`, `원시 시계열`, `기준선` 같은 말은 있었지만, 어떤 표현을 권장하고 어떤 표현을 피해야 하는지 한곳에서 고정해 두지 않았다. 이 상태로는 이후 실제 원고를 다시 손볼 때 문서마다 조금씩 다른 표현이 돌아올 가능성이 컸다.

그래서 공통 어휘와 치환 가이드를 별도 문서로 만들고, 각 용어가 어느 층위를 가리키는지와 어디에 주로 쓰는지를 함께 적었다.

### 2. 공통 표 세트에는 표는 있었지만 표를 붙이는 문장 구조가 부족했다

기존 `11-common-example-table-set.md`는 표 자체는 이미 있었지만, 실제 원고에 넣을 때 어떤 질문을 답하게 할지와 어떤 경계 문장을 붙일지까지는 고정하지 않았다.

그래서 각 표마다 다음 항목을 추가했다.

- 이 표가 답하는 질문
- 도입 문장 예시
- 함께 붙일 경계 문장

이 구조를 넣으면 표가 뜬금없는 삽입처럼 보이지 않고, 본문에 넣을 때도 같은 전개를 유지하기 쉬워진다.

### 3. Python 예제 계획은 있었지만 실제 출력과 해석 흐름이 약했다

기존 `13`, `14` 문서는 예제 목록과 최소 코드 스니펫 수준에는 도달했지만, 책 본문에 옮길 때 바로 복사해 쓸 수 있는 출력 예시와 해석 문장이 충분하지 않았다.

그래서 `14-python-example-draft-snippets.md`에 다음을 보강했다.

- 각 예제 앞의 입력 설명
- 더 긴 장난감 원시 로그
- 요약 특징에 구간 평균과 차이 열 추가
- 예상 출력 예시
- 출력 바로 아래에 둘 해석 문장 예시

## 현재 결론

이제 다음 실제 본문 편집에서는 새 표현을 즉흥적으로 만들기보다, `43`, `11`, `14` 문서를 공통 자산으로 참조해 문단과 예제를 옮기는 방식으로 진행하는 편이 맞다.

남은 우선순위는 `12-part-draft-paragraphs.md`와 연결된 Part별 삽입 문단 정밀화, 그리고 과장 방지 문장 세트를 별도 체크리스트로 묶는 일이다.
