# P6-6.2 검토 로그

## 대상

- `docs/parts/part-06/chapter-06/section-02.md`

## 이번 검토의 목적

권한과 로그 절에서 `blocked`를 곧바로 기능 실패로 읽지 않게 하고, 현재 권한 정책과 현재 승인 상태 아래에서 멈춤이 발생했다는 운영 신호로 분리해 남기는 태도를 더 분명히 고정하는 것이 목적이었다.

## 반영 내용

- 결과 해석 문단에 `blocked`는 도구 불가능이 아니라 현재 권한 정책과 승인 상태 기준의 운영 신호라는 문장을 추가했다.
- 좋은 기록 예시의 결론을 `기능 오류`보다 `현재 승인 절차 미완료 신호`로 먼저 해석하는 방향으로 조정했다.
- 기억할 관점에 `blocked는 현재 권한 정책 아래의 운영 상태이며 항상 기능 실패와 같지 않다`는 문장을 추가했다.

## 판단 이유

- agent 운영 절에서는 독자가 blocked를 기능적 실패로 바로 읽기 쉬우므로, 권한 정책과 승인 상태를 분리해 적는 문장이 사례 해석과 요약 양쪽에 모두 필요했다.
- 묶음 E의 핵심인 `관찰된 상태`, `해석 경계`, `다음 질문` 구조를 운영 절에도 유지하려면, blocked 해석을 더 보수적으로 바꿔 둘 필요가 있었다.
