# 데이터 모델링 모듈 집필 템플릿

## 왜 템플릿이 필요한가

같은 주제를 여러 Part에 나누어 배치하면, 각 Section이 서로 다른 질문에 답하면서도 같은 개념 축을 유지해야 한다.

이를 위해 모듈 단위 템플릿을 먼저 고정하는 편이 안전하다.

## 기본 템플릿

각 모듈은 가능하면 다음 순서를 따른다.

1. 문제 장면
2. 사람이 원래 보던 기준
3. 그 기준만으로는 부족한 이유
4. 데이터 모델링이 추가하는 구조
5. 간단한 표 또는 장난감 데이터
6. AI 활용으로 이어지는 연결
7. 과장하면 안 되는 해석

## 항목별 설명

### 1. 문제 장면

독자가 왜 이 모듈을 읽는지 한 문단 안에서 이해해야 한다.

예를 들어 `동작 1회는 잘 끝났는데도 품질이 흔들리는 이유를 알고 싶다` 같은 식으로 시작할 수 있다.

### 2. 사람이 원래 보던 기준

현장에서 이미 보고 있던 숫자나 표식을 먼저 제시한다.

이 단계는 독자의 직관을 버리지 않고 표준 표현으로 연결하기 위한 장치다.

### 3. 그 기준만으로는 부족한 이유

단일 평균값, 마지막 측정치, 한 번의 경고만으로는 왜 판단이 불안정한지 설명한다.

### 4. 데이터 모델링이 추가하는 구조

여기서 샘플 단위, 요약 행, 기준선, 특징, 비교 구간 같은 구조를 도입한다.

### 5. 간단한 표 또는 장난감 데이터

숫자를 몇 줄이라도 직접 보여 주어야 한다.

이때 기업 내부 형식은 제거하고, 일반화된 열 이름으로 작성한다.

### 6. AI 활용으로 이어지는 연결

이 모듈이 어떻게 분류, 예측, 이상 탐지, 리포트 생성으로 이어지는지 짧게 연결한다.

### 7. 과장하면 안 되는 해석

데이터 모델링으로 할 수 있는 것과 아직 할 수 없는 것을 구분한다.

## 문장 수준 편집 원칙

- `추출기록`처럼 일반 독자에게 표준적이지 않은 표현은 피한다.
- `동작 1회`, `샘플 1건`, `원시 시계열`, `요약 행`처럼 역할이 보이는 표현을 우선한다.
- 특정 장비 이름이 없어도 이해되는 문장으로 다시 쓴다.
- 내부 명칭 대신 관찰 구조와 판단 구조를 드러낸다.

## 현재 결론

이 템플릿을 따르면 같은 사례를 여러 Part에 나누어 쓰더라도 전개가 어긋나지 않고, AI 활용 관점의 데이터 모델링 설명을 일관되게 유지할 수 있다.
