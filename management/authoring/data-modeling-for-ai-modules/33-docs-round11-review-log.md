## 이번 반영의 핵심 판단

### 1. 부스팅 성능 절은 점수 변화만이 아니라 중단 판단까지 남겨야 한다

`part-03/chapter-16/section-02.md`는 부스팅의 성능과 과적합 위험을 다룬다. 이번 라운드에서는 여기에 다음 구조를 붙였다.

- 성능 변화
- 과적합 신호
- 중단 판단

이 보강으로 부스팅 성능 절은 `강한 성능 후보` 설명을 넘어서 `어디서 멈추고 무엇을 다시 조정할 것인가`를 남기는 절로 읽히게 된다.

### 2. 클러스터링 입문 절은 묶음 가설과 대표 사례를 같이 남겨야 한다

`part-03/chapter-17/section-01.md`는 라벨 없는 구조 찾기의 출발점을 설명한다. 이번 라운드에서는 여기에 다음 구조를 더했다.

- 묶음 가설
- 대표 사례
- 다음 확인 질문

이 보강의 목적은 클러스터링 입문 절을 `알고리즘 소개`가 아니라 `구조 가설을 어떤 샘플 수준에서 읽을 것인가`를 남기는 절로 바꾸는 데 있다.

### 3. 군집 해석 절은 정책 연결 전에 해석 경계를 먼저 적게 해야 한다

`part-03/chapter-17/section-02.md`는 군집 결과를 과신하지 않는 태도를 다룬다. 이번 라운드에서는 여기에 다음 구조를 붙였다.

- 먼저 보인 군집 결과
- 바로 붙일 해석 경계
- 다시 확인할 review 질문

이 보강으로 군집 해석 절은 `주의하라`는 추상 문장을 넘어서, 실제 검토 메모 형식으로 안전한 읽기 순서를 제공하게 된다.

### 4. Part 3 마무리는 지도학습과 비지도학습의 공통 기록 언어를 묶어야 한다

`docs/parts/part-03/summary.md`는 Part 3 전체를 정리하는 마무리 페이지다. 이번 라운드에서는 여기에 다음 구조를 추가했다.

- 비지도학습에도 적용되는 `fact / interpretation / next question`
- `보인 구조 -> 해석 경계 -> 다음 검증 질문` 요약 표

이 보강으로 Part 3 전체가 개별 알고리즘 목록이 아니라, 공통 review 구조 위에 놓인 파트라는 점이 더 분명해진다.

## 파일별 반영 이유

### `part-03/chapter-16/section-02.md`

반영한 내용:

- 성능 변화, 과적합 신호, 중단 판단 표
- 먼저 보인 신호 표에 `멈춤 후보 지점` 행 추가
- 기억할 관점 아래에 `같이 봐야 할 것` 표 추가

반영 이유:

- 부스팅 절이 높은 점수 설명에 머물지 않고, 언제 멈출지와 무엇을 다시 조정할지 연결될 필요가 있었다.

### `part-03/chapter-17/section-01.md`

반영한 내용:

- 묶음 가설, 대표 사례, 다음 확인 질문 표
- 쇼핑몰 고객 사례를 review 메모 형식으로 다시 적는 표
- 기억할 관점 아래에 `같이 봐야 할 것` 표 추가

반영 이유:

- 군집 번호나 알고리즘 이름보다, 어떤 샘플 묶음을 어떤 질문으로 해석할지 남기는 구조가 필요했다.

### `part-03/chapter-17/section-02.md`

반영한 내용:

- 군집 결과와 해석 경계를 바로 묶는 표
- 쿠폰 정책 사례를 프로젝트 메모 형식으로 다시 적는 표
- 기억할 관점 아래에 `같이 봐야 할 것` 표 추가

반영 이유:

- 군집 결과를 정책 규칙으로 성급하게 넘기지 않도록, 해석 경계와 다음 검증 질문을 더 명시할 필요가 있었다.

### `docs/parts/part-03/summary.md`

반영한 내용:

- 비지도학습도 `fact / interpretation / next question` 구조로 적는 표
- Part 3 전체 handoff를 `보인 구조 -> 해석 경계 -> 다음 검증 질문`으로 다시 압축한 표

반영 이유:

- Part 3 전체를 지도/비지도/강화학습의 목록이 아니라 공통 검토 언어로 다시 묶을 필요가 있었다.
