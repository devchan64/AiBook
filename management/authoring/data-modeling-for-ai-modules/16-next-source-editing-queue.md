# 데이터 모델링 모듈 기준의 다음 원본 편집 큐

## 목적

이 문서는 실제 원고 편집 전에 어떤 참조 자료를 어떤 순서로 다시 읽고, 그 결과를 어떤 원고 반영 준비 문서로 옮길지 작업 큐 형태로 정리한다.

`management/authoring/brewing-shot-ai-notes`는 참고 원천으로만 읽고, 직접 수정 대상으로 두지 않는다. 실제 편집 판단과 근거 기록은 `data-modeling-for-ai-modules` 안에서 계속 쌓는다.

## 현재 상태

`02-problem-framing-from-shot-to-dataset.md`는 현재 커밋 기준의 표현 축을 참조본으로 사용한다. 다른 `brewing-shot-ai-notes` 문서는 수정 대상이 아니라, 공통 어휘와 삽입 문단을 만들 때 다시 읽는 참고 자료로만 사용한다.

또한 `01`부터 `10`까지의 노트는 한 차례 참조 검토가 끝나 있으며, 현재 상태 추적은 다음 로그에 남아 있다.

- `17-notes-01-02-review-log.md`
- `18-notes-03-05-review-log.md`
- `19-notes-06-08-review-log.md`
- `20-notes-09-10-review-log.md`
- `47-notes-01-02-refresh-log.md`
- `48-note-02-problem-framing-commit-log.md`

따라서 이 문서는 `아직 읽지 않은 순서`를 적는 큐라기보다, `다음에 다시 열 경우 어떤 조건에서 참조 라운드를 재개할지`를 정리하는 문서로 읽는 편이 맞다.

## 큐 1. 참조 읽기: 01-domain-opportunity-and-boundaries.md

다음에 확인할 것:

- 사례 소개가 특정 장비에 과도하게 기대고 있지 않은가
- `동작 1회`를 샘플로 보는 설명이 충분한가
- 문제 정의가 모델 선택보다 먼저 나오는가

반영 목표:

- 도메인 소개를 일반화된 문제 구조 설명으로 다시 읽고, 필요한 표현은 `43-common-vocabulary-and-usage-map.md`와 Part별 삽입 문단 쪽으로 옮긴다.

현재 메모:

- 이 노트 자체는 더 수정하지 않는다.
- 사례 소개, LLM 비교, 경고/진단 대비에서 원고에 재사용할 수 있는 문장을 별도 관리 문서로 추출할 필요가 있다.

## 큐 2. 참조 읽기: 02-problem-framing-from-shot-to-dataset.md

다음에 확인할 것:

- `shot`이 정확히 무엇을 뜻하는지 문맥 안에서 스스로 설명되는가
- 한 행, 한 측정값, 동작 1회, 데이터셋의 층위가 구분되는가

반영 목표:

- 샘플 단위 정의와 데이터셋 구성 흐름을 다시 읽고, 필요한 대비표와 문제 정의 질문을 `data-modeling-for-ai-modules` 쪽 자산 문서로 옮긴다.

현재 메모:

- 이 노트는 현재 커밋 상태를 참조본으로 사용한다.
- 이후에는 노트 자체를 더 손보기보다, 이 노트에서 드러난 문제 정의 층위를 원고 삽입 체크리스트로 옮기는 편이 맞다.

## 큐 3. 참조 읽기: 03-time-series-normalization-and-segmentation.md

다음에 확인할 것:

- 정규화와 구간 분할이 왜 필요한지 문제 장면과 연결되는가
- 원시 시계열과 요약 구조의 관계가 자연스럽게 이어지는가

반영 목표:

- 시계열 정렬과 분할이 표현 설계의 일부라는 점을 읽어 내고, Part 2/3용 삽입 자산으로 다시 정리한다.

현재 상태:

- 1차 참조 검토는 `18-notes-03-05-review-log.md`에 반영되어 있다.
- 다음 재개는 Part 2/3 본문 확장 위치가 새로 생기거나, `원시 시계열 -> 구간 분할 -> 요약 구조` 설명이 부족한 사례가 다시 보일 때만 연다.

## 큐 4. 참조 읽기: 04-sensor-tokenization-and-explainable-features.md

다음에 확인할 것:

- `토큰화`가 과장되어 쓰이지 않는가
- 설명 가능한 특징 설계라는 표현이 더 적절한가

반영 목표:

- 표현 설계와 특징 설계의 맥락을 먼저 읽고, 필요한 표현은 공통 어휘와 Part별 후보 문단 쪽으로 재정리한다.

현재 상태:

- 1차 참조 검토는 `18-notes-03-05-review-log.md`에 반영되어 있다.
- 다음 재개는 `토큰화`와 `설명 가능한 특징`의 경계가 본문에서 다시 흐려질 때만 연다.

## 큐 5. 참조 읽기: 05-window-aggregation-baseline-drift.md

다음에 확인할 것:

- `drift`라는 표현이 일반 독자 기준에서 과도하거나 좁지 않은가
- 최근 구간과 기준선 비교가 먼저 설명되는가

반영 목표:

- 최근 구간과 기준선 비교를 원고에 옮길 때 필요한 표, 경계 문장, 비교 순서를 별도 자산으로 정리한다.

현재 상태:

- 1차 참조 검토는 `18-notes-03-05-review-log.md`에 반영되어 있다.
- 다음 재개는 `drift`, `버킷`, `baseline` 잔여 표현이 새 본문 후보에서 다시 충돌할 때만 연다.

## 큐 6. 참조 읽기: 06-sample-size-repeatability-and-false-alarms.md

다음에 확인할 것:

- 경고와 진단의 경계가 선명한가
- 표본 수가 적을 때의 해석 한계가 충분한가

반영 목표:

- 표본 수, 반복성, 경고 해석을 원고용 체크리스트와 과장 방지 문장 세트로 더 정교하게 옮긴다.

현재 상태:

- 1차 참조 검토는 `19-notes-06-08-review-log.md`에 반영되어 있다.
- 다음 재개는 경고/진단 경계나 작은 표본 보수 해석이 새 원고 위치에서 다시 약해질 때만 연다.

## 재개 후보 메모

다음 참조 라운드를 실제로 다시 열 상황은 아래 셋으로 한정한다.

- 새 본문 확장 위치가 생겨 노트의 예시나 비교 구조를 다시 호출해야 할 때
- 현재 공통 어휘와 충돌하는 과거 표현이 새 초안이나 관리 문서에서 다시 발견될 때
- Part 2, Part 3, Part 6의 삽입 자산을 더 세분화해야 해 참조본의 문제 구조를 다시 추출할 필요가 생길 때

## 현재 결론

지금 단계에서 다음 실편집은 `brewing-shot-ai-notes` 자체를 다시 읽는 것보다, 이미 끝난 참조 검토 결과를 `data-modeling-for-ai-modules` 안의 자산 문서와 순차 검토 기준에 유지하는 쪽이 맞다. 참조 큐는 위 재개 조건이 생길 때 다시 여는 편이 적절하다.
