# 데이터 모델링 모듈 기준의 다음 원본 편집 큐

## 목적

이 문서는 실제로 다음에 손댈 원본 문서를 어떤 순서로 검토하고 편집할지 작업 큐 형태로 정리한다.

대상은 우선 `management/authoring/brewing-shot-ai-notes` 아래 노트다.

## 큐 1. 01-domain-opportunity-and-boundaries.md

다음에 확인할 것:

- 사례 소개가 특정 장비에 과도하게 기대고 있지 않은가
- `동작 1회`를 샘플로 보는 설명이 충분한가
- 문제 정의가 모델 선택보다 먼저 나오는가

편집 목표:

- 도메인 소개를 일반화된 문제 구조 설명으로 다듬는다.

## 큐 2. 02-problem-framing-from-shot-to-dataset.md

다음에 확인할 것:

- `shot`이 정확히 무엇을 뜻하는지 문맥 안에서 스스로 설명되는가
- 한 행, 한 측정값, 동작 1회, 데이터셋의 층위가 구분되는가

편집 목표:

- 샘플 단위 정의와 데이터셋 구성 흐름을 더 명확히 만든다.

## 큐 3. 03-time-series-normalization-and-segmentation.md

다음에 확인할 것:

- 정규화와 구간 분할이 왜 필요한지 문제 장면과 연결되는가
- 원시 시계열과 요약 구조의 관계가 자연스럽게 이어지는가

편집 목표:

- 시계열 정렬과 분할이 표현 설계의 일부라는 점을 강화한다.

## 큐 4. 04-sensor-tokenization-and-explainable-features.md

다음에 확인할 것:

- `토큰화`가 과장되어 쓰이지 않는가
- 설명 가능한 특징 설계라는 표현이 더 적절한가

편집 목표:

- 토큰화보다 표현 설계와 특징 설계의 맥락이 먼저 보이게 정리한다.

## 큐 5. 05-window-aggregation-baseline-drift.md

다음에 확인할 것:

- `drift`라는 표현이 일반 독자 기준에서 과도하거나 좁지 않은가
- 최근 구간과 기준선 비교가 먼저 설명되는가

편집 목표:

- 용어를 일반화하고, 변화 해석과 원인 확정을 구분하는 문장을 보강한다.

## 큐 6. 06-sample-size-repeatability-and-false-alarms.md

다음에 확인할 것:

- 경고와 진단의 경계가 선명한가
- 표본 수가 적을 때의 해석 한계가 충분한가

편집 목표:

- 경고 문장과 검토 필요 판단 구조를 더 명료하게 만든다.

## 현재 결론

다음 실편집은 `01`부터 `06`까지를 순차적으로 재검토하면서, 모듈 문서에서 고정한 공통 어휘와 표, 예제 구조를 반영하는 흐름으로 가는 것이 맞다.
