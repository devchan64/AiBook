# 책 배치 원칙과 편집 원칙

## 새 Part보다 모듈 배치가 더 나은 이유

이 주제는 독립 Part보다 여러 Part에서 호출되는 공통 모듈로 둘 때 장점이 크다.

이유는 다음과 같다.

- Part 1에서는 문제 정의용으로 얕게 쓴다
- Part 2에서는 표와 집계, 시각화용으로 쓴다
- Part 3에서는 특징, baseline, 평가용으로 쓴다
- Part 6에서는 프로젝트 산출물 구조용으로 쓴다

즉 같은 사례를 다른 질문으로 재독하게 만드는 편이 더 교육적이다.

## Part별 권장 배치

### Part 1

- 샘플 단위 정의
- 문제 구조 정의

### Part 2

- 원시 로그와 요약 표
- 진행도 구간 집계
- 같은 평균, 다른 패턴

### Part 3

- 특징 설계
- 기준선 비교
- 표본 수와 반복성
- 모델링 사다리

### Part 6

- 프로젝트 질문
- 최근 구간과 평소 기준선 비교 리포트

## 편집 원칙

### 넣어야 할 것

- 층위 비교표
- 흐름 도식
- 짧은 장난감 데이터
- 사람이 읽는 해석 문장

### 빼야 할 것

- 실제 기업 내부 용어
- 실제 장비 규칙
- 실제 임계값
- 특정 구현을 유추할 수 있는 상세 구조

### 과장하지 말아야 할 것

- 변화 추세 = 곧 고장
- 기준선 이탈 = 곧 원인 확정
- 토큰화 = 만능 표현

## 현재 결론

이 주제는 `반복 등장하는 공통 사례 모듈`로 편집하는 편이 가장 안전하다.
