# 실제 본문 편집 8차 반영 검토 메모

## 목적

이 문서는 `data-modeling-for-ai-modules`의 관점을 실제 `docs/` 본문에 8차로 반영하면서, 왜 이번 라운드에서 `결정트리`, `트리의 과적합`, `이미지 분류 목표`, `오류 사례 분석` 절을 공통 review 기록 구조와 더 직접 연결했는지 기록한다.

이번 라운드 대상은 다음 네 파일이다.

- `docs/parts/part-03/chapter-14/section-01.md`
- `docs/parts/part-03/chapter-14/section-02.md`
- `docs/parts/part-06/chapter-03/section-01.md`
- `docs/parts/part-06/chapter-03/section-02.md`

## 이번 반영의 핵심 판단

### 1. 결정트리는 첫 분기와 분기 근처 사례를 같이 남기는 구조여야 한다

`part-03/chapter-14/section-01.md`는 원래 질문 흐름으로 예측하는 모델을 설명하는 절이다. 이번 라운드에서는 여기에 다음 구조를 추가했다.

- baseline과 결정트리 비교
- 첫 분기 근처 사례
- leaf에 모인 대표 사례
- 다음 질문

이 보강으로 결정트리는 `질문을 나누는 모델`에 그치지 않고, `어떤 사례가 분기 경계에서 애매한가`를 review 대상으로 남기는 비교 후보로 읽히게 된다.

### 2. 과적합 절은 복잡도 변화와 남는 실패를 같이 기록해야 한다

`part-03/chapter-14/section-02.md`는 깊이, leaf 크기, pruning을 설명한다. 이번 라운드에서는 여기에 다음 구조를 붙였다.

- 깊이 또는 leaf 크기 변화
- train/test 차이
- 계속 남는 실패 사례
- 다음 가지치기 질문

이 보강의 목적은 과적합 절을 `깊어지면 위험하다`는 일반론보다 `복잡도가 늘 때 어떤 실패가 남는가`를 기록하는 절로 읽게 만드는 데 있다.

### 3. 이미지 분류 목표 절도 입력과 review 기준을 앞단에서 같이 보여야 한다

`part-06/chapter-03/section-01.md`는 이미지 분류 최소 구조를 소개한다. 이번 라운드에서는 입력 shape, 라벨, review 대상 샘플 기준, 다음 점검 질문을 입구에서 같이 남기는 표를 추가했다.

이 보강으로 이미지 프로젝트 입구에서부터 `어떤 샘플이 다음 절 분석 대상으로 넘어갈지`가 문서에 드러난다.

### 4. 오류 사례 분석 절은 사실, review 사례, 다음 보강 질문을 같은 묶음으로 남겨야 한다

`part-06/chapter-03/section-02.md`는 이미지 오류 사례를 해석하는 절이다. 이번 라운드에서는 여기에 오류 샘플 ID, review 이유, 다음 보강 항목, 공통 회고 문장을 남기는 구조를 추가했다.

이 보강으로 오류 분석 절은 단순 감상문이 아니라 `다음 실험을 여는 기록`이라는 점이 더 분명해진다.

## 파일별 반영 이유

### `part-03/chapter-14/section-01.md`

반영한 내용:

- 첫 분기 근처 사례와 review 필요 여부를 남기는 표
- 결정트리 후보를 프로젝트 메모 형식으로 적는 예시

반영 이유:

- 결정트리 절이 알고리즘 설명만이 아니라 `비교 후보 -> 분기 근처 사례 -> 다음 질문` 구조를 갖추게 만들 필요가 있었다.

### `part-03/chapter-14/section-02.md`

반영한 내용:

- 복잡도 변화와 남는 실패 사례를 같이 남기는 표
- 과적합 절을 `복잡도 변화 -> 가지치기 질문` 구조로 읽게 하는 문장

반영 이유:

- 과적합 절이 성능 숫자 비교를 넘어, 어떤 복잡도 조정이 실제 실패를 줄이는지 기록하는 절이라는 점을 더 분명히 할 필요가 있었다.

### `part-06/chapter-03/section-01.md`

반영한 내용:

- 입력 shape, 라벨, review 기준, 다음 점검 질문을 입구에서 남기는 표
- 단계별 review 상태와 다음 행동을 잇는 간단한 표

반영 이유:

- 이미지 프로젝트 입구에서부터 `입력 -> 비교 기준 -> review 질문` 구조가 보여야 뒤 절 오류 사례 분석도 더 자연스럽게 읽힌다.

### `part-06/chapter-03/section-02.md`

반영한 내용:

- 오류 샘플 ID, review 이유, 다음 보강 항목을 남기는 표
- 오류 분석 절을 `사실 -> review 사례 -> 다음 보강 질문` 구조로 읽게 하는 문장

반영 이유:

- 이미지 오류 분석이 Part 6 전체의 공통 review 기록 구조와 같은 형식으로 보이도록 만들 필요가 있었다.
