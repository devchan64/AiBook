# 현재 작업 세트 가이드

## 목적

이 문서는 `data-modeling-for-ai-modules` 문서 수가 많아진 현재 상태에서, 작업을 재개할 때 실제로 먼저 열어야 할 문서 묶음을 짧게 고정하기 위해 만든다.

전체 목록은 `README.md`가 유지하고, 이 문서는 `지금 당장 무엇부터 읽을 것인가`만 안내한다.

가장 짧은 재개 시작점만 필요하면 `118-minimum-restart-packet.md`를 먼저 본다.

운영 문서끼리의 역할 차이는 `120-operations-doc-overlap-audit.md`에 따로 정리했다.

## 언제 이 문서를 쓰는가

- 작업을 며칠 뒤에 다시 이어서 시작할 때
- 과거 로그가 많아 현재 큐를 바로 찾기 어려울 때
- 새 본문 확장 위치가 생겨 재개 조건을 확인해야 할 때

## 재개 순서

### 1. 현재 목표와 상태 확인

먼저 다음 두 문서를 본다.

- `105-goal-requirements-audit.md`
- `100-plan-status-audit.md`

여기서 확인할 것:

- 현재 목표 요구사항이 무엇인가
- 현재 상태가 `완료`, `준비 완료`, `1차 라운드 완료` 중 어디까지 왔는가
- 새 작업이 `미완료 계획 수행`인지 `재개 조건 기반 작업`인지

### 2. 현재 큐와 재개 조건 확인

다음으로 다음 두 문서를 본다.

- `25-next-docs-editing-queue.md`
- `51-section-level-review-sequence.md`
- `112-commit-boundary-and-branch-audit.md`

여기서 확인할 것:

- 실제 다음 후보가 무엇인가
- Part 2, Part 3, Part 6의 1차 순차 검토가 어디까지 끝났는가
- 새 본문 확장 위치가 생겼을 때 어떤 묶음을 다시 열어야 하는가
- 현재 커밋 예외와 비커밋 범위가 무엇인가

### 3. 참조 노트 재개 여부 확인

참조 노트를 다시 열 필요가 있는지 보려면 다음 문서를 본다.

- `16-next-source-editing-queue.md`
- `99-source-queue-status-refresh-log.md`

여기서 확인할 것:

- 참조 라운드를 다시 열 조건이 생겼는가
- 현재는 노트를 다시 읽을 단계인지, 이미 추출한 자산을 재사용할 단계인지

### 4. 자산과 경계 문장 확인

실제 본문 확장 위치가 생겼다면 다음 문서를 바로 연다.

- `49-manuscript-insertion-prep-checklist.md`
- `21-docs-insertion-asset-map.md`
- `43-common-vocabulary-and-usage-map.md`
- `45-overstatement-guard-sentences.md`

여기서 확인할 것:

- 어떤 반영 묶음을 호출할지
- 어떤 표, 예제, 후보 문단을 붙일지
- 어떤 과장 방지 문장을 같이 넣을지

## 과거 로그는 언제 보는가

위 문서들만으로 현재 상태 판단이 끝난 뒤에만 과거 로그를 본다.

- 당시 왜 그렇게 고쳤는지를 보려면 `53` 이후 파일별 검토 로그
- 참조 노트 정리 이유를 보려면 `17`부터 `20`, `47`, `48`
- 관리 문서 상태 정렬 이유를 보려면 `97`부터 `104`

과거 로그 읽기 원칙은 `104-historical-log-reading-guide.md`를 따른다.

## 현재 결론

지금 이 디렉터리를 다시 열 때는 전체 목록부터 훑기보다, `105 -> 100 -> 25 -> 51 -> 16 -> 99` 순서로 현재 상태를 먼저 고정하는 편이 가장 빠르다. 실제 본문 확장이 필요해질 때만 `49`, `21`, `43`, `45`를 이어서 여는 구조로 보는 것이 맞다.
