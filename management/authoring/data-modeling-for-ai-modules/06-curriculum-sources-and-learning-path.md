# 데이터 모델링 학습 출처와 학습 경로

## 왜 이 문서가 필요한가

`데이터 모델링`은 흔히 데이터베이스 설계 과목의 일부로만 이해되지만, AI 활용 맥락에서는 훨씬 넓다.

독자가 실제로 배워야 하는 것은 테이블 정규화만이 아니라, 어떤 현상을 어떤 샘플 단위로 자르고, 어떤 값을 요약하고, 어떤 비교 기준을 세워야 모델이 의미 있게 작동하는가다.

따라서 이 주제는 한 과목에서 완결되기보다 여러 학습 전통이 합쳐져 형성된다.

## 일반적으로 이 주제를 배우는 곳

### 1. 데이터베이스와 정보시스템

여기서 배우는 것은 주로 다음이다.

- 엔터티와 관계
- 테이블 구조
- 정규화
- 키와 제약조건
- 트랜잭션 관점의 저장 구조

이 전통은 `무엇을 안정적으로 저장할 것인가`에는 강하지만, 시계열 특징 설계나 모델 입력 표현에는 직접 답하지 못하는 경우가 많다.

### 2. 통계와 실험 설계

여기서 배우는 것은 주로 다음이다.

- 표본 수
- 반복성
- 변동성
- 기준선 비교
- 잘못된 경고와 잘못된 확신

이 전통은 `얼마나 믿을 수 있는가`를 다루는 데 강하다.

### 3. 데이터 분석과 시계열 분석

여기서 배우는 것은 주로 다음이다.

- 로그 정리
- 윈도우 집계
- 결측 처리
- 추세와 변동 해석
- 시계열 구간 분할

이 전통은 `원시 로그를 어떤 분석 단위로 바꿀 것인가`를 다루는 데 유용하다.

### 4. 머신러닝 실무

여기서 배우는 것은 주로 다음이다.

- feature engineering
- train/validation/test 분리
- label 정의
- leakage 방지
- 모델 입력 스키마 설계

이 전통은 `모델이 학습 가능한 표 형태나 텐서 형태로 어떻게 바꿀 것인가`를 다룬다.

### 5. 데이터 엔지니어링과 MLOps

여기서 배우는 것은 주로 다음이다.

- 데이터 파이프라인
- 피처 저장 구조
- 배치와 스트리밍
- 재현 가능한 전처리
- 운영용 리포트 구조

이 전통은 `한 번 만든 데이터 모델을 반복 운영 가능한 구조로 고정하는 방법`을 다룬다.

## 책에서 제시할 학습 경로

이 책은 위 전통을 학문사적으로 길게 나열하기보다, 독자가 따라가기 쉬운 순서로 다시 배열해야 한다.

추천 순서는 다음과 같다.

1. 샘플 단위부터 정의한다.
2. 원시 로그와 요약 표를 구분한다.
3. 비교 가능한 기준선을 만든다.
4. 특징과 중간 표현을 설계한다.
5. 표본 수와 반복성을 해석한다.
6. 마지막에 규칙 기반과 학습 기반 모델을 비교한다.

이 순서는 `저장 구조`보다 `문제 표현 구조`를 먼저 잡는 흐름이다.

## 편집상 주의점

- `데이터 모델링 = DB 스키마 설계`로 축소하지 않는다.
- `데이터 모델링 = 곧 머신러닝 모델 선택`으로 점프하지 않는다.
- 먼저 샘플, 비교 기준, 요약 구조를 잡고 그 위에 특징과 모델을 올린다.
- 통계, 시계열, ML, 운영을 따로 가르치지 말고 하나의 사례 위에서 연결한다.

## 현재 결론

이 책에서의 데이터 모델링은 전통적인 DB 설계 단원으로 처리하기보다, `AI가 읽을 수 있는 관찰 구조를 만드는 교차 모듈`로 다루는 편이 맞다.
