# 실제 본문 편집 3차 반영 검토 메모

## 목적

이 문서는 `data-modeling-for-ai-modules`의 관점을 실제 `docs/` 본문에 3차로 반영하면서, 왜 이번 라운드에서 `모델 선택 메모`와 `개선 기록 문서화`를 보강했는지 기록한다.

이번 라운드 대상은 다음 두 파일이다.

- `docs/parts/part-03/chapter-08/section-01.md`
- `docs/parts/part-06/chapter-02/section-02.md`

## 이번 반영의 핵심 판단

### 1. 모델 선택은 알고리즘 이름보다 먼저 데이터 구조 메모와 붙어야 한다

사용자 요구의 핵심은 특정 사례를 단순히 일반화된 용어로 바꾸는 것에 그치지 않고, 책 전체에서 `무엇을 샘플로 보고`, `어떤 비교 구조를 만들며`, `어디까지를 경고로 읽는가`를 재사용 가능한 관점으로 만드는 데 있다.

따라서 `part-03/chapter-08/section-01.md`에는 후보 모델군을 적기 전에 다음 항목을 먼저 확인하게 하는 표를 넣었다.

- 샘플 단위
- 원시 로그와 요약 특징 표의 구분
- 최근 결과와 기준선 비교 프레임
- 경고와 원인 확정의 경계

이 보강은 모델 선택을 `알고리즘 서랍 고르기`로만 읽는 것을 막는다.

### 2. 개선 기록은 예측 정확도 보고서보다 더 넓은 비교 문서다

`part-06/chapter-02/section-02.md`는 원래 baseline과 1-NN 비교를 문서화하는 절이다. 이번 라운드에서는 여기서 한 걸음 더 나아가, 개선 기록이 프로젝트 유형마다 다른 형태를 가진다는 점을 짧은 표로 고정했다.

- 분류 모델 vs 기준 모델
- 최근 결과 vs 평소 기준선
- 새 버전 vs 이전 규칙 또는 이전 모델

이 구분이 있어야 독자가 모든 프로젝트를 `정확도 개선 보고서` 형태로만 쓰지 않게 된다.

## 파일별 반영 이유

### `part-03/chapter-08/section-01.md`

반영한 내용:

- 모델 후보 메모 전에 점검해야 할 데이터 구조 표
- 모델 선택이 비교 가능한 데이터 구조 고정과 붙어 있다는 연결 문장

반영 이유:

- `part-03/chapter-08`은 모델 선택, 기준 모델, 튜닝으로 이어지는 묶음이므로, 여기서부터 샘플 단위와 기준선 프레임을 함께 적는 습관을 넣는 편이 뒤 절과 더 자연스럽게 이어진다.
- 특히 앞서 보강한 `part-03/chapter-07/section-01.md`, `part-03/chapter-08/section-02.md`의 논리를 중간에서 끊지 않고 이어 주는 역할이 필요했다.

### `part-06/chapter-02/section-02.md`

반영한 내용:

- 프로젝트 유형별 baseline 위치와 최소 산출물 표
- 개선 해석에 붙는 경계 문장 세트

반영 이유:

- `part-06`은 실습과 회고가 중심이므로, 무엇을 결과로 남겨야 하는지를 더 직접적으로 적어 둘 필요가 있다.
- 이번 보강은 `점수 상승`과 `검토 가능한 개선 기록`을 구분해, Part 6 이후 프로젝트들에도 반복 호출 가능한 문장 구조를 마련한다.

## 이번 라운드에서 의도적으로 하지 않은 것

- 새 Python 예제를 추가하지 않았다.
- 특정 도메인 배경을 길게 설명하지 않았다.
- 기존 절의 중심 질문을 바꾸지 않았다.
- 현재 비커밋 상태의 `docs/` 본문을 커밋하지 않았다.
