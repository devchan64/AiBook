# Section 학습 평가 리포트 준비 메모

작성일: 2026-07-31

이 문서는 Section 원고별 학습 평가 리포트를 만들기 전에 적용 범위, 읽기 순서, 평가 기준, 1차 점검 신호를 정리한다. 실제 Section별 중심 학습 산출물은 이 문서에 누적하지 않고, 기존 기준에 따라 `management/authoring/part-XX-open-checklist.md`의 `목차 기준 체크포인트` 구간에서 관리한다.

실제 1차 Section별 평가 표는 `management/authoring/section-learning-evaluation-report.md`에서 관리한다.

## 목적

- 한국어 Section 원고를 `Section ID` 기준으로 읽고, 각 Section이 독자에게 남겨야 할 학습 판단 기준을 평가한다.
- 평가는 원고의 좋고 나쁨을 포괄적으로 점수화하는 작업이 아니라, 해당 Section을 읽은 독자가 무엇을 구분하거나 판단할 수 있어야 하는지 확인하는 작업으로 둔다.
- 리포트는 본문 수정 지시서가 아니라 후속 수정 우선순위를 세우는 근거 문서로 작성한다.

## 적용 범위

1차 대상은 한국어 원고 원본이다.

- 대상: `docs/parts/part-*/chapter-*/section-*.md`
- 제외: `*.en.md`, `*.zh.md`
- 보조 대조 문서: `management/authoring/part-XX-open-checklist.md`
- 공개 진입 문서인 Part 시작 페이지와 마무리 페이지는 별도 라운드에서 다룬다.

## 1차 인벤토리

2026-07-31 현재 한국어 Section 원고는 364개다. 제목의 `Section ID`와 파일 위치가 일치하지 않는 원고는 1차 점검에서 발견되지 않았다.

| Part | Section 수 | 체크리스트 보유 | 출처 절 보유 | Python 예제 포함 | Mermaid 포함 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Part 1 | 57 | 57 | 57 | 0 | 16 |
| Part 2 | 63 | 63 | 63 | 39 | 18 |
| Part 3 | 52 | 0 | 52 | 22 | 35 |
| Part 4 | 59 | 56 | 59 | 46 | 59 |
| Part 5 | 53 | 53 | 53 | 36 | 44 |

1차 구조 신호:

- Part 3 전체 52개 Section에는 `## 체크리스트` 절이 없다.
- Part 4에는 체크리스트가 없는 Section이 3개 있다.
- Part 6 Chapter 1의 3개 Section은 2026-07-31에 출처 절을 보강했다.
- Python 예제는 205개 Section에 있고, Mermaid 도식은 240개 Section에 있다. 평가 리포트에서는 설명형 Section과 실습형 Section의 판정 기준을 분리해야 한다.

## 평가 축

각 Section은 다음 여섯 축으로 읽는다.

| 축 | 판정 질문 | 주요 근거 |
| --- | --- | --- |
| 중심 질문 | 이 Section이 하나의 중심 질문에 답하는가? | 제목, 도입부, 결론 문단 |
| 학습 산출물 | 독자가 무엇을 구분하거나 판단할 수 있어야 하는지 한 문장으로 잡히는가? | Part 체크포인트 항목, 본문 핵심 설명 |
| 초심자 진입성 | 선행 지식이 부족한 독자가 막힐 지점을 본문, 표, 예시, 보충학습 중 적절한 방식으로 넘길 수 있는가? | 첫 정의, 예시, 보충학습 배치 |
| 적용 가능성 | 읽은 뒤 독자가 분류, 표시, 계산, 비교, 값 변경, 오류 해석 중 하나 이상을 해 볼 수 있는가? | 체크리스트, 연습, Python 예제 |
| 근거 안정성 | 사실 주장, 외부 기준, 최신성 있는 설명이 출처와 조심스러운 표현으로 뒷받침되는가? | 출처 절, 날짜, 단정 표현 |
| 흐름 연결 | 앞 Section에서 받은 개념과 뒤 Section으로 넘길 질문이 과도한 반복 없이 연결되는가? | 도입부, 후속 연결 문장, 개념사전 링크 |

## 판정 등급

리포트에서는 숫자 점수보다 작업 판단에 바로 연결되는 등급을 쓴다.

- `유지`: 중심 질문, 학습 산출물, 확인 장치가 현재 수준에서 충분하다.
- `보강`: 중심은 맞지만 예시, 체크리스트, 출처, 초심자 연결 중 일부가 약하다.
- `재구성`: 여러 질문이 섞였거나 Section 경계가 흔들려 본문 흐름을 다시 잡아야 한다.
- `검증 필요`: 근거, 최신성, 저작권, 표준 용어 연결이 불안정해 외부 자료 확인이 먼저 필요하다.

## Section별 기록 형식

실제 리포트의 Section별 항목은 다음 형식으로 작성한다.

```md
### `P6-16.2` Section 제목

- 파일: `docs/parts/part-06/chapter-16/section-02.md`
- 기존 중심 학습 산출물: Part 체크포인트의 해당 항목을 인용 없이 요약
- 본문에서 실제로 남는 학습 산출물: 독자가 할 수 있어야 하는 판단을 한 문장으로 정리
- 평가 등급: 유지 / 보강 / 재구성 / 검증 필요
- 근거: 도입, 핵심 설명, 예제, 체크리스트, 출처 중 확인한 신호
- 후속 조치: 필요할 때만 짧게 작성
```

## 읽기 순서

1. Part 체크포인트의 `목차 기준 체크포인트` 항목을 먼저 읽고 해당 Section의 기대 학습 산출물을 확인한다.
2. 원고의 제목과 도입부를 읽어 중심 질문이 같은지 확인한다.
3. 본문 소제목을 따라 설명 흐름이 하나의 질문으로 모이는지 본다.
4. 예시, 표, Python 예제, Mermaid 도식이 학습 산출물에 직접 기여하는지 확인한다.
5. 체크리스트가 있으면 실제 판단 행동으로 이어지는지 본다.
6. 출처 절과 본문 단정 표현을 대조해 `검증 필요` 항목을 분리한다.
7. Section별 평가는 한 줄 결론을 먼저 쓰고, 근거는 필요한 만큼만 남긴다.

## 우선 검토 묶음

리포트 작성의 첫 라운드는 다음 순서가 적절하다.

1. Part 3: 체크리스트가 비어 있어 학습 평가 장치가 본문 안에 충분히 남아 있는지 먼저 확인한다.
2. Part 4의 체크리스트 누락 Section 3개: 실습형 또는 혼합형 원고라면 적용 가능성 축을 보강해야 할 수 있다.
3. Python 예제가 있는 Section: 예제가 단순 실행 안내인지, 조작할 값과 관찰할 출력 변화가 있는지 확인한다.
4. Mermaid가 많은 Section: 도식이 설명을 대체하지 않고 판단 순서를 압축하는지 확인한다.

## 리포트 작성 시 주의점

- Section별 중심 학습 산출물을 이 문서에 영구 목록으로 만들지 않는다.
- 체크리스트가 없다는 사실만으로 곧바로 미흡 판정하지 않는다. 본문 안의 연습, 표, 예제가 같은 역할을 하는지 먼저 본다.
- 실습형 Section은 코드 실행 여부보다 독자가 무엇을 바꿔 보고 무엇을 관찰하는지가 평가 기준이다.
- 이론형 Section은 정의의 정확성뿐 아니라 초심자가 구분 기준을 말할 수 있는지를 본다.
- 외부 자료 확인이 필요한 판단은 원고 수정 제안으로 바로 넘기지 않고 `검증 필요`로 분리한다.
