# Part 1 원고 대조 리포트

> 작성일: 2026-07-30
> 범위: `management/authoring/part-01-open-checklist.md`부터 `part-07-open-checklist.md`까지 중심선 확인 후, Part 1 한국어 원고를 우선 대조

## 점검 기준

- Part 1 체크포인트 노트는 작업 로그가 아니라 원고가 유지해야 할 중심선 문서다.
- Part 1의 전체 경계는 `AI 지형도`, `용어 층위`, `규칙에서 학습으로의 전환`, `LLM 사용 구조`, `사회적 판단 기준`을 입문 수준에서 닫고, 수식·구현·고급 알고리즘은 뒤 Part로 넘기는 구조다.
- 초반 Chapter 1-2의 `주요 학습내용`, `세부 학습내용` 계열 제목은 오래된 진행 메타 형식이지만, 소제목 교체 자체를 독립 수정 과제로 두지는 않는다.
- 한국어 원문에서 Section 경계나 소제목을 바꾸면 영어·중국어 번역본도 같은 `Section ID` 기준으로 후속 동기화 대상에 올린다.

## 요약 판단

Part 1 원고의 큰 흐름은 체크포인트 중심선과 대체로 맞는다. 특히 시작 페이지와 마무리 페이지는 AI를 LLM 하나로 좁히지 않고, 규칙·탐색·확률·학습·서비스 책임을 한 지도 안에 놓는 역할을 수행한다.

수정이 필요한 부분은 내용 압축보다 사례와 절차 설명의 유지 여부를 확인하는 쪽이다. P1-3.1은 독자 기준에서는 이미 많이 압축된 원고로 볼 수 있으므로, 추가 압축보다 현재 사례가 규칙 기반 시스템의 강점과 한계를 따라가게 하는지 확인하는 정도가 적절하다. 소제목 관리는 필수 작업으로 보지 않는다. 법률·보안·제품 문서·전망 자료를 쓰는 후반부는 원고가 조심스럽게 쓰였지만, 배포 전 출처 최신성 점검 대상으로 따로 남기는 것이 좋다.

## 수정 필요 항목

- 대상:
  - `docs/parts/part-01/chapter-01/section-01.md:28`, `:53`
  - `docs/parts/part-01/chapter-01/section-02.md:28`, `:40`

  - `docs/parts/part-01/chapter-02/section-01.md:29`, `:51`
  - `docs/parts/part-01/chapter-02/section-02.md:27`, `:49`
  - `docs/parts/part-01/chapter-02/section-03.md:29`, `:41`
- 확인된 원고 근거: Chapter 1-2의 여섯 Section이 모두 `## 주요 학습내용`, `## 세부 학습내용`을 사용한다.
- 검토 의견: Part 1 체크포인트 노트가 이 제목군을 오래된 진행 메타 형식으로 지정했지만, 현재 단계에서는 소제목 교체보다 본문 이해 흐름이 더 중요하다.
- 수정 방향: 필수 수정 없음. 실제 원고 개정 중 소제목이 독해를 방해한다고 확인될 때만 제한적으로 바꾼다.
- 후속 영향: 한국어 원문 제목을 바꾸는 경우에만 `*.en.md`, `*.zh.md` 번역본을 같은 `Section ID` 기준으로 동기화한다.

### 2. P1-3.3의 경계 설명 유지

- 대상: `docs/parts/part-01/chapter-03/section-03.md:68`
- 확인된 원고 근거: `## 이 절의 경계: 학습 전체가 아니라 표현을 본다`
- 검토 의견: 본문 내용은 3.2와 3.3의 역할을 잘 나눈다. 제목만 바꾸는 작업은 현재 우선순위가 낮다.
- 수정 방향: 표와 연결 문장을 유지한다. 소제목 교체는 실제 독해 문제가 확인될 때만 선택한다.

### 3. P1-5.2의 진행 안내형 제목 유지 가능 여부

- 대상: `docs/parts/part-01/chapter-05/section-02.md:14`
- 확인된 원고 근거: `## 이 절에서는 어떻게 받아들이면 좋은가`
- 검토 의견: 본문은 inference를 reasoning, prediction, statistical inference와 구분하는 방향이 좋다. 제목이 읽기 안내를 앞세우지만, 이 자체를 독립 수정 과제로 둘 필요는 낮다.
- 수정 방향: 바로 뒤의 정의 문장과 세 줄 대비를 유지한다. 소제목은 필요할 때만 제한적으로 조정한다.

### 4. P1-3.1의 역할 위치 확인

- 대상: `docs/parts/part-01/chapter-03/section-01.md:186`, `:198`부터 이어지는 흐름 설명
- 확인된 원고 근거: P1-3.1은 규칙 기반 시스템의 강점과 한계를 설명하는 중간에 `사례: 손으로 설계한 특징과 절차의 한계`, `흐름을 어떻게 표현할 것인가`를 배치하고, 데이터·계산 자원·도구 생태계 변화까지 설명한다.
- 수정 필요 이유: P1-3.1의 중심 질문은 사람이 규칙을 직접 쓰는 방식의 강점과 한계를 실제 판단 장면으로 설명하는 것이다. 다만 독자 기준에서는 이미 많이 압축된 설명으로 보일 수 있으므로, 추가 분량 축소를 기본 조치로 삼지 않는다.
- 수정 방향: 본문 압축보다 사례와 연결 문장의 역할만 점검한다. 현재 내용은 유지하되, P1-2.3과 P1-9.1로 넘어가는 연결이 과도한 역사 설명처럼 보이지 않는지 확인한다. 명시적 규칙, 설명 가능성, 통제 가능성, 지식 획득 문제, 예외 증가, 현대 서비스에서의 규칙 역할은 유지한다.

### 5. P1-14.5의 `하네스` 근거 성격 유지 점검

- 대상: `docs/parts/part-01/chapter-14/section-05.md:91`
- 확인된 원고 근거: 2026년 arXiv 프리프린트를 하네스 용어의 보조 근거로 사용하면서, 표준 정의 근거가 아니라고 명시한다.
- 수정 필요 이유: 현재 원고는 이미 조심스럽게 처리되어 있다. 다만 `하네스(harness)`를 이후 Part에서 반복 핵심 용어로 계속 쓸 경우, 최근 프리프린트 하나에 기대는 인상을 줄 수 있다.
- 수정 방향: 현재 문장의 보수적 단서를 유지한다. 다음 개정 때는 소프트웨어 테스트 하네스, 평가 하네스, LLM/agent 실행 기록 도구 문서처럼 더 안정적인 보조 근거를 함께 붙일지 검토한다.

### 6. P1-14.6, P1-15.2, P1-17.1의 변동 가능 출처 최신성 점검

- 대상:
  - `docs/parts/part-01/chapter-14/section-06.md:100`, `:126`, `:128`, `:132`
  - `docs/parts/part-01/chapter-15/section-02.md:14`, `:28`
  - `docs/parts/part-01/chapter-17/section-01.md`의 AI Index, WEF 전망 자료 사용 구간
- 확인된 원고 근거: 비용 최적화, 스트리밍, 프롬프트 캐싱, 레이트 리밋, 저작권법, 생성형 AI 학습 데이터 논쟁, 전망 자료처럼 시간이 지나며 바뀔 수 있는 자료를 사용한다.
- 수정 필요 이유: 원고 자체는 특정 가격이나 법률 결론, 전망을 단정하지 않도록 작성되어 있다. 다만 이 범주는 배포 전 최신성 확인이 필요한 고변동 주제다.
- 수정 방향: 본문 구조 수정 항목과 별도로, 배포 직전 확인 날짜와 출처 상태를 재점검한다. 법률 판단은 계속 `법률 결론을 단정하지 않음` 기조를 유지한다.

## 유지 확인 항목

- P1-8.1부터 P1-8.3은 지도학습, 비지도학습, 강화학습을 학습 신호의 차이로 설명하고 있어 체크포인트 중심선과 맞는다. 범위 안내 표가 있지만 본문 설명을 압도하지는 않는다.
- P1-9.1부터 P1-11.3은 딥러닝 확산 사례와 LLM 직접 계보를 구분하는 방향이 유지된다. 이미지 인식, 객체 검출, 음성 생성은 주변 근거로 두고, 통계적 언어 모델, Seq2Seq, Attention, Transformer를 직접 계보로 두는 현재 구분은 유지 대상이다.
- P1-14.3부터 P1-14.6은 에이전트, MCP, 하네스, 서비스 제약을 서로 다른 층위로 나누려는 구조가 유지된다.
- P1-15.1부터 P1-17.3은 사례, 법률·정책, 전망, 작업 가설을 단정하지 않고 구분하려는 장치가 있다.

## 검토 의견과 대안

### A안. 본문과 사례를 유지하고 검토 의견만 갱신

- 의견: 가장 비용이 낮고 현재 독자 기준에 맞는 방식이다. Chapter 1-2, P1-3.3, P1-5.2의 소제목은 당장 바꾸지 않고, P1-3.1 사례와 절차 설명을 유지한다.
- 장점: 원고 의미 변화가 없고, 초심자에게 필요한 사례 손잡이를 보존한다.
- 단점: 표면 제목의 오래된 형식은 그대로 남는다.
- 채택 기준: 현재 작업 목표가 리포트 기준 조정이면 이 안을 우선한다.

### B안. P1-3.1 연결 문장만 제한적으로 점검

- 의견: P1-3.1의 분량을 더 줄이는 방식은 기본으로 두지 않는다. 독자 기준에서는 이미 압축된 원고로 보일 수 있으므로, P1-2.3과 P1-9.1로 이어지는 연결 문장만 점검하는 편이 안전하다.
- 장점: Part 1의 중심축인 `규칙에서 학습으로의 전환`이 더 선명해진다.
- 단점: 본문 분량 자체는 줄지 않는다.
- 채택 기준: Part 1 개정 작업을 한 번에 마무리하려면 이 안이 적합하다.

### C안. 출처 최신성 점검까지 묶어 처리

- 의견: 법률·정책·제품 문서까지 확인하면 배포 안정성은 올라가지만, 제목 정리 작업과 성격이 다르다. 외부 확인이 필요한 작업이므로 별도 작업 단위로 분리하는 편이 낫다.
- 장점: 배포 전 리스크를 줄인다.
- 단점: 현재 원고의 구조 수정 속도를 늦출 수 있다.
- 채택 기준: 배포 직전이면 포함하고, 일반 원고 정리 단계라면 별도 이슈로 분리한다.

### 권장안

먼저 A안을 적용하고, B안은 P1-3.1의 연결 문장이 실제로 중복처럼 읽힐 때만 제한적으로 적용한다. C안은 배포 전 검증 작업으로 분리한다. Part 1은 책의 진입부이므로 추가 압축이나 소제목 관리보다 사례와 절차 설명을 유지하는 편이 더 적절하다.

## 다음 작업 순서 제안

1. P1-3.1은 추가 압축하지 않고 사례와 절차 설명을 유지한다.
2. P1-2.3/P1-9.1과의 연결 문장만 필요 시 조정한다.
3. 소제목 교체는 실제 독해 문제가 확인될 때만 제한적으로 처리한다.
4. 한국어 원문 변경이 생길 때만 영어·중국어 번역본을 Section ID 기준으로 동기화한다.
5. 배포 전 P1-14.6, P1-15.2, P1-17.1의 변동 가능 출처를 최신성 중심으로 재확인한다.
