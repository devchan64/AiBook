# Part 7 Section별 분석 리포트

작성일: 2026-08-01

## 범위와 판정 기준

이 리포트는 현재 작업 트리의 `docs/parts/part-07/` 한국어 본문 34개 Section을 `management/authoring/part-07-open-checklist.md`의 현재 개편 목차와 대조한 결과다. 현재 작업 트리에는 Chapter 재배치와 파일 이동이 진행 중이므로, 이 문서는 작업 상태표가 아니라 **현재 본문이 유지하는 학습 흐름과 다음 보강 판단**을 남긴다.

각 Section은 다음 네 축으로 읽었다.

1. **중심축 정합성**: 체크포인트의 중심 질문과 현재 제목·도입·판단 기준이 같은 질문을 가리키는가.
2. **실습 리듬**: 입력 또는 조건 변경, 출력 비교, 독자가 할 행동이 실제로 보이는가.
3. **실패 해석**: 결과를 성공/실패 한 줄로 닫지 않고 실패 범주와 다음 조치로 연결하는가.
4. **재현성**: 입력, 코드 또는 workflow, 실행 조건, 산출물·기록 양식이 다시 실행할 수준으로 남는가.

판정 표기에서 `유지`는 현재 중심축을 충족한다는 뜻이고, `보강`은 중심축은 맞지만 해당 축의 증거가 더 필요하다는 뜻이다. 이는 사실 정확성이나 외부 도구의 최신성을 별도로 검증한 결과가 아니다.

## 전체 판단

- **Module 1~2 (P7-1.1~P7-4.4)**: 표·이미지·표현 사례가 모두 입력 파일, 조작 변수, Python 실행, 비교표/도식, 회고와 체크리스트로 이어진다. Part 7의 공통 리듬을 가장 안정적으로 구현한 구간이다.
- **Module 3 (P7-5.1~P7-8.1)**: 현재 모델을 실습 재료로 쓴다는 방향은 정확하다. 다만 실제 모델 실행 비용과 설치·입력 자산 제약 때문에, 일부 Section은 기록 양식이 실행 산출물보다 앞서 있다. 각 절에 최소 한 개의 공유 가능한 input/workflow 또는 실제 결과 묶음을 더하면 Part 7의 실행성에 맞아진다.
- **Module 4 (P7-9.1~P7-12.1)**: RAG와 agent 모두 실패 상태를 분리하고 다음 행동으로 넘기는 흐름이 강하다. P7-9.4는 제목·체크포인트의 `ANN 설정/지연 시간`과 예제의 `bucket 범위 필터`가 다르므로 가장 먼저 정합성을 고쳐야 한다.
- **Module 5 (P7-13.1~P7-14.1)**: 배포 확인, 장애 기록, 우선순위, 경고 등급, 재현 패키지의 순서가 자연스럽다. AiBook을 사례로 쓰는 범위도 프로젝트 운영 기록으로 제한되어 있다.

## 보강 우선순위

1. **P7-9.4 정합성 결정**: 실습을 진짜 ANN 설정·지연 시간 비교로 확장할지, 현재 구현에 맞춰 후보군 필터 비교로 이름과 체크포인트를 좁힐지 먼저 결정한다.
2. **Module 3 실행 자산 보강**: P7-5.2, P7-5.3, P7-6.1, P7-7.1, P7-8.1에 최소 입력·정확한 실행 조건·결과 기록을 추가한다. 모든 환경을 저장소 안에서 실행 가능하게 만들 필요는 없지만, 독자가 무엇을 받아 어떤 조건을 바꾸고 어떤 파일을 비교하는지는 추적 가능해야 한다.
3. **P7-10.1과 P7-12.1의 도구 증거 추가**: 평가 도구와 trace를 설명 표에만 두지 말고 작고 공개 가능한 입력과 출력으로 한 번 연결한다.
4. **P7-14.1 재대조**: 위 보강 뒤 대표 실습 패키지를 다시 점검해 환경·명령·결과 기록 중 빠진 필수 항목을 확인한다.

## 확인한 구조적 정합성

- 현재 본문 34개 Section은 모두 제목의 `P7-*`와 본문 `Section ID`를 함께 가진다.
