# Part 5 사례 중복설명 검토 리포트

작성일: 2026-07-12
검토 대상: `docs/parts/part-05/chapter-*/section-*.md`
검토 목적: Part 5의 `사례 및 예시`가 학습을 돕는 재사용인지, 아니면 과하게 같은 장면을 반복 설명하는지 점검한다.

## 결론

Part 5 사례는 전반적으로 `사람이 먼저 보기 쉬운 기준 -> 한계 -> 개념이 바꾸는 점 -> 확인할 결과` 구조를 잘 맞추고 있다. 다만 인접한 Transformer 계열 구간에서 같은 운영 장면을 거의 같은 문장 축으로 재사용한 부분이 있어, `과한 중복설명` 판정은 1건, `경계 사례` 판정은 2건으로 본다.

가장 강한 중복 후보는 다음이다.

- `P5-14.1`과 `P5-14.2`의 세 사례 축
  - 다국어 작업 지시 번역
  - 장애 보고서 요약
  - 운영 스크립트 생성/분석

이 구간은 `Transformer 블록 구성`과 `병렬 처리·긴 문맥`이라는 설명 목표는 다르지만, 사례 장면과 설명 문장 전개가 너무 비슷해 독자가 `같은 사례를 다시 읽는다`는 느낌을 받을 가능성이 높다.

## 검토 기준

- 같은 사례 장면을 재사용하더라도, 현재 절의 중심 질문이 실제로 달라져 새로운 판단 차이를 만든다면 허용한다.
- 같은 사례 장면, 같은 문제 구조, 같은 결과 문장이 인접 절에서 거의 같은 표현으로 반복되면 과한 중복으로 본다.
- 어휘가 비슷해도 `무엇을 비교하게 만드는가`가 다르면 우선 보류하고 재독으로 판정한다.

## 3차 시도: 사례 문체 골격 반복 점검

3차 시도에서는 사례별 서두, 전환 문장, 마감 문장이 얼마나 같은 틀로 반복되는지 따로 확인했다.

관찰 결과:

- 대부분 사례가 `사람은 ... 느끼기 쉽습니다` 계열 서두를 쓴다.
- `여기서 바뀌는 점은`은 총 15개 사례에서 반복된다.
- `그래서 이 사례에서 확인해야 할 결과`는 Part 5 전체에서 96회 등장한다.

이 수치만 보면 반복이 커 보이지만, 판정은 두 층으로 나눠야 한다.

1. 구조 반복
   - 저장소 원칙이 의도한 공통 학습 구조이므로 문제로 보지 않는다.
2. 장면 반복
   - 같은 도메인과 같은 문제 장면이 인접 절에서 다시 나오면 실제 중복설명 위험이 커진다.

즉, Part 5는 `문체 틀의 반복`은 강하지만, 그 자체만으로는 감점 사유가 아니다. 실제로 봐야 할 것은 `같은 장면과 같은 결과가 거의 같은 초점으로 다시 나오느냐`이다.

이 관점에서 보면 `P5-14.1`과 `P5-14.2`는 문체 틀 반복을 넘어 장면 반복까지 겹친다. 반대로 `P5-15.1`과 `P5-15.2`는 문체는 비슷하지만 질문 층위가 달라 허용 가능하다.

## 4차 시도: 서두/결말 유사도 분리 점검

4차 시도에서는 사례 블록의 앞부분 2문장과 끝부분 2문장을 나눠 비교했다. 목적은 `같은 도메인이라도 서두가 비슷한가`, `결말 판단까지 같은가`를 분리해 보는 데 있다.

상위 후보:

1. `P5-14.1` 다국어 작업 지시 번역 <-> `P5-14.2` 다국어 작업 지시 번역
   - 서두 유사도 `0.93`
   - 마감 유사도 `0.27`
2. `P5-10.2` 설비 카메라 장면 재식별 <-> `P5-11.1` 설비 장면 재식별
   - 서두 유사도 `0.49`
3. `P5-12.2` 다국어 작업 지시 번역 <-> `P5-14.2` 다국어 작업 지시 번역
   - 마감 유사도 `0.39`
4. `P5-13.2` 교대 인수인계 요약 <-> `P5-14.2` 긴 장애 보고서 요약
   - 마감 유사도 `0.34`

이 시도에서 새로 분명해진 점은 다음이다.

- `P5-14.1`과 `P5-14.2`는 장면만 같은 것이 아니라, 사례를 여는 문제 장면 자체가 거의 같은 문장으로 반복된다.
- `P5-12.2`와 `P5-14.2`는 서두는 다르지만 결말이 비슷하다.
  - 즉, `앞 단서를 다시 끌어와야 한다`는 판정 축이 겹친다.
- `P5-10.2`와 `P5-11.1`은 도메인 서두는 비슷하지만, 마감 결과는 각 절의 개념 차이에 맞춰 갈라진다.

따라서 4차 시도는 `P5-14.1`/`P5-14.2` 중복 판정을 더 강하게 만들고, `P5-10.2`/`P5-11.1`은 허용 가능 판정을 다시 지지한다.

## 5차 시도: 중복 유형 분류

5차 시도에서는 후보들을 한 덩어리로 두지 않고, 중복을 세 가지 유형으로 분류했다.

### 유형 A. 장면 중복

같은 운영 장면, 같은 문제 구조, 같은 결과 축이 인접 절에서 반복되는 경우다.

- 대표 사례: `P5-14.1` <-> `P5-14.2`

이 유형은 독자가 가장 쉽게 `또 같은 예시`라고 느낀다. 실제 수정 우선순위도 가장 높다.

### 유형 B. 도메인 재사용

같은 산업 도메인이나 비슷한 시각 자산을 쓰지만, 절이 묻는 질문은 다른 경우다.

- 대표 사례: `P5-10.2` <-> `P5-11.1`
- 대표 사례: `P5-11.1` 산업 비전 <-> `P5-11.2` 의료 이미지나 산업 비전

이 유형은 운영 도메인 일관성을 위해 허용 가능하다. 다만 인접 절에서 같은 명사 묶음이 반복될 때는 설명 초점을 더 빨리 분기시키는 편이 좋다.

### 유형 C. 설명 기능 재사용

같은 장면을 써도 하나는 `무엇을 배웠는가`, 다른 하나는 `어떻게 선택되는가`처럼 기능이 달라지는 경우다.

- 대표 사례: `P5-15.1` <-> `P5-15.2`
- 대표 사례: `P5-13.1` attention <-> `P5-13.3` multi-head

이 유형은 중복설명으로 보기보다 커리큘럼 재사용으로 보는 편이 맞다. 오히려 동일 장면 덕분에 층위 차이를 비교하기 쉬워진다.

## 6차 시도: 섹션 간 동일 케이스 맵

사용자 지적처럼, Part 5는 `같은 문장 틀`뿐 아니라 `같은 운영 장면 축`이 여러 섹션에 다시 나타나는 구간이 실제로 있다. 이 재등장 자체가 곧바로 문제는 아니지만, 독자가 `다른 섹션에도 같은 케이스를 또 썼다`고 느끼는 근거는 분명히 존재한다.

이번 시도에서는 사례 제목과 본문 장면을 다시 묶어, 서로 다른 섹션에 퍼진 `동일 케이스 계열`을 확인했다.

- 변수명 일관성, 차단 조건 유지, 재기동 로직 안전성이 결과로 닫힌다

판정:

- `코드도 긴 문맥 문제를 가진다`는 설명 자체는 유효하다
- 하지만 인접 절에서 `앞 정의를 다시 봐야 한다`는 같은 판단 구조가 반복되어 체감 중복이 커진다

## 7차 시도: 섹션 설명 효율이 낮은 케이스 점검

이번 시도에서는 `같은 사례인가`가 아니라, `이 사례가 현재 섹션의 중심 개념을 가장 직접적으로 설명하는가`를 따로 봤다. 즉, 좋은 사례라도 현재 절의 질문보다 다른 절의 질문을 더 강하게 떠올리게 만들면 `설명 효율이 낮은 케이스`로 분류했다.

판정 기준은 다음과 같다.

- 사례가 현재 절의 핵심 용어와 판단 차이를 바로 밀어주면 효율적이다.
- 사례를 읽은 뒤 독자가 다른 절의 질문을 먼저 떠올리게 되면 효율이 낮다.
- 사례 설명의 절반 이상이 `현재 개념 자체`보다 `공통 도메인 배경`을 푸는 데 쓰이면 비효율 가능성이 크다.

판정: 설명 효율이 낮음

근거:

- 하지만 실제 사례 문단은 세 경우 모두 `먼 단서를 다시 참고하는가`를 먼저 강하게 설명한다.
- 즉, 사례를 읽고 난 뒤 독자가 먼저 떠올리게 되는 질문은 `왜 긴 문맥에서 직접 재참조가 중요한가`이고, 이는 `P5-14.2`의 중심 질문에 더 가깝다.
- 뒤 표에서 각 부품 책임을 억지로 다시 매핑해 회수하고 있지만, 사례 자체만 놓고 보면 `블록 부품별 역할 차이`가 자연스럽게 떠오르지 않는다.

왜 비효율적인가:

- `Transformer 블록 구성`을 설명해야 하는 절에서 사례의 1차 긴장 구조가 `long context` 문제로 잡혀 있다.
- 따라서 독자는 사례를 한 번 읽고, 다시 표를 통해 `이걸 attention / feed-forward / residual / norm으로 나눠 읽으라`는 추가 해설을 한 번 더 거쳐야 한다.
- 좋은 사례라면 사례 본문만 읽어도 `관계 읽기`, `위치별 가공`, `원래 정보 유지`, `값 정리`가 자연스럽게 분리되어야 하는데, 현재는 그 분리가 약하다.

권고:

- `P5-14.1`은 긴 문맥 과업 사례보다 `한 토큰 표현이 블록 내부 단계마다 어떻게 달라지는가`가 직접 보이는 사례로 바꾸는 편이 낫다.
- 예: 경보 토큰, 조치 토큰, 원인 토큰이 한 블록을 지나며 어떻게 달라지는지 같은 `표현 변화 중심` 장면

## 8차 시도: 수정 반영 후 설명 효율 재평가

앞선 7차 시도는 수정 전 본문을 기준으로 했기 때문에, `P5-14.1`, `P5-12.2`, `P5-13.2`를 손본 뒤에는 다시 판정을 갱신할 필요가 생겼다. 이번 시도에서는 `중복이 줄었는가`와 별도로, `사례를 읽을 때 현재 섹션 질문이 가장 먼저 떠오르는가`를 최신 본문 기준으로 다시 봤다.

- 같은 절의 사례 1 `운전 절차 변환 문서`, 사례 3 `매뉴얼 질의응답`과 비교해도 이제 세 사례 모두 `현재 출력/질문이 달라지면 참조 비중도 달라진다`는 공통 질문으로 더 가지런히 정렬된다.

근거:

- 현재 사례는 `마지막 요약 문장을 만드는가`가 아니라 `지금 재가동을 승인해도 되는가`를 판단하는 장면으로 바뀌어, 같은 교대 로그를 두고도 `현재 위치의 결정`이 전면에 나온다.
- 따라서 `요약` 계열 attention 사례들과 겹치던 표면 감각이 줄었고, `현재 판단 위치가 앞 로그를 다시 끌어오는가`라는 이 절의 질문이 더 또렷해졌다.
- `긴 작업 허가 질의응답`, `긴 교대 인수인계 위험 판단`, `긴 설정 파일 검토`는 이제 각각 질의응답, 운영 판단, 설정 해석으로 더 분명히 갈라진다.
