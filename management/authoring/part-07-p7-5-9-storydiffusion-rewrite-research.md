# P7-5.9 StoryDiffusion 재작성 근거와 구성안

- 대상: `P7-5.9`
- 조사일: 2026-09-11
- 범위: 공식 논문·프로젝트·구현과 현재 공개 자산 대조. 생성 실험 및 원고 수정은 수행하지 않음.

## 재작성 방향

제목 후보는 **StoryDiffusion으로 같은 인물의 연속 장면 만들기**다. 공통 인물 설명과 컷별 행동을 입력하고, 기준 컷을 생성한 뒤 후속 컷을 이어 만드는 과정을 본문의 중심에 둔다. 독자는 프롬프트와 결과를 나란히 보며 인물의 특징과 장면 변화가 함께 남았는지 판단할 수 있어야 한다.

기존 실험은 사용자의 판단에 따라 목표 미달로 정리한다. 베이스 체크포인트는 `darkSushiMixMix_225D.safetensors`이고 제3자 SeaArt 노드를 사용했으나 공식 CSA 구현과의 대응이 확인되지 않았다. 기존 결과를 StoryDiffusion 재현이나 검증된 보강 응용으로 채택하지 않는다. SD 계열 베이스 모델 사용 자체가 배제 사유는 아니며, 적용 코드와 실행 결과의 검증이 필요하다.

## 현재 원고에서 부족한 근거

| 현재 구성 | 문제 | 재작성 조치 |
| --- | --- | --- |

현재 파일은 `p7-5-9-storydiffusion-torso-multiview-anchor-*` PNG 2개와 workflow JSON 2개다. workflow의 `LoadImage`는 `p7-5-9-storydiffusion-5-7/` 아래 별도 ComfyUI 입력을 요구한다. `SeaArtApplyStory`를 사용하는 포트를 공식 구현과 구분해야 한다.

## 외부 자료에서 확인한 내용

### 논문: 결과·원리·조건 변화

논문의 Figure 2는 여러 장면의 이미지 특징을 연결하는 CSA 구조를 보여 준다. 각 이미지의 query는 유지하고, 다른 이미지에서 뽑은 중간 특징을 key/value 계산에 함께 사용하는 설명으로 도식을 새로 작성할 수 있다. 얼굴만 자동 추출해 공유하는 장치로 설명하지 않는다.

Figure 4·5는 다른 방법과의 결과 비교, Figure 7과 Table 3은 샘플링 비율에 따른 일관성과 텍스트 제어의 절충을 설명할 자료다. 논문의 기본 비율은 0.5지만, 이를 모든 구현에서 최적인 값으로 일반화하지 않는다. 부록 B는 넥타이 같은 작은 복장 요소의 불일치를 명시한다. 이미지 생성과 후속 영상 생성은 별개 단계다.

출처: Yupeng Zhou 외, [StoryDiffusion, NeurIPS 2024 논문](https://proceedings.neurips.cc/paper_files/paper/2024/file/c7138635035501eb71b0adf6ddc319d6-Paper-Conference.pdf), 확인일 2026-09-11. 원문은 `.tmp/storydiffusion-review/paper.pdf`에 보관해 확인했다.

### 공식 노트북: 입력부터 만화 배치까지

공식 예제는 검은 정장을 입은 인물을 공통 설명으로 두고 기상·식사·출근·근무·운동·독서 장면을 만든다. 기본 예제는 `id_length=4`로 앞 네 프롬프트를 기준 묶음으로 생성하면서 `id_bank`에 특징을 기록하고, 뒤의 프롬프트는 기록된 특징을 읽으며 생성한다. 추가 프롬프트로 후속 장면을 더 만들 수 있다. 마지막 `get_comic_4panel`은 생성된 이미지를 만화 형태로 배치하는 후처리다.

원고에는 ‘기준 컷 생성 → 특징 기록 → 후속 컷 생성 → 컷 배치’를 분리해 보여 준다. 특징 저장소는 완성 PNG나 얼굴 임베딩만 보관하는 파일함으로 설명하지 않는다.

출처: HVision-NKU, [Comic_Generation.ipynb](https://github.com/HVision-NKU/StoryDiffusion/blob/main/Comic_Generation.ipynb), 확인일 2026-09-11. 원문과 추출 텍스트는 `.tmp/storydiffusion-review/`에 보관했다.

### 공식 실행 안내와 시각 자료

README는 현재 구현에서 최소 3개 프롬프트, 레이아웃에는 5~6개를 권장한다. 이는 CSA 이론 전체의 고정 제한과 구분한다. low-memory Gradio 안내는 24GB GPU·30GB RAM 시험 및 20GB 초과 VRAM 예상을 적고 있다. 8GB 실행 보장으로 바꾸지 않는다.

출처: HVision-NKU, [공식 README](https://github.com/HVision-NKU/StoryDiffusion#how-to-use), 확인일 2026-09-11.

공식 프로젝트의 Comics Generation과 More Comic Generation Example은 원고 첫 사례의 외부 결과 열람 링크로 쓸 수 있다. 웹사이트는 콘텐츠에 CC BY-NC-SA 4.0을 표시한다. 저장소의 Apache-2.0 표시를 웹사이트 이미지 재배포 허락으로 대신하지 않는다. 책의 배포 조건과 이미지 이용 조건을 확인하기 전에는 외부 이미지를 복사하지 않고 원본 링크를 제공한다.

출처: 저자 공식 [프로젝트 페이지](https://storydiffusion.github.io/), 확인일 2026-09-11. 논문 도판의 재수록 조건은 별도 검증 필요.

## 제안하는 본문 순서

| 소제목 | 보여 줄 내용 | 필요한 자료 |
| --- | --- | --- |
| 여섯 장면, 같은 인물 | 공통 인물 설명과 장면별 행동을 결과 바로 옆에 배치 | 프롬프트 6개와 결과 6장 |
| 기준 컷과 후속 컷 | 앞 네 컷에서 특징을 기록하고 뒤 두 컷에서 읽는 흐름 | 자체 도식, 기준·후속 구분 캡션 |
| 컷 사이의 특징 공유 | 일반 self-attention과 CSA의 참조 범위 차이 | 자체 도식과 짧은 설명 |
| 독립 생성과 비교 | 같은 장면에서 CSA 유무에 따라 달라지는 얼굴·머리·복장 | 2행×6열 비교표 또는 3장씩 나눈 표 |
| 장면을 더 이어 만들기 | 같은 기준 특징으로 일곱 번째 장면 추가 | 추가 프롬프트·출력·실행 기록 |
| 남은 불일치 | 작은 의상 요소, 손과 소품 접점 등 실제 출력의 오류 | 해당 컷 확대 또는 원본 링크 |

기존 ‘중심 질문’, ‘이 절을 읽고 나면’, ‘현재 산출물까지의 최단 경로’, ‘다음 실험’ 안내는 실제 사례 설명으로 대체한다. 메모리 조건은 실행 방법 옆의 짧은 표로 줄인다. 영상 Motion Predictor는 이번 이미지 사례의 실행 경로에 포함하지 않는다.

## 자체 실험안 — 아직 실행하지 않음

첫 재현은 텍스트만 입력하는 단일 인물·6컷으로 구성한다. PhotoMaker, 다중 인물, OpenPose, 기존 이미지 img2img를 동시에 넣지 않아 CSA 경로를 읽기 쉽게 한다. 공식 노트북의 구조를 먼저 재현한 뒤 기존 캐릭터 사례로 확장한다.

자체 예시 공통 설명: 청록 단발, 흰 재킷, 회색 이너, 청록 바지의 성인 인물. 얼굴·복장은 공통 문자열로 유지하고 다음 행동만 바꾼다.

1. 집에서 가방을 챙긴다.
2. 거리에서 걷는다.
3. 카페에서 컵을 든다.
4. 공원 벤치에서 책을 읽는다.
5. 서점에서 책을 고른다.
6. 집에서 책상에 앉는다.

네 컷을 기준 묶음, 두 컷을 후속 생성으로 나누는 것은 공식 노트북을 따르는 재현 설계이며 아직 결과가 없다. 전신 점프·슛은 인체와 소품 오류가 섞이므로 첫 재현 이후 별도 사례로 둔다.

대조 실험은 동일 베이스 모델·프롬프트·해상도·scheduler·step·CFG·컷별 초기 latent를 사용하고 CSA만 끈다. seed 숫자만 같아도 배치와 난수 소비 순서가 달라 초기 latent가 달라질 수 있으므로 실제 초기 latent 또는 재현 가능한 생성 절차를 기록한다. 가능하면 3개 seed 묶음을 비교해 한 묶음의 우연을 구분한다.

저장할 항목: 코드 commit, 모델 식별자·해시, 라이브러리 버전, GPU·VRAM 관찰값, 프롬프트별 순서, 기준 컷 수, 샘플링 비율, 초기 latent 생성 규칙, 생성 시간, 컷별 PNG와 result JSON, 후처리 전 개별 결과. 코드는 독립된 lazy-source 행, 실행 명령은 Bash 코드블록으로 배치한다.

## 원고 확정에 필요한 최소 근거

- 외부 공식 결과만 설명하는 경우: 외부 사례임을 명시하고 실제 실행했다고 쓰지 않는다.
- 프로젝트 실습 원고로 완성하는 경우: 새 장면 6컷과 CSA 없는 대조군, 입력·실행 조건·출력 기록이 필요하다.
- 현재 8GB 멀티뷰 결과는 연속 장면 생성 성공이나 CSA의 인과적 효과를 입증하지 않는다. 해당 주장에는 별도 실험이 필요하다.

권장안은 공식 결과와 코드 구조를 읽는 도입을 먼저 만들고, 자체 연속 장면·대조 결과를 확보한 뒤 실습 본문을 완성하는 것이다.
