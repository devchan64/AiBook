# Part 6 개편 기준

작성일: 2026-07-21

## 문서 역할

이 문서는 Part 6을 실제로 개편할 때 기준으로 삼는 작업 문서다. 목적은 기존 원고를 단순 재번호화하는 것이 아니라, Part 6을 `LLM 구조 설명`에서 `생성형 AI를 LLM 중심 사례로 이해하고, 사용, 보강, 검토, 운영 구조까지 읽는 파트`로 재구성하는 데 있다.

기존 Part 6은 토큰, 임베딩, Transformer, GPT, next-token prediction, 프롬프트, RAG, 도구 사용, 에이전트, 평가, 운영으로 이어지는 LLM 설명 흐름은 갖추고 있다. 그러나 Part 5에서 넘어온 질문인 `생성 모델과 샘플링이 실제 생성형 AI 서비스 경험에서는 어떻게 나타나는가`를 초반에 직접 회수하지 못한다.

따라서 Part 6의 첫 질문을 다음처럼 바꾼다.

| 기존 첫 질문 | 개편 후 첫 질문 |
| --- | --- |
| 왜 토큰이 필요한가? | 생성형 AI를 이해하려면 왜 LLM의 생성 과정을 중심 사례로 읽어야 하는가? |

## 핵심 결정

Part 6 개편의 핵심 판단은 다음 세 문장이다.

1. Part 6은 `토큰`이 아니라 `생성형 AI 산출물`에서 시작한다.
2. LLM은 생성형 AI 전체가 아니라, 생성형 AI를 깊게 읽기 위한 대표 사례로 둔다.
3. 낯선 용어는 모두 `계산 단위`, `사용 보강 구조`, `검토와 운영 기준` 중 하나에 배치한다.

개편 후 본류는 다음 순서로 잡는다.

```text
생성형 AI 산출물
-> LLM을 대표 경로로 선택
-> 후보 분포와 선택 반복
-> 토큰과 임베딩
-> Transformer, GPT, next-token prediction
-> 사전학습, 파인튜닝, 지시 튜닝, 정렬
-> 프롬프트, RAG, 벡터 DB, 도구 사용, 에이전트, MCP, 하네스
-> 평가, 운영, 실패 대응, 실행 기록
-> 발전사와 BERT 비교 지도
```

## 개편 원칙

| 원칙 | 적용 방식 |
| --- | --- |
| 첫 질문을 바꾼다 | 기존 `왜 토큰이 필요한가`를 Part 6의 첫 질문으로 두지 않고, `생성형 AI를 LLM 중심으로 어떻게 읽을 것인가`를 먼저 세운다. |
| 낯선 용어의 등장 이유를 붙인다 | tokenizer, context window, RAG, agent, MCP 같은 용어가 나올 때마다 사용 장면과 앞 Part의 연결을 먼저 설명한다. |
| 전환 속도를 늦춘다 | 각 Module 도입부와 전환 문단에 `왜 지금 다음 개념으로 넘어가는가`를 명시한다. |
| 흡수구간을 설계한다 | 대형 LLM 구현이 아니라 작은 표, CSV, Python 예제, Mermaid, 비교 체크리스트로 판단 구조를 확인하게 한다. |
| Part 경계를 지킨다 | Part 1의 개론, Part 5의 딥러닝 일반론, Part 7의 프로젝트 실행을 반복하거나 선행하지 않는다. |
| 목표 달성을 우선한다 | 기존 P6-1.1~P6-19.2는 재료로 삼되, 필요하면 Section 이동, 통합, 분리, 재작성, 예제 교체를 적용한다. |

## 목차 설계 기준

Chapter와 Section의 분량을 기계적으로 맞추지 않는다. 중요한 개념, 후속 Section에서 계속 회수되는 개념, 독자가 자주 막히는 병목은 더 길어질 수 있다. 반대로 얇아도 독립된 중심 질문을 닫고 다음 판단을 준비한다면 별도 Section으로 둘 수 있다.

통합과 분리의 기준은 분량 균등이 아니라 `중요도`, `학습 병목`, `후속 회수 빈도`, `흡수구간 필요성`이다.

| 판단 | 적용 기준 |
| --- | --- |
| 독립 유지 | 현재 질문이 후속 Section에서 계속 회수되거나, 독자가 별도 흡수구간을 거쳐야 다음 개념으로 넘어갈 수 있다. |
| 통합 | 두 Section이 같은 중심 질문을 나누어 설명하고 있어, 분리 때문에 정의와 영향이 끊겨 보인다. |
| 분리 | 한 Section이 개념 정의, 사용 장면, 실패 기준, 실습을 한꺼번에 품어 중심 질문이 둘 이상으로 갈라진다. |
| 보충학습 전환 | 본류 이해에는 필요하지만 세부 계열, 구현 방식, 역사 배경이 길어져 독해 속도를 끊는다. |

## 학습 설계 기준

Part 6에서 필요한 학습 행동은 다음 네 가지다.

| 학습 행동 | 의미 | 적용 예 |
| --- | --- | --- |
| 비교한다 | 비슷해 보이는 결과나 용어를 나란히 놓고 차이를 말한다. | 분류, 예측, 생성 산출물의 차이, GPT와 BERT의 차이, 프롬프트와 RAG의 차이 |
| 구분한다 | 한 덩어리처럼 보이는 구조를 역할별로 나눈다. | 토큰 문자열, token ID, 임베딩, 후보 분포, 검색 결과, 도구 실행 결과 |
| 판정한다 | 결과가 충분한지, 다음 보강이 필요한지 기준을 적용한다. | 프롬프트로 충분한지, RAG가 필요한지, 도구 호출이 필요한지, 사람 검토가 필요한지 |
| 기록을 읽는다 | 생성 결과만 보지 않고 입력, 근거, 실행, 실패, 평가 흔적을 함께 본다. | trace, 검색 후보, 함수 인자, 평가표, 운영 실패 로그 |

각 Module은 다음 학습 산출물을 남겨야 한다.

| Module | 독자가 할 수 있어야 하는 일 | 필수 흡수구간 |
| --- | --- | --- |
| Module 1 | 분류 결과, 예측값, 생성 산출물이 어떻게 다른지 말하고, LLM을 대표 사례로 읽는 이유를 설명한다. | 같은 요청을 분류, 예측, 생성 산출물로 바꾸어 보는 비교표와 작은 후보 선택표 |
| Module 2 | 문자열, 토큰 수, token ID, 임베딩 표현을 구분하고, 비용, 길이, 검색에 미치는 영향을 설명한다. | token 수, token ID, 잘림 여부 비교와 간단한 유사도 top-k 표 |
| Module 3 | 문맥이 다음 후보 점수를 바꾸고, 선택된 토큰이 다시 문맥에 붙는 반복을 설명한다. | 작은 문맥 단서가 후보 점수를 바꾸는 표 또는 그래프 |
| Module 4 | 사전학습, 파인튜닝, 지시 튜닝, 정렬이 각각 무엇을 배우거나 맞추는지 구분한다. | 일반 응답, 도메인 조정 응답, 지시 튜닝 응답 비교표 |
| Module 5 | 프롬프트만으로 되는 일과 RAG, 벡터 DB, 도구 사용이 필요한 일을 구분한다. | 프롬프트만 쓴 답과 근거 문서를 붙인 답의 비교 |
| Module 6 | 생성, 조회, 계산, 실행, 승인, 기록을 같은 답변 과정 안에서 분리해 본다. | 답변만으로 충분한 요청과 함수 호출 또는 agent loop가 필요한 요청 판정표 |
| Module 7 | 자연스러운 답변과 서비스 가능한 답변을 구분하고, 실패 대응 경로를 판단한다. | 정확성, 근거성, 형식, 비용, latency, 실패 대응 기준 판정표 |
| Module 8 | GPT 중심 생성 계열을 과장하지 않고, 발전사와 BERT 계열을 비교 배경으로 읽는다. | GPT 계열과 BERT 계열의 입력, 출력, 강한 태스크 비교표 |

## Part 경계

| 경계 | Part 6에서 할 일 | 피할 일 |
| --- | --- | --- |
| Part 1과의 경계 | 생성형 AI의 기본 구분을 짧게 회수하고 LLM 중심 사례로 들어간다. | 분류, 예측, 생성의 기본 정의를 다시 길게 설명하지 않는다. |
| Part 5와의 경계 | Transformer, 생성 모델, 후보 분포, 샘플링을 텍스트 LLM과 사용 구조로 회수한다. | Transformer block 자체나 생성 모델 일반론을 다시 본류로 확장하지 않는다. |
| Part 7과의 경계 | 기록과 검증이 왜 필요한지 설명하고 작은 통합 흐름까지만 닫는다. | Part 7 수준의 프로젝트 템플릿, 배포, 운영 회고를 앞당기지 않는다. |

## 완료 기준

개편 후 Part 6를 다 읽은 독자는 다음 질문에 답할 수 있어야 한다.

- 생성형 AI가 만드는 산출물은 분류나 숫자 예측 결과와 어떻게 다른가?
- 왜 Part 6은 생성형 AI 전체가 아니라 LLM을 중심 사례로 읽는가?
- LLM의 생성은 왜 후보 분포와 선택의 반복으로 읽어야 하는가?
- 텍스트 생성에서 토큰, 임베딩, Transformer, GPT, next-token prediction은 어떤 순서로 연결되는가?
- 프롬프트만으로 되는 일과 RAG, 도구 사용, 에이전트가 필요한 일은 무엇이 다른가?
- 생성 결과가 자연스럽다는 것과 근거가 충분하거나 운영 가능하다는 것은 왜 다른가?
- 작은 생성형 AI 기능을 요청, 근거, 출력, 평가, 기록 흐름으로 설명할 수 있는가?
- LLM 발전사와 BERT 계열 비교를 본류 뒤에 붙는 배경 축으로 읽을 수 있는가?
