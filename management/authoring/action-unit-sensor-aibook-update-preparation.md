# 동작 단위 센서 노트를 Part 7 연습 Section에 연결하기 위한 준비 문서

## 이 문서의 목적

이 문서는 `management/authoring/action-unit-sensor-ai-notes/` 아래에 만든 10개 노트를 AiBook Part 7의 연습 Section에 연결할 수 있도록 준비 상태를 정리한다.

실제 본문 편집 순서와 자산 준비 항목은 `action-unit-sensor-part-07-exercise-section-plan.md`를 따른다.

핵심 목표는 다음 세 가지다.

- 동작 단위 센서 사례를 책에 넣을 때 기존 목차 흐름을 깨지 않고 Part 7 연습 Section에만 배치할 기준을 만든다.
- 10개 노트 각각이 Part 7의 어느 연습 흐름에 연결되는지 정리한다.
- 본문 편집을 시작하기 전에 필요한 자산, 주의점, 편집 순서를 미리 고정한다.

이 문서는 `새 Part를 만들기 위한 문서`가 아니다.

오히려 현재 책 구조를 유지한 채, 동작 단위 사례를 Part 7의 `실행형 연습 사례`로만 삽입하기 위한 관리 문서다.

## 현재 판단

동작 단위 센서 사례는 AiBook 본문에 흡수할 가치가 충분하다.

다만 다음 방식으로 쓰는 것은 피해야 한다.

- 동작 단위 사례만을 위한 별도 Module 추가
- 기존 본문을 대량 교체하는 구조 개편
- 도메인 세부가 개념 설명을 압도하는 서술
- 실제 운영 문서나 내부 구현을 연상시키는 구체 표현

반대로 다음 방식은 적합하다.

- Part 7의 기존 연습 Section 안에서만 사용
- 기준선 재설계, 비교 실험, 표현 정규화, 운영 점검처럼 이미 있는 연습 질문에 연결
- 공개형 합성 데이터, 작은 비교표, 회고 질문, 운영 점검 카드로 구성
- Part 1-6 본문 흐름에는 직접 삽입하지 않고, 필요한 선행 개념은 Part 7 안에서 짧게 회수

즉, 이 사례는 `여러 Part를 가로지르는 반복 사례`가 아니라 `Part 7에서 앞선 개념을 한 번에 실행해 보는 종합 연습 사례`로 쓰는 편이 맞다.

## 전제

### 전제 1. 본문 언어는 한국어다

동작 단위 사례도 본문에서는 한국어로 설명하되, 필요한 핵심 기술 용어만 영어를 병기한다.

### 전제 2. 초심자 기준을 유지한다

특정 장비를 모르는 독자도 따라올 수 있어야 한다.

따라서 커피 추출 자체보다 `센서 로그`, `사건 단위`, `구간 요약`, `기준선 비교` 같은 일반 개념으로 설명한다.

### 전제 3. Part 7의 기존 연습 구조를 우선한다

새 Chapter를 추가하기보다, Part 7의 기존 연습 Section 중심 질문에 직접 필요한 경우만 사례 문단, 표, 실습, 회고 질문으로 녹인다.

### 전제 4. 공개 안전 원칙을 유지한다

본문과 관리 자료 모두 다음 항목은 직접 반영하지 않는다.

- 구현 전용 경로 표기
- 운영 규칙 세부
- 제품 내부 명칭
- 구현 전용 인터페이스 이름
- 재현 가능한 실제 장비 식별자

## Part 7 배치 원칙

### 원칙 1. 사례는 Part 7에서만 사용한다

동작 단위 사례는 다른 Part의 설명 흐름을 방해할 수 있으므로 Part 1-6 본문에는 직접 넣지 않는다.

Part 7에서는 앞선 Part에서 배운 개념을 실제 실행 흐름으로 묶는 재료로 쓴다.

- 프로젝트 질문과 입력 단위 정의
- 기준선 재설계
- 비교 실험
- 표현 정규화와 특징 정의 비교
- 운영 점검과 false alarm 분류

### 원칙 2. 사례가 본문 주제를 먹어버리면 안 된다

Section의 중심 질문은 언제나 현재 Section의 제목이 담당한다.

동작 단위 사례는 그 질문을 더 선명하게 만드는 도구여야 한다.

### 원칙 3. 새 설명보다 기존 설명 보강을 우선한다

동작 단위 사례를 넣기 위해 Part 7 목차 흐름을 갈아엎지 않는다.

우선은 기존 연습 Section 안에 아래 중 하나를 추가하는 방식으로 본다.

- 작은 표
- 간단한 시계열 예시
- Python 예제
- 비교 조건 카드
- 회고 질문

### 원칙 4. 현재 Section 범위를 넘기면 보충학습으로 분리한다

예를 들어 다음은 현재 Section 안에 짧게 넣기보다 보충학습 후보로 보는 편이 맞다.

- 센서 시계열 정렬 알고리즘 세부
- 길이가 다른 시계열 비교의 수학적 세부
- 복잡한 변화 추세 지표
- 고급 이상 탐지 알고리즘

## 본문 편집 전에 먼저 준비할 것

### 1. 공개형 합성 데이터셋 최소 세트

Part 7 연습 Section을 구성하려면 먼저 다음 정도의 공개형 자산이 필요하다.

- 작은 원시 로그 CSV
- 샷 요약 CSV
- 버킷 요약 CSV

이 자산은 실제 로그를 반영하지 않아야 하며, 다음 질문에 답할 수 있어야 한다.

- 샷 하나는 무엇인가
- 샷 여러 개를 어떻게 묶는가
- 기준선과 최근 버킷은 어떻게 비교되는가

### 2. 작은 Python 예제 세트

Part 7에서 바로 재사용할 수 있는 예제가 필요하다.

- `groupby event_id`
- 구간 평균 계산
- slope 계산
- 최근 버킷 vs 기준선 비교
- 설명 문장 2~3개 생성

### 3. 시각화 자산 후보

최소한 다음 도식 또는 차트가 있으면 편집이 쉬워진다.

- 시간축 vs 진행도축 비교
- 평균은 같지만 패턴은 다른 두 샷
- 샷 -> 버킷 -> 기준선 비교 흐름도
- exact token / shape / density 비교표

## 새 Chapter를 만들지 말고 기존 연습 Section을 보강하는 이유

동작 단위 사례는 강하지만, 별도 장이나 다른 Part 삽입으로 넓히면 다음 문제가 생길 수 있다.

- 도메인 사례가 책의 개념 구조를 대신해 버린다
- 초심자가 도메인 지식이 부족하다고 느끼기 쉽다
- 기존 Part의 설명 흐름이 특정 사례 중심으로 흔들린다

반대로 Part 7의 기존 연습 Section을 보강하면 다음 장점이 있다.

- 현재 목차와 충돌이 적다
- 사례를 실행, 비교, 실패 해석, 운영 회고 단계로 나누기 쉽다
- 독자가 앞선 개념을 하나의 프로젝트 흐름 안에서 다시 확인할 수 있다

## 편집 중 계속 확인할 체크리스트

- 이 사례가 현재 Section 질문에 직접 답하는가
- 사례 설명이 연습의 실행·비교·회고보다 길어지지 않는가
- 센서 도메인을 모르는 독자도 따라올 수 있는가
- 내부 운영 규칙처럼 보이는 표현이 남지 않았는가
- Part 1-6 본문에 끼워 넣고 싶은 설명을 Part 7 안의 짧은 선행 회수 문장으로 처리할 수 있는가
- 필요한 경우 연습 해설이나 회고 질문으로 분리할 후보를 남겼는가

## 새 보충학습 후보

Part 7 본문에 바로 넣기보다 보충학습 후보로 남기기 좋은 항목은 다음과 같다.

- 길이가 다른 시계열을 비교하는 기본 전략
- 시계열 segmentation을 처음 읽는 법
- 변화 추세를 평균 변화와 구간 구조 변화로 구분하는 법
- false alarm을 운영 비용 관점에서 읽는 법
- 설명 가능한 특징과 표현 학습의 차이

이 후보들은 현재 본문에 꼭 필요한지 판단한 뒤 추가한다.
