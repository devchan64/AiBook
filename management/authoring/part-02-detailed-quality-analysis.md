# Part 2 상세 품질 분석

## 목적

이 문서는 `management/authoring/part-quality-analysis.md`에서 Part 2를 다음 우선 보강 대상으로 판정한 뒤, 실제 편집 단위로 이어 가기 위한 상세 작업 문서입니다.

Part 2는 실용성이 강한 Part입니다. 동시에 초심자에게는 가장 쉽게 `과목이 너무 많다`는 인상을 줄 수 있는 Part이기도 합니다. 현재 Part 2는 다음 네 층이 한 Part 안에 함께 들어 있습니다.

- 수학 언어 복구: 변수, 함수, 선형대수, 미분, 확률, 통계, 최적화
- 실행과 문법 복구: 로컬 환경, 터미널, Python, 자료 구조
- 데이터 도구 복구: NumPy, Pandas, Matplotlib
- 기록과 재현성: Git, 브랜치, 커밋, 배포 전 확인

최근 작업으로 `왜 지금 필요한가`, `보충학습으로 어디서 우회하는가`, `Part 3에서 어디에 다시 쓰이는가`는 많이 보강되었습니다. 이제 남은 과제는 `현재 순서를 유지한 채 독자가 도구 이름보다 역할을 먼저 읽는가`를 더 세밀하게 점검하는 일입니다.

## 현재 독서 경로 진단

### 현재 구조 판단

현재 Part 2는 `대규모 목차 재배치`보다 `수학 축과 도구 축을 어떤 역할 묶음으로 읽히게 할 것인가`가 더 큰 과제입니다.

지금 가장 안정적인 읽기 흐름은 다음과 같습니다.

| 읽기 묶음 | 해당 Chapter | 현재 판단 |
| --- | --- | --- |
| 계산 언어 복구 | Chapter 1-6 | 대체로 안정적 |
| 실행 자리와 Python 입문 | Chapter 7-10 | 가장 길고 피로가 누적되기 쉬움 |
| 계산 도구와 시각화 | Chapter 11-13 | 목적은 분명하지만 장 수가 많아 보일 수 있음 |
| 기록과 재현성 | Chapter 14-15 | 의도는 좋지만 `왜 여기까지 보나`를 더 자주 회수해야 함 |

핵심은 `Chapter 7-15`입니다. 이 구간은 내용이 틀린 것은 아니지만, 독자가 다음처럼 읽기 쉽습니다.

- 터미널, Python, 노트북, NumPy, Pandas, Matplotlib, Git이 모두 별도 과목처럼 보임
- 보충학습이 잦아지면서 본류와 우회 경계가 흐릴 수 있음
- Part 3로 넘어가기 전에 `무엇만 남기면 되는가`보다 `아직 배울 도구가 많다`는 감각이 커질 수 있음

즉, Part 2의 현재 리스크는 `도구가 정말 많다`기보다 `도구가 하나의 계산-확인-기록 흐름으로 계속 읽히는가`에 가깝습니다.

### 수학 축과 도구 축 판단

`docs/parts/part-02/index.md`와 `docs/parts/part-02/summary.md` 기준으로 보면 다음 판단은 유지하는 편이 맞습니다.

- Part 2는 수학 Part와 코딩 Part로 따로 떼지 않는다.
- 수학 축은 `무엇을 계산하는가`를 읽는 언어다.
- 도구 축은 `그 계산을 어떻게 실행하고 확인하고 남기는가`를 읽는 도구다.
- Part 3 진입 전에는 모든 장을 완벽히 끝내는 것보다 `어디로 다시 돌아올지`를 아는 편이 더 중요하다.

이 판단은 현재 맞습니다. 따라서 구조를 다시 나누기보다, 각 도구 장에서 `지금 장의 역할`과 `Part 3에서 다시 쓰이는 장면`을 더 짧고 반복적으로 못박는 편이 낫습니다.

## 리스크 장면 목록

### 1. Chapter 7-10이 모두 `Python 배우기`로 뭉개질 수 있다

- 관련 Section: `P2-7.1`, `P2-8.1`, `P2-9.*`, `P2-10.*`
- 왜 피로를 만드는가:
  - 실행 환경
  - 코드 문법
  - 자료 구조
  - 노트북 기록
  가 서로 다른 층위인데, 연속으로 읽으면 모두 같은 `초반 도구 학습`처럼 보이기 쉽습니다.
- 해결 방향:
  - 순서를 바꾸기보다, 각 장 끝이나 다음 장 도입에서 `지금은 어디서 실행하나`, `무엇을 적나`, `어떤 모양으로 담나`, `어떻게 남기나`를 더 짧게 반복해야 합니다.
- 우선 판단:
  - 문단 보강으로 해결 가능

### 2. NumPy, Pandas, Matplotlib, Git이 각각 유용해 보여도 한 흐름으로 닫히지 않을 수 있다

- 관련 Section: `P2-11.1`, `P2-12.*`, `P2-13.1`, `P2-14.2`
- 왜 피로를 만드는가:
  - Chapter 11~14는 현재도 `계산 가능한 모양 -> 표 -> 그래프 -> 기록`이라는 흐름이 들어가 있습니다.
  - 하지만 독자가 도구 이름을 먼저 잡으면 `왜 이 네 장이 이어지는가`보다 `또 새 도구가 나온다`가 먼저 보일 수 있습니다.
- 해결 방향:
  - 각 장 말미에 `바로 다음 장에서 무엇을 더 보나`와 `Part 3에서 어디에 다시 쓰이나`를 더 통일해 회수하면 좋습니다.
- 우선 판단:
  - 문단 보강으로 해결 가능

### 3. 보충학습이 많아 본류와 우회 기준이 흐려질 수 있다

- 관련 Section: `P2-7.6`, `P2-7.7`, `P2-8.6`, `P2-8.7`, `P2-9.4` 등
- 왜 피로를 만드는가:
  - 보충학습 자체는 필요하지만, 초심자는 `지금 당장 여기로 빠져야 하는가`를 판단하기 어렵습니다.
  - 잘못 읽히면 본편을 따라가다 자주 옆길로 새는 느낌이 강해질 수 있습니다.
- 해결 방향:
  - 본편 장에서 `지금 막히는 유형이면 이 보충학습으로 간다`, `아니면 그냥 다음 본편으로 간다`는 재진입 기준을 더 명시하는 편이 좋습니다.
- 우선 판단:
  - 문단 보강으로 해결 가능

### 4. Part 3 진입 전 최소 복습선이 더 실전형으로 보일 여지가 있다

- 관련 파일: `docs/parts/part-02/index.md`, `docs/parts/part-02/summary.md`
- 왜 피로를 만드는가:
  - 현재 요약과 완료 기준은 잘 되어 있지만, 독자가 `내가 지금 Part 3로 넘어가도 되나`를 더 빠르게 자가점검할 질문이 있으면 좋습니다.

- 우선 판단:
  - 문단 보강으로 해결 가능

### 5. Git 장이 `부록 도구`처럼 보일 위험이 남아 있다

- 관련 Section: `P2-14.1`, `P2-14.2`, `P2-15.*`
- 왜 피로를 만드는가:

- 해결 방향:
  - Git이 개발자 부록이 아니라 `바꾼 계산과 해석을 다시 설명하기 위한 기록 도구`라는 점을 더 짧고 반복적으로 회수합니다.
- 우선 판단:
  - 문단 보강으로 해결 가능
