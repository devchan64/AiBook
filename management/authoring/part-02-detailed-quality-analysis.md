# Part 2 상세 품질 분석

## 목적

이 문서는 `management/authoring/part-quality-analysis.md`에서 Part 2를 다음 우선 보강 대상으로 판정한 뒤, 실제 편집 단위로 이어 가기 위한 상세 작업 문서입니다.

Part 2는 실용성이 강한 Part입니다. 동시에 초심자에게는 가장 쉽게 `과목이 너무 많다`는 인상을 줄 수 있는 Part이기도 합니다. 현재 Part 2는 다음 네 층이 한 Part 안에 함께 들어 있습니다.

- 수학 언어 복구: 변수, 함수, 선형대수, 미분, 확률, 통계, 최적화
- 실행과 문법 복구: 로컬 환경, 터미널, Python, 자료 구조
- 데이터 도구 복구: NumPy, Pandas, Matplotlib
- 기록과 재현성: Git, 브랜치, 커밋, 배포 전 확인

최근 작업으로 `왜 지금 필요한가`, `보충학습으로 어디서 우회하는가`, `Part 3에서 어디에 다시 쓰이는가`는 많이 보강되었습니다. 추가로 Chapter 7~10의 `실행 환경 -> 코드 문장 -> 노트북 기록` handoff, Chapter 11~14의 `계산 가능한 모양 -> 표 -> 그래프 -> 기록` handoff, 그리고 주요 보충학습의 `여기까지만 회수하면 본편으로 돌아온다` 기준도 상당 부분 직접적으로 정리했습니다. 이제 남은 과제는 `현재 순서를 유지한 채 독자가 도구 이름보다 역할을 먼저 읽는가`를 더 세밀하게 점검하는 일입니다.

## 현재 독서 경로 진단

### 현재 구조 판단

현재 Part 2는 `대규모 목차 재배치`보다 `수학 축과 도구 축을 어떤 역할 묶음으로 읽히게 할 것인가`가 더 큰 과제입니다.

지금 가장 안정적인 읽기 흐름은 다음과 같습니다.

| 읽기 묶음 | 해당 Chapter | 현재 판단 |
| --- | --- | --- |
| 계산 언어 복구 | Chapter 1-6 | 대체로 안정적 |
| 실행 자리와 Python 입문 | Chapter 7-10 | 최근 라운드에서 역할 구분 표를 보강해 이전보다 안정적이지만, 여전히 구간 길이는 긴 편 |
| 계산 도구와 시각화 | Chapter 11-13 | handoff 문장은 많이 정리됐고, 이제는 잔여 어색 문장 점검이 더 중요함 |
| 기록과 재현성 | Chapter 14-15 | Git 장의 역할은 더 선명해졌지만, Part 3 연결은 계속 유지 점검이 필요함 |

핵심은 `Chapter 7-15`입니다. 이 구간은 내용이 틀린 것은 아니지만, 독자가 다음처럼 읽기 쉽습니다.

- 터미널, Python, 노트북, NumPy, Pandas, Matplotlib, Git이 모두 별도 과목처럼 보임
- 보충학습이 잦아지면서 본류와 우회 경계가 흐릴 수 있음
- Part 3로 넘어가기 전에 `무엇만 남기면 되는가`보다 `아직 배울 도구가 많다`는 감각이 커질 수 있음

즉, Part 2의 현재 리스크는 `도구가 정말 많다`기보다 `도구가 하나의 계산-확인-기록 흐름으로 계속 읽히는가`에 가깝습니다. 최근 문장 보강으로 `실행 환경 -> 코드 문장 -> 노트북 기록`, `계산 가능한 모양 -> 표 -> 그래프 -> 기록` 축은 이전보다 선명해졌으므로, 다음 단계는 대규모 손질보다 잔여 장면을 선택적으로 점검하는 쪽에 더 가깝습니다.

### 수학 축과 도구 축 판단

`docs/parts/part-02/index.md`와 `docs/parts/part-02/summary.md` 기준으로 보면 다음 판단은 유지하는 편이 맞습니다.

- Part 2는 수학 Part와 코딩 Part로 따로 떼지 않는다.
- 수학 축은 `무엇을 계산하는가`를 읽는 언어다.
- 도구 축은 `그 계산을 어떻게 실행하고 확인하고 남기는가`를 읽는 도구다.
- Part 3 진입 전에는 모든 장을 완벽히 끝내는 것보다 `어디로 다시 돌아올지`를 아는 편이 더 중요하다.

이 판단은 현재 맞습니다. 따라서 구조를 다시 나누기보다, 각 도구 장에서 `지금 장의 역할`과 `Part 3에서 다시 쓰이는 장면`을 더 짧고 반복적으로 못박는 편이 낫습니다.

- 관련 Section: `P2-7.1`, `P2-8.1`, `P2-9.*`, `P2-10.*`
- 왜 피로를 만드는가:

- 해결 방향:
  - 순서를 바꾸기보다, 각 장 끝이나 다음 장 도입에서 `지금은 어디서 실행하나`, `무엇을 적나`, `어떤 모양으로 담나`, `어떻게 남기나`를 더 짧게 반복해야 합니다.
- 우선 판단:
  - 핵심 입구 문장은 최근 라운드에서 많이 정리됨
  - 이제는 `P2-9.*`와 `P2-10.*` 안의 잔여 연결 문장이 실제로 같은 기준을 유지하는지 점검하는 쪽이 더 중요함

  - 주요 보충학습의 복귀 기준은 최근 라운드에서 많이 정리됨
  - 이제는 실제 본편 입구와 보충학습 말미가 서로 같은 방향으로 읽히는지 유지 점검하는 단계에 가까움

## 현재 결론

Part 2의 다음 단계는 `도구 장을 줄이는 작업`보다 `도구가 어떤 역할 흐름으로 이어지는지 더 짧게 반복 고정하는 작업`입니다.

따라서 편집 우선순위는 다음처럼 잡는 편이 맞습니다.

1. Chapter 9~10과 Chapter 14~15의 잔여 닫힘 문장을 선택적으로 점검한다.
2. Part 2가 실제로 `도구 과밀 Part`보다 `역할 흐름이 꽤 안정된 Part`에 가까워졌다는 점을 관리 문서에도 계속 반영한다.
3. 이후 우선순위는 Part 3의 baseline·오류 사례 축과 Part 5 후반 전환 유지 점검으로 자연스럽게 넘길 준비를 한다.

이 문서의 기준은 다음 한 문장으로 압축할 수 있습니다.

`Part 2의 문제는 도구 수 자체보다 도구를 하나의 계산-확인-기록 흐름으로 계속 읽히게 하느냐에 더 가깝고, 최근 라운드 이후에는 대규모 보강보다 잔여 닫힘 문장과 상태 문서 정합성을 유지하는 일이 더 중요해졌다.`
