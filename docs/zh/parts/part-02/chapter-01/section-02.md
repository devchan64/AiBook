# P2-1.2 公式、代码与数据相遇的地方

> Section ID: `P2-1.2`
> Version: `v2026.07.09`

P2-1.1 已经把数学放回“阅读 AI 计算的语言”这个位置。接下来要看的是：这种语言在实际学习里到底落在什么地方。公式、代码、数据并不是互不相干的东西，它们更像是同一个计算的三张脸。

1. 公式压缩计算结构。
2. 代码执行计算过程。
3. 数据提供计算对象与要检查的结果。

## 先抓住的共同场景

继续使用前一节的小表：

| 学生 | 学习时间 `x` | 测验分数 `y` |
| --- | --- | --- |
| A | 1 小时 | 55 |
| B | 2 小时 | 65 |
| C | 3 小时 | 80 |
| D | 4 小时 | 90 |

这张表就是 Chapter 1 中公式、代码、数据相遇的最小场景。

- 当成数据看，它是一张有 `x`、`y` 两列的小表。
- 当成公式看，它是写平均值、函数与误差的材料。
- 当成代码看，它可以被翻译成列表、数组与变量。

## 本节范围

这里首先要解决的问题是：当文档里的公式落到代码单元与真实数据上时，什么东西保持不变，什么只是外形变了？

因此这里只先固定四个位置。

- 公式在说什么？
- 代码怎样执行这个公式？
- 数据呈现成什么形状？
- 结果应该怎样重新解释？

## 三个基准

| 基准 | 为什么重要 | 本节所需理解水平 |
| --- | --- | --- |
| 同一个计算可以分别表现成公式、代码、数据 | 即使表面不同，也能知道自己在读同一件事 | 理解一个平均值可以用三种方式说明 |
| 公式压缩结构，代码展开执行顺序 | 能解释为什么文档与示例代码长得不一样 | 理解“加什么、除什么、按什么顺序执行” |
| 结果还需要放回语境解释 | 它会直接连到后面阅读 metric 与 loss | 理解像 72.5 这样的数值仍然需要说明 |

## 同一个计算的三种读法

还是用平均值(mean)来说明。如果只看分数那一列，数据就是 `55, 65, 80, 90`。

公式可以写成：

\[
\mathrm{mean} = \frac{55 + 65 + 80 + 90}{4}
\]

代码可以写成：

```python
scores = [55, 65, 80, 90]
mean = sum(scores) / len(scores)

print(mean)
```

示例输出：

```text
72.5
```

这三种写法虽然外表不同，但做的是同一件事。

- 数据：分数集合 `55, 65, 80, 90`
- 公式：把结构压缩写出来
- 代码：把步骤展开执行
- 输出：计算后检查到的结果

## 公式会命名并压缩关系

\[
y = f(x)
\]

这行看起来很简单，但在 AI 文档里非常重要。

- `x`：输入
- `f`：函数或模型
- `y`：输出

在机器学习语境里，可以读成：输入数据 `x` 经过 `f`，产生输出 `y`。

代码里也会出现同样结构：

```python
y = model(x)
```

语法不完全相同，但结构相同：输入、变换、输出。

## 数据会以可计算的形状进入

真实数据通常会先被转成可计算形式，如数组、向量、矩阵、张量。

```python
import numpy as np

one_value = np.array(3)
vector = np.array([1, 2, 3])
matrix = np.array([[1, 2, 3], [4, 5, 6]])

print(one_value.shape)
print(vector.shape)
print(matrix.shape)
```

示例输出：

```text
()
(3,)
(2, 3)
```

重点不是先学高级 NumPy 技巧，而是先看清：即使数字看起来相似，放进不同 shape 后，计算意义也会变。

## 代码把公式变成可执行过程

平均值写成公式很短：

\[
\mathrm{mean} = \frac{\sum_{i=1}^{n}x_i}{n}
\]

但在代码里，你仍然需要把执行步骤显式写出来。

```python
scores = [55, 65, 80, 90]
n = len(scores)
total = sum(scores)
mean = total / n

print(n)
print(total)
print(mean)
```

示例输出：

```text
4
290
72.5
```

代码会比公式更长，但它会把执行顺序暴露出来。

## 结果还需要重新解释

计算结束并不等于理解结束。

- 平均值是 72.5，表示这四个分数的大致中心在 72.5 附近。
- 如果 loss 是 0.2，表示模型输出与参考值之间的差，在某种损失定义下是 0.2。
- 如果 accuracy 是 90%，仍然要继续看错的是哪些例子。

数字结果不会自动变成意义。你还需要回头确认：它来自什么数据、用什么公式定义、由哪段代码执行。

## 本节要记住的视角

公式、代码、数据并不是彼此竞争的东西，而是在不同位置上解释同一个计算。公式更像蓝图，代码更像执行步骤，数据既是材料也是验证对象，而结果仍然要回到原问题语境里重新解释。

## 简短检查

- 能说明公式、代码、数据可以用不同方式表达同一个计算。
- 能把 `y = f(x)` 读成输入、函数、输出的关系。
- 能说明数据形状会改变计算方式。
- 能说明代码是怎样把公式变成可执行步骤的。
