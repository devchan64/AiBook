# P1-3.2 从数据中学习模式意味着什么

> Section ID: `P1-3.2`
> Version: `v2026.07.07`

3.1 回顾了人直接写规则这种方式的优势与限制。这一节继续追问：如果人无法把每一条有用规则都显式写出来，系统怎么从数据里获得判断标准？

这里的目标不是详细讲机器学习算法，而是先理解 `learning patterns from data` 这句话背后的基本结构，以及它为什么和规则式系统不同。线性回归、决策树等算法会在 Part 4 再展开，神经网络与深度学习会在 Part 5 继续说明。

这一节围绕 `example`、`feature`、`label`、`model`、`training` 和 `generalization` 来建立模式学习的基线。`representation` 的内部结构，以及它与规则式方法的对照，会在 3.3 继续展开。

## 这一节的范围

这一节整理以下问题：

- “从数据中学习模式”指的是什么结构？
- `example`、`feature`、`label` 和 `model` 分别扮演什么角色？
- 为什么模式学习不能被理解成单纯的记忆？

这一节不会深入展开以下内容：

- 线性回归、决策树、神经网络的具体计算
- 防止过拟合方法的数学比较
- 大规模数据集的完整实验设计

这里的重点，是机器学习最基础的思维方式本身。

## 这一节的目标

- 理解“从数据中学习模式”这句话的基本结构。
- 区分 `example`、`feature`、`label` 和 `model` 的角色。
- 看到 `training` 与后续实际使用之间的差别。
- 理解为什么模式学习不等于记忆。
- 理解为什么数据质量与 `generalization` 很重要。

## 三个基准

| 基准 | 为什么重要 | 这一节需要达到的理解程度 |
| --- | --- | --- |
| 学习是 `在例子中寻找关系`，而不是 `把所有规则都直接写出来` | 这样能立刻看见它与规则式系统的差异。 | 分清模型是通过例子调整判断标准。 |
| `example`、`feature`、`label` 和 `model` 是 `不同位置上的角色` | 这些是后面阅读机器学习章节所需的最低限度术语。 | 把 `feature` 看成输入线索，把 `label` 看成答案，把 `model` 看成计算关系。 |
| 学习不是 `记忆`，而是找出能在新数据上继续有效的模式 | 这样会自然通向 `generalization` 与 `overfitting`。 | 理解“好的学习”要能处理没见过的输入。 |

## 先看一个小例子

假设客户支持团队想把用户消息做分类。

| 消息 | 人工标注的类别 |
| --- | --- |
| “我想退款。” | 退款 |
| “可以取消付款吗？” | 退款 |
| “配送什么时候到？” | 配送 |
| “如果明天还不到我就取消。” | 配送 |
| “商品寄来时是坏的。” | 换货或补发 |
| “请再寄一次。” | 换货或补发 |
| “我想修改地址。” | 配送信息修改 |

如果只靠显式规则，某个人就得不断写出类似下面这样的规则：

- 如果消息里有 `退款` 或 `取消`，就归类为退款
- 如果有 `配送` 或 `明天`，就归类为配送
- 如果有 `坏了` 或 `再寄`，就归类为换货或补发

一开始看起来还能工作，但模糊情况很快就会出现。

> 如果配送晚了，我可以不要退款而改成补发吗？

学习式方法会换一个问题来问：

> 看过很多过去的消息和它们的类别之后，这条新消息在结构上更像哪一类？

后面的说明都可以围绕这个例子来理解。

## 它不是写规则，而是找关系

规则式系统从显式条件出发。

> if condition A and condition B hold, produce result C

机器学习则把工作的中心换掉了。

> example data -> training -> model -> prediction for a new input

把两种方式并排比较，会更清楚。

| 方法 | 核心问题 | 主要工作 |
| --- | --- | --- |
| 规则式 | 应把什么书面条件映射成什么类别？ | 由人写规则和例外 |
| 学习式 | 过去的输入与输出之间，什么关系不断重复？ | 让系统利用数据来调整模型 |

两种方法都会接收输入并产出结果。差别在于，判断标准到底来自哪里。

## 模式是可以复用的关系

这里说的 `pattern`，不是指旧数据里任何看起来重复的东西，而是指在新数据上仍然有帮助的关系。

| 观察 | 为什么要谨慎 |
| --- | --- |
| 单词 `取消` 常出现在退款消息里 | “如果配送晚了我就取消” 也可能主要是配送问题 |
| 单词 `再` 常出现在补发请求里 | “我又登录了一次还是失败” 并不是补发请求 |
| 单词 `地址` 常出现在地址修改里 | “地址填错了所以想退款” 也可能仍是退款问题 |

所以，有用的模式不是某个单词本身，而是当语境改变时仍然有帮助的关系。

这就是为什么会出现 `overfitting`、`underfitting` 和 `generalization` 这些词。

| 术语 | 在这里的最小含义 |
| --- | --- |
| overfitting | 模型对旧数据贴得太死，在新数据上变弱 |
| underfitting | 模型连旧数据中的主要结构都没学到 |
| generalization | 模型在没见过的数据上也还能工作得比较合理 |

这一节只把这些词作为“学习出来的模式质量如何”的名称来介绍。更详细的评价方法会在后面再展开。

## example、feature、label 和 model

在 `supervised learning` 里，数据通常可以被看成一组 `examples`。每个 `example` 都会同时包含输入信息，以及需要被预测的答案。

| 术语 | 含义 |
| --- | --- |
| example | 一个案例或一次观测 |
| feature | 模型作为输入使用的值 |
| label | 模型要预测的答案或目标 |
| model | 把 `features` 映射到预测结果的计算结构 |
| training | 利用例子调整模型内部值的过程 |
| inference | 用训练后的模型处理新输入 |

在这一阶段，最重要的基准就是：一个 `example` 里同时包含 `features` 和 `label`，而模型学习的是它们之间的关系。

| 例子 | feature 视角 | label |
| --- | --- | --- |
| “我想退款。” | 像 `退款` 这样的词和线索 | 退款 |
| “配送什么时候到？” | 像 `配送` 这样的词和线索 | 配送 |
| “商品寄来时是坏的。” | 像 `寄来`、`坏了` 这样的线索 | 换货或补发 |

这个表是为了学习而简化过的。真实系统通常还要先做一步准备：把原始记录整理成 `examples`，决定 `label`，并判断什么才算可用的 `feature`。

## training 是在调整内部标准

在规则式系统里，人通过修改规则来改标准。在机器学习里，`training` 会利用数据和评估标准，去调整模型内部的 `parameters`。

这个过程可以先被简化成四步：

1. 模型根据输入做出预测。
2. 计算预测和答案之间的差异。
3. 调整内部值，让差异变小。
4. 对很多例子重复这一过程。

把它和规则式系统对照起来，会更清楚。

| 区分 | 规则式系统 | 学习式模型 |
| --- | --- | --- |
| 谁来设定标准 | 由人直接写规则 | 由数据与训练过程调整参数 |
| 如何修正 | 添加、删除或调整规则顺序 | 修改数据、特征、目标函数或内部值 |
| 如何检查错误 | 看是哪条规则写错了 | 看数据质量、标签、模型行为与评估结果 |

因此，机器学习系统的检讨方式不再只是读逻辑，而必须连同数据与失败案例一起看。

## 学习不是记忆

“从数据中学习”不能被理解成“把旧例子存下来然后照抄”。目标是找到在新例子上仍然有效的关系。

如果模型只记住旧消息，它就并没有真正学会分类结构。好的学习意味着：即使一条新消息和旧例子的措辞不同，但意思相近，模型仍然能比较合理地处理。

这也是为什么数据质量如此重要。如果例子很嘈杂、标签不一致，或者收集到的情境过于狭窄，那么学出来的模式就会变弱。

## 案例

### 案例 1. 客服消息分类

一个团队也许最开始只写关键词规则，但很快就会遇到把配送、退款、换货语言混在一起的消息。到了这个阶段，问题已经不再是“把所有可能短语都列出来”，而是“从大量带标签的例子里学到可复用的关系”。这个案例展示了从显式规则写作转向模式学习的转折点。

### 案例 2. 从行为日志预测流失

一家公司可能希望根据访问频率、付款记录和最近活跃度去预测客户流失。没有人能现实地手写出每一条有效行为规则。这就是机器学习变得有吸引力的场景：关系必须从大量例子中被发现，而不是由人直接编写。

## 这一节要记住的内容

- 从数据中学习，指的是从例子里学关系，而不是把每条规则都手写出来
- `example`、`feature`、`label` 和 `model` 分别占据不同角色
- 好的学习不是记忆，它应该也能处理新数据
- 数据质量与 `generalization` 很重要，因为目标是超出训练集后的复用

这一节至少要留下的一句话是：`machine learning 会从 examples 中学习可复用的关系，而不是要求人把每一条判断规则都显式写出来。`
