# Part 4 마무리. 딥러닝 정리

Part 4는 머신러닝의 공통 질문 위에 신경망(neural network)이라는 더 큰 함수 계열이 어떻게 쌓였는지를 실제로 설명하는 구간이었습니다. Part 3가 데이터 분리, 일반화, 평가를 중심으로 모델을 읽는 기준을 세웠다면, Part 4는 그 기준을 유지한 채 `표현(representation)을 더 깊게 학습하는 구조`와 `그 구조를 실제로 학습시키는 절차`를 회수해야 하는 파트였습니다.

이 Part의 핵심은 딥러닝을 단지 `층이 많은 모델`로 외우는 것이 아니라, 입력이 가중치(weight)와 활성화 함수(activation function)를 거쳐 점점 다른 표현으로 바뀌고, 손실(loss)과 역전파(backpropagation)를 통해 그 표현을 조정하는 반복 구조로 읽는 것입니다.

즉, Part 4는 Part 1~3에서 `후속에서 설명한다`고 남겨 둔 퍼셉트론, 표현 학습, 손실 함수, 역전파, optimizer, CNN, Transformer를 실제로 설명해야 하는 첫 본문 파트였습니다.

이때 중요한 원칙은 Part 4를 `Part 5를 위한 예고편`으로 끝내지 않는 것입니다. CNN, RNN, Attention, Transformer는 모두 뒤의 LLM 설명과 연결되지만, 그 연결은 `다음에 더 본다`는 식의 유예가 아니라 `현재 구조를 먼저 닫은 뒤 다음 파트에서 다른 문제로 확장한다`는 순서여야 합니다.

## 이 마무리를 읽는 순서

이 문서는 다음 순서로 읽으면 충분합니다.

1. 먼저 Part 4 전체가 어떤 큰 흐름으로 구성되었는지 다시 잡습니다.
2. 그 다음 반드시 기억할 개념과 오해하기 쉬운 지점을 함께 정리합니다.
3. 이어서 Part 4에서 의도적으로 닫지 않은 질문이 무엇인지 확인합니다.
4. 마지막에 Part 5에서 그 질문이 어떤 형태로 다시 열리는지 연결합니다.

## 이 파트에서 다룬 핵심 흐름

Part 4의 흐름은 다음처럼 정리할 수 있습니다.

> 퍼셉트론과 다층 신경망
> -> 활성화 함수, 출력층, 손실, 역전파
> -> 학습과 모델 실행의 구분
> -> 옵티마이저, 정규화, 드롭아웃
> -> GPU, 배치, 텐서 계산과 표현 학습
> -> CNN, RNN, LSTM, GRU
> -> Attention과 self-attention
> -> Transformer
> -> 생성 모델과 샘플링
> -> Part 5의 LLM과 생성형 AI

이 흐름을 한 문장으로 줄이면 다음과 같습니다.

`딥러닝은 큰 함수 하나를 외우는 기술이 아니라, 데이터를 점점 더 적절한 표현으로 바꾸고 그 과정의 오차를 다시 뒤로 보내 조정하는 학습 체계다.`

이 구조는 Part 5에서 곧바로 다음 같은 질문과 산출물 언어로 이어집니다.

| Part 4에서 잡은 구조 감각 | Part 5에서 다시 읽히는 질문 | 이후 프로젝트에서 남게 되는 기록 |
| --- | --- | --- |
| 입력을 표현으로 바꾼다 | 문장은 어떤 토큰 단위로 잘리는가? | `tokens`, `coverage`, `oov_tokens` |
| 손실과 역전파로 조정한다 | 다음 토큰 예측이 왜 생성으로 이어지는가? | `project_run`, 예측 비교 결과 |
| Attention과 Transformer가 문맥을 다룬다 | 왜 긴 문맥과 생성 서비스가 가능해졌는가? | `selected_evidence`, `retrieval_records` |
| 생성과 샘플링이 결과를 바꾼다 | 왜 답변 품질과 서비스 품질을 함께 봐야 하는가? | `evaluation_records`, `review_summary` |

현재 목차 기준으로 보면 이 흐름은 `신경망의 출발점 -> 출력, 손실, 역전파 -> 학습 루프와 안정화 -> 계산 환경과 표현 학습 -> 구조 분기 -> 생성`으로 다시 묶여 읽히는 편이 더 자연스럽습니다.

이 마무리에서 특히 중요한 점은 Part 4를 `구조 이름을 많이 본 파트`로 끝내지 않고, `표현 학습 -> 구조 분기 -> 생성 기반`으로 이어지는 하나의 흐름으로 다시 묶는 것입니다. 그래야 Part 5를 읽을 때도 `Transformer를 이미 안다`가 아니라 `왜 이 구조가 생성형 언어 모델의 기반이 되었는가`를 설명할 수 있습니다.

후반부 구조 장들을 가장 짧게 다시 묶으면 다음과 같습니다.

| 구조 장 | 이름보다 먼저 읽어야 할 문제 |
| --- | --- |
| CNN | 이미지에서 지역 패턴이 왜 먼저 중요해지는가 |
| RNN/LSTM/GRU | 순서와 누적 상태가 왜 현재 판단을 바꾸는가 |
| Attention/self-attention | 먼 위치 단서를 왜 지금 다시 참조해야 하는가 |
| Transformer | 관계 계산을 왜 병렬 블록 구조로 묶어야 했는가 |
| 생성/샘플링 | 출력을 만든 뒤 실제 후보를 왜 따로 골라야 하는가 |

## 반드시 기억할 개념

Part 4를 지나며 가장 오래 남겨야 할 개념은 다음입니다.

| 구분 | 기억할 관점 |
| --- | --- |
| 퍼셉트론 | 입력과 가중치의 선형 결합 위에 판단 구조를 얹는 가장 작은 출발점입니다. |
| 은닉층 | 중간층은 단순한 계산 단계가 아니라 입력을 다른 표현으로 바꾸는 자리입니다. |
| 활성화 함수 | 비선형성이 없으면 깊게 쌓아도 표현력 증가가 제한됩니다. |
| 출력층과 손실 | 출력 해석과 손실 함수는 문제 유형에 맞게 함께 선택해야 합니다. |
| 역전파 | 역전파는 신경망 전체를 마법처럼 학습시키는 이름이 아니라, 오차 기여도를 효율적으로 전달하는 계산 절차입니다. |
| 옵티마이저 | 손실을 줄이는 방향은 같아도 실제 업데이트 규칙은 다를 수 있습니다. |
| 정규화 | 좋은 학습은 단순히 더 오래 맞추는 일이 아니라, 보지 못한 데이터에서도 무너지지 않게 만드는 일입니다. |
| GPU와 배치 | 딥러닝 확산은 좋은 아이디어만이 아니라 병렬 계산 환경과 함께 일어났습니다. |
| 표현 학습 | 사람이 특징을 쓰는 대신 모델이 특징을 직접 학습한다는 점이 딥러닝 전환의 핵심입니다. |
| CNN / RNN / Attention | 데이터 종류와 의존성 구조에 따라 유리한 모델 설계가 달라졌습니다. |
| Transformer | self-attention과 병렬 처리 구조가 LLM 시대의 기반이 되었습니다. |
| 생성과 샘플링 | 생성형 AI는 출력 자체를 만들며, 실제 결과는 샘플링 전략의 영향을 받습니다. |

이 개념들을 다시 묶을 때도 두 축으로 나누면 덜 헷갈립니다.

| 먼저 나눌 축 | 여기에 들어가는 것 | 왜 나누어 읽어야 하는가 |
| --- | --- | --- |
| 구조 | 퍼셉트론, 은닉층, CNN, RNN, Attention, Transformer, 생성 구조 | 입력을 어떤 형태로 바꾸고 어떤 의존성을 다루는지 설명합니다. |
| 학습 절차 | 손실, 역전파, optimizer, regularization, dropout, 배치 | 같은 구조라도 학습 안정성, 일반화, 계산 비용이 달라질 수 있음을 보여 줍니다. |

즉, Part 4에서는 `어떤 구조를 썼는가`와 `그 구조를 어떻게 학습시켰는가`를 따로 읽는 습관이 중요합니다.

## 오해하기 쉬운 지점

Part 4에서 특히 조심해야 할 오해는 다음입니다.

- 딥러닝은 `머신러닝과 완전히 다른 것`이 아니라, 머신러닝의 한 계열을 더 큰 표현 학습 구조로 확장한 것입니다.
- 층이 많아진다고 자동으로 더 좋은 모델이 되는 것은 아닙니다.
- 손실이 내려간다고 바로 실제 품질이 좋아진다고 단정할 수는 없습니다.
- 역전파는 학습 전체의 이름이 아니라 기울기 계산 절차입니다.
- GPU는 단순한 속도 향상 장치가 아니라, 딥러닝 연구 방향 자체에 영향을 준 계산 환경입니다.
- Attention이 생겼다고 RNN 계열이 완전히 무의미해진 것은 아닙니다. 다만 대규모 언어 모델의 주류 구조가 바뀐 것입니다.
- Transformer를 이해했다고 바로 LLM 전체를 이해한 것은 아닙니다. Part 5에서는 토큰(token), 사전학습(pretraining), 정렬(alignment), 도구 연결까지 함께 봐야 합니다.
- 생성 결과가 이상하면 모델이 `모른다`고만 해석하면 부족합니다. 샘플링 방식, 문맥 길이, 입력 구조도 함께 봐야 합니다.
- Part 4가 구조 이름만 소개하고 지나가면 Part 5의 LLM 설명도 다시 표면적인 용어 소개로 약해질 수 있습니다.

## 이 파트에서 끝내지 않는 질문

Part 4는 딥러닝의 구조와 학습 절차를 설명하는 데 집중했습니다. 따라서 다음 질문은 의도적으로 Part 5로 넘깁니다.

- 입력 문장이 실제 서비스에서는 어떤 토큰 단위로 잘리는가?
- Transformer가 왜 긴 대화, 요약, 코드 생성 같은 사용자 경험으로 이어지는가?
- 생성 결과의 품질과 근거를 서비스 수준에서 어떻게 보완하는가?

즉, Part 4는 `구조적 기반`을 닫는 파트이지, LLM 서비스 경험 전체를 여기서 끝내는 파트는 아닙니다.

즉, Part 4의 마지막 질문은 `어떤 구조가 있는가`에서 멈추지 않고, `그 구조가 실제 생성형 AI 서비스 경험으로 어떻게 이어지는가`로 넘어가야 합니다.

이 전환을 가장 짧게 줄이면 다음과 같습니다.

- Part 4는 `왜 이런 계산 구조가 필요한가`를 설명합니다.
- Part 5는 `그 구조가 왜 토큰, 생성, RAG, agent, 운영으로 이어지는가`를 설명합니다.

## 다음 파트로 넘어가기 전에 확인할 질문

Part 5로 넘어가기 전에 다음 질문에 답할 수 있으면 충분합니다.

- 퍼셉트론, 다층 신경망, 은닉층의 관계를 설명할 수 있는가?
- 활성화 함수가 왜 필요한지 말할 수 있는가?
- 출력층과 손실 함수가 문제 유형과 연결된다는 점을 설명할 수 있는가?
- 역전파가 무엇을 계산하는 절차인지 말할 수 있는가?
- 옵티마이저와 학습률이 학습 안정성에 어떤 영향을 주는지 설명할 수 있는가?
- 정규화와 드롭아웃이 과적합과 어떤 관계가 있는지 말할 수 있는가?
- GPU, 배치, 텐서 계산이 왜 딥러닝 확산과 연결되는지 설명할 수 있는가?
- CNN, RNN, Attention, Transformer가 각각 어떤 데이터 구조나 문제에서 등장했는지 말할 수 있는가?
- 생성 모델과 분류 모델의 차이를 설명할 수 있는가?
- 샘플링이 생성 품질과 다양성에 영향을 준다는 점을 말할 수 있는가?

## 다음 파트와 연결되는 관점

Part 5에서는 딥러닝 구조 설명을 LLM과 생성형 AI의 실제 사용 경험으로 이어갑니다. Part 4에서 이미 구조적 기반은 마련되었습니다.

이제 질문은 다음처럼 바뀝니다.

> 입력 문장은 실제로 어떤 단위로 잘리는가?
> 임베딩은 그 단위를 어떤 벡터로 바꾸는가?
> 사전학습은 무엇을 대규모로 배우는가?
> GPT, BERT, instruction tuning, RAG, tool use, agent는 어느 지점에서 갈라지는가?

즉, Part 5는 Part 4의 구조를 버리고 새로 시작하는 파트가 아닙니다. 오히려 Part 4에서 본 신경망, attention, Transformer, 생성, 샘플링이 어떻게 실제 LLM 서비스 경험으로 이어지는지를 구체적으로 설명하는 확장 파트입니다.

따라서 이 마무리에서 확인해야 할 최종 결과는 Part 4를 `딥러닝 일반론`으로 닫는 것이 아니라, Part 5의 LLM과 생성형 AI 설명을 이해하기 위한 구조적 기반으로 다시 읽을 수 있는가입니다.

즉, Part 4를 마쳤다는 말은 단순히 CNN, RNN, Transformer 이름을 안다는 뜻이 아니라, 이후 Part 5에서 나올 토큰, 생성, 검색, 도구, 운영 설명을 `같은 계산 구조의 확장`으로 읽을 준비가 되었다는 뜻이어야 합니다.

## Part 4를 마치며

Part 4를 지나면 딥러닝을 더 이상 `가중치가 많은 복잡한 블랙박스`로만 보지 않게 됩니다. 입력이 표현으로 바뀌고, 손실이 계산되고, 오차가 다시 전달되고, 병렬 계산 자원이 이를 떠받치며, attention과 Transformer가 긴 문맥과 생성 문제를 열었다는 큰 흐름이 잡히기 시작합니다.

이 흐름이 잡혀 있어야 Part 5에서 LLM을 단지 유명한 제품 이름이나 API 호출 대상으로 보지 않고, 어떤 입력 단위와 계산 구조 위에서 작동하는지 설명할 수 있습니다.

Part 4의 목적은 바로 그 기반을 만드는 것이었습니다.
