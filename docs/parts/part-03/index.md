# Part 3. 데이터 모델링

Part 2에서 우리는 수학, Python, 배열, 표, 그래프를 다시 읽는 기초를 복구했습니다. 이제 남은 질문은 이 도구들로 무엇을 어떤 구조로 표현할 것인가입니다. 실제 원천데이터를 만나면 먼저 부딪히는 문제는 모델 이름을 고르는 일보다 샘플 단위를 정하고, 요약 구조를 만들고, 비교 기준을 세우는 일에 더 가깝습니다.

이 Part는 바로 그 지점을 다룹니다. 이 책에서 데이터 모델링은 저장 구조를 정리하는 일만을 뜻하지 않습니다. 데이터 모델링은 현실에서 발생한 원천데이터를 사람이 비교하고 AI가 활용할 수 있는 샘플, 특징, 기준선, 출력 구조로 다시 표현하는 일입니다.

이 Part에서는 샘플 단위를 정하고, 원시 로그와 요약 표를 구분하고, 특징과 중간 표현을 설계하고, 최근 구간과 기준선을 비교하는 구조를 배웁니다. 이어서 적은 표본에서 어떤 해석을 보류해야 하는지, 어떤 문제는 분류기보다 경고 후보 생성이나 비교 리포트로 다루는 편이 더 현실적인지까지 정리합니다.

## 이 Part의 목적

- 데이터 모델링을 DB 설계로만 오해하지 않게 한다.
- 원천데이터를 샘플, 요약 표, 특징, 기준선으로 다시 표현하는 흐름을 익히게 한다.
- Part 4에서 다룰 머신러닝이 기대는 데이터 표현 전제를 먼저 세운다.

## 왜 필요한가

- 원시 로그가 곧바로 데이터셋이 아니라는 점을 먼저 배워야 하기 때문이다.
- 샘플 단위와 비교 기준이 정해지지 않으면 feature와 label 설명이 흔들리기 때문이다.
- 경고 후보와 진단 확정, 기준선 비교와 절대값 판단을 자주 혼동하기 때문이다.

## 주요 질문

- 측정값과 샘플은 어떻게 다른가
- 원시 시계열을 왜 요약 표로 다시 묶는가
- 특징은 어떤 기준으로 설계하는가
- 기준선은 왜 평가 단계가 아니라 데이터 모델링 단계에서 먼저 등장하는가
- 어떤 문제는 왜 분류보다 비교 리포트가 더 적합한가

## 범위와 비범위

이 Part에서는 샘플 단위, 원시 로그와 요약 표, 특징과 중간 표현, 기준선 비교, 표본 수와 반복성, 경고 후보와 라벨 예측의 경계를 다룹니다.

반면 특정 머신러닝 알고리즘의 학습 방식, train/validation/test 분리의 세부 절차, 복잡한 시계열 딥러닝 구조는 Part 4 이후에서 다시 다룹니다.
