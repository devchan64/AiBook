# P3-8.7 运行干预如何改变数据解释

> Section ID: `P3-8.7`
> Version: `v2026.09.20`

看到风险信号后采取措施，之后没有发生故障，是最初信号错误，还是措施预防了故障？仅凭结果无法确认其中任何一种解释。理解[干预反馈](/AiBook/zh/reference/concept-glossary-pinyin/g/#glossary-intervention-feedback)，需要区分信号观察时点、复核与处置，以及后续结果确认。

## 按时间排列信号、复核、处置与结果

以下A、B、C是本节自行构造的虚拟事件，与其他节同名事件无关。所有时间使用相同时区。`review_needed`是信号时点的复核请求，实际复核与干预另有记录。`none`表示记录中没有该项干预，不表示最初没有风险。

| event_id | 信号时点 | review_needed | 复核时点 | 干预开始时点与内容 |
| --- | --- | ---: | --- | --- |
| A | 2026-09-01 09:00 | 1 | 09-01 09:05 | 09-01 09:10，调整阀门设置 |
| B | 2026-09-01 10:00 | 1 | 09-01 10:08 | 09-01 10:20，更换部件 |
| C | 2026-09-01 11:00 | 0 | 未进行初始复核 | none |

`failure_within_7d`表示**从信号时点起的七天内**是否至少确认一次所定义的故障：是则为1，完整观察该期间且没有故障则为0。包含开始时点，不包含结束时点。本例假定通过独立后续确认，对三个事件采用相同故障定义并完成整个期间的观察。C虽没有初始复核请求，也获得了后续结果。

| event_id | 结果观察期间 | 结果确认时点 | failure_within_7d |
| --- | --- | --- | ---: |
| A | 09-01 09:00（含）至09-08 09:00（不含） | 09-08 09:00 | 0 |
| B | 09-01 10:00（含）至09-08 10:00（不含） | 09-08 10:00 | 0 |
| C | 09-01 11:00（含）至09-08 11:00（不含） | 09-08 11:00 | 1 |

A的0表示在包含干预开始时点的七天观察中未确认故障，不表示最初没有风险，也不表示不干预仍会得到0。如果观察三天后中断，就不能按此定义赋值0，需要分别保留结果未确认与观察完成状态。

## 区分干预后结果与干预效果

A、B结果均为0，因此已干预集合的观察故障比例为`0/2=0%`；C为`1/1=100%`。不能将其改写为“预防故障成功率100%”。已干预与未干预组不是同一批事件，初始状态及选择理由也可能不同。

对A实际观察到的只有**接受干预这一路径的结果0**，没有观察到同一个A在相同情况下不接受干预时的七天结果。措施可能有帮助，也可能原本就不会发生故障。不能直接用C的结果1替代A未观察到的“不干预结果”。因此仅凭此表无法确认初始信号错误或干预效果。

| 表述 | 此表是否支持？ |
| --- | --- |
| A在信号十分钟后开始调整设置，观察期间结果为0 | 支持，描述时点、内容与结果 |
| A最初没有风险 | 不支持，由结果0断定初始风险 |
| A的设置调整阻止了故障 | 不支持，不知道同一A不干预的结果 |
| 同时保存A的处置内容与结果观察期间 | 支持，这是后续解释需要的记录 |

## 分开干预前输入与干预后记录

解释初始信号时，应关联信号时点已经可用的测量值、基线与复核政策版本。不能把A在09:10的设置变更或09-08的结果，当作09:00已经知道的输入。报告干预后的运行结果时，要同时标明措施及其时点。

提前停止可能缩短动作，使后续传感器区段本身消失；加强检查则可能在相同情况下留下更详细的标签。因此需要记录，以区分测量减少是状态变化还是观察中断，以及确认故障增多是否源于检查得更多。未获得标签与确认非故障的区别可联系[P3-8.6](section-06.zh.md)。

## 记录措施与观察期间

请用记录代替A的“警告后处置成功”备注，写出信号时点、干预开始时点与内容、结果观察期间、完成状态及结果，并补充一项仍不支持的主张。

参考答案：`signal_at=2026-09-01 09:00`、`intervention_at=2026-09-01 09:10`、`intervention=valve_setting_adjustment`、`followup_start=2026-09-01 09:00`、`followup_end=2026-09-08 09:00`、`followup_complete=1`、`failure_within_7d=0`。补充：“设置调整后观察期间未确认故障，但由于不知道不干预的结果，预防效果尚未确认。”还应在记录定义中保留结束时点不计入的规则与确认来源。

如果观察在09-04 09:00结束，则`followup_complete=0`，`failure_within_7d`保留为未确认。不能把前三天没有故障扩写成七天结果为0。

## 检查清单

- 能否区分信号前后的输入、复核、干预与结果确认时点？
- 能否说明为什么结果0无法确认初始风险不存在或措施成功？
- 能否记录措施内容、时点、观察期间与完成状态，不把短期观察改成七天非故障？
