# P3-8.3 保守解读句子应当按什么顺序、用什么词来写

> Section ID: `P3-8.3`
> Version: `v2026.07.25`

保守解读句子需要在一句话里分开写出`哪里变了`、`可以多大程度地说得更强`、以及`人下一步该做什么`。这里的关键，是在读完[比较表](/AiBook/zh/reference/concept-glossary-pinyin/c/#glossary-comparison-table)之后，句子该按照什么顺序和词汇留下来，才能同时避免夸大，也避免因为过弱而什么信息都没留下。与其重新发明新的边界，不如先把已经确认的[比较结果](/AiBook/zh/reference/concept-glossary-pinyin/c/#glossary-comparison-result)和[证据强度（evidence strength）](/AiBook/zh/reference/concept-glossary-pinyin/z/#glossary-evidence-strength)按正确顺序放进句子里。

最安全的基本顺序如下。

1. 先说比较结果。
2. 然后附上会降低或提高解读强度的条件。
3. 最后写上人接下来要做的[下一步行动](/AiBook/zh/reference/concept-glossary-pinyin/n/#glossary-next-action)。
4. 如果没有额外证据，就不要写原因确认。

把这个顺序再压缩一点，就是`比较结果 -> 确信强度 -> 下一步动作`。

| 句子顺序 | 为什么要先放在这里 |
| --- | --- |
| 比较结果 | 因为要先说明实际观测到的差异 |
| 确信强度条件 | 因为表达强度要按样本量和重复性来调节 |
| 下一步动作 | 因为需要在运营上留下人该做什么 |
| 排除原因确认 | 因为不能提前写进还不存在的证据 |

## 安全的句子与危险的句子

即使是同样的观测状态，只要词汇不同，解读强度也会明显改变。

| 观测状态 | 危险的句子 | 更安全的句子 |
| --- | --- | --- |
| 最近几条里看见差异 | 状态已经明确改变了 | 最近少量案例里出现差异，还需要继续观察 |
| 下降模式反复出现 | 发生了传感器异常 | 出现了重复的下降模式，因此提高复核优先级 |
| 差值很大，但样本量小 | 立刻确认告警 | 差值虽然大，但样本量小，所以告警强度保持保守 |
| 相对基线变化很大且存在重复 | 原因已经很明确 | 变化信号较强，值得由人工优先确认 |

这张表的重点不是`说得弱一点`，而是`只把证据直接支撑到的层级准确说出来`。

## 先把句子骨架固定下来

如果一边看比较表一边直接写句子，很容易把原因断言混进去。因此在这个阶段，最好先把下面这个骨架固定下来。

安全的基本骨架是这样的：最近区间相对[基线（baseline）](/AiBook/zh/reference/concept-glossary-pinyin/b/#glossary-baseline)表现出[怎样的差异]，考虑到[样本量/重复性条件]，[复核强度或下一步动作]更合适。

把实际数值代进去后，就会变成下面这样的句子。

- 最近区间相对基线，后段下降率更大，而最近只有 4 条样本，因此在不确认原因的前提下还需要继续观察。
- 最近区间相对基线，同时出现平均值下降和波动性上升，而且最近 20 条里同方向变化在重复，因此提高复核优先级。
- 最近区间相对基线差异较小，重复性也弱，因此先保留在记录级别。

这三句话都先陈述比较结果，再附上强度条件，最后以下一步动作收尾。相反，像`发生了传感器异常`、`故障已经确认`这样的句子，就是在提前调用还不存在的证据。

## 按解读强度排列的句子阶梯

把上一节里的`记录`、`复核候选`、`强告警`移动到真实句子的结尾层级，可以整理成下面这样。

| 解读强度 | 更自然的句子结尾 |
| --- | --- |
| 记录级别 | 保留为记录，并继续观察 |
| 复核候选级别 | 值得由人工优先复核 |
| 高复核优先级 | 提高复核优先级 |
| 并非原因确认 | 暂缓原因确认 |

这张表并不是说`只要某种状态就一定对应这个标签`。它的作用，是在写句子时先固定默认收尾，避免不知不觉滑向过强的确认式用语。
