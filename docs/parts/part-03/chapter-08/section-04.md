# P3-8.4 보수적 해석과 운영 열

> Section ID: `P3-8.4`
> Version: `v2026.09.20`

“검토가 필요하다”는 문장만으로 우선순위 점수가 계산되지는 않습니다. 같은 관측에서 같은 [운영 출력](../../../reference/concept-glossary-parts/05-mieum.md#output-structure)을 만들려면, 입력값과 적용 조건, 판정 규칙을 정해야 합니다. 문장은 관측과 한계를 설명하고, 운영 열은 명시한 정책의 결과를 저장합니다.

| 층위 | 남기는 내용 | 이 사례에서의 역할 |
| --- | --- | --- |
| 비교 결과 | 차이·건수·규칙 충족 비율 | 관측한 내용을 보존 |
| 해석 문장 | 관측·불확실성·확인 행동 | 사람이 의미와 한계를 이해하도록 설명 |
| 운영 출력 | 경고 표시·검토 여부·우선순위 등급 | 정해진 정책에 따른 검색·분류·후속 처리 |

## 입력 조건과 계산 규칙 고정하기

다음은 운영 열을 만드는 연습을 위한 별도 가상 집계입니다. A·B·C는 비교 구간 식별자입니다. `diff`는 최근 동작별 후반 평균의 평균에서 기준선의 같은 평균을 뺀 값이며 단위는 L/min입니다. `event_count`는 최근 완료 동작 수입니다. 하강 조건은 [P3-7.2](../chapter-07/section-02.md)와 같은 `후반 평균−초반 평균 ≤ −0.30 L/min`이며, 동작당 한 번만 셉니다.

| window_id | diff (L/min) | event_count | decline_count | decline_ratio |
| --- | ---: | ---: | ---: | ---: |
| A | -0.35 | 20 | 14 | 14/20=0.70 |
| B | -0.35 | 3 | 1 | 1/3≈0.333 |
| C | -0.10 | 10 | 2 | 2/10=0.20 |

`decline_ratio=decline_count/event_count`입니다. A의 70%는 정한 하강 조건의 충족 비율이지 고장 확률이나 확신 점수가 아닙니다. 기준선 대비 차이와 동작 내부 하강 비율도 서로 다른 비교입니다.

여기서는 필요한 측정이 모두 있고, 기준선과 최근의 유형·운전 조건·단위·구간 정의가 같다고 가정합니다. 건수는 양의 정수이며 하강 건수는 0 이상 전체 건수 이하입니다. 별도 허용 한계 점검에서도 위반이 없다고 가정합니다. 측정 누락, 비교 조건 불일치, 한계 위반 또는 위반 여부 미확인인 행은 아래 정책의 적용 대상이 아닙니다. 그런 행은 데이터 확인이나 기존 대응 절차로 보내며, 이 정책의 마지막 행을 적용해 정상처럼 처리하지 않습니다.

## 수치와 운영 결정을 연결하는 정책

가상 운영팀이 다음을 검토 배정 정책 `review-v1`로 정했다고 하겠습니다. 위의 적용 조건을 만족하는 행에 한해 **위에서부터 처음 일치하는 규칙 하나**를 적용합니다. 0.30과 0.60은 이 연습에서 정한 정책값이며, 통계적으로 검증된 경계나 실제 설비의 안전 기준이 아닙니다.

| 규칙 | 입력 조건 | warning_level | review_needed | priority_band |
| --- | --- | --- | ---: | --- |
| R1 | diff ≤ −0.30이고 decline_ratio ≥ 0.60 | caution | 1 | first |
| R2 | R1에 해당하지 않고 diff ≤ −0.30 | caution | 1 | standard |
| R3 | 위 두 규칙에 해당하지 않음 | watch | 0 | none |

`caution`은 이 정책의 검토 표시이며 고장 진단이 아닙니다. `first`는 이 정책 안에서 `standard`보다 먼저 검토한다는 뜻일 뿐, 원인이 더 확실하다는 뜻이 아닙니다. `watch`와 `review_needed=0`은 **이 규칙으로 검토 큐에 넣지 않음**을 뜻하며 안전 보증이나 모든 후속 확인의 취소가 아닙니다. 두 경계는 등호를 포함합니다. 비율은 표시용 반올림 값이 아니라 원래 분수로 판정합니다.

## 해석 문장과 운영 열의 역할 비교 {#_4}

A를 끝까지 따라가 봅니다. `−0.35 ≤ −0.30`이고 `14/20=0.70 ≥ 0.60`이므로 R1입니다. 그래서 `warning_level=caution`, `review_needed=1`, `priority_band=first`를 저장합니다. 판단을 설명할 때는 “최근 20건의 후반 평균은 기준보다 0.35 L/min 낮고 하강 조건은 14건이 충족했다. 원인은 미확인이다. review-v1의 R1에 따라 우선 검토 대상으로 배정한다”라고 쓸 수 있습니다.

| window_id | warning_level | review_needed | priority_band | rule_id |
| --- | --- | ---: | --- | --- |
| A | caution | 1 | first | R1 |
| B | caution | 1 | standard | R2 |
| C | watch | 0 | none | R3 |

B는 차이 조건을 만족하지만 `1/3 < 0.60`이므로 R2입니다. 최근 3건이라는 이유로 검토에서 제외하지 않습니다. C는 `−0.10 > −0.30`이므로 R3입니다. 모든 출력 행에는 공통으로 `policy_version=review-v1`을 남기고, `window_id`로 원래 비교 행을 찾을 수 있게 합니다. 기준선 버전과 사용한 입력도 함께 보존해야 정책 적용을 다시 확인할 수 있습니다.

같은 A라도 다른 정책이 R1의 비율 경계를 0.80으로 정했다면 R1이 아닌 R2가 됩니다. 관측값과 원인에 대한 불확실성은 그대로인데 배정 등급만 달라집니다. 따라서 정책이 바뀌면 버전도 바꾸어 기록하며, 문장 속 “검토 필요”라는 표현에서 등급을 임의로 추출하지 않습니다.

문장 작성은 판단을 독자에게 풀어 설명하는 단계입니다. 실제 시스템이 반드시 자연어 문장을 먼저 생성하고 그것을 다시 해석해야 하는 것은 아닙니다. 검증한 입력에 정책을 직접 적용해 운영 열을 만들고, 같은 입력·정책·출력으로 설명 문장을 함께 만들 수도 있습니다. 어느 구현이든 관측 사실과 정책으로 정한 행동을 구분해 추적할 수 있어야 합니다.

## 직접 적용하기

적용 조건을 모두 만족하는 D가 `diff=−0.30`, `event_count=5`, `decline_count=3`이라면 review-v1의 출력은 무엇일까요? 같은 행에서 하강 건수만 2로 바꾸면 어떻게 될까요?

해설: 처음에는 `3/5=0.60`이고 두 경계의 등호를 포함하므로 R1, `caution·1·first`입니다. 2건으로 바꾸면 `2/5=0.40`이 되어 R2, `caution·1·standard`입니다. 이는 정책의 배정 결과이며 5건의 대표성이나 고장을 인증하지 않습니다. 측정이 누락되어 비율을 구할 수 없다면 R3으로 보내는 대신 적용 조건부터 다시 확인해야 합니다.

## 체크리스트

- 관측 비율·정책 등급·고장 확률을 구분하고 규칙 ID와 정책 버전을 남기는 이유를 설명할 수 있는가?
- 적용 조건 미충족을 정상으로 처리하지 않고, 자연어 문장이 필수 계산 단계가 아님을 설명할 수 있는가?
