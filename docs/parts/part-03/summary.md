# Part 3 마무리

이 Part에서는 데이터 모델링을 저장 구조 설명이 아니라 문제 표현 구조 설계로 읽었습니다. 핵심은 원천데이터가 곧바로 데이터셋이 아니라는 점입니다. 먼저 샘플 단위를 정하고, 원시 로그와 요약 표를 구분하고, 특징과 기준선을 설계해야 뒤의 머신러닝 설명이 제대로 읽힙니다.

## 이 Part의 핵심 흐름

- 한 행이 뜻하는 대상을 먼저 정한다.
- 원시 로그를 비교 가능한 샘플 표로 다시 묶는다.
- 특징과 중간 표현을 설계한다.
- 최근 구간과 기준선을 비교하는 구조를 만든다.
- 표본 수와 반복성을 보고 해석 경계를 둔다.

## 반드시 기억할 개념

- 샘플 단위
- 요약 표
- 특징
- 기준선
- 경고 후보와 진단 확정의 차이

## 오해하기 쉬운 지점

- 눈앞의 한 행이 곧 샘플 1건이라고 생각하는 것
- 원시 로그와 요약 표를 같은 층위의 표처럼 읽는 것
- 기준선 이탈을 바로 원인 확정으로 읽는 것

## 다음 Part로 넘어가기 전 질문

- 지금 한 행은 무엇을 뜻하는가
- 이 요약값은 어떤 질문에 답하기 위해 남겼는가
- 어떤 라벨은 만들 수 있고 어떤 라벨은 아직 만들 수 없는가

다음 Part에서는 이 구조 위에서 실제로 모델이 무엇을 학습하는지, 왜 train/validation/test를 나누는지, 점수와 일반화를 어떻게 읽어야 하는지를 다룹니다.
