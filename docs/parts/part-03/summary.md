# Part 3 마무리

이 Part에서는 데이터 모델링을 저장 구조 설명이 아니라 문제 표현 구조 설계로 읽었습니다. 핵심은 원천데이터가 곧바로 데이터셋이 아니라는 점입니다. 먼저 데이터셋 환상을 걷어 내고, 샘플 단위를 정하고, 원시 로그와 요약 표를 구분하고, 특징과 기준선을 설계해야 뒤의 머신러닝 설명이 제대로 읽힙니다.

대표 사례를 한 줄로 다시 쓰면 이렇습니다. 자동으로 실행되는 동작 1회가 있고, 그 안에 제어 파라미터 시계열과 센서 시계열이 남고, 여러 동작을 최근 구간과 기준선으로 다시 비교합니다. Part 3은 결국 이 구조를 사람이 읽고 모델이 이어받을 수 있는 표 구조로 바꾸는 과정을 설명했습니다.

Part 3 전체를 모듈 흐름으로 다시 보면 다음처럼 정리할 수 있습니다.

| 모듈 | 이 Part에서 회수한 질문 | 남긴 결과 |
| --- | --- | --- |
| 역할과 문제 장면 | 왜 눈앞의 표가 바로 데이터셋이 아닌가 | 데이터 모델링의 위치 |
| 샘플과 표 구조 | 한 행과 한 샘플은 어떻게 다른가 | 동작 단위 표와 요약 표 |
| 특징과 비교 구조 | 무엇을 남기고 무엇과 비교할 것인가 | feature와 기준선 비교표 |
| 해석 경계 | 어디까지 말할 수 있는가 | 보수적 문장과 검토 신호 |
| 문제 유형과 handoff | 무엇을 리포트로 두고 무엇을 예측 문제로 만들 것인가 | target 후보와 Part 4 전제 |

이 표가 중요한 이유는 단순히 목차를 다시 보여 주기 위해서가 아닙니다. 독자가 `데이터 모델링`을 하나의 기술 이름이 아니라, 문제를 표현 가능한 구조로 바꾸는 여러 판단의 연쇄로 기억하게 하기 위해서입니다.

## 이 Part의 핵심 흐름

- 눈앞의 표가 처음부터 데이터셋이 아니라는 점을 확인한다.
- 한 행이 뜻하는 대상을 먼저 정한다.
- 원시 로그를 비교 가능한 샘플 표로 다시 묶는다.
- 특징과 중간 표현을 설계한다.
- 최근 구간과 기준선을 비교하는 구조를 만든다.
- 표본 수와 반복성을 보고 해석 경계를 둔다.
- 비교 리포트로 남길 문제와 예측 문제를 구분한다.

## 반드시 기억할 개념

- 샘플 단위
- 저장 구조와 문제 표현 구조의 차이
- 요약 표
- 특징
- 기준선
- 경고 후보와 진단 확정의 차이
- 비교 리포트와 예측 문제의 차이

짧게 다시 보면 이 Part의 대표 산출물은 다음처럼 정리할 수 있습니다.

| 단계 | 남는 것 |
| --- | --- |
| 샘플 정의 | 동작 1회 기준 행 구조 |
| 요약과 특징 | 구간 평균, 기울기, 변동성, 토큰 표현 |
| 비교 구조 | 최근 구간, 기준선, 차이값 |
| 해석 | 경고 후보, 검토 필요, 보수적 문장 |
| handoff | feature, target 후보, split 전제 |

## 오해하기 쉬운 지점

- 눈앞의 한 행이 곧 샘플 1건이라고 생각하는 것
- 원시 로그가 이미 완성된 데이터셋이라고 생각하는 것
- 원시 로그와 요약 표를 같은 층위의 표처럼 읽는 것
- 기준선 이탈을 바로 원인 확정으로 읽는 것
- 모든 운영 문제를 곧바로 분류 문제로 만들 수 있다고 생각하는 것
- 경고를 자동 진단 확정처럼 읽는 것

## 다음 Part로 넘어가기 전 질문

- 지금 한 행은 무엇을 뜻하는가
- 이 요약값은 어떤 질문에 답하기 위해 남겼는가
- 어떤 라벨은 만들 수 있고 어떤 라벨은 아직 만들 수 없는가
- 비교 리포트로 남겨야 할 문제를 억지로 예측 문제로 바꾸고 있지는 않은가

이 질문들에 답할 수 있다면, Part 4의 머신러닝 설명은 더 이상 갑작스러운 모델 소개가 아니라 `이미 정리된 표 구조 위에 학습 구조를 얹는 단계`로 읽히기 시작합니다. 반대로 이 질문들에 답하지 못하면, train/validation/test나 evaluation 지표도 표면적인 절차처럼 보이기 쉽습니다.

다음 Part에서는 이 구조 위에서 실제로 모델이 무엇을 학습하는지, 왜 train/validation/test를 나누는지, 점수와 일반화를 어떻게 읽어야 하는지를 다룹니다.
