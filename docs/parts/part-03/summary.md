# Part 3 마무리

이 Part에서는 데이터 모델링을 저장 구조 설명이 아니라 문제 표현 구조 설계로 읽었습니다. 핵심은 원천데이터가 곧바로 데이터셋이 아니라는 점입니다. 먼저 데이터셋 환상을 걷어 내고, 샘플 단위를 정하고, 원시 로그와 요약 표를 구분하고, 특징과 기준선을 설계해야 뒤의 머신러닝 설명이 제대로 읽힙니다.

## 이 Part의 핵심 흐름

- 눈앞의 표가 처음부터 데이터셋이 아니라는 점을 확인한다.
- 한 행이 뜻하는 대상을 먼저 정한다.
- 원시 로그를 비교 가능한 샘플 표로 다시 묶는다.
- 특징과 중간 표현을 설계한다.
- 최근 구간과 기준선을 비교하는 구조를 만든다.
- 표본 수와 반복성을 보고 해석 경계를 둔다.
- 비교 리포트로 남길 문제와 예측 문제를 구분한다.

## 반드시 기억할 개념

- 샘플 단위
- 저장 구조와 문제 표현 구조의 차이
- 요약 표
- 특징
- 기준선
- 경고 후보와 진단 확정의 차이

짧게 다시 보면 이 Part의 대표 산출물은 다음처럼 정리할 수 있습니다.

| 단계 | 남는 것 |
| --- | --- |
| 샘플 정의 | 동작 1회 기준 행 구조 |
| 요약과 특징 | 구간 평균, 기울기, 변동성, 토큰 표현 |
| 비교 구조 | 최근 구간, 기준선, 차이값 |
| 해석 | 경고 후보, 검토 필요, 보수적 문장 |
| handoff | feature, target 후보, split 전제 |

## 오해하기 쉬운 지점

- 눈앞의 한 행이 곧 샘플 1건이라고 생각하는 것
- 원시 로그가 이미 완성된 데이터셋이라고 생각하는 것
- 원시 로그와 요약 표를 같은 층위의 표처럼 읽는 것
- 기준선 이탈을 바로 원인 확정으로 읽는 것
- 모든 운영 문제를 곧바로 분류 문제로 만들 수 있다고 생각하는 것
