# Part 3 마무리

> Section ID: `P3-summary`
> Version: `v2026.07.07`

이 Part에서는 데이터 모델링을 저장 구조 설명이 아니라 문제 표현 구조 설계로 읽었습니다. 핵심은 원천데이터가 곧바로 데이터셋이 아니라는 점입니다. Part 2와 Part 3은 함께 기본기 점검 구간을 이루며, Part 3은 그중 `데이터과학 문제 구조 복구`를 맡습니다. 먼저 데이터 모델링의 목표와 범위를 고정하고, 저장된 기록을 데이터셋 후보로 다시 읽고, 샘플과 표 구조를 정하고, 특징과 기준선을 설계하고, 해석 경계를 세운 뒤에야 뒤의 머신러닝 설명이 제대로 읽힙니다.

대표 사례는 자동으로 실행되는 동작 1회가 있고, 그 안에 제어 파라미터 시계열과 센서 시계열이 남으며, 여러 동작을 최근 구간과 기준선으로 다시 비교하는 구조입니다. Part 3은 이 구조를 사람이 읽고 모델이 이어받을 수 있는 표 구조로 바꾸는 과정을 설명했습니다.

Part 3 전체의 권장 흐름은 다음 9개 Chapter 구조로 요약할 수 있습니다.

이 표가 중요한 이유는 단순히 목차를 다시 보여 주기 위해서가 아닙니다. 독자가 `데이터 모델링`을 하나의 기술 이름이 아니라, 문제를 표현 가능한 구조로 바꾸는 여러 판단의 연쇄로 기억하게 하기 위해서입니다.

## 이 Part의 핵심 흐름

- 데이터 모델링의 목표와 범위를 먼저 고정한다.
- 데이터 모델링을 어떤 순서로 진행할지 먼저 고정한다.
- 저장된 기록이 곧바로 데이터셋이 아니라는 점을 확인한다.
- 한 행과 한 샘플의 뜻을 먼저 정한다.
- 원시 로그를 요약 표와 집계 표로 다시 묶는다.
- 특징과 중간 표현을 설계한다.
- 최근 구간과 기준선을 비교하는 구조를 만든다.
- 표본 수와 반복성을 보고 해석 경계를 두고, 보수적 문장을 구조화된 운영 출력으로 옮길 준비를 한다.
- 비교 리포트와 예측 문제를 구분한다.
- Part 4와 Part 5로 넘길 입력을 표 벡터로 접을지, 시계열 묶음으로 남길지까지 정리한다.
- 뒤 Part로 넘기기 전에 입력/결과 구분, 누수 방지, 운영 시점 재현성, 예측 시간축만 최소한으로 닫아 둔다.

이 마지막 줄을 조금 더 풀어 쓰면, Part 4와 Part 5로 넘기는 것은 `아무 표나`가 아닙니다. 샘플 단위가 이미 고정되어 있고, 입력으로 줄 특징과 나중에 맞히고 싶은 결과 후보가 구분되어 있으며, 아직 비교 리포트로 남겨 두어야 할 범위도 함께 정리된 구조를 넘깁니다. 또한 같은 샘플을 Part 4 쪽의 한 줄 특징 벡터로 접을지, Part 5 쪽의 시간 순서가 남은 시계열 묶음으로 남길지도 함께 정해 둡니다. 여기서 Part 3의 마지막 확인은 가능한 한 짧아야 합니다. 결과 뒤 단서가 특징에 섞이지 않았는지, 학습 때 만든 특징을 운영 시점에도 같은 규칙으로 다시 만들 수 있는지, 어디까지의 정보를 보고 언제의 결과를 맞히는지 정도만 닫아 두고, 시간 순서 분할, 개체 분리, proxy target, ranking 같은 세부 규칙은 뒤 Part에서 다시 중심 설명으로 다룹니다.

## 오해하기 쉬운 지점

- 눈앞의 한 행이 곧 샘플 1건이라고 생각하는 것
- 원시 로그가 이미 완성된 데이터셋이라고 생각하는 것
- 샘플 단위만 맞으면 전체 운영 상황도 자동으로 대표된다고 생각하는 것
- 원시 로그와 요약 표를 같은 층위의 표처럼 읽는 것
- 일부 값 누락과 샘플 경계 붕괴를 같은 빈칸처럼 읽는 것
- 기준선 이탈을 바로 원인 확정으로 읽는 것
- 모든 운영 문제를 곧바로 분류 문제로 만들 수 있다고 생각하는 것
- 경고를 자동 진단 확정처럼 읽는 것
- 결과 뒤 단서나 미래 정보를 특징(feature)으로 함께 넘겨도 된다고 생각하는 것
- 학습용 표에 있는 특징은 운영 시점에도 항상 같은 방식으로 다시 만들 수 있다고 생각하는 것
- target 이름만 정하면 예측 문제 정의가 끝났다고 생각하는 것
- 예측값 하나가 실제로 무엇을 바꾸는지 정하지 않아도 된다고 생각하는 것
- 보수적 해석 문장을 바로 운영 열이나 최종 진단으로 읽는 것
- 모델이 낸 점수와 실제 검토·보류 규칙이 같은 것이라고 생각하는 것
- 같은 샘플을 표 벡터로 넘길지 시계열 묶음으로 넘길지를 정하지 않아도 뒤 Part를 읽을 수 있다고 생각하는 것
- 특징 표의 숫자 크기만 보면 열의 역할도 함께 읽힌다고 생각하는 것
- 같은 열 이름이면 같은 특징 뜻도 그대로 유지된다고 생각하는 것
- 여러 비교 열을 묶기 전에 차이값 하나로 바로 검토 우선순위를 정해도 된다고 생각하는 것
- 비교 리포트, 검토 후보 큐, 목표 라벨 후보 표가 달라지면 같은 사건 추적 기준도 없어져도 된다고 생각하는 것
- 목표 라벨 후보 열이 있으면 그 의미도 이미 안정적일 것이라고 생각하는 것
- 목표 라벨 후보 열이 있으면 그 값도 운영 시점에 바로 확정되어 있을 것이라고 생각하는 것
- 목표 기간을 다 보지 못한 0도 닫힌 음성 라벨과 같다고 생각하는 것
- 여러 후속 사건을 하나의 target 열에 접어 넣었는데도 어떤 규칙으로 접었는지는 안 적어도 된다고 생각하는 것
- 여러 target 후보가 보여도 무엇을 먼저 대표 문제로 세웠는지는 안 적어도 된다고 생각하는 것
- 겹치는 창이 많아져 샘플 수가 늘면 실제 사건 수도 그만큼 늘었다고 생각하는 것
- 같은 target 이름을 계속 쓰고 있으니 판정 기준도 같은 뜻으로 유지되었을 것이라고 생각하는 것
- 지금 학습하는 target 점수가 좋으면 실제로 알고 싶은 목표도 바로 잘 맞히고 있다고 생각하는 것
- 확정 라벨이 있는 사례 집합을 전체 사건 집합처럼 읽어도 된다고 생각하는 것
- 현재의 검토 규칙이나 조치가 이후 결과와 로그를 바꾸지 않았을 것이라고 자동으로 생각하는 것
- 같은 target이면 오탐과 미탐도 같은 무게의 실수라고 자동으로 생각하는 것
- 점수의 순서가 쓸 만하면 숫자 자체도 곧바로 확률처럼 믿어도 된다고 생각하는 것
- binary target이면 실제 행동도 자동으로 두 갈래뿐일 것이라고 생각하는 것
- 범주가 여러 개 보이면 자동으로 multiclass라고 생각하는 것
- 숫자 target이 보이면 바로 임계값으로 잘라 class 문제로 바꿔도 된다고 생각하는 것
- 상위 몇 건 선별이 핵심인데도 그냥 분류 점수 하나로만 읽으면 충분하다고 생각하는 것

## 다음 Part로 넘어가기 전 질문

- 지금 한 행은 무엇을 뜻하는가
- 이 요약값은 어떤 질문에 답하기 위해 남겼는가
- 지금 표가 많이 본 조건과 거의 못 본 조건은 무엇인가
- 값이 비거나 구간이 빠진 샘플을 여전히 같은 비교 단위로 둘 수 있는가
- 어떤 라벨은 만들 수 있고 어떤 라벨은 아직 만들 수 없는가
- 비교 리포트로 남겨야 할 문제를 억지로 예측 문제로 바꾸고 있지는 않은가
- 특징 열이 예측 시점 이전 정보인지, 결과 뒤 단서가 섞이지 않았는가
- 학습 때 만든 특징을 실제 운영 시점에도 같은 규칙으로 다시 만들 수 있는가
- 어디까지의 정보를 보고 언제의 결과를 얼마 뒤까지 맞히는지 한 줄로 쓸 수 있는가
- 예측 1회가 어떤 단위에 대해 어떤 행동 하나를 결정하는지 쓸 수 있는가
- 보수적 해석 문장이 어떤 구조화된 운영 출력으로 바뀌는지 적을 수 있는가
- 모델 출력값과 실제 판단 규칙을 따로 적을 수 있는가
- 같은 샘플을 한 줄 특징 벡터로 접을지, 시간 순서가 남은 입력 묶음으로 남길지 적을 수 있는가
- 특징 열마다 단위와 구조 역할을 따로 적을 수 있는가
- 같은 열 이름이라도 단위, 버전, 계산 규칙 차이를 따로 적을 수 있는가
- 여러 비교 열을 변화 크기, 반복성, 해석 신뢰도, 운영 중요도로 다시 묶을 수 있는가
- 서로 다른 산출물 사이에서 같은 사건을 무엇으로 계속 추적하는지 적을 수 있는가
- 현재 목표 라벨 후보가 자주 갈리는 사례와 기준 변경 시점을 적을 수 있는가
- 현재 목표 라벨 후보가 언제 정답으로 닫히는지와 임시 상태를 적을 수 있는가
- 현재 목표 라벨 후보에서 0의 닫힘 조건과 미완료 상태를 적을 수 있는가
- 현재 목표 라벨 후보가 any/first/worst/count 중 어떤 규칙으로 접힌 것인지 적을 수 있는가
- 현재 여러 후보 중 무엇을 대표 target으로 먼저 세웠는지 적을 수 있는가
- 현재 시계열 입력에서 창 길이, stride, 원천 사건 수 대비 창 수를 적을 수 있는가
- 현재 target 후보의 기준 변경 시점과 정의 버전을 적을 수 있는가
- 현재 target이 실제 목표 자체인지, 아니면 대신 쓰는 대리 target인지 적을 수 있는가
- 현재 확정 라벨이 어떤 검토 경로를 거쳐 붙었는지 적을 수 있는가
- 현재 출력이나 조치가 이후 데이터와 라벨을 바꿀 수 있는지 적을 수 있는가
- 현재 문제에서 어떤 오류가 더 아픈지 적을 수 있는가
- 현재 점수를 순위용으로 쓰는지, 확률처럼 읽는지 적을 수 있는가
- 현재 binary target이 실제로 몇 갈래 행동으로 연결되는지 적을 수 있는가
- 현재 정답이 정확히 하나인지, 여러 라벨이 동시에 가능한지 적을 수 있는가
- 현재 숫자 target이 원래 연속값을 맞히는 문제인지 적을 수 있는가
- 현재 실제 목표가 상위 몇 건 선별이나 순서 최적화인지 적을 수 있는가
- 목표 라벨 후보의 비율과 편중을 한 줄로 적을 수 있는가
- 이 문제가 random split보다 time split을 먼저 요구하는지 적을 수 있는가
- 이 문제가 group split을 먼저 요구하는지 적을 수 있는가

이 질문들에 답할 수 있다면, 다음 Part의 머신러닝 설명은 `이미 정리된 표 구조 위에 학습 구조를 얹는 단계`로 읽힙니다. 반대로 이 질문들에 답하지 못하면, 학습/검증/평가 분할(train/validation/test)이나 평가(evaluation) 지표도 표면적인 절차처럼 보이기 쉽습니다. 다시 말해 Part 3의 목적은 Part 4를 읽기 전에 데이터 과학의 입력 구조를 먼저 이해하게 만드는 데 있습니다.

다음 Part에서는 이 구조 위에서 실제로 모델이 무엇을 학습하는지, 왜 학습/검증/평가 분할을 두는지, 점수와 일반화를 어떻게 읽어야 하는지 설명합니다. 즉 Part 4는 Part 3의 결과를 받아 `표 데이터 중심 데이터 과학 절차`를 본격적으로 읽는 단계입니다.

Part 5로 넘어갈 때도 같은 전제가 이어집니다. 딥러닝은 특징을 자동으로 더 학습할 수 있지만, 무엇을 한 입력 구간으로 볼지, 어떤 결과를 맞히고 싶은지, 원시 시계열과 요약 표현 중 무엇을 넘길지는 여전히 먼저 정해져 있어야 합니다. 같은 샘플이라도 Part 4에서는 한 줄 특징 벡터로, Part 5에서는 시간 순서가 남은 입력 묶음으로 갈라질 수 있다는 점도 이 단계에서 닫아 두어야 합니다. 따라서 Part 3의 마무리는 Part 4의 입력 정의이면서, 동시에 Part 5의 입력 구조 정의이기도 합니다. Part 5도 결국 시계열과 표현 학습으로 확장된 데이터 과학 판단 위에서 읽히므로, Part 3은 두 뒤 Part를 위한 공통 기초로 남아야 합니다.
