# Part 3 마무리

> Section ID: `P3-summary`
> Version: `v2026.09.20`

Part 3에서 다룬 [데이터 모델링](../../reference/concept-glossary-parts/03-digeut.md#data-modeling)은 저장된 기록을 어떤 질문에 답하는 입력과 결과로 표현할지 정하는 일입니다. 원천 기록도 데이터셋이지만, 열이 있다는 사실만으로 비교나 학습에 적합해지지는 않습니다. 기록의 뜻과 범위를 확인하고, 무엇을 한 샘플로 볼지와 어떤 정보를 남길지 선택해야 합니다.

자동 동작의 센서 기록을 한 줄로 요약하면 모델이 볼 정보도 달라집니다. 평균은 전체 수준을 보여 주지만 순서를 지웁니다. 최근 값과 기준선의 차이는 변화를 보여 주지만 그 원인을 확정하지 않습니다. 검토 요청을 정답으로 쓰면 모델이 배우는 것도 우선 검토 요청이며, 실제 고장과 같다고 볼 수 없습니다.

## 기록에서 질문까지 이어지는 선택

| 선택 | 다시 확인할 질문 | 함께 남길 근거 |
| --- | --- | --- |
| 기록의 의미 | 값의 단위, 측정 조건, 한 행이 가리키는 것은 무엇인가? | 원기록 ID, 장비·동작·시간, 단위와 조건 |
| 범위와 품질 | 어느 기간·대상을 보았고 무엇이 빠졌는가? | 관측 범위, 누락·중복·이상 기록의 처리와 제외 사유 |
| 샘플 경계 | 동작 한 번인가, 여러 동작을 묶은 구간인가? | 시작·종료 규칙과 원기록 연결 |
| 표현 | 어떤 특징을 계산했고 어떤 순서·세부값이 사라졌는가? | 계산법·단위·입력 창, 보존한 원자료 |
| 비교와 해석 | 무엇과 비교했으며 관측 차이로 어디까지 말할 수 있는가? | 기준선 기간·조건·버전, 건수, 확인되지 않은 원인 |
| 목표와 시간 | 변화 설명, 검토 선택, 미래 결과 예측 중 무엇이 필요한가? | 산출물, 정책, 결과 정의·관측 기간·확정 상태 |

이 선택들은 무조건 예측 모델로 올라가는 단계가 아닙니다. 비교 리포트나 검토 큐만으로 목적을 이룰 수도 있습니다. 모델이 필요한 경우에는 예측 당시 쓸 수 있는 입력과 이후 확인한 결과를 분리하고, 적용할 대상에 맞추어 평가 범위를 정합니다.

## 한 장의 설계 메모로 검토 10건을 고른다

연습: “최근 완료 동작 중 먼저 검토할 최대 10건을 고른다”는 질문으로 아래 메모를 작성해 보세요. 특징 두 개는 선택 이유·계산법·단위·해석 한계까지 적습니다. 검토를 배정한 것과 실제 검토를 완료한 것은 구분합니다.

| 메모 항목 | 작성할 내용 |
| --- | --- |
| 기록과 범위 | 동작 ID, 시작·종료 시각, 측정 단위·운전 조건, 후보 기간과 전체 동작 목록 |
| 품질과 누락 | 누락·중복 여부와 처리 근거. 계산할 수 없는 동작도 ID와 제외 사유를 보존 |
| 샘플과 표현 | 동작 한 번을 한 후보로 정의. 특징 두 개와 요약으로 잃는 정보, 원자료 연결 |
| 비교 기준 | 같은 조건의 기준선 기간·버전과 특징 정의. 기준선에 비교 대상이나 미래 자료가 섞였는지 확인 |
| 검토 정책 | 어떤 값으로 정렬할지, 동점 처리, 최대 10건의 선택 범위, 미선택 사유 |
| 출력과 한계 | 순위·특징·근거·선택 상태를 기록하고 실제 검토 결과는 별도 열로 연결. 고장 원인이나 확률은 미확인 |

계산 예시로, 한 동작에서 같은 간격으로 측정한 유량이 시간순으로 `2.5, 2.7, 2.1, 2.3 L/min`이라고 합시다. 네 측정은 누락 없이 같은 조건에서 얻었다는 교육용 가정입니다. 앞 두 값을 전반, 뒤 두 값을 후반으로 정합니다.

| 선택한 특징 | 계산과 값 | 선택 이유와 한계 |
| --- | --- | --- |
| 동작 평균 유량 | `(2.5 + 2.7 + 2.1 + 2.3) / 4 = 2.4 L/min` | 전체 수준을 비교하려고 선택. 순서와 순간 변동은 사라짐 |
| 후반−전반 평균 차이 | `(2.1 + 2.3) / 2 − (2.5 + 2.7) / 2 = 2.2 − 2.6 = -0.4 L/min` | 동작 안의 앞뒤 차이를 보려고 선택. 변화의 정확한 시각·원인과 시간당 변화율은 알려 주지 않음 |

같은 조건·계산 정의의 기준선 평균 유량이 2.8 L/min이라면 이 동작의 평균 차이는 `2.4 − 2.8 = -0.4 L/min`입니다. 앞 표의 후반−전반도 -0.4이지만 비교 대상은 다릅니다. 하나는 동작 안의 두 구간, 다른 하나는 이 동작과 기준선입니다. 숫자가 같다고 같은 특징이 아닙니다.

가능한 해설 하나는 “기준선 평균과의 차이의 절댓값 내림차순, 동점은 동작 ID 오름차순으로 최대 10건 배정”입니다. 이 규칙에서는 후반−전반 차이를 설명 근거로 남기되 정렬에는 쓰지 않습니다. 계산 불가 동작과 용량 때문에 대기하는 동작을 구분하고, 둘 다 정상으로 바꾸지 않습니다. 이 예의 숫자와 규칙은 교육용이며 실제 안전 기준이 아닙니다.

## 질문을 다음 7일 고장 예측으로 바꾸면

검토 큐는 비교 규칙으로 만들 수 있지만, 고장 예측을 학습하려면 고장 결과의 정의와 확정 근거가 추가로 필요합니다. 위 큐에서 선택된 기록만 모아 정답표를 만들면 미선택 대상의 결과를 확인하지 못할 수 있습니다.

| 추가할 항목 | 메모에 적을 최소 내용 |
| --- | --- |
| 예측 대상과 시점 | 장비 ID와 예측 시점의 쌍. 동작 후보 단위에서 장비·시점 단위로 바뀌는지 명시 |
| 실제 사용 가능한 입력 | 각 특징의 원자료 도착·계산 완료 시각. 예측 뒤 도착 값과 미래 기준선 제외 |
| 결과 정의와 기간 | 예: `failure-v1`, 2026-09-01 10:00 KST 이상부터 9월 8일 10:00 KST 미만까지 고장 여부 |
| 확정과 미확정 | 기간 내 고장 확인은 1, 전체 추적·기록 확인 후 고장 없음은 0. 미완료·확인 대기는 별도 상태 |
| 평가와 남은 확인 | 기존 장비의 미래인지 새 장비인지, 확인된 결과 범위, 조치 이력, 오류 비용과 검토 용량 |

`failure-v1`의 구체적인 정의와 입력 예시는 [P3-9.7](chapter-09/section-07.md), 미확정 처리와 확인 시각은 [P3-9.10](chapter-09/section-10.md), 인계 메모는 [P3-9.13](chapter-09/section-13.md)에서 다시 확인할 수 있습니다. 검토 필요나 규칙 충족을 실제 고장으로 대체하지 않고, 미확정 결과를 0으로 채우지 않는 것이 두 질문을 구분하는 핵심입니다.

## 문서에서도 같은 질문을 적용한다

짧은 연습: 문서의 문단 하나를 샘플로 삼아 “이 문단에 질문의 답이 있는가”를 판단하려고 합니다. 본문에서 한 문장만 남기면 무엇이 사라지며, 어떤 원기록을 함께 남겨야 할까요?

해설: 같은 문장이라도 제목과 앞뒤 문단에 따라 대상이나 조건이 달라질 수 있습니다. 문서 ID·버전·문단 위치와 필요한 문맥을 연결하고, 수집에서 빠진 페이지나 읽지 못한 부분을 표시합니다. 읽지 못한 부분을 “답이 없음”으로 바꾸지 않습니다. 센서 평균이 순서를 지우듯 문장 추출도 문맥을 줄이므로, 질문에 필요한 정보가 남았는지 확인합니다.

## Part 4에 가져갈 것

Part 4는 이렇게 정한 입력과 결과에서 모델이 무엇을 배우고 어떻게 평가되는지 다룹니다. 넘길 것은 데이터 파일, 샘플·특징·결과 정의, 원기록과 버전의 연결, 당시 가용성, 비교·선택 규칙, 아직 검증하지 못한 항목입니다. 모든 질문을 해결한 척하기보다 확인한 근거와 남은 확인을 나누어 적어야 다음 학습이 현재 자료의 한계를 이어받을 수 있습니다.

## 체크리스트

- 한 샘플을 원기록까지 추적하고, 관측 범위·누락·제외 사유를 설명할 수 있는가?
- 특징 두 개의 계산·단위·선택 이유와 요약으로 잃은 정보를 설명할 수 있는가?
- 같은 -0.4라도 동작 안의 차이와 기준선 차이를 구분할 수 있는가?
- 검토 선택과 미래 고장 예측에 필요한 결과·시점·평가 조건의 차이를 적을 수 있는가?
