# P3-4.5 지금 모은 샘플은 전체 운영 상황을 얼마나 대표하는가

> Section ID: `P3-4.5`
> Version: `v2026.07.07`

샘플 단위를 동작 1회나 최근 구간 1개처럼 정하고 나면, 한 번 더 놓치기 쉬운 질문이 남습니다. `지금 모은 샘플이 전체 운영 상황을 얼마나 대표하는가?` 표가 잘 정리되어 있어도, 그 표가 특정 공정 모드나 특정 기간, 특정 장비 상태에서만 모인 사례라면 뒤에서 읽게 될 평가(evaluation)와 일반화(generalization)는 쉽게 흔들립니다.

샘플 단위를 잘 정한 것과, 그 샘플 묶음이 전체 상황을 고르게 대표하는 것은 같은 말이 아닙니다.

## 왜 이 질문이 Part 3에 필요한가

대표성 문제를 너무 늦게 보면 보통 뒤 Part에서만 증상을 보게 됩니다.

| 겉으로 보이는 상태 | Part 3에서 먼저 물어야 하는 질문 |
| --- | --- |
| 샘플 단위는 잘 정리되었다 | 어떤 운영 조건에서 모인 샘플인가 |
| 특징과 라벨 후보도 있다 | 특정 기간이나 특정 모드에만 몰려 있지 않은가 |
| 표 건수도 충분해 보인다 | 전체 운영 장면을 고르게 덮고 있는가 |

즉 `샘플 한 건의 정의`와 `샘플 묶음의 대표성`은 다른 문제입니다.

## 대표성이 흔들리는 대표 장면

아래처럼 같은 동작 1회 샘플이어도, 어떤 구간에서 모였는지에 따라 대표성은 달라질 수 있습니다.

| 지금 모인 샘플 상태 | 왜 대표성이 약해질 수 있는가 |
| --- | --- |
| 낮 시간대 정상 운전만 많다 | 야간, 고부하, 전환 구간을 거의 못 본다 |
| 유지보수 직후 구간이 대부분이다 | 평소 장기 운영 상태를 덜 담는다 |
| 특정 장비 한 대에서만 많이 모였다 | 장비 간 차이를 놓칠 수 있다 |
| 한 달 중 한 주에만 집중됐다 | 계절성, 주기 변화, 정책 변화를 놓칠 수 있다 |

즉 샘플 수가 많아도, 덮는 조건이 좁으면 대표성은 여전히 약할 수 있습니다.

## 먼저 적어 두면 좋은 네 가지

Part 3에서는 아직 엄밀한 표본추출 이론보다, 아래 네 가지를 먼저 메모하는 편이 더 중요합니다.

| 먼저 적을 것 | 질문으로 바꾸면 |
| --- | --- |
| 시간 범위 | 어느 기간의 샘플인가 |
| 운영 모드 범위 | 어떤 조건과 상태에서 모인 샘플인가 |
| 장비/개체 범위 | 어느 설비, 어느 개체에서 모인 샘플인가 |
| 부족한 구간 | 거의 보지 못한 조건이나 모드는 무엇인가 |

이 메모는 뒤에서 일반화를 증명하기 위한 것이 아니라, 지금 표가 무엇을 대표하고 무엇을 아직 대표하지 못하는지 먼저 드러내기 위한 것입니다.

## 작은 예시로 보기

| event_id | shift | load_mode | machine_id | maintenance_phase |
| --- | --- | --- | --- | --- |
| A | day | normal | M1 | stable |
| B | day | normal | M1 | stable |
| C | day | high | M1 | stable |
| D | day | normal | M2 | stable |
| E | night | normal | M1 | stable |
| F | day | normal | M1 | after-maintenance |

이 표는 얼핏 다양한 것처럼 보일 수 있습니다. 하지만 조금만 보면 편중이 드러납니다.

1. `day`가 대부분입니다.
2. `M1`이 대부분입니다.
3. `high` 부하는 한 건뿐입니다.
4. `after-maintenance`는 한 건뿐입니다.

즉 샘플 단위는 모두 `동작 1회`로 맞더라도, 전체 운영 범위를 고르게 대표한다고 보기는 어렵습니다.

## 왜 이 문제가 샘플 단위 다음에 와야 하는가

대표성 문제는 샘플 단위가 먼저 정해져 있어야 읽을 수 있습니다. 한 행이 시점 기록인지 동작 1회인지 아직 모호하면, `야간 동작 1회가 몇 건 있는가`, `고부하 조건 샘플이 몇 건 있는가` 같은 질문도 제대로 세기 어렵기 때문입니다.

즉 순서는 다음과 같습니다.

1. 먼저 무엇을 샘플 1건으로 볼지 정한다.
2. 그 다음 그 샘플들이 어떤 조건 범위를 덮는지 본다.

그래서 이 절은 Chapter 4의 끝에 두는 편이 자연스럽습니다.

이 메모를 남겨 두어야 뒤에서 평가 점수를 읽을 때도 `어떤 조건 범위에서 얻은 결과인가`를 함께 볼 수 있고, 시계열 입력으로 넘어가더라도 `어떤 운영 조건을 거의 보지 못했는가`를 놓치지 않게 됩니다. 즉 대표성 문제는 뒤 Part의 평가 기술보다 먼저, 현재 샘플 묶음이 무엇을 덮고 무엇을 놓쳤는지 적어 두는 문제에 가깝습니다.

## 작은 코드 예시

```python
import pandas as pd

samples = pd.DataFrame(
    [
        {"event_id": "A", "shift": "day", "load_mode": "normal", "machine_id": "M1"},
        {"event_id": "B", "shift": "day", "load_mode": "normal", "machine_id": "M1"},
        {"event_id": "C", "shift": "day", "load_mode": "high", "machine_id": "M1"},
        {"event_id": "D", "shift": "day", "load_mode": "normal", "machine_id": "M2"},
        {"event_id": "E", "shift": "night", "load_mode": "normal", "machine_id": "M1"},
        {"event_id": "F", "shift": "day", "load_mode": "normal", "machine_id": "M1"},
    ]
)

print(samples["shift"].value_counts())
print(samples["load_mode"].value_counts())
print(samples["machine_id"].value_counts())
```

예상 출력:

```text
shift
day      5
night    1
Name: count, dtype: int64
load_mode
normal    5
high      1
Name: count, dtype: int64
machine_id
M1    5
M2    1
Name: count, dtype: int64
```

이 예시에서 중요한 것은 분류 기법이 아니라, `현재 표가 무엇을 많이 보고 무엇을 거의 못 보고 있는가`를 한눈에 드러내는 일입니다.

## 인계 직전의 마지막 판정

Part 4와 Part 5로 넘기기 전에는 아래처럼 짧게 판정하면 좋습니다.

| 점검 질문 | 예라고 답할 수 있어야 하는 것 |
| --- | --- |
| 이 표가 모은 시간·모드·장비 범위를 말할 수 있는가 | 현재 대표하는 범위를 설명할 수 있다 |
| 거의 보지 못한 조건을 적어 둘 수 있는가 | 대표하지 못한 공백을 드러낼 수 있다 |
| 평가 점수를 읽을 때 이 대표성 범위를 함께 떠올릴 수 있는가 | 뒤 Part에서 과한 일반화를 줄일 수 있다 |

이 세 줄이 있어야 샘플 표는 단순히 `정리된 표`가 아니라, `어떤 운영 범위를 대표하는지 메모가 붙은 표`로 남습니다.

## 한 문장으로 묶기

이 절에서 붙잡아야 할 문장은 다음과 같습니다.

`샘플 단위를 잘 정했다고 해서 그 샘플 묶음이 전체 운영 상황을 자동으로 대표하는 것은 아니므로, Part 3에서는 시간·모드·장비 범위와 남은 공백을 함께 적어 두어야 한다.`

## 짧은 점검

- 왜 샘플 단위가 올바르다는 사실만으로 대표성까지 보장되지는 않는지 설명할 수 있는가
- 특정 기간이나 특정 장비에만 몰린 샘플이 왜 뒤 Part의 일반화 해석을 흔들 수 있는지 말할 수 있는가
- 현재 표가 많이 본 조건과 거의 못 본 조건을 한 줄씩 적을 수 있는가

## 언제 이 관점을 먼저 떠올려야 하는가

- 샘플 표가 잘 정리되어 보여도, 실제로 어떤 운영 범위를 덮는지는 아직 불분명할 때 이 절을 떠올립니다.
- Part 4의 평가 점수를 전체 운영 성능처럼 읽기 전에, 지금 표가 무엇을 대표하고 무엇을 대표하지 못하는지 다시 확인해야 할 때 이 절로 돌아옵니다.
- Part 5에서 특정 패턴을 잘 잡는 것처럼 보여도 입력이 특정 모드에만 몰린 것은 아닌지 점검할 때 이 절이 기준이 됩니다.
