# 3.17 Part 4가 이어받을 특징과 목표 라벨의 전제

> Section ID: `P3-9.1`
> Version: `v2026.07.05`

Part 3의 마지막 단계는 이제 Part 4로 무엇을 넘길 수 있는지 정리하는 것입니다. 머신러닝은 데이터를 자동으로 이해하는 마법 단계가 아닙니다. 오히려 머신러닝 Part는 이미 정리된 샘플 단위, 특징(feature) 후보, 목표 라벨(target) 후보를 이어받아 학습 구조로 바꾸는 단계에 가깝습니다.

따라서 Part 4가 시작되기 전에 적어도 다음 질문에는 답할 수 있어야 합니다.

- 한 행은 무엇을 뜻하는가
- 특징(feature)으로 남길 열은 무엇인가
- 목표 라벨(target) 후보는 실제로 무엇인가
- 비교 리포트로 남길 문제와 예측 문제를 구분했는가

예를 들어 동작 1회 요약 표가 있다면 총 시간, 구간 평균, 기울기, 변동성, 세그먼트 표현은 특징 후보가 될 수 있습니다. 반면 `검토 필요`, `정상/주의`, 특정 결과 상태 같은 값은 목표 라벨 후보가 될 수 있습니다. 하지만 이 목표 라벨 후보가 실제로 충분한 라벨인지, 운영상 일관되게 붙는 값인지는 다시 따져야 합니다.

여기서 중요한 것은 특징과 목표 라벨을 기계적으로 나누는 것이 아니라, 그 구분이 어떤 질문을 위해 필요한지 이해하는 일입니다. 특징은 `입력으로 주고 싶은 정보`이고, 목표 라벨은 `나중에 맞히고 싶은 결과`입니다. 이 설명이 서야 독자는 Part 4에서 `X`와 `y`를 나누는 이유를 단순 문법이 아니라 문제 설정의 결과로 읽을 수 있습니다.

이 절에서 중요한 것은 특징과 목표 라벨에 이름만 붙이는 것이 아니라, 왜 그 구분이 가능한지 설명하는 것입니다. `이 열은 설명 변수로 쓸 수 있다`, `이 열은 나중에 맞히고 싶은 결과다`라는 구분이 서지 않으면 Part 4의 모델 설명도 공중에 뜹니다.

예를 들어 다음처럼 같은 표 안에서도 역할이 다릅니다.

| 열 이름 | 역할 후보 |
| --- | --- |
| `mid_flow_mean` | 특징(feature) |
| `late_drop_rate` | 특징(feature) |
| `flow_variability` | 특징(feature) |
| `review_needed` | 목표 라벨(target) 후보 |
| `window_start` | 식별 또는 운영 문맥 |

```python
import pandas as pd

dataset = pd.DataFrame(
    [
        {"event_id": "A", "mid_flow_mean": 2.3, "late_drop_rate": -0.8, "flow_variability": 0.22, "review_needed": 1},
        {"event_id": "B", "mid_flow_mean": 2.5, "late_drop_rate": -0.2, "flow_variability": 0.07, "review_needed": 0},
    ]
)

feature_cols = ["mid_flow_mean", "late_drop_rate", "flow_variability"]
target_col = "review_needed"

print("X shape:", dataset[feature_cols].shape)
print("y shape:", dataset[target_col].shape)
print(dataset[feature_cols])
print(dataset[target_col])
```

예상 출력:

```text
X shape: (2, 3)
y shape: (2,)
   mid_flow_mean  late_drop_rate  flow_variability
0            2.3            -0.8              0.22
1            2.5            -0.2              0.07
0    1
1    0
Name: review_needed, dtype: int64
```

이 출력은 Part 4가 이어받는 기본 형태를 그대로 보여 줍니다. 어떤 열은 입력 `X`로 가고, 어떤 열은 출력 `y`로 갑니다. 이 구분이 선명해야 뒤에서 학습/평가 분할(split), 학습, 평가를 설명할 수 있습니다.

초심자에게는 여기서 `바로 넘기는 열`과 `아직 넘기지 않는 열`을 한 번 더 나눠 보는 것이 도움이 됩니다.

| 열 종류 | 지금 바로 Part 4로 넘기는가 | 이유 |
| --- | --- | --- |
| 설명 가능한 특징 열 | 보통 넘긴다 | 입력으로 쓸 정보이기 때문 |
| 비교적 안정된 목표 라벨 후보 | 조건부로 넘긴다 | 실제로 맞히고 싶은 결과인지 다시 확인해야 하기 때문 |
| 식별 열 | 보통 바로 넘기지 않는다 | 샘플을 구분하는 데는 필요하지만 모델 입력 의미가 약하기 때문 |
| 운영 메모성 문장 | 넘기지 않는다 | 설명용 문장이지 학습 입력이 아니기 때문 |

Part 4로 넘기기 직전에는 실제 인계 표를 한 번 더 짧게 확인하는 편이 좋습니다.

| 확인 대상 | 현재 예시에서 무엇을 보는가 | Part 4로 넘길 수 있는가 |
| --- | --- | --- |
| 샘플 단위 | `event_id` 한 건이 동작 1회인가 | 예 |
| 특징 열 | `mid_flow_mean`, `late_drop_rate`, `flow_variability` | 예 |
| 목표 라벨 후보 | `review_needed` | 조건부 예 |
| 식별/운영 문맥 열 | `event_id` | 모델 입력에는 직접 쓰지 않음 |

이 표가 중요한 이유는 `무엇이 있느냐`보다 `무엇을 바로 학습 입력으로 쓰고, 무엇은 아직 보류해야 하는가`를 한눈에 보여 주기 때문입니다. 예를 들어 `review_needed`는 목표 라벨 후보로 넘길 수 있지만, 실제로는 라벨 일관성과 운영 정의를 다시 확인해야 합니다. 반면 `event_id`는 샘플을 식별하는 데는 필요하지만, 보통 모델이 그대로 학습할 입력 열로 쓰지는 않습니다.

Part 4가 이어받기 전에 마지막으로 확인해야 할 것은 다음과 같습니다.

- 이 열이 특징(feature)인 이유를 한 문장으로 설명할 수 있는가
- 이 열이 목표 라벨(target) 후보라면 실제로 나중에 알고 싶은 결과인가
- 운영 문맥 열과 식별 열을 특징과 섞어 쓰고 있지 않은가
- 비교 리포트로 남길 문제를 억지로 목표 라벨로 만들고 있지 않은가

이 네 질문은 결국 한 문장으로 다시 묶을 수 있습니다. `지금 이 표에서 모델이 바로 배워도 되는 정보와, 아직 사람 판단으로 남겨 두어야 하는 정보를 구분했는가.` 이 문장이 서야 Part 4의 입력 `X`와 출력 `y` 구분도 문법이 아니라 판단 결과로 읽힙니다.

즉 Part 4가 이어받는 것은 단순한 CSV 파일이 아니라, `샘플 단위가 고정된 표`, `설명 가능한 특징`, `후보 목표 라벨`, `비교 리포트로 남길 범위`까지 정리된 전제입니다. 다음 절에서는 이 전제 위에서 학습/평가 분할(split), 기준 모델(baseline), 평가(evaluation)로 넘어가기 전에 무엇을 다시 점검해야 하는지 정리하겠습니다.
