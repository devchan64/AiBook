# P3-9.13 시간 순서 분할, 개체 분리, 데이터 누출, ranking 문제는 왜 여기서 예고만 하는가

> Section ID: `P3-9.13`
> Version: `v2026.07.07`

여기까지 오면 자연스럽게 다음 질문을 떠올립니다. 시간 순서 분할(time split)은 언제 필요한가, 같은 개체를 train/test 양쪽에 두면 왜 안 되는가, 데이터 누출(data leakage)은 무엇인가, 상위 몇 건 선별은 왜 분류와 다른가. 모두 중요한 질문입니다. 다만 Part 3의 역할은 이 항목들의 이름과 필요성을 잡는 데 있고, 중심 설명 자체는 Part 4 본편에서 다루는 편이 구조상 더 정확합니다.

`이 항목들은 중요하지만, Part 3에서는 문제 구조를 닫는 수준까지만 다루고 평가·학습 본편은 뒤 Part로 넘긴다.`

| 뒤 Part로 넘길 항목 | 지금 여기서 붙잡을 최소 문장 |
| --- | --- |
| time split | 시간 순서가 중요한 문제는 무작위 분할과 다르게 봐야 한다 |
| group split | 같은 개체가 양쪽에 섞이면 과장된 성능이 생길 수 있다 |
| data leakage | 예측 시점 이후 정보가 섞이면 점수가 좋아 보여도 쓸 수 없다 |
| evaluation design | 어떤 지표와 분할이 맞는지는 문제 구조와 연결된다 |
| ranking | 상위 몇 건 선별은 순서 문제가 중심일 수 있다 |
| multiclass / regression | 결과 구조가 0/1 하나가 아닐 수 있다 |

즉 Part 3은 다음 정도까지만 닫아 두면 충분합니다.

- 이 문제가 시간 순서 분할을 먼저 요구하는가
- 같은 개체를 양쪽에 두지 말아야 하는가
- 결과 뒤 정보가 입력에 섞이지 않았는가
- 실제 목표가 0/1 분류보다 순서나 연속값에 더 가까운가

이 이상은 Part 4의 학습·평가 설명에서 중심으로 읽는 편이 더 정확합니다.

## 짧은 점검

- 왜 time split, group split, data leakage를 여기서 이름만 잡고 넘기는지 설명할 수 있는가
- 현재 문제에서 무엇을 Part 4 본편의 평가 설계 질문으로 넘겨야 하는지 적을 수 있는가
- ranking이나 regression이 왜 분류와 다른 문제 구조인지 한 줄로 구분할 수 있는가
