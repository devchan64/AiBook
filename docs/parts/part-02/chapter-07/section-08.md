# P2-7.8 보충학습: 셸 스크립트(shell script), 파이프(pipe), 리다이렉션(redirection), 환경 변수(environment variable) 읽기

> Section ID: `P2-7.8`
> Version: `v2026.07.20`

P2-7.2와 P2-7.6에서는 터미널을 열고 현재 위치를 확인하는 수준까지 다뤘습니다. 그런데 실제 학습 자료를 따라가다 보면 금방 더 낯선 표현을 만납니다.

```bash
python train.py > train.log
cat data.csv | python inspect.py
export OPENAI_API_KEY=...
```

여기서는 `셸 스크립트(shell script)`, `파이프(pipe)`, `리다이렉션(redirection)`, `환경 변수(environment variable)`를 읽는 기본 기준을 설명합니다. 이 보충학습은 실제 문서에서 이런 기호를 만났을 때 어떤 종류의 동작인지 읽는 기준을 정리합니다.

이 보충학습에서는 이 문법을 모두 자유롭게 쓰기보다, 앞으로 문서나 튜토리얼에서 이런 표현을 봤을 때 적어도 `무슨 종류의 동작인지`를 읽을 수 있게 만드는 데 집중합니다.

## 처음엔 이것만 읽으면 됩니다

재실습하거나 튜토리얼을 따라가다 다시 돌아왔을 때는 아래 네 줄부터 먼저 떠올리면 충분합니다.

- `|`는 앞 명령의 결과를 뒤 명령으로 넘기는 연결입니다.
- `>`와 `<`는 입출력 방향을 파일 쪽으로 바꾸는 표기입니다.
- `KEY=...`나 `export ...`는 코드 밖 설정값을 넘기는 환경 변수 장면일 가능성이 큽니다.
- `sudo`, `rm`, 비밀값 노출, 파일 덮어쓰기가 보이면 뜻을 다 알기 전에는 바로 실행하지 않습니다.

즉 이 절을 처음부터 다시 다 읽지 않아도, `연결`, `방향`, `설정값`, `위험 신호` 네 단어를 먼저 붙잡으면 낯선 한 줄을 훨씬 안전하게 읽을 수 있습니다.

| 용어 | 이 절에서 먼저 잡을 뜻 |
| --- | --- |
| 셸 스크립트(shell script) | 터미널 명령 여러 줄을 파일에 묶어 둔 실행 기록입니다. |
| 파이프(pipe) | 앞 명령의 출력을 뒤 명령의 입력으로 넘기는 연결입니다. |
| 리다이렉션(redirection) | 화면이나 파일의 입출력 방향을 바꾸는 표기입니다. |
| 환경 변수(environment variable) | 프로그램이 바깥 실행 환경에서 읽는 설정값입니다. |
| 위험 신호 | 삭제, 권한 상승, 네트워크 호출, 비밀값 노출처럼 먼저 확인할 요소입니다. |

## 처음 읽는 기준: 셸 스크립트(shell script), 파이프(pipe), 리다이렉션(redirection), 환경 변수(environment variable) 읽기

- 셸 스크립트(shell script)를 여러 명령을 묶어 실행하는 텍스트 파일로 설명할 수 있습니다.
- 파이프(pipe)를 한 명령의 출력을 다른 명령의 입력으로 넘기는 연결로 설명할 수 있습니다.
- 리다이렉션(redirection)을 화면 출력을 파일로 보내거나 파일 내용을 입력으로 읽게 하는 방식으로 설명할 수 있습니다.
- 환경 변수(environment variable)를 실행 환경이 공유하는 이름표 붙은 설정값으로 설명할 수 있습니다.
- 낯선 명령을 봤을 때 삭제, 권한 상승, 네트워크 호출, 비밀값 노출 여부를 먼저 점검할 수 있습니다.

## 먼저 붙잡을 네 가지

| 표현 | 먼저 읽을 감각 |
| --- | --- |
| 셸 스크립트 | 명령 여러 개를 한 파일에 적어 두는 방식 |
| 파이프 `|` | 앞 명령 결과를 뒤 명령으로 넘기는 연결 |
| 리다이렉션 `>` `<` | 화면이나 파일의 입출력 방향을 바꾸는 기호 |
| 환경 변수 | 프로그램이 바깥에서 읽는 설정값 |

## 셸 스크립트는 명령을 묶어 두는 파일이다

셸 스크립트(shell script)는 셸에서 실행할 명령들을 텍스트 파일에 차례로 적어 둔 것입니다. 여기서는 `터미널에서 한 줄씩 치던 명령을 파일에 모아 두고 반복 실행할 수 있게 만든 것`으로 이해합니다.

예를 들어 다음처럼 적을 수 있습니다.

```bash
pwd
ls
python hello.py
```

이 파일은 `현재 위치 확인 -> 파일 목록 확인 -> Python 실행`을 묶어 둔 기록처럼 볼 수 있습니다.

셸 스크립트는 `새로운 프로그래밍 언어 전체`보다 `터미널 명령을 여러 줄로 모아 둔 것`으로 읽습니다.

## 파이프는 한 명령의 출력을 다음 명령으로 넘긴다

파이프(pipe)는 `|` 기호로 적습니다. 여기서는 `앞 명령이 화면에 보여 주려던 결과를 뒤 명령이 입력처럼 받아서 이어서 처리한다`는 한 문장으로 읽습니다.

예를 들어 다음 문장은 `python inspect.py`가 앞의 내용을 받아 처리한다는 뜻으로 읽을 수 있습니다.

```bash
cat data.txt | python inspect.py
```

지금은 `cat`이나 `inspect.py`의 세부 동작을 몰라도 됩니다. 핵심은 `|`가 `연결`을 뜻한다는 점입니다.

파이프가 왜 유용한지는 다음 표로 보면 됩니다.

| 장면 | 파이프가 하는 일 |
| --- | --- |
| 긴 출력 중 필요한 줄만 보고 싶다 | 앞 명령 결과를 뒤 명령 필터로 넘긴다 |
| 파일 내용을 다른 프로그램이 바로 읽게 하고 싶다 | 파일 내용을 화면에 찍지 않고 바로 다음 처리로 넘긴다 |
| 여러 단계 처리를 한 줄에 이어 쓰고 싶다 | 명령을 순서대로 연결한다 |

이 단계에서는 파이프를 직접 많이 쓰는 것보다, 문서에서 봤을 때 `아, 결과를 다음 단계로 넘기고 있구나`라고 읽는 일이 더 중요합니다.

## 리다이렉션은 입출력 방향을 바꾼다

리다이렉션(redirection)은 출력이나 입력이 향하는 대상을 바꾸는 것입니다.

가장 먼저 만나는 표기는 보통 다음 두 가지입니다.

| 표기 | 입문 수준에서 읽는 뜻 |
| --- | --- |
| `>` | 화면에 보여 줄 출력을 파일로 보낸다 |
| `<` | 파일 내용을 입력으로 읽는다 |

예를 들어 다음 명령은 화면에 보일 내용을 `train.log` 파일에 저장하는 쪽으로 읽을 수 있습니다.

```bash
python train.py > train.log
```

다음 명령은 `input.txt` 내용을 읽어 프로그램에 넣는 쪽으로 읽을 수 있습니다.

```bash
python read.py < input.txt
```

여기서 중요한 것은 기호 자체를 외우는 것이 아니라 `방향` 감각입니다.

- `>`는 대체로 밖으로 내보낸다
- `<`는 대체로 안으로 읽어 온다

여기서 특히 중요한 경고는 다음입니다.

- 출력 파일을 덮어쓸 수 있다
- 명령이 어디에 결과를 저장하는지 눈으로 확인해야 한다

즉, 리다이렉션이 붙어 있으면 `이 명령은 화면만 보는 것이 아니라 파일도 바꿀 수 있나?`를 먼저 확인하는 편이 안전합니다.

## 환경 변수는 프로그램이 바깥에서 읽는 설정값이다

환경 변수(environment variable)는 실행 환경이 프로그램에 넘겨 주는 이름표 붙은 값입니다. 여기서는 `코드 안에 직접 적지 않고 실행 환경 바깥에서 프로그램이 읽는 설정값`으로 이해합니다.

예를 들어 API 키, 데이터 경로, 모드 선택 같은 값이 환경 변수로 전달될 수 있습니다.

```bash
export OPENAI_API_KEY=...
python app.py
```

이 예시의 핵심은 `python app.py`가 실행될 때 `OPENAI_API_KEY`라는 값을 바깥 환경에서 읽을 수 있다는 점입니다.

Windows PowerShell에서는 표기가 조금 다르게 보일 수 있습니다. 하지만 지금 단계에서는 운영체제별 문법 차이보다 `환경 변수는 코드 본문 밖의 설정값`이라는 개념이 더 중요합니다.

## 왜 이런 표현이 AI 학습 문서에 자주 나오는가

AI 학습 문서와 프로젝트 예제는 파일, 로그, 데이터, 비밀값, 실행 환경을 자주 다룹니다. 그래서 터미널 한 줄 안에서도 다음 일이 자주 함께 일어납니다.

- 파일 읽기
- 결과 저장
- 명령 연결
- 설정값 전달

즉, 파이프와 리다이렉션과 환경 변수는 고급 장식이 아니라, `실행 환경을 다루는 기본 표기`에 가깝습니다.

## 먼저 점검할 체크포인트

낯선 터미널 명령을 봤을 때는 의미를 전부 해석하려 하기보다 다음을 먼저 봅니다.

1. 파일을 지우는 명령이 있는가?
2. 관리자 권한이 필요한가?
3. 네트워크에서 무언가를 내려받는가?
4. API 키나 비밀값을 그대로 드러내는가?
5. 결과를 파일에 덮어쓰는가?

다음 표처럼 읽어도 좋습니다.

| 신호 | 먼저 확인할 질문 |
| --- | --- |
| `sudo` | 관리자 권한이 정말 필요한가? |
| `rm`, `del`, `Remove-Item` | 파일을 지우는 명령인가? |
| `>` | 어떤 파일에 저장하거나 덮어쓰는가? |
| `|` | 앞 결과를 뒤 단계에 넘기고 있는가? |
| `KEY=...`, `TOKEN=...` | 비밀값을 직접 노출하고 있지 않은가? |

## 지금은 무엇을 읽을 수 있어야 하는가

이 보충학습이 끝난 뒤 바로 셸 스크립트를 자유롭게 짤 필요는 없습니다. 지금 필요한 수준은 다음 정도입니다.

- `|`, `>`, `<`를 봤을 때 입출력 방향이 바뀌는 표기라는 점을 안다
- 환경 변수가 코드 밖 설정값이라는 점을 안다
- 셸 스크립트가 명령 묶음이라는 점을 안다
- 위험한 명령을 무심코 복사 실행하지 않도록 먼저 점검한다

## 사례 및 예시

### 사례 1. 튜토리얼 명령 한 줄이 갑자기 위험해 보일 때

한 학습자가 인터넷 튜토리얼에서 `python train.py > train.log`나 `export OPENAI_API_KEY=...` 같은 명령을 봤다고 하겠습니다. 기호가 많아 보여서 전부 외워야 할 새 문법처럼 느껴질 수 있습니다.

사람이 쓰던 기준은 대개 `일단 복사해서 실행해 보자`에 가깝습니다. 하지만 이런 줄에는 출력 저장, 파일 덮어쓰기, 환경 변수 전달, 명령 연결처럼 서로 다른 동작이 한 번에 들어 있을 수 있습니다. 그래서 뜻을 모르고 실행하면 로그 파일을 덮어쓰거나, 비밀값을 그대로 남기거나, 위험한 삭제 명령과 섞인 줄을 따라 실행할 위험이 있습니다.

여기서 목표로 삼는 수준은 `파이프`, `리다이렉션`, `환경 변수`, `셸 스크립트`를 자유롭게 쓰는 단계가 아니라, 적어도 `무슨 종류의 동작인지` 읽는 단계입니다. 즉 `|`는 연결, `>`는 출력 방향 변경, `KEY=...`는 바깥 설정값 전달이라는 감각만 있어도 훨씬 안전하게 읽을 수 있습니다.

확인 가능한 결과는 명령 한 줄을 기능별로 쪼개 읽을 수 있는지입니다. 예를 들어 `python train.py > train.log`를 보고 `학습을 실행하고, 화면 출력 대신 로그 파일에 저장하는구나`라고 설명할 수 있다면, 무심코 복사 실행하는 단계에서 한 걸음 나아간 것입니다.
