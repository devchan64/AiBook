# P5-15.4 Stable Diffusion은 텍스트 조건에서 이미지를 어떻게 복원하는가

> Section ID: `P5-15.4`
> Version: `v2026.08.03`

P5-15.1부터 P5-15.3까지는 생성물이 사용자에게 도착하는 방식, 가능한 결과의 분포, 텍스트에서 실제 출력을 고르는 샘플링을 구분했습니다. 이미지 생성도 생성 모델의 한 사례지만, 텍스트처럼 다음 토큰을 왼쪽에서 오른쪽으로 붙이는 일로 설명하면 핵심을 놓칩니다.

여기서 던지는 질문은 다음과 같습니다.

> 프롬프트가 들어오면 Stable Diffusion은 어떤 중간 상태와 반복 과정을 거쳐 이미지를 만드는가?

이 절은 설치나 제작 요령을 설명하지 않습니다. `텍스트 조건 -> 잠재 노이즈 -> 반복 복원 -> 이미지`라는 최소 계산 흐름을 붙잡고, seed·sampler·steps·LoRA 같은 Part 7의 실습 값을 나중에 어떤 역할로 읽을지 준비합니다.

## 픽셀 그림을 한 번에 그리는 모델이 아니다

Stable Diffusion은 latent diffusion 모델을 text-to-image 생성에 적용한 대표 사례입니다. 여기서 `latent`는 사람이 보는 픽셀 이미지보다 압축된 계산 공간을 뜻합니다. 모델은 보통 이 잠재 공간의 무작위 노이즈에서 출발해, 프롬프트 조건을 참고하며 여러 단계에 걸쳐 노이즈를 줄입니다. 마지막에는 복원된 잠재 표현을 이미지로 되돌립니다.

| 단계 | 최소 역할 | 이 절에서 붙잡을 질문 |
| --- | --- | --- |
| 텍스트 조건 | 프롬프트를 계산 가능한 조건 표현으로 바꾼다 | 무엇을 만들라는 조건인가 |
| 초기 잠재 노이즈 | 이미지가 아직 드러나지 않은 출발 상태다 | 어느 출발점에서 복원을 시작하는가 |
| 반복 복원 | 현재 잠재 표현에서 줄일 노이즈를 여러 번 계산한다 | 조건을 참고하며 무엇을 조금씩 바꾸는가 |
| 이미지 복원 | 마지막 잠재 표현을 사람이 볼 이미지로 바꾼다 | 어떤 결과가 실제 산출물로 나타나는가 |

따라서 프롬프트는 픽셀 배치표가 아닙니다. 프롬프트는 복원 과정이 참고하는 조건이고, 초기 노이즈와 반복 경로도 최종 이미지에 영향을 줍니다.

## 네 부품을 역할로만 구분하기

Stable Diffusion의 구현에는 많은 부품이 있지만, 입문 단계에서는 이름 암기보다 역할 분리가 중요합니다.

| 구성요소 | 맡는 역할 | 오해하지 않을 점 |
| --- | --- | --- |
| text encoder | 프롬프트를 조건 표현으로 바꾼다 | 프롬프트를 완성 이미지를 뜻하는 명령으로 바꾸는 것은 아니다 |
| U-Net | 현재 단계에서 줄일 노이즈를 예측한다 | 한 번의 계산으로 이미지를 완성하지 않는다 |
| scheduler / sampler | 다음 잠재 상태로 이동하는 반복 규칙을 정한다 | 텍스트의 top-k·top-p와 같은 후보 단어 선택기가 아니다 |
| VAE decoder | 복원된 잠재 표현을 픽셀 이미지로 바꾼다 | 이미지 품질의 모든 판단을 혼자 맡지는 않는다 |

텍스트 조건은 보통 cross-attention을 통해 복원 계산에 들어갑니다. 여기서 필요한 이해는 “U-Net이 노이즈만 보고 복원하는 것이 아니라, 프롬프트 조건도 함께 참고한다”는 정도입니다. cross-attention의 수식이나 구현은 이 절의 범위가 아닙니다.

## 같은 프롬프트여도 결과가 달라지는 이유

다음 조건을 생각해 봅시다.

> `stainless mixing tank with side valve and warning beacon, clean technical illustration`

같은 프롬프트를 넣어도 이미지가 하나로 고정되지 않을 수 있습니다. 이때 먼저 나누어 볼 값은 다음과 같습니다.

| 값 | 무엇을 바꾸는가 | 비교할 때 고정하거나 기록할 이유 |
| --- | --- | --- |
| seed | 초기 잠재 노이즈의 출발점 | 같은 출발점인지 구분한다 |
| steps | 노이즈 제거를 반복하는 횟수 | 계산량과 복원 경로를 함께 본다 |
| sampler | 다음 잠재 상태로 이동하는 규칙 | 같은 모델이라도 복원 방식이 달라질 수 있음을 남긴다 |
| guidance | 텍스트 조건을 얼마나 강하게 참고할지의 조절 | 조건 충족과 결과 다양성을 함께 검토한다 |
| base model | 학습된 이미지 패턴의 기반 | LoRA 같은 추가 가중치와 구분한다 |

이 표는 특정 값이 항상 더 좋다는 뜻이 아닙니다. 목적은 결과가 달라졌을 때 “프롬프트가 달라졌나, 출발 노이즈가 달라졌나, 복원 규칙이 달라졌나, 모델 자체가 달라졌나”를 분리하는 것입니다.

## LoRA와 조건 제어는 다른 층이다

LoRA는 base model 전체를 새로 학습하는 대신, 일부 가중치에 덧붙이는 작은 조정값입니다. 특정 인물·스타일·물체와 같은 적응을 만들 때 사용될 수 있습니다. 반면 ControlNet이나 IP-Adapter 같은 조건 제어 경로는 pose, 윤곽, 참조 이미지처럼 텍스트 외의 정보를 복원 과정에 더하는 데 쓰일 수 있습니다.

| 구분 | 먼저 읽을 역할 |
| --- | --- |
| base model | 어떤 이미지 패턴을 기본적으로 복원할 수 있는가 |
| LoRA | base model의 일부 표현을 어떤 대상이나 스타일 쪽으로 조정하는가 |
| ControlNet / IP-Adapter | 텍스트만으로 부족한 구조·참조 조건을 어떻게 더하는가 |

이 구분은 이미지 제작 팁이 아니라 비교 기록의 기준입니다. LoRA weight와 ControlNet 조건을 동시에 바꾸면 어느 변화가 결과 차이를 만들었는지 설명하기 어려워집니다.

## 체크리스트

- Stable Diffusion이 픽셀 이미지를 한 번에 꺼내는 모델이 아니라 잠재 노이즈를 반복 복원하는 흐름임을 설명할 수 있는가?
- 프롬프트, 초기 노이즈, 반복 복원, 이미지 변환의 역할을 구분할 수 있는가?
- text encoder, U-Net, scheduler/sampler, VAE decoder의 역할을 최소 수준에서 구분할 수 있는가?
- 텍스트의 token sampling과 이미지 디퓨전의 sampler를 같은 알고리즘처럼 설명하지 않을 수 있는가?
- seed·steps·sampler·guidance·base model을 바꾸었을 때 무엇이 달라졌는지 기록할 수 있는가?
- LoRA와 텍스트 외 조건 제어 경로를 같은 역할로 묶지 않을 수 있는가?
