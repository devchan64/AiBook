# P5-15.1 생성 모델(generative model)은 무엇을 배우는가

Section ID: `P5-15.1`
Version: `v2026.07.12`

P5-14.2에서는 Transformer가 병렬 처리와 긴 문맥 처리에서 큰 전환점이 되었고, 이 구조가 결국 LLM과 생성형 AI 확산의 기반이 되었다는 점을 보았습니다. 이제 다음 질문이 생깁니다.

그렇다면 생성 모델(generative model)은 분류 모델과 무엇이 다르며, 도대체 무엇을 배우는가?

생성 모델은 입력을 어느 클래스에 넣을지만 배우는 것이 아니라, 데이터가 어떤 패턴으로 나타나는지와 다음에 무엇이 그럴듯하게 이어질지를 함께 학습하려는 모델이다.

분류와 생성의 차이를 다시 짧게 복습해야 할 때는 개념사전의 [생성 모델(generative model)](../../../reference/concept-glossary.md#generative-model) 항목으로 돌아갑니다.

## 이 절의 범위

- 생성 모델은 분류 모델과 무엇이 다른가?
- `데이터 분포(data distribution)를 배운다`는 말은 독자에게 어떻게 설명할 수 있는가?
- 생성은 왜 확률적 출력(probabilistic output)과 자주 연결되는가?
- 이 관점이 LLM과 이미지 생성 모델로 어떻게 이어지는가?

이 절에서 먼저 닫아야 하는 핵심은 `생성 모델은 정답 라벨을 고르는 데서 멈추지 않고, 어떤 출력이 자연스러운지 자체를 배운다`는 점입니다.

이 절은 `후보 분포 학습 축`으로 먼저 고정해 두는 편이 덜 흔들립니다.

즉, 지금 장의 핵심은 `입력을 어느 라벨로 고를까`에서 `가능한 다음 출력 분포를 어떻게 배울까`로 손잡이가 바뀐다는 점입니다.

여기서 먼저 읽는 것은 temperature나 sampling 설정 같은 출력 조절 절차가 아니라, 모델이 어떤 후보 분포 자체를 학습하는가라는 생성 구조입니다.

| 지금 이 절에서 읽는 것 | 바로 다음 절이나 뒤 Part로 넘기는 것 |
| --- | --- |
| 생성 모델이 어떤 패턴과 후보 분포를 학습하는가 | 학습된 후보 중 실제 출력을 어떤 규칙으로 꺼내는가 |
| 분류 문제와 생성 문제가 던지는 질문의 차이 | 토큰 단위 생성 설정과 서비스 품질 조정이 어떻게 달라지는가 |

이 절에서는 다음 내용을 깊게 다루지 않습니다.

- diffusion, GAN, VAE의 세부 알고리즘 비교
- likelihood 수식의 엄밀한 전개
- 샘플링 전략의 상세 수학

샘플링(sampling)과 출력 품질 변동은 바로 다음 P5-15.2에서 더 구체적으로 다루고, 텍스트 생성의 다음 토큰 예측은 P6-5.1에서 다시 연결합니다. diffusion, GAN, VAE의 세부 알고리즘 비교와 likelihood 수식 전개는 이 책의 현재 본편 범위 밖에 둡니다.

## 이 절의 목표

- 생성 모델을 `데이터 패턴을 배워 새로운 샘플이나 다음 출력을 만드는 모델`로 설명할 수 있습니다.
- 분류 모델과 생성 모델의 차이를 입문 수준에서 비교할 수 있습니다.
- `다음 토큰 예측`과 `이미지 생성`을 같은 생성 관점에서 묶어 설명할 수 있습니다.
- 실행 가능한 Python 예제로 분포 기반 생성 직관을 확인할 수 있습니다.

## 이 절을 읽는 순서

1. 먼저 분류 모델과 생성 모델이 던지는 질문이 어떻게 다른지 비교합니다.
2. 그 다음 `데이터 분포를 배운다`는 말을 입문 수준에서 풀어 읽습니다.
3. 이어서 텍스트 생성과 이미지 생성을 같은 생성 관점으로 묶어 봅니다.
4. 마지막에 왜 생성 문제가 `무엇을 배웠는가` 다음에 `무엇을 실제로 꺼내는가`로 이어지는지 정리합니다.

## 분류 모델과 생성 모델은 무엇이 다른가

분류 모델(classification model)은 보통 다음 질문에 답합니다.

- 이 입력은 어떤 클래스인가?
- 즉시 정지인가 기록만 남기면 되는가?
- 잔여 이상인가 안정 복귀인가?

즉, 입력을 어떤 범주로 매핑할지를 중심에 둡니다.

반면 생성 모델은 다음과 같은 질문에 더 가깝습니다.

- 이 데이터는 어떤 패턴으로 나타나는가?
- 이 문장 다음에는 어떤 토큰이 그럴듯한가?
- 이 그림 스타일에서는 어떤 픽셀 패턴이 자연스러운가?

즉, 생성 모델은 `새로운 출력 자체를 만들어 내는 문제`와 더 직접적으로 연결됩니다.

이 차이를 먼저 표로 보면 다음과 같습니다.

| 관점 | 분류 모델 | 생성 모델 |
| --- | --- | --- |
| 중심 질문 | 어떤 클래스인가 | 어떤 출력이 자연스러운가 |
| 대표 출력 | 라벨, 점수 | 다음 토큰, 새 문장, 새 이미지 |
| 대표 예 | 경보 등급 분류, 잔여 이상 판정 | 운영 안내 문장 생성, 장애 요약, 설비 이미지 생성 |

같은 장면을 두 방식으로 나눠 보면 차이가 더 직접 보입니다.

| 같은 입력 장면 | 분류 모델이 먼저 내놓는 것 | 생성 모델이 먼저 내놓는 것 |
| --- | --- | --- |
| 운영 문의 `라인 정지 후 재기동 순서를 알려줘` | `재기동 절차 문의` 같은 문의 유형 라벨 | `인터록 확인 후 저속 재기동을 시작하세요` 같은 실제 응답 문장 |
| 정비 보고 문장 `온도는 복귀했지만 압력 흔들림은 남아 있다` | `부분 회복` 또는 `잔여 이상` 같은 상태 라벨 | 회복 상태와 잔여 위험을 함께 담은 요약 문장 |
| 설비 장면 사진 | `혼합 탱크` 같은 설비 유형 라벨 | 설비 설명 문구나 대체 텍스트 초안 |

즉, 분류는 `무엇으로 볼 것인가`를 먼저 고르고, 생성은 `무엇을 실제로 말하거나 만들어 낼 것인가`를 바로 다룹니다.

## `데이터 분포를 배운다`는 말은 무엇을 뜻하나

독자는 `분포(distribution)`라는 말에서 바로 어려움을 느낄 수 있습니다. 여기서는 이를 `자주 함께 나타나는 패턴과 자연스러운 조합에 대한 통계적 감각`으로 먼저 잡습니다.

`데이터 분포를 배운다는 것은, 어떤 패턴이 자주 나타나고 어떤 조합이 자연스러운지에 대한 통계적 감각을 모델이 익힌다는 뜻이다.`

예를 들어 텍스트라면:

- 어떤 단어 뒤에 어떤 단어가 자주 오는지
- 어떤 문장 구조가 자연스러운지

를 배웁니다.

이미지라면:

- 어떤 색과 모양 조합이 함께 나타나는지
- 어떤 부분 구조가 자연스러운 객체를 이루는지

를 배울 수 있습니다.

이 말을 독자가 실제 장면으로 다시 붙잡으려면, `무엇을 많이 보고`, `무엇이 자연스럽게 함께 나오는지`, `무엇을 결과에서 확인해야 하는지`를 최소한으로 나눠 보는 편이 좋습니다.

| 데이터 종류 | 모델이 많이 보게 되는 패턴 | 결과에서 먼저 확인할 것 |
| --- | --- | --- |
| 운영 문장 | 어떤 조치 문구가 자주 이어지고 어떤 경고 문장 구조가 반복되는가 | 다음 문장과 안내 톤이 현재 경보 문맥에 맞게 이어지는가 |
| 설비 이미지 | 어떤 색, 윤곽, 배치가 자주 함께 나타나는가 | 구도와 형태가 어색하게 깨지지 않고 자연스러운가 |
| 현장 지원 응답 | 질문 유형마다 어떤 설명 길이와 답 구조가 자주 쓰이는가 | 답 순서와 경고 문구 배치가 상황에 맞게 달라지는가 |

즉, 생성 모델은 `정답 라벨만 맞추는 모델`보다 더 넓게 데이터 패턴 자체를 학습하려는 쪽에 가깝습니다.

## 왜 생성은 확률적 출력과 자주 연결되나

생성은 종종 하나의 정답만 있는 문제가 아닙니다.

예를 들어:

- 문장 다음 단어는 하나만 가능하지 않을 수 있고
- 그림을 그리는 방식도 여러 개가 자연스러울 수 있으며
- 요약 문장도 여러 표현이 가능할 수 있습니다

따라서 생성 모델은 `가능한 여러 출력 중 어떤 것이 더 그럴듯한가`를 다루는 경우가 많습니다. 이 때문에 확률(probability), 샘플링(sampling), temperature 같은 개념이 자연스럽게 따라옵니다.

`생성은 정답 하나를 찍는 일이 아니라, 그럴듯한 후보들 중 무엇을 낼지를 다루는 경우가 많다.`

## LLM과 이미지 생성은 어떻게 같은 관점으로 묶이나

표면적으로는 텍스트 생성과 이미지 생성이 매우 달라 보입니다. 하지만 생성 모델 관점에서는 공통점이 있습니다.

- 둘 다 데이터 패턴을 배웁니다
- 둘 다 새로운 출력을 만듭니다
- 둘 다 확률적 선택이나 샘플링과 연결될 수 있습니다

즉, 생성형 AI는 다양한 데이터 도메인에서 그럴듯한 새 출력을 만드는 모델들을 가리킵니다.

### 텍스트 생성

다음 토큰(next token)을 예측하며 문장을 이어 갑니다.

### 이미지 생성

픽셀이나 잠재 표현(latent representation)을 점차 구성하며 이미지를 만듭니다.

도메인은 달라도, `패턴을 학습해 새로운 결과를 만든다`는 공통 관점이 있습니다.

### 사례 1. 다음 단어 예측

운영 알림 문장 `배치 점검 결과` 뒤를 이어 쓰는 장면을 생각해 보겠습니다. 사람도 `재확인이 필요합니다`, `담당자 확인 후 재개합니다`, `10분 뒤 재측정합니다`처럼 여러 후속 조치 문구를 떠올릴 수 있지만, 처음에는 하나의 정답만 있어야 할 것처럼 느끼기 쉽습니다. 그런데 실제 운영 문장에서는 경보 맥락, 현장 상태, 안내 톤에 따라 자연스러운 다음 문구가 달라집니다. 예를 들어 센서 이상이 반복되면 `재확인이 필요합니다`가 더 어울리고, 이미 조치를 시작한 상태라면 `담당자 확인 후 재개합니다`가 더 자연스러울 수 있습니다. 분류처럼 정답 라벨 하나만 고르는 방식으로는 이 차이를 잘 담기 어렵습니다. 생성 모델은 바로 이 여러 후보의 상대적 가능성을 함께 배우고, 현재 맥락에서 더 자연스러운 쪽을 출력 후보로 올립니다.

### 사례 2. 현장 지원 응답

운영자가 `라인을 정지한 뒤 재기동은 어떤 순서로 하나요?`라고 묻는 현장 지원 장면을 생각해 볼 수 있습니다. 사람은 이런 질문에 SOP처럼 `정답 문장 하나`가 있을 것이라고 먼저 기대하기 쉽습니다. 하지만 실제 서비스에서는 정지 원인, 현재 설비 상태, 안전 주의사항에 따라 자연스러운 답 형태가 달라집니다. 예를 들어 센서 경보 정지였다면 `센서 상태 확인 -> 인터록 해제 -> 저속 재기동` 같은 짧은 단계 안내가 먼저 필요할 수 있고, 압력 이상 정지였다면 잔압 해소와 밸브 확인 순서를 먼저 보여 주는 편이 더 자연스러울 수 있습니다. 또 안전상 `재기동 전 현장 인원 이탈을 먼저 확인하세요` 같은 경고 문구를 앞에 둘지 뒤에 둘지도 답변 구성에 영향을 줍니다. 즉, 이 장면에서는 하나의 라벨보다 여러 그럴듯한 응답 구성이 존재합니다. 생성 모델은 이런 후보 분포를 다루며, 현재 문맥에서 더 자연스러운 길이, 말투, 순서를 가진 답을 이어 가는 쪽에 가깝습니다.

### 사례 3. 이미지 생성

`stainless mixing tank with side valve and warning beacon` 같은 프롬프트로 교육용 설비 이미지를 만든다고 해 보겠습니다. 사람은 머릿속에 한 장면을 먼저 떠올리며 그것이 정답처럼 느껴질 수 있습니다. 하지만 실제 시각 장면에서는 탱크 각도, 밸브 위치, 경광등 강조 방식, 배경 배관 배치가 달라도 모두 자연스러울 수 있습니다. 예를 들어 어떤 결과는 측면 밸브가 크게 보이고, 다른 결과는 상단 배관과 경광등이 더 강조될 수 있습니다. 사람이 단일 정답 그림만 기대하면 이런 차이를 오류로 읽기 쉽지만, 생성 모델 관점에서는 이것이 오히려 자연스러운 결과 공간입니다. 모델은 시각 패턴 분포를 학습해 여러 장면 조합을 출력 후보로 만들고, 그중 하나를 실제 결과로 냅니다.

세 사례에서 공통으로 확인해야 할 결과는 하나의 고정 답이 아니라 후보 분포가 실제 출력으로 펼쳐진다는 점입니다. 운영 문장에서는 어떤 조치 문구가 더 자주 선택되는지, 현장 지원 응답에서는 핵심 절차를 유지한 채 답 구조가 달라지는지, 이미지에서는 구도와 색감이 달라져도 핵심 장면이 유지되는지를 보면 충분합니다.

| 사람이 먼저 보기 쉬운 기준 | 생성 모델 관점으로 다시 읽는 기준 |
| --- | --- |
| 정답 하나만 찾으면 설명이 끝난다고 느끼기 쉽다 | 실제 핵심은 어떤 후보들이 얼마나 그럴듯한지 분포 전체를 함께 배우는 데 있다 |
| 가장 가능성 높은 후보 하나만 보면 충분하다고 본다 | 가장 높은 후보 뒤에도 다른 자연스러운 후보들이 함께 남아 있어야 생성 감각이 닫힌다 |
| 텍스트 생성과 이미지 생성은 전혀 다른 문제처럼 느끼기 쉽다 | 도메인은 달라도 `패턴을 학습해 새 출력을 만든다`는 후보 분포 학습 구조를 공유한다 |

같은 세 사례를 운영 판단 관점으로 다시 나눠 보면, 왜 생성 모델을 `정답 문장 하나 뽑기`로 읽으면 부족한지도 더 직접 보입니다.

| 사례 | 고정 답 하나만 찾을 때 남기 쉬운 것 | 후보 분포까지 볼 때 실제로 남는 것 |
| --- | --- | --- |
| 운영 안내 문구 생성 | 경보마다 템플릿 문구 하나만 반복하기 쉽다 | 같은 경보라도 재확인, 재측정, 담당자 확인 같은 여러 후속 문구 후보를 함께 유지한다 |
| 현장 지원 응답 | SOP 문장 한 줄만 정답처럼 내보내기 쉽다 | 잔압 해소 우선, 인터록 확인 우선, 경고 문구 선배치처럼 답 구조 후보를 함께 남긴다 |
| 설비 이미지 생성 | 정답 그림 한 장만 머릿속에 고정하기 쉽다 | 같은 프롬프트에서도 밸브 강조, 경광등 강조, 배관 배치 차이 같은 시각 후보 공간을 함께 남긴다 |

여기서 한 번 멈추고, `언제 라벨 예측보다 생성 관점 자체를 먼저 떠올려야 하는가`를 짧게 고정해 두면 다음 샘플링 절로 넘어갈 때 학습 단계와 출력 단계가 덜 섞입니다.

| 먼저 떠올릴 질문 | 생성 모델 관점이 먼저 필요한 이유 | 바로 다음 절에서 이어질 것 |
| --- | --- | --- |
| 왜 정답 하나가 아니라 여러 자연스러운 답이 가능한가 | 생성 문제는 라벨 선택보다 후보 분포 자체를 다루기 때문 | 그 후보들 중 무엇을 실제로 꺼낼 것인가 |
| 왜 LLM과 이미지 생성이 같은 축으로 설명되는가 | 도메인은 달라도 패턴을 학습해 새 출력을 만든다는 공통 구조를 가지기 때문 | 샘플링과 다양성 조절 |
| 왜 분류 설명만으로는 운영 안내 문구 생성이나 현장 지원 응답을 설명하기 어려운가 | 출력이 범주명이 아니라 실제 문장, 이미지, 구성 자체이기 때문 | 출력 선택 절차와 사용자 경험 차이 |

## 연습 및 예제

이번 예제의 목표는 생성 모델이 `경보 유형마다 어떤 후속 조치 문구가 자주 이어졌는가`를 분포로 배우는 모습을 확인하는 것입니다. 아직 실제 샘플링은 하지 않지만, 모델이 무엇을 배운다고 말하는지 운영 기록 관점에서 먼저 잡는 데 목적이 있습니다.

코드를 읽기 전에 아래 세 값부터 같이 보면 이 절의 질문이 덜 흩어집니다.

| 먼저 볼 값 | 왜 먼저 보아야 하는가 |
| --- | --- |
| `probabilities` | 생성 모델이 `무엇이 자주 이어졌는가`를 하나의 라벨이 아니라 분포로 붙잡는다는 점을 보여 줘서 |
| `most_likely` | 가장 그럴듯한 후보가 무엇인지와, 그것이 분포 전체와 어떻게 다른지 함께 볼 수 있어서 |
| `temperature_alert`와 `seal_edge_alert`의 차이 | 같은 생성 모델도 맥락이 바뀌면 전혀 다른 후보 분포를 배운다는 점을 확인할 수 있어서 |

입력:

- 서로 다른 두 종류의 운영 경보 맥락
- 각 맥락에서 과거에 자주 이어졌던 후속 조치 문구 횟수

출력:

- 경보 유형별 후속 조치 확률 분포
- 각 경보에서 가장 가능성이 큰 후속 조치

문제 상황:

- 생성 모델이 무엇을 배운다고 할 때, 실제 운영 기록에서는 `다음에 이어질 수 있는 문구 분포`를 어떻게 이해할지 먼저 확인할 필요가 있다

확인할 개념:

- 생성 모델은 후보 하나만 결정하는 대신 후보 분포 자체를 배운다
- 같은 맥락이라도 하나의 후속 조치만 있는 것이 아니라 여러 문구가 상대적 비중으로 함께 남는다
- 맥락이 바뀌면 가장 가능성이 큰 후보와 전체 분포가 함께 달라진다

코드를 보기 전에, 두 경보 맥락을 `하나의 라벨만 고르는 읽기`와 `후보 분포를 남기는 읽기`로 나눠 예상해 보면 좋습니다.

| 맥락 | 라벨 하나만 고르는 읽기에서 생기기 쉬운 오해 | 생성 모델 관점에서 먼저 예상할 변화 |
| --- | --- | --- |
| `temperature_alert` | `가장 흔한 후속 조치 하나`만 알면 충분하다고 느끼기 쉽다 | 첫 후보가 가장 높더라도 다른 점검 문구들이 함께 분포에 남아야 한다 |
| `seal_edge_alert` | 앞 경보와 비슷한 운영 응답이 나올 것이라고 느끼기 쉽다 | 맥락이 바뀌면 가장 높은 후보와 전체 분포가 함께 달라져야 한다 |
| 두 경보 모두 | `most_likely`만 보면 생성 설명이 끝났다고 느끼기 쉽다 | `probabilities`를 같이 봐야 모델이 무엇을 배웠는지 설명할 수 있다 |

여기서 실제로 확인하려는 차이도 분명합니다. `most_likely`만 들고 가는 읽기는 `이 경보에는 이 문구`처럼 템플릿 하나만 남기기 쉽고, `probabilities`까지 보는 읽기는 `같은 경보라도 어떤 점검 순서와 경고 문구가 함께 가능한가`를 후보 집합으로 남기게 합니다. 즉, 생성 모델은 답 하나를 고정하는 대신 `운영 응답 공간`을 함께 배운다고 읽어야 합니다.

입력(input):

위에 정리한 경보 유형별 후속 조치 기록 횟수를 사용합니다.

```python
history = {
    "temperature_alert": {
        "냉각수 유량을 먼저 점검한다.": 14,
        "열교환기 팬 상태를 확인한다.": 9,
        "센서 보정 여부를 다시 본다.": 5,
    },
    "seal_edge_alert": {
        "실링 압력을 다시 맞춘다.": 13,
        "필름 장력을 재조정한다.": 8,
        "칼날 마모 상태를 확인한다.": 4,
    },
}

for case, counts in history.items():
    total = sum(counts.values())
    probabilities = {text: round(count / total, 2) for text, count in counts.items()}
    ranked = sorted(probabilities.items(), key=lambda item: (-item[1], item[0]))
    print(case)
    print("probabilities =", probabilities)
    print("most_likely =", ranked[0])
```

출력에서는 각 맥락마다 하나의 답만 남는 것이 아니라, `다음에 이어질 수 있는 후속 조치 분포`가 통째로 정리되는지를 보면 됩니다.

```text
temperature_alert
probabilities = {'냉각수 유량을 먼저 점검한다.': 0.5, '열교환기 팬 상태를 확인한다.': 0.32, '센서 보정 여부를 다시 본다.': 0.18}
most_likely = ('냉각수 유량을 먼저 점검한다.', 0.5)
seal_edge_alert
probabilities = {'실링 압력을 다시 맞춘다.': 0.52, '필름 장력을 재조정한다.': 0.32, '칼날 마모 상태를 확인한다.': 0.16}
most_likely = ('실링 압력을 다시 맞춘다.', 0.52)
```

| 먼저 볼 출력 | 이 출력이 뜻하는 것 | 바꿔 보면 달라지는 것 |
| --- | --- | --- |
| `temperature_alert`의 `probabilities` | 온도 경보 맥락에서는 `냉각수 유량 점검`이 가장 자주 이어지되, 다른 조치도 함께 분포에 남는다는 뜻 | 기록 비중을 바꾸면 가장 가능성 큰 조치와 분포 폭이 함께 달라집니다 |
| `seal_edge_alert`의 `probabilities` | 실링 경계 경보에서는 전혀 다른 후속 조치 집합이 중심이 된다는 뜻 | 맥락 종류를 더 추가하면 생성 모델이 맥락별로 다른 문구 분포를 배우는 모습이 더 선명해집니다 |
| 각 맥락의 `most_likely` | 분포 전체와 별개로 가장 가능성 높은 한 후보를 따로 읽을 수 있다는 뜻 | 하나만 고정해 읽으면 뒤에 남아 있는 다른 후보 가능성을 놓치게 됩니다 |

| 운영 응답 설계 기준 | `most_likely`만 보면 쉬운 판단 | `probabilities`까지 읽고 바뀌는 판단 |
| --- | --- | --- |
| 온도 경보 안내 | `냉각수 유량 점검` 문구 하나만 고정 응답처럼 내보내기 쉽다 | 팬 상태 확인, 센서 보정 재확인도 함께 후보에 남겨 두고, 상황에 따라 후속 문장을 더 붙일 수 있다고 읽게 된다 |
| 실링 경계 경보 안내 | 앞 경보와 비슷한 점검 문구를 재사용해도 된다고 느끼기 쉽다 | 실링 압력, 필름 장력, 칼날 마모처럼 전혀 다른 후보 집합을 따로 유지해야 한다고 읽게 된다 |

이 차이를 운영 문구 설계 결정으로 더 직접 바꾸면, `가장 높은 후보 하나를 곧바로 고정 템플릿으로 잠글 것인가`, `후보 공간을 남겨 두고 뒤 문장과 경고 배치를 조정할 것인가`의 차이로 읽을 수 있습니다.

| 예제 맥락 | `most_likely`만 붙잡았을 때 덜 나쁜 읽기 | `most_likely`만 붙잡았을 때 더 위험한 읽기 | `probabilities`까지 읽고 더 안전해지는 다음 판단 |
| --- | --- | --- | --- |
| `temperature_alert` | `냉각수 유량 점검`을 첫 문장으로 두고 끝낼 수 있다 | 팬 상태나 센서 보정 재확인 후보를 버려, 후속 점검 순서를 템플릿 하나로 굳혀 버릴 수 있다 | 첫 문장은 유량 점검으로 시작하되, 팬 상태와 센서 보정 재확인을 뒤 문장 후보로 함께 남겨 상황별 후속 안내를 조정한다 |
| `seal_edge_alert` | `실링 압력을 다시 맞춘다`를 기본 조치로 제시할 수 있다 | 온도 경보와 비슷한 응답 톤을 재사용해 필름 장력, 칼날 마모 확인을 늦게 붙이거나 빠뜨릴 수 있다 | 실링 압력 조정을 첫 후보로 두되, 필름 장력과 칼날 마모 확인을 같은 후보 공간 안에 유지해 다른 설비 원인에도 바로 이어지게 한다 |

- 생성 모델은 `다음에 뭐가 올까`를 한 문장으로 외우는 것이 아니라, `이 맥락에서는 무엇이 얼마나 자주 이어졌는가`를 분포로 정리합니다.
- 가장 가능성이 큰 후보가 하나 있어도, 그 뒤에는 여전히 다른 후보들이 함께 남아 있습니다.
- 따라서 `most_likely`만 보면 분류처럼 읽히기 쉽고, `probabilities`까지 함께 봐야 생성 모델이 배운 후보 공간이 보입니다.
- 이 차이를 봐야 생성 문제를 `정답 라벨 하나 선택`이 아니라 `후보 분포를 학습하는 일`로 읽게 됩니다.

이 결과를 운영 지원 시스템으로 바꾸면, `most_likely`만 보는 시스템은 경보마다 고정 문구 하나만 반복하는 템플릿처럼 읽히기 쉽고, `probabilities`까지 보는 시스템은 같은 경보에서도 점검 순서, 경고 문구, 후속 안내를 여러 후보 조합으로 준비할 수 있는 구조에 가깝습니다. 생성 모델이 배우는 것은 바로 이 `후보 응답 공간`이며, 실제 출력 단계에서는 이 공간을 얼마나 좁힐지와 얼마나 남겨 둘지를 다음 절의 샘플링에서 다시 결정하게 됩니다.

이 예제도 한 번 보고 끝내기보다, 어떤 값을 바꿔 보면 후보 분포 감각이 더 선명해지는지 바로 이어서 확인하는 편이 좋습니다.

| 먼저 보인 출력 신호 | 지금 바로 해 볼 변화 | 아직 이 예제만으로 서두르지 않을 결론 |
| --- | --- | --- |
| 온도 경보에서 한 후보가 0.5로 가장 높다 | 첫 후보 기록 수를 늘리거나 줄여 가장 가능성 큰 조치가 얼마나 빨리 바뀌는지 본다 | 가장 높은 후보가 있다고 해서 생성이 곧 결정론적이라고 단정하지 않는다 |
| 실링 경보에서도 세 후보가 함께 남아 있다 | 후보를 더 추가하거나 제거해 분포 폭이 어떻게 달라지는지 본다 | 후보가 여러 개 남는다는 사실만으로 바로 좋은 운영 품질이라고 단정하지 않는다 |
| 맥락이 바뀌면 분포 전체가 달라진다 | 새로운 경보 유형을 더 추가해 문구 분포가 어떻게 갈라지는지 본다 | 지금 본 축약 운영 예제 두 개만으로 실제 대규모 생성 모델 학습 전체를 바로 일반화하지 않는다 |

## 체크리스트

- 생성 모델(generative model)이 분류 모델과 다른 질문을 푼다는 점을 설명할 수 있는가?
- 생성 모델이 `어떤 출력이 자연스러운가`를 배운다는 뜻을 말할 수 있는가?
- 생성 모델은 데이터 패턴을 학습해 새로운 샘플이나 다음 출력을 만드는 모델이라는 점을 설명할 수 있는가?
- 분류 모델은 범주를 고르고, 생성 모델은 출력 자체를 만든다는 점을 말할 수 있는가?
- 생성 문제는 여러 그럴듯한 답이 가능하므로 확률적 출력과 자주 연결된다는 점을 설명할 수 있는가?
- 생성 모델을 `무언가를 만들어 내는 모델` 정도로만 말하지 않고, `어떤 출력이 자연스러운지에 대한 후보 분포를 학습하는 모델`로 설명할 수 있는가?
- 같은 입력 장면에서 분류가 먼저 주는 것과 생성이 먼저 주는 것을 사례로 구분할 수 있는가?
- 다음 절의 샘플링을 읽을 때도 먼저 `무엇을 배웠는가`와 `무엇을 실제로 꺼낼 것인가`를 나눠 볼 준비가 되어 있는가?
