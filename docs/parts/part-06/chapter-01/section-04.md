# P6-1.4 토큰화(tokenization)는 무엇인가

Section ID: `P6-1.4`
Version: `v2026.07.12`

토큰이 계산 단위라는 점을 알았다면, 이제 문자열이 실제로 그 계산 단위로 어떻게 바뀌는지를 봐야 합니다. 토큰화(tokenization)는 원문 텍스트를 모델이 읽는 토큰 시퀀스로 바꾸는 절차입니다.

이 절에서 먼저 붙잡아야 할 문장은 하나입니다.

`토큰화는 문자열을 모델 계산에 들어갈 조각들로 바꾸는 과정이다.`

## 토큰화는 왜 따로 필요한가

사람은 문장을 글자, 단어, 문장으로 봅니다. 하지만 모델은 이 단위를 그대로 계산에 쓰지 않습니다. 먼저 입력을 계산 가능한 조각들로 바꿔야 하고, 그 조각에 번호를 붙여 계산으로 넘겨야 합니다.

즉 토큰화는 부가 기능이 아니라, `문자열 -> 계산 입력`으로 넘어가는 첫 관문입니다.

## 토큰화는 실제로 무엇을 하나

토큰화에서는 보통 다음 일이 함께 일어납니다.

- 원문 문자열을 끊을 경계를 정한다.
- 끊어 낸 조각을 토큰 vocabulary와 연결한다.
- 각 조각을 토큰 ID로 바꿔 모델 계산으로 넘긴다.

사람이 보기에는 한 단어처럼 보여도 더 잘게 나뉠 수 있고, 반대로 자주 함께 나오는 조각은 하나로 묶일 수도 있습니다.

같은 과정을 더 단계적으로 적으면 다음과 같습니다.

| 단계 | 여기서 일어나는 일 | 사람이 흔히 하는 오해 |
| --- | --- | --- |
| 1. 문자열을 본다 | 원문에서 어디를 끊을지 정한다 | 글자나 단어 경계가 그대로 유지될 것이라고 생각한다 |
| 2. 조각을 고른다 | 토큰 vocabulary에 있는 조각과 연결한다 | 사람이 느끼는 단어와 같은 조각이 항상 있을 것이라고 생각한다 |
| 3. ID로 바꾼다 | 각 조각에 대응하는 토큰 ID를 만든다 | 모델이 문장을 바로 이해한다고 생각한다 |

즉, 토큰화는 `문자열을 자른다`에서 끝나지 않고, `모델이 실제로 계산 가능한 입력으로 바꾼다`까지 이어지는 절차입니다.

## 사례 및 예시

### 사례 1. 단어처럼 보이는 것을 그대로 믿을 때

사람은 `환불정책`이나 `Authorization` 같은 표현을 한 덩어리로 읽기 쉽습니다. 하지만 토큰화 단계에서는 이런 표현이 더 잘게 나뉠 수 있습니다. 그래서 토큰화는 `사람이 어디서 끊어 읽는가`와 `모델이 어디서 계산 단위를 잡는가`를 분리해서 보게 만듭니다.

### 사례 2. 공백이 있으니 단위도 같을 것이라고 생각할 때

`회의는 내일 오전 10시에 시작합니다`처럼 공백이 있는 문장도, 모델 쪽에서는 `오전`, `10`, `시`처럼 다른 조각 경계로 바뀔 수 있습니다. 이 장면에서 중요한 것은 공백 자체보다 `어떤 조각이 vocabulary에 있고 어떤 조각으로 계산에 넘겨지는가`입니다.

### 사례 3. 문장을 바로 계산한다고 느낄 때

초심자는 모델이 문장을 통째로 읽는다고 상상하기 쉽습니다. 하지만 실제로는 `문장 -> 토큰 시퀀스 -> 토큰 ID -> 벡터` 흐름을 거칩니다. 그래서 토큰화는 의미 해석 이전의 사소한 전처리가 아니라, 계산을 시작시키는 필수 단계입니다.

이 사례에서 확인해야 할 결과는 토큰화가 부가 작업이 아니라, 문자열을 실제 계산 입력으로 넘기는 출발 단계라는 점입니다.

## 무엇과 무엇을 구분해야 하나

토큰화를 이해할 때는 아래 세 층위를 구분하는 편이 안전합니다.

| 층위 | 여기서 하는 일 |
| --- | --- |
| 원문 문자열 | 사람이 읽는 글자와 표기 |
| 토큰화 | 문자열을 계산 조각으로 나누는 과정 |
| 모델 계산 | 토큰 ID와 벡터로 실제 계산을 수행하는 단계 |

이 구분이 없으면 `토큰이 곧 단어인가`, `모델이 문장을 그대로 읽는가` 같은 혼동이 반복됩니다.

## 여기서 아직 하지 않아도 되는 일

이 절에서 아직 몰라도 되는 것도 분명합니다.

- 각 토큰이 정확히 몇 개인지 손으로 셀 필요는 없습니다.
- BPE, WordPiece, SentencePiece 차이를 여기서 먼저 외울 필요도 없습니다.
- 비용, 청크, 출력 길이 변화까지 이 절에서 모두 닫을 필요도 없습니다.

지금 필요한 수준은 다음 정도면 충분합니다.

- 토큰화는 문자열을 토큰 시퀀스로 바꾸는 절차다.
- 토큰화가 있어야 문자열이 모델 계산 입력으로 넘어간다.
- 사람이 보는 단위와 모델이 계산하는 조각은 다를 수 있다.

같은 내용을 마지막으로 한 번 더 줄이면 다음과 같습니다.

| 지금 붙잡을 것 | 뒤 절에서 이어질 질문 |
| --- | --- |
| 문자열은 바로 계산되지 않는다 | 그러면 이 분절 차이가 실제로 무엇을 바꾸는가 |
| 토큰화는 조각과 ID를 만든다 | 그 결과 비용, 청크, 출력 길이는 어떻게 달라지는가 |
| 사람 단위와 모델 단위는 다를 수 있다 | 어떤 장면에서 그 차이가 더 크게 드러나는가 |

다음 절에서는 바로 이 토큰화가 실제로 무엇을 바꾸는지 봅니다.
