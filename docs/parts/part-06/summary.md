# Part 6 마무리. 프로젝트 정리

Part 6은 앞선 다섯 Part에서 복구하고 정리한 개념을 `작은 산출물`로 다시 확인하는 구간입니다. 이 Part의 핵심은 대형 서비스를 완성하는 것이 아니라, 문제 정의, 데이터 준비, 구현, 평가, 회고라는 공통 흐름을 직접 밟아 보는 데 있습니다.

프로젝트 파트는 특히 두 가지를 동시에 확인하게 합니다.

- 개념을 설명할 수 있는가?
- 설명한 개념을 작은 코드와 결과로 다시 확인할 수 있는가?

즉, 이 Part는 `알고 있다`는 감각을 `해 보고 기록했다`는 상태로 바꾸는 구간입니다.

## 이 파트의 목적

Part 6의 목적은 책 전체에서 배운 개념을 작은 프로젝트 문서와 실행 결과로 다시 묶어, 다음 학습이 스스로 반복 가능한 형태가 되게 만드는 데 있습니다.

## 이 파트의 목표

이 Part를 마친 뒤에는 문제 정의, baseline, 결과, 실패 기록, 다음 개선 계획을 작은 산출물로 남기는 흐름을 스스로 설명할 수 있어야 합니다.

## 이 파트에서 다룬 핵심 흐름

Part 6의 전체 흐름은 다음처럼 정리할 수 있습니다.

> 작은 데이터 읽기
> -> 질문을 정하고 탐색 결과를 요약하기
> -> 기준 모델(baseline)과 개선 모델 비교하기
> -> 딥러닝/텍스트 분류 흐름을 작은 예제로 축소해 보기
> -> RAG와 agent 구조를 작은 서비스 프로젝트로 연결하기
> -> 배포, 로그, 실패 대응, 회고 문서까지 남기기

프로젝트마다 주제가 다르더라도, 공통적으로 남아야 하는 질문은 같습니다.

> 무엇을 풀려는가?
> 입력과 출력은 무엇인가?
> 데이터는 어떻게 준비했는가?
> 기준점은 무엇인가?
> 결과는 어떻게 확인했는가?
> 실패와 한계는 무엇이었는가?
> 다음 개선은 어디에서 시작해야 하는가?

## 반드시 기억할 개념

Part 6에서 꼭 가져가야 할 관점은 다음과 같습니다.

| 구분 | 기억할 관점 |
| --- | --- |
| 문제 정의 | 프로젝트는 구현보다 먼저 질문을 분명히 해야 합니다. |
| 기준점 | baseline이 없으면 좋아졌다는 말도 약해집니다. |
| 데이터 | 작은 장난감 데이터라도 입력(input), 출력(output), 분리 기준은 분명해야 합니다. |
| 평가 | 프로젝트 결과는 숫자와 사례를 함께 읽어야 합니다. |
| 회고 | 실패, 누락, 모호함을 남기는 일이 프로젝트 문서의 핵심입니다. |
| 재현성 | 다시 실행할 수 있는 입력과 코드, 출력 기록이 필요합니다. |
| 서비스 관점 | LLM 프로젝트는 답변 품질만이 아니라 검색 실패, 권한, 지연 시간, 로그까지 함께 봐야 합니다. |

## 오해하기 쉬운 지점

이 Part에서 특히 조심할 오해는 다음과 같습니다.

- 프로젝트는 `성공 사례 모음`만 남기면 된다고 생각하기 쉽습니다.
- 결과 숫자 하나만 높으면 프로젝트가 잘 끝났다고 오해하기 쉽습니다.
- 작은 예제를 만들었다고 해서 바로 실무형 서비스 구조를 이해한 것은 아닙니다.
- 코드가 실행된 것과, 문제 정의가 타당한 것은 같은 말이 아닙니다.
- LLM 프로젝트에서 답변이 한두 번 잘 나온다고 평가가 끝난 것은 아닙니다.
- 운영 실패를 기록하지 않으면 다음 개선이 어려워집니다.

## 이 파트에서 설명하는 범위와 설명하지 않을 범위

Part 6은 프로젝트 입문 구조를 설명하는 데 집중했습니다. 따라서 작은 목표 설정, 구현, 평가, 회고, 운영 기록은 다루지만, 대규모 인프라와 장기 운영 체계 전체를 여기서 끝내지는 않습니다.

## 앞선 Part와의 연결

Part 6은 Part 1의 지도, Part 2의 계산 언어, Part 3의 머신러닝 공통 구조, Part 4의 딥러닝, Part 5의 LLM·RAG·agent 관점을 하나의 프로젝트 문서 흐름으로 다시 묶는 파트였습니다.

## 이후 Part로의 연결

이 책 안의 다음 numbered Part는 없지만, Part 6 이후에는 더 큰 데이터셋, 더 긴 실험 기록, 더 정교한 평가 체계, 더 실제적인 운영 문서로 학습을 확장해야 합니다.

## 이 파트에서 끝내지 않는 질문

Part 6은 다음 질문을 독자의 이후 프로젝트로 넘깁니다.

- 어떤 주제를 다음 실제 프로젝트로 확장할 것인가?
- 평가와 실패 기록을 팀 단위 문서로 어떻게 키울 것인가?
- 운영과 배포를 어디까지 자동화하고 어디서 사람 검토를 둘 것인가?

즉, Part 6은 책의 종착점이라기보다 이후 자율 프로젝트의 출발점입니다.

## 다음 파트와 연결되는 관점

이 책의 다음 numbered Part는 없지만, 이후 학습은 `더 큰 문제 정의 -> 더 나은 기준점 -> 더 긴 실험 기록 -> 더 엄격한 운영 검토`로 이어집니다. Part 6의 관점은 그 다음 반복을 직접 설계하게 만드는 기준점입니다.

## 다음 학습으로 넘어가기 전에 확인할 질문

- 각 프로젝트에서 문제 정의와 출력 기준을 한 문장으로 설명할 수 있는가?
- baseline과 개선안을 분리해 기록했는가?
- 데이터 준비와 분리 과정을 다시 실행할 수 있는가?
- 결과를 수치와 사례로 함께 읽었는가?
- 실패 사례와 개선 계획을 남겼는가?
- LLM 프로젝트라면 검색, 도구 호출, 권한, 로그, 실패 대응을 함께 점검했는가?

## 이 책 전체와 연결되는 관점

Part 6까지 왔다면 이 책의 전체 흐름은 다음처럼 묶입니다.

> Part 1에서 지도를 잡았다.
> Part 2에서 계산 언어와 실행 환경을 복구했다.
> Part 3에서 머신러닝의 공통 구조를 정리했다.
> Part 4에서 신경망과 딥러닝의 핵심 계산을 연결했다.
> Part 5에서 LLM과 생성형 AI의 구조를 서비스 관점까지 확장했다.
> Part 6에서 그 흐름을 작은 프로젝트로 다시 검증했다.

이 흐름이 연결되면 AI를 `유행하는 모델 이름 모음`으로 보지 않고, 문제 정의, 데이터, 모델, 평가, 운영의 연속된 구조로 읽을 수 있게 됩니다.

## Part 6을 마치며

프로젝트 파트의 목적은 거대한 결과물을 만드는 데 있지 않습니다. 오히려 작은 결과물을 통해 `내가 무엇을 이해했고, 무엇이 아직 불안정한지`를 드러내는 데 있습니다.

이 Part를 마치면 독자는 다음 단계를 스스로 설계할 수 있어야 합니다.

- 더 큰 데이터셋으로 확장하기
- 더 적절한 평가 지표를 붙이기
- RAG 품질을 비교 실험하기
- agent 권한과 로그 정책을 더 정교하게 다듬기
- 운영 비용과 실패 대응을 별도 문서로 분리하기

즉, Part 6은 끝이라기보다 `이제부터는 스스로 프로젝트를 만들어 다시 배우는 단계`로 넘어가는 출발점입니다.
