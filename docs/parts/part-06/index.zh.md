# Part 6. LLM 与生成式 AI

> Section ID: `P6-index`
> Version: `v2026.07.21`

Part 6 以 LLM 作为代表案例来阅读生成式 AI。这个 Part 的起点不是 token，而是生成式 AI 的产出物。首先要抓住生成式 AI 到底制造什么，为什么以 LLM 作为代表路径，以及为什么生成要被读成候选分布与选择的反复。

随后，文本生成会进入 token 与 embedding 这样的输入单位，Transformer 与 GPT 结构会被读成制造下一个候选的流程。接着，预训练、微调、指令微调与对齐会说明回答习惯怎样形成，prompt、RAG、向量数据库、工具使用、agent、MCP 与 harness 则会把生成结果补强成实际可用的服务结构。

最后，通过 LLM 评价、自动评价与人工评价、服务运营约束、失败应对，以及一个小型生成式 AI 功能流程，区分自然回答与可检查的服务结果。发展史与 BERT 系列放在主线之后，作为背景地图与比较轴，避免把 GPT 中心说明过度泛化。

## 这个 Part 要抓住的问题

- 生成式 AI 的产出物与分类值或数值预测有什么不同？
- 为什么以 LLM 为中心案例，而不是把它等同于全部生成式 AI？
- 为什么 LLM 的生成要读成候选分布与选择的反复？
- token、embedding、Transformer、GPT、next-token prediction 按什么顺序连接？
- 只靠 prompt 能处理的事，与需要 RAG、工具使用、agent 的事有什么不同？
- 自然的生成回答与可运营的服务结果为什么不同？

## 阅读顺序

```text
生成式 AI 产出物
-> LLM 代表路径
-> 候选分布与选择反复
-> token 与 embedding
-> 制造下一个候选的 LLM 结构
-> 形成回答习惯的学习与调节
-> prompt 与证据补强
-> 工具与 agent 执行结构
-> 可检查的服务状态
-> 背景地图与比较
```
