# Part 6 收尾

> Section ID: `P6-summary`
> Version: `v2026.07.21`

Part 6 以 LLM 作为代表案例来阅读生成式 AI。核心不是把 LLM 等同于全部生成式 AI，而是把它作为一条路径，用来把生成式 AI 的产出物、计算单位、生成结构、使用补强、评价与运营放在同一流程中观察。

## 必须留下的感觉

- 生成式 AI 的输出是需要检查的产出物。
- LLM 的生成不是一次性取出完成答案，而是反复从候选分布中选择。
- 文本生成会经过 token 与 embedding，变成可计算的表示。
- Transformer 与 GPT 结构要读成反映上下文并制造下一个候选的流程。
- 预训练、微调、指令微调与对齐，各自学习或调节的对象不同。
- prompt、RAG、向量数据库、工具使用与 agent 会把生成结果补强成实际可用的服务结构。
- 好句子与可服务的回答不同，评价、成本、延迟、失败应对与执行记录要一起检查。
- 发展史与 BERT 系列是背景地图，用来避免把 GPT 中心主线过度泛化。

## 交给下一个 Part 的问题

Part 7 会通过实际项目产出物确认这条流程。现在重要的问题不是先问 `要做什么生成式 AI 功能`，而是先问 `请求、证据、输出、评价、失败应对与记录要怎样留下来`。
